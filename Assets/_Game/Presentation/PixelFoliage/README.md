# 픽셀 풀 바람 — UV 변형 버전

이전 PixelWind의 밝기 파동/레이어 이동은 삭제했습니다. 이 버전은 **원본 그림을 읽는 좌표를 정수 픽셀만큼 바꿔 무늬 자체를 흔듭니다.** 색을 밝게/어둡게 애니메이션하지 않습니다.

## 지금 적용된 곳

`Assets/_Game/Content/Maps/Development/BunnySlimeBattleLab/Scenes/BunnySlimeBattleLab.unity`

Hierarchy **Grid → Tilemap**에 새 머티리얼과 **PixelFoliageWind**를 연결했습니다. 씬을 열고 Play하면 기존 잔디 그림에 바로 적용됩니다. 이미 해당 씬이 열려 있다면 디스크 변경을 반영한 뒤 확인하세요. 저장하지 않은 다른 작업이 있다면 먼저 보존하고, 이전 씬 상태를 그대로 저장해 새 연결을 덮어쓰지 않도록 주의하세요.

현재 씬은 **Tilemap = 잔디 252칸(바람)**, **Tilemap_Walls = 벽 168칸(정적)**으로 분리되어 있습니다. 이전에는 grass.png와 wall.png를 한 Tilemap에 그려 둬서 안전 검사가 바람 전체를 끄고 있었습니다. 앞으로도 벽은 Tilemap_Walls에, 잔디는 Tilemap에 그리세요. 기존 420칸의 위치·타일·그림·색·변환은 그대로 보존했습니다.

## 조절은 컴포넌트에서

### 빠른 사용

1. **불러올 프리셋**을 선택하고 **프리셋 적용**을 누릅니다. 선택만으로 기존 값이 바뀌지는 않습니다.
2. 좌우/상하 픽셀과 속도를 조절합니다. 적용 후 수동 편집해도 프리셋이 다시 덮어쓰지 않습니다.
3. 같은 장식을 복제했다면 **엇박자 바꾸기**로 움직임 시점을 다르게 합니다. 위치에 따른 차이도 원래 적용됩니다.
4. Edit Mode에서 적용/엇박자 변경은 Undo/Redo 가능합니다. Play 중 조절값은 일반 Unity 런타임 변경처럼 종료 후 유지되지 않습니다.

### 7가지 시작값

픽셀 이동은 그대로이며 속도·폭·고정점을 조합합니다. 아래 값은 32~64px 아트의 **조정 시작값**이지 모든 그림에서 검증된 최종 연출은 아닙니다.

| 프리셋 | 좌우 / 상하 | 속도 | 공간 차이 | 고정점 / 강도 | 경계 고정 | 추천 용도 |
|---|---:|---:|---:|---|---:|---|
| 잔디 · 잔잔함 | 1 / 0px | 0.25 | 0.8 | 없음 / 0 | 2px | 마을, 실내 화단 옆 바닥 |
| 잔디 · 기본 바람 | 2 / 0px | 0.45 | 1.1 | 없음 / 0 | 2px | 현재 실험실과 같은 바닥 잔디 |
| 잔디 · 강한 바람 | 3 / 0px | 0.75 | 1.4 | 없음 / 0 | 2px | 바람 센 절벽·고지대 |
| 꽃 / 세워진 풀 | 2 / 0px | 0.35 | 0.4 | 아래 / 1 | 0px | 꽃대, 갈대, 장식용 풀 |
| 덤불 / 나뭇잎 | 2 / 1px | 0.30 | 0.8 | 아래 / 0.25 | 0px | 나뭇잎 덩어리, 관목 윗부분 |
| 매달린 천 / 덩굴 | 3 / 0px | 0.28 | 0.4 | 위 / 1 | 0px | 커튼, 위에서 늘어진 덩굴 |
| 몽환 흔들림 | 1 / 1px | 0.20 | 0.6 | 없음 / 0 | 0px | 환상 식물·작은 장식의 그림 변형 |

연결된 바닥 Tilemap에는 첫 3개를 권장합니다. 나머지는 투명 여백이 있는 별도 SpriteRenderer용 시작값입니다. **몽환 흔들림은 오브젝트 부유 이동이 아니고, 천 프리셋은 천 물리 시뮬레이션이 아닙니다.**

### 세부 조절

| 항목 | 현재 값 | 용도 |
|---|---:|---|
| 좌우 흔들림 | 2px | 먼저 2~3px로 확인 |
| 상하 흔들림 | 0px | 필요할 때 1px 정도 |
| 초당 흔들림 주기 | 0.45 | 작게 하면 천천히 |
| 구역별 바람 차이 | 1.1 | 위치에 따라 다른 파동 |
| 고정 강도 | 0 | 바닥 잔디는 0, 세워진 풀은 1에 가깝게 |
| 위쪽을 고정 | 꺼짐 | 꺼짐=아래, 켜짐=위. 고정 강도 0이면 차이 없음 |
| 타일 경계 고정 폭 | 2px | 타일 경계가 갈라지지 않도록 가장자리는 덜 움직임 |

머티리얼 수치보다 컴포넌트의 값이 우선합니다. Inspector의 **연결 상태**에 `정상: Tilemap / grass / 32×32px / UV 픽셀 이동`이 나오면 설정이 전달된 것입니다. 체크 해제하면 원본 그림으로 돌아갑니다. 텍스처를 섞으면 `바람 꺼짐: grass / wall ...`처럼 원인과 분리 방법을 표시합니다.

## 다른 곳에 적용

1. 실제 SpriteRenderer 또는 **Grid 아래 TilemapRenderer**의 Material에 `Mat_PixelFoliage_Grass` 지정.
2. 같은 오브젝트에 `PixelFoliageWind` 추가. Grid 부모에는 붙이지 않습니다.
3. `설정 적용 / 연결 확인` 버튼과 연결 상태 확인. Material을 나중에 바꾸었다면 이 버튼을 누릅니다.

현재 Tilemap 지원 조건은 **한 텍스처 안에 같은 크기로 정렬된 타일, 동일 PPU, SpriteAtlas 패킹 없음**입니다. 현재 `grass.png`의 96×96 시트/32×32 타일/32 PPU에 맞습니다. 지원하지 않는 혼합 크기·텍스처·패킹은 상태에 이유를 표시하고 효과를 끕니다. UI Image, Sprite Skin, Sliced/Tiled SpriteRenderer는 대상이 아닙니다.

일반 스프라이트에서 외곽까지 크게 흔들려면 Full Rect 메쉬와 2~4픽셀 정도의 투명 여백을 권장합니다. UV 변형은 원래 메쉬 밖에 그림을 새로 그리지 않습니다. 타일맵 바닥은 무늬가 움직이는 효과이며, 원본에 없는 독립 풀잎을 생성하지 않습니다.

## 맵을 꾸밀 때의 분리 기준

- **바닥 잔디 / 벽·길:** 서로 다른 Tilemap. 벽·길에는 바람을 붙이지 않습니다.
- **꽃 / 화분:** 꽃 부분만 바람 SpriteRenderer, 화분은 정적 SpriteRenderer.
- **나무:** 잎 부분만 덤불 프리셋, 줄기는 정적. 나무 전체를 흔들면 줄기도 변형됩니다.
- **천 / 지지대:** 천 부분만 위쪽 고정. 기둥·봉은 별도 정적 그림.
- **왼쪽에 매달린 깃발·물결·불·접촉 반응:** 현재 제공 범위가 아닙니다. 위쪽 고정을 옆쪽 고정으로 대신 사용하지 마세요.

고정점은 그림의 사각형 위/아래를 기준으로 합니다. 여백이 크면 실제 줄기 시작점과 차이가 날 수 있으므로 아트 여백·고정 강도를 함께 조절하세요. 부드러운 서브픽셀 이동을 추가한 것이 아니므로 작은 폭에서는 픽셀이 잠시 머물다가 한 칸씩 이동하는 것이 정상입니다.

## 참고와 범위

- 참고: [aarthificial PixelGraphics](https://github.com/aarthificial/pixelgraphics), [셰이더 설명](https://github.com/aarthificial/pixelgraphics/blob/master/Documentation~/shaders.md), [참고 영상](https://www.youtube.com/watch?v=ecYWvfMoRIM).
- 원본의 픽셀 버전이 UV를 변형하는 접근을 참고한 자체 HLSL 구현입니다. Unity 2020용 패키지를 그대로 설치하거나 원본 ShaderGraph를 복사한 것은 아닙니다.
- 영상에 있는 캐릭터 접촉/충격파 반응용 Velocity Buffer는 이번 바람 효과 범위에 넣지 않았습니다.
- URP 2D Lit/Normals/Forward 모두 같은 UV 변형을 사용합니다. 조명·색상·정렬은 기존 경로를 사용하며, 기본 2D Lit이므로 2D Light가 필요합니다.
- Transform/타일/Collider/카메라/Renderer Chunk 모드를 바꾸지 않습니다. 매 프레임 C# 갱신·개별 타일 오브젝트·추가 카메라·RenderTexture·머티리얼 복제 없음. 픽셀당 UV 계산은 추가되므로 실제 기기의 GPU 비용은 별도 확인 대상입니다.
- 원본 Point 필터를 유지하세요. 정수 UV 이동은 카메라의 비정수 줌/회전까지 픽셀 정합을 보장하는 기능이 아닙니다.
- C# 컴파일/참조/이동 수식은 검사하되 Unity Play 및 실제 GPU 출력 검증은 별도입니다.
