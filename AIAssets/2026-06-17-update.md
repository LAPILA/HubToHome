- 기존 `Enemy_ZEV.asset`, ZEV 스킬, battle scene, encounter wiring은 수정하지 않았습니다.
- 비교용 `Enemy_ZEV_ArchitectureClone.asset`을 새로 만들고 `EnemyId`를 `zev_architecture_clone`으로 분리했습니다.
- `zev_architecture_clone.scenario.yaml`을 추가했습니다.
  - `openingModule: turn_qte`
  - HP 50% 미만 이벤트 후 `aim_shooter`로 전환
  - `module.completed` victory outcome 이후 승리 시퀀스 실행
  - 대사, BGM, fade, module switch/start, battle flag, participant damage action을 사용합니다.
- `ZevArchitectureCloneSampleBuilder`를 추가했습니다.
  - 메뉴: `HubToHome/Scenario/Samples/Rebuild ZEV Architecture Clone`
  - 한국어 메뉴: `HubToHome/시나리오/샘플/ZEV 아키텍처 복제 에셋 재생성`
  - 샘플 dialogue asset, catalog asset, runtime `BattleScenarioData`, 복제 EnemyData를 생성/동기화합니다.
- `ZEV_ArchitectureClone_BattleScenario.asset`과 관련 dialogue/catalog runtime asset을 생성했습니다.
- `ZevScenarioCloneVerticalSliceTests`를 추가했습니다.
  - YAML import와 dialogue/audio 참조 해석
  - runtime asset과 catalog validation
  - 원본 ZEV와 복제 EnemyData 분리 여부를 검증합니다.
- `ScenarioSourceYamlParser`가 action parameter indentation을 더 유연하게 읽도록 수정했습니다.
  - 기존에는 action line보다 정확히 2칸 깊은 parameter만 읽었습니다.
  - 현재 문서화된 4-space YAML 예시처럼 더 깊은 indentation도 action parameter로 읽습니다.
- `ScenarioSourceRuntimeAssetReimportCommand`에서 새 sequence sub-asset 생성 시 `Undo.RegisterCreatedObjectUndo`를 제거했습니다.
  - recursive `ScenarioActionData.Children` 구조 때문에 Unity Undo가 serialization depth error를 내는 문제를 방지합니다.

## [의도]

- 이번 단계는 실제 ZEV 전투를 교체하는 작업이 아니라, 같은 재료를 복제한 새 sample battle scenario가 우리가 만든 상위 아키텍처를 탈 수 있는지 확인하는 작업입니다.
- 원본 ZEV와 복제 ZEV를 나란히 비교할 수 있어야 하므로, 기존 battle entry나 serialized reference는 건드리지 않았습니다.
- `zev_architecture_clone`은 향후 수동 연결 승인을 받은 뒤에만 encounter wiring에 붙일 수 있는 검증용 slice입니다.
- parser indentation 수정은 사람이 읽는 YAML 예시와 실제 parser 규칙이 어긋나는 문제를 해결한 것입니다.
- Undo 정책 수정은 runtime asset reimport가 에디터 콘솔을 더럽히지 않고 반복 실행될 수 있게 하기 위한 안전장치입니다.

## [위험 / 후속]

- Play Mode와 실제 scene 연결 검증은 아직 하지 않았습니다. 기존 ZEV 전투 비교를 위해서는 사람이 승인한 뒤 clone scenario를 별도 entry에 연결해야 합니다.
- `aim_shooter`는 아직 실제 슈팅 전투가 아니라 module shell과 pure combat session 중심입니다. `module.start: aim_shooter` 이후 실제 마우스 조준/UI/VFX 입력 루프는 후속 작업입니다.
- 샘플 ActionCatalog는 vertical slice용 최소 catalog입니다. production catalog가 생기면 샘플 catalog와 병합 또는 생성 규칙 정리가 필요합니다.
- generated runtime asset은 source YAML에서 재생성 가능한 결과물이지만, 현재는 비교와 에디터 확인을 위해 커밋 대상에 포함합니다.
