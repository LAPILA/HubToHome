## [수정된 버그] BattleNarration 말풍선 크기 보정

- 전투 중 `BattleNarrationUI`에서 사용하는 `Backg` 말풍선이 텍스트 길이에 맞춰 충분히 늘어나지 않는 문제를 코드로 보정했습니다.
  - 대상 파일: `Assets/_Game/Presentation/UI/Scripts/BattleNarrationUI.cs`

### 원인

- 실제 전투 내레이션 말풍선은 `DialogueCanvas.prefab` 안의 `BattleNarrationPanel > Backg`였지만, 기존 `BattleNarrationUI`는 텍스트 출력만 처리하고 `Backg`의 크기는 조정하지 않았습니다.
- `Backg`의 RectTransform 값은 프리팹에 고정되어 있었고, 640x480 같은 작은 창 모드에서는 가로 폭이 텍스트 선 길이와 자연스럽게 맞지 않을 수 있었습니다.
- 별도로 존재하는 `BattleSpeechBubble.ResizeToText()`는 다른 말풍선 컴포넌트용 코드라, 현재 보이는 `BattleNarrationPanel > Backg`에는 적용되지 않는 구조였습니다.

### 수정

- `BattleNarrationUI`가 런타임에 `Backg` RectTransform을 찾아 `_bubbleBackground`로 사용하도록 했습니다.
- 메시지를 표시하기 전에 TMP `GetPreferredValues()`로 텍스트 선호 크기를 계산하고, 패딩을 더한 뒤 말풍선과 텍스트 영역 크기를 함께 조정하도록 했습니다.
- 최대 가로 크기는 캔버스 가로폭의 50%로 제한했습니다. 즉 640x480 기준으로는 최대 약 320px, 4K 기준으로는 해당 UI 캔버스 좌표계의 절반까지 확장됩니다.
- 세로 크기도 캔버스 높이의 35% 안에서 늘어나도록 제한해 긴 문장이 화면을 과하게 덮지 않게 했습니다.

### 검증

- `dotnet build .\HubToHome.sln --no-restore` 통과.
- `git diff --check -- Assets/_Game/Presentation/UI/Scripts/BattleNarrationUI.cs` 기준 신규 whitespace 문제 없음.

## [UI 레이아웃] BattleSubMenu Upper/Down 패널 분리

- 현재 열려 있는 `BattleScene`의 `BattleSubMenu` 하위 구조를 정리했습니다.
  - `BattleSubMenu`
    - `UpperPanel`
      - `TitleText`
      - `DescriptionText`
    - `DownPanel`
      - `ScrollArea`

### 수정

- `BattleSubMenu`에 `VerticalLayoutGroup`을 추가해 위/아래 패널이 세로 방향으로 배치되도록 했습니다.
- `UpperPanel`과 `DownPanel`에는 각각 `LayoutElement`를 추가했습니다.
  - `UpperPanel`: 고정 상단 영역, preferred height 70
  - `DownPanel`: 스크롤 영역, preferred height 144, flexible height 1
- `TitleText`와 `DescriptionText`는 `UpperPanel` 아래로 이동하고, 패널 내부 stretch 기준으로 다시 배치했습니다.
- `ScrollArea`는 `DownPanel` 아래로 이동하고, `DownPanel` 전체를 채우도록 stretch 설정했습니다.
- 새로 생성된 패널들의 RectTransform Z 값이 비정상적으로 남지 않도록 `anchoredPosition3D.z = 0`으로 정리했습니다.

### 검증

- 계층 구조가 `BattleSubMenu > UpperPanel/DownPanel` 두 직계 자식 구조로 바뀐 것을 Unity MCP로 확인했습니다.
- `BattleSubMenu`의 기존 스크립트 참조 `_titleText`, `_descriptionText`, `_container`는 오브젝트 이동 후에도 유지되는 것을 확인했습니다.
- 씬 저장은 수행하지 않았습니다.
- 콘솔에는 MCP 직렬화 경고만 있었고, 새 UI 구조 자체의 Unity 에러는 확인되지 않았습니다.

## [사용자 확인 기록] DialogueCanvas Canvas Scaler Match 기준 수정

- 사용자가 해상도별 UI 폭 문제의 원인을 확인했습니다.
  - 대상: `DialogueCanvas`의 `CanvasScaler`
  - 기존 원인: `Match Width Or Height`가 `height(1)` 기준이라 640x480 같은 4:3 창 모드에서 가로 UI 좌표계가 예상보다 좁게 잡혔습니다.
  - 수정 확인: 값을 `width(0)` 기준으로 바꾸면 `OverworldPanel`, `Backg`, `DialogueText`의 가로 대응이 더 자연스럽게 동작하는 것으로 확인했습니다.

### 비고

- 4K 16:9에서는 width/height 스케일 차이가 거의 없지만, 640x480에서는 width 기준이 현재 UI 배치 의도에 더 잘 맞습니다.
- 이후 해상도 대응 확인 시 `CanvasScaler.Match Width Or Height = 0`을 기준 설정으로 봅니다.
- 추가 확인 대상은 `CinematicPanel`, `OverworldPanel`, 선택지 UI, 이름 입력 UI의 세로 겹침/잘림 여부입니다.

## [수정된 버그] BattleSubMenu 위치 기준 보정

- 전투 중 스킬/아이템 서브메뉴인 `BattleSubMenu`가 갑자기 아래로 길게 내려가는 문제 가능성을 코드에서 보정했습니다.
  - 대상 파일: `Assets/_Game/Presentation/UI/Scripts/BattleSubMenu.cs`

### 원인

- 기존 `BattleSubMenu`는 `_showY`, `_hideY`를 절대 anchoredPosition Y값으로 사용했습니다.
- 현재 `BattleScene.unity`에는 `_showY = -190`, `_hideY = -320`처럼 아래쪽으로 치우친 절대값이 들어가 있었고, `Awake()`에서 무조건 `_hideY`로 이동하기 때문에 씬에 배치된 위치와 상관없이 실행 시 아래로 밀릴 수 있었습니다.
- 반면 `BattleScene 1.unity`에는 `_showY = 50`, `_hideY = -80`이 들어가 있었고, 두 씬 모두 `show - hide = 130`이라는 표시 이동 거리만은 일관적이었습니다.

### 수정

- 절대 Y 좌표를 직접 쓰지 않고, 씬에 배치된 `BattleSubMenu`의 초기 anchoredPosition Y를 숨김 위치로 저장하도록 변경했습니다.
- 표시 위치는 `초기 숨김 위치 + _showOffsetY`로 계산합니다.
- 기본 `_showOffsetY`는 `130`입니다.
- 기존 `_showY`, `_hideY`는 레거시 serialized 값으로만 보존하고 Inspector에서는 숨겼습니다. 새 값이 비어 있는 경우에만 기존 `showY - hideY` 차이를 fallback으로 사용합니다.

### 결과

- 현재 `BattleScene.unity`처럼 절대값이 잘못 들어가 있어도, 씬의 실제 배치 위치를 기준으로 서브메뉴가 130만큼만 올라오게 됩니다.
- 코드 수정만 했고 씬 파일은 수정하지 않았습니다.

### 검증

- `dotnet build .\HubToHome.sln --no-restore` 통과.
- `git diff --check -- Assets/_Game/Presentation/UI/Scripts/BattleSubMenu.cs` 기준 신규 whitespace 문제 없음.
- 실제 전투 중 Skill/Item 진입 시 서브메뉴 위치 확인은 Unity Play Mode 허락 후 확인이 필요합니다.

## [디버그 로그] DialogueManager Console Pro 필터 로그 추가

### 출력되는 로그

- `StartDialogue requested`
  - 다이얼로그 호출 진입 여부 확인
- `StartDialogue ignored`
  - 이미 재생 중, 데이터 null, 노드 없음 등으로 무시된 이유 확인
- `StartDialogue started`
  - 실제 UI 패널 오픈까지 진행된 다이얼로그 확인
- `PlayNode`
  - 현재 다이얼로그 이름, 노드 인덱스, speaker, localization key, event id 확인
- `ShowChoices`
  - 선택지 노드 진입 및 선택지 수 확인
- `Choice selected`
  - 전투 시작 선택지 또는 다음 다이얼로그 이동 확인
- `EndDialogue`

## [공용 UI 텍스트] SmartTextWrapper 추가 및 말풍선 계열 적용

### 목적
- TMP 기본 줄바꿈이 한국어/짧은 전투 대사에서 마지막 단어 조각만 다음 줄로 떨어뜨리는 경우를 줄이기 위해 공용 스마트 줄바꿈 유틸을 추가했습니다.
- 예: `지금부터 A 공격을 사용할거야.`가 폭을 넘을 때 `사용할거야.` 같은 단어 단위를 다음 줄로 넘기는 것을 우선합니다.

### 공용 인터페이스
- 신규 파일: `Assets/_Game/Shared/Scripts/Text/SmartTextWrapper.cs`
- TMP UI에서는 아래 형태로 바로 사용할 수 있습니다.
  - `SmartTextWrapper.Wrap(tmpText, rawText, maxTextWidth)`
- TMP 없이 테스트하거나 다른 측정기를 쓰는 경우에는 아래 overload를 사용합니다.
  - `SmartTextWrapper.Wrap(rawText, maxTextWidth, measureWidth)`
- 옵션은 `SmartTextWrapOptions`로 제공합니다.
  - `Enabled`: 기능 on/off.
  - `PreserveExistingLineBreaks`: 원본 `\n` 유지 여부.
  - `CollapseWhitespace`: 여러 공백을 한 칸으로 정리할지 여부.

### 동작 방식
- 공백 기준 토큰을 먼저 사용해 greedy 방식으로 줄을 채웁니다.
- 같은 토큰/공백의 폭은 호출 중 캐시해 반복 측정을 줄입니다.
- 한 토큰 자체가 최대 폭보다 길면 그때만 문자 단위 chunk로 fallback합니다.
- TMP 버전은 `TMP_Text.GetPreferredValues(...)`를 측정기로 사용합니다.

### 적용 대상
- `BattleSpeechBubble`: 적/플레이어 전투 말풍선 텍스트에 적용했습니다.
- `BattleNarrationUI`: 전투 narration 말풍선 텍스트에 적용했습니다.
- QTE 라벨, HP/MP 수치, 메뉴 버튼, 옵션 값처럼 짧고 고정적인 UI 텍스트에는 적용하지 않았습니다.
- SmartWrap이 줄바꿈의 최종 권한을 갖도록, 적용 대상 TMP의 자동 wrapping은 런타임에 `TextWrappingModes.NoWrap`으로 끕니다.
  - 이유: TMP 자동 wrapping이 켜져 있으면 SmartWrap 이후에도 TMP가 다시 한국어 음절 단위로 `있어.`를 `있/어.`처럼 쪼갤 수 있습니다.

### 테스트

## [공용 UI 텍스트] SmartWrap 적용 대상 TMP 자동 wrapping 비활성화

### 원인
- `BattleSpeechBubble`에서 `이 정도는 버틸 수 있어.`가 `이 정도는 버틸 수 있\n어.`처럼 표시되는 문제가 있었습니다.
- 원문과 `SmartTextWrapper` 토큰 처리에서는 `있어.`가 하나의 토큰으로 유지됩니다.
- 실제 원인은 SmartWrap 이후 TMP 자체 자동 wrapping이 다시 동작하면서 한국어 음절 단위로 줄을 나누는 것이었습니다.

### 변경
- `BattleSpeechBubble`에서 `_speechText.textWrappingMode = TextWrappingModes.NoWrap`을 Awake와 출력 직전에 적용했습니다.
- `BattleNarrationUI`에서도 동일하게 `_messageText.textWrappingMode = TextWrappingModes.NoWrap`을 Awake와 출력 직전에 적용했습니다.
- 이제 SmartWrap이 삽입한 명시적 `\n`만 말풍선 줄바꿈 기준으로 사용됩니다.
- 프리팹/씬 파일은 수정하지 않고 코드에서 런타임 보정합니다.

### 검증
- C# LSP 단일 파일 진단 통과.
- `dotnet build .\HubToHome.sln --no-restore` 통과.

## [공용 UI 텍스트] SmartWrap 폭 판정 후보 줄 기준으로 수정

### 원인
- TMP 자동 wrapping을 끈 뒤, SmartWrap이 줄을 자르지 않은 문장은 그대로 한 줄로 출력됩니다.
- 기존 SmartWrap은 `토큰 폭 + 공백 폭`을 누적해서 다음 토큰이 들어갈지 판단했습니다.
- 하지만 실제 TMP 표시 폭은 최종 후보 줄 문자열 전체의 glyph/spacing/폰트 메트릭 기준으로 결정되므로, 토큰별 합산값과 차이가 날 수 있습니다.
- 그 결과 `이 정도는 버틸 수 있어.` 같은 문장이 줄바꿈 없이 남고, TMP 자동 wrapping이 꺼진 상태에서는 텍스트 박스 밖으로 튀어나올 수 있었습니다.

### 변경
- `SmartTextWrapper`의 줄바꿈 판정을 `토큰별 합산`에서 `후보 줄 전체 문자열 측정`으로 변경했습니다.
- 예: 현재 줄이 `이 정도는 버틸 수`이고 다음 토큰이 `있어.`라면, `이 정도는 버틸 수 있어.` 전체 후보를 TMP로 측정한 뒤 최대 폭을 넘으면 `있어.`를 다음 줄로 보냅니다.
- 긴 무공백 토큰 fallback은 유지했습니다.
- 회귀 테스트 `WrapMeasuresWholeCandidateLineInsteadOfAddingTokenWidths`를 추가했습니다.

### 검증
- C# LSP 단일 파일 진단 통과.
- `dotnet build .\HubToHome.sln --no-restore` 통과.
