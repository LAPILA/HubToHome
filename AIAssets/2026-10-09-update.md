# 2026-10-09 자체 스크립트 정리

브랜치 `codex/gameplayEdit`. 기존 미커밋 변경 189항목을 보존한 상태에서 자체 스크립트만 정리했다. 커밋·푸시는 하지 않았다.

## 변경 범위

- 코드·파일 삭제는 `Assets/_Game/Scripts`와 소속 `.meta`에 한정했다. 외부 플러그인·패키지·씬·프리팹·콘텐츠 자산은 수정하지 않았다.
- 시작 시 C# 691개를 구문 기반으로 조사했다. 동일 메서드, 빈 파일, 낮은 코드 참조 수를 후보로 삼고 실제 코드 호출·문자열·Unity GUID 참조를 별도로 확인했다. 전체 파일의 모든 동작을 검증했다는 의미는 아니다.
- 결과는 C# 685개, 변경 C# 10개, 삭제 C# 6개와 해당 meta 6개다. 시작 시 로컬 복사본 대비 C# 줄 수 166,363 → 165,864로 499줄 감소했다. 회귀 테스트 추가분을 포함한다.

## 중복과 미사용 구현

- ActionLibrarySourceParser/Writer의 중복 YAML 보조 함수를 기존 ScenarioLibraryYamlUtility로 통합했다. 문법·검증·공개 Parse/Write 진입점은 그대로다. 기존 내부 Unquote/ParseList 진입점도 위임으로 보존했다.
- BattleCinematicService가 슬롯 및 앵커 위치 계산을 소유한다. BattleTweenCinematicService도 이를 사용한다. 두 서비스는 원래부터 공통 연출 함수를 공유하던 관계다. 위치·이동·취소 연출의 정책은 바꾸지 않았다.
- GameConfigManager.IsPressed는 WasPressed에 위임한다. 방향/달리기는 Held, 확정/취소/메뉴는 Pressed인 기존 호환 의미를 유지했다.
- 호출되지 않는 private 함수 7개를 제거했다: BattleManager.EnemyHasSequenceSkill, SequenceMakerWindow의 CreateNavigatorRow/AddSectionLabel/ActionSummary/MatchesSearch, TriggerRuleEditorView.EnsureCurrentChoice, ShowcaseStationDataBuilder.ValidateScenarioSource.
- BattleManager.GetEnemySequenceSkill 들여쓰기를 바로잡았다.
- 기존 ActionLibrarySourceSyncTests에 한글·인용·역슬래시·쉼표 목록 왕복, 소수점 문화권, 세 가지 줄바꿈 회귀 사례를 추가했다.

## 유지한 코드

- ADR 0006의 구 ScenarioAuthoringWindow/Odin 호환 경로, 공개 데이터 enum, 직렬화 필드, Unity/Odin/메뉴 특성으로 호출되는 함수는 유지했다.
- BackgroundManager, OverworldMenuUI, TitleMenuManager는 실제 씬·프리팹에 연결된다. VFXAutoDespawn은 외부 VFX 프리팹에도 연결되므로 자체 폴더에 있다는 이유로 제거하지 않았다.
- 수동 추가 가능한 상호작용 컴포넌트와 공개 샘플 생성 진입점은 현재 자산 연결 수만으로 삭제하지 않았다.
- 짧은 UI 배치식, 서로 다른 수명주기의 콜백, ID 생성 구현 등은 무리하게 공통 계층을 추가하지 않았다. BattleSpeechBubble와 전투 규칙·세이브·장비·연출 데이터는 그대로다.

## 검증

- Runtime·Editor 최종 CLI 컴파일 오류 0개. 기존 CS0649 경고 3개: ConfigPanelUI의 직렬화 필드 2개, 외부 Febucci AnimatedLabelBase.settings 1개. 외부 패키지는 수정하지 않았다.
- 기존 YAML 보조 함수와 통합 대상의 실제 출력 3,844개 비교 통과. 무작위 문자열, 인용/주석/목록, Assets/_Game의 YAML, 세 가지 숫자 문화권을 포함한다.
- 추가한 Unity NUnit 사례는 컴파일까지 확인했다. Unity Play·EditMode 실행·Refresh·Reimport·씬 저장은 하지 않았다.
- Git 제외 CLI 보조 도구는 `Library/CodexChecks/CodeCleanup`에 있다. 생성 csproj는 수정하지 않고 Compile.targets로 이전 신규 파일을 포함하고 이번 삭제 파일을 제외했다.

## 재사용할 검증 절차 교훈

- 2026-10-09, 자체 코드 정리용 .NET 보조 도구: 도구 하위에 C# 원본 백업을 복사했더니 SDK 기본 Compile glob이 백업까지 컴파일해 Unity 타입 누락 오류가 대량 발생했다. `EnableDefaultCompileItems=false`와 명시적 Compile 항목으로 복구했고 구문 조사 및 3,844개 비교를 통과했다. 원본 백업을 둔 임시 검사 프로젝트에는 기본 재귀 Compile을 사용하지 않는다.
- 같은 날짜, 자동 패치 구성: 한 apply_patch에서 같은 파일의 Update 헤더를 여러 번 만들면 중복 대상 오류가 났다. 파일당 Update 헤더 하나와 복수 구간 또는 단일 변경 구간으로 합쳐 적용했다. 다음 자동 패치도 파일별로 묶는다.
- Windows Git 검사에서 임시로 core.autocrlf=false를 지정하면 기존 CRLF가 전체 변경·공백 오류처럼 표시됐다. 원본 변환 없이 저장소의 기본 줄바꿈 정책으로 diff를 검사한다. 콘솔 출력만 보고 파일 손상으로 판단하지 않는다.
- 전역 yjlim 메모리 경로는 이 호스트의 쓰기 허용 범위 밖이므로 저장소의 본 기록을 사용한다. 관련 계획은 [자체 스크립트 정리](../docs/superpowers/plans/2026-10-09-own-scripts-cleanup.md)다.
