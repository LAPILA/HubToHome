## 후속 · 전투 대사 중앙 교체

사용자 두 번째 화면 기준으로 하단 파티/자원은 남기고 중앙 명령+상세를 빠르게 아래로 내린 뒤 기존 파란 대사를 표시한다. 이전 구현은 상세만 숨기고 명령을 흐리게 남겼으며, 시나리오 cinematic gate가 파티와 HUD 배경까지 숨겼다.

- `BattleMenuUI`: 기존 BattleHudEntryMotion으로 두 형제 메뉴를0.16초/164px 이동·페이드, 이동 전 합집합 저장, 복귀/외부중단/재오픈 트윈 소유권. 시나리오가 먼저 숨긴 메뉴도 퇴장 장면은 표시하고 gate해제 때 복귀한다. 반복 상태 갱신이 복귀를 즉시 끊지 않는다.
- `BattleSubMenu`: 표시 전환 중 입력만 잠그고 기존 선택/콜백 유지.
- `BattleDialogueLayout`, `DialogueUI`: 고정된 명령+상세 합집합으로 도킹, 메뉴 퇴장 뒤0.1초 페이드인. 오버월드 원래 배치/폰트 복원.
- `BattleUIController`: 도킹 이벤트를 구독해 시나리오 중 파티/자원/턴 큐 장식 표시. 카메라/시나리오 모드/전투 규칙은 유지.
- `BattleHudViewport`: 중첩 Canvas가 아니라 rootCanvas를 출력 소유자로 사용하고 런타임 viewport에 옮길 때 anchoredPosition/sizeDelta 보존. 실제 월드 루트는 제외.
- `BattleDialoguePresentationTests`: 중앙범위/재오픈/외부 Hide/턴갱신/시나리오 숨김→퇴장→복귀/중첩 Canvas 회귀 사례. 기존 스킵 안내 기대값을 현재 계약으로 수정.

검증: 전체CLI Runtime405/Editor343소스 오류0, 경고225/0. 실제 프리팹의 명령 영역 y132..154와 상세 y24..128의 합집합362×130, 164px 하향 시 두 패널이 화면 하단을 벗어나는 것을 읽기 전용 산술 검사로 확인했다. Unity Play/EditMode 실행·시각 검수는 하지 않았다. 씬/프리팹/대본·시나리오 자산은 변경하지 않았으며 기존 작업트리 변경은 보존했다. 커밋/push 없음.

조절 위치와 수동 확인 항목: [전투 하단 메인 대화](yjlim/feedback/2026-10-08-battle-submenu-dialogue.md). 브레인스토밍/구현계획 지침은 첨부된 확정 시안의 범위 고정에, 진단/Unity 지침은 두 소유자(시나리오 표시와 대사 표시) 경계·트윈 수명 점검에 적용했다.

## 후속 · 메뉴 입력 잠금 / 하단 여백 / 레터박스

브랜치 `codex/gameplayEdit`, HEAD `8d8a848`. 사용자 첨부 화면의 하단 맵 띠, 세 번째 파티 행 가림, 스킬/아이템 확정 후 입력 정지를 수정했다. 기존 작업트리는 보존했고 커밋/push와 Unity Play/강제 refresh는 하지 않았다.

### 원인과 변경

- `BattleMenuUI.Confirm`이 먼저 `_inputEnabled=false`로 재입력을 잠근 뒤 `OnSkillSelected/OnItemSelected`를 호출했으나, 두 콜백의 `CommandsEnabled` 검사가 방금 수락한 요청을 거부했다. 대상 선택 모드에도 진입하지 않아 명령 키가 정지했다. 콜백은 입력 수신 플래그 대신 대화/복귀 모션/모듈 정지/전역 모달 소유권만 검사한다. 잠금을 콜백 뒤로 옮기지 않아 동기적인 대상 없음/사용 불가 복귀를 덮지 않는다.
- 메뉴 대화 전환 기본시간을0.16→0.3초로 변경. 이동거리164와 대사 fade-in0.1초는 유지한다. 기존 prefab/scene에는 `_dialogueSlideDuration` 직렬화 override가 없어 자산 수정 없이 기본값을 적용한다.
- `BattleHudViewport`의 min(width/640,height/480) 중앙 배치로 남는 아래 영역에 검정 Image1개를 재사용한다. 출력 원점/scale을 반영하고 raycast=false. 콘텐츠 좌표와 형제 순서를 보존하며 `BattleUIController.IsHudChromeVisible` 및 Canvas 표시 상태를 따른다.
- `CinematicLetterboxOverlay`는 현재 도킹 대화의 하단 높이만 HUD 아래 여백+기준20px로 제한한다. 안내줄 y2..18은 가리고 파티 시작 y24는 보존한다. 상단과 원본 CurrentThickness는 변경하지 않고, show 트윈 완료 후에도 대화/resize 변화를 반영한다. 일반 필드·전체 컷씬은 기존 두께로 돌아간다.

- 실제 화면의 움직임과 입력 최종 확인은 Unity에서 스킬/아이템 확정→타깃변경→X취소, 대화 왕복, 세로 여백 있는Game View로 확인해야 한다. 검사 코드가 Unity 수명주기나 실제 조작 QA를 대체한다고 주장하지 않는다.

이 작업 환경의 저장소는 작업 시작 디렉터리 바로 아래 `HubToHome/`에 있다. 바깥 경로의 git status 실패 후 실제 `AGENTS.md`와 `.git` 경계를 확인해 내부 디렉터리를 명령의 workdir로 지정했다. 이후에는 먼저 `git rev-parse --show-toplevel`로 저장소 경계를 확인한다. 이 머신에는 전역 yjlim 메모리 경로가 없어 기존 운영에 따라 프로젝트 기록에 보존한다.
