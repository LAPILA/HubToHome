# 2026-06-16 업데이트

> 작업 단계: implement / verify
> 목적: QTE 이후 첫 비-QTE 전투 모듈이 기본 Game Module 아키텍처를 탈 수 있음을 검증

## [변경]

- 기본 Battle Game Module registry에 `aim_shooter` 모듈을 추가했습니다.
- `BattleAimShooterGameModuleRuntime`을 추가했습니다.
  - 현재 범위는 presentation/input-ownership shell입니다.
  - `Enter` / `Start` 시 `AIM SHOOTER` 라벨을 적용하고 legacy Turn QTE 입력을 끕니다.
  - `Exit` 시 자기 모듈 presentation 상태를 정리합니다.
- `IBattleGameModulePresentationController`를 추가했습니다.
  - 현재 concrete adapter는 `BattleUIController`입니다.
  - 모듈별로 QTE 메뉴, 타겟팅, 방어 QTE UI, party panel 위치, turn label을 정리할 수 있게 했습니다.
- `BattleUIController`가 active module presentation 상태와 `acceptsTurnQteInput` 플래그를 관리합니다.
  - 비-QTE 모듈이 활성화된 동안 기존 QTE targeting/menu state change가 새어 들어가지 않게 막습니다.
- `BattleManager`의 기본 Game Module runner 생성 시 `BattleUIController.Instance`를 registry factory에 주입합니다.
- `GameModuleActionRunnerTests`에 비-QTE module 등록과 presentation/input-ownership 동작 검증을 추가했습니다.
- `IBattleAimShooterModuleController`를 추가했습니다.
  - `BattleAimShooterGameModuleRuntime`이 controller가 주입되면 `Enter` / `Start` / `Exit` lifecycle을 controller에 위임합니다.
  - 테스트 controller가 `GameModuleRuntimeContext.ModuleEvents`로 module completed outcome을 보고할 수 있음을 검증했습니다.
- `BattleAimShooterCombatSession`을 추가했습니다.
  - 살아있는 enemy target인지 `IBattleSessionStateReader`로 검증합니다.
  - `IBattleParticipantCommandRunner.ApplyPureDamage(...)`로 데미지를 요청합니다.
  - shot / hit count를 추적하고, victory 또는 failed outcome을 `IGameModuleEventSink`로 보고합니다.
  - 실제 Unity mouse input, projectile, VFX, UI는 아직 붙이지 않았습니다.
- `CONTEXT.md`, `RuleFileforAI/battle.clinerules`, `.agents/skills/hubtohome-scenario-authoring/SKILL.md`, 구현 계획, Spec Kit task를 함께 갱신했습니다.

## [의도]

- QTE 모듈화가 끝난 뒤 다음 위험은 “새 모듈을 추가해도 결국 QTE UI와 입력이 남아 있는가”였습니다.
- 이번 변경은 아직 완성된 슈팅 게임을 만드는 단계가 아니라, 비-QTE 모듈이 전투 Primary Mode 안에서 QTE와 같은 Game Module Runner를 타고 들어오며 자기 UI/입력 소유권을 잡을 수 있는지 확인하는 단계입니다.
- `aim_shooter`를 registry에 넣어둠으로써 Battle Scenario Data의 `module.switch: aim_shooter` / `module.start: aim_shooter`가 hard-coded BattleManager 분기 없이 동작할 토대를 만들었습니다.
- `IBattleAimShooterModuleController`는 다음 단계의 실제 shooter gameplay loop가 들어갈 자리입니다. 이 seam이 없으면 mouse aim, projectile, damage, outcome 보고가 다시 BattleManager 또는 UI controller에 섞일 위험이 큽니다.
- `BattleAimShooterCombatSession`은 그 controller 뒤에서 호출될 순수 규칙 Module입니다. 이 코어가 있으면 input/projectile/VFX 구현은 presentation/input adapter에 머물고, 데미지와 outcome policy는 테스트 가능한 곳에 남습니다.

## [위험 / 후속]

- `aim_shooter`는 아직 완성 모듈이 아닙니다.
  - 남은 것: 조준 입력, 타겟/탄환/피격 판정, UI, 카메라/배경 presentation, `IBattleParticipantCommandRunner` damage 요청, `IGameModuleEventSink` outcome 보고.
- 다음 구현자는 `aim_shooter` gameplay를 `IBattleAimShooterModuleController` 뒤에 붙이고, mouse input/projectile hit 결과를 `BattleAimShooterCombatSession.FireAt(...)`으로 전달해야 합니다.
- 실제 적 HP 스냅샷은 현재 read-only snapshot이므로, shot 후 UI/스냅샷 갱신 타이밍은 기존 `IBattleParticipantCommandRunner` adapter와 BattleManager event bridge 검증이 필요합니다.
- 실제 Unity Editor Play/EditMode validation은 MCP 연결이 다시 잡힌 뒤 필요합니다.
- 비-QTE 모듈이 늘어날수록 `IBattleGameModulePresentationController`가 임시 UI adapter에서 더 정식 Presentation Service로 깊어질 가능성이 큽니다.
