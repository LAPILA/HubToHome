### Google Docs 연결 결과의 탭 구조

- 맥락/날짜: 2026-09-28 작업을 2026-10-02에 마무리하며 기록.
- 실패 접근: 네이티브 REST 예시의 `tabProperties/documentTab` 구조를 커넥터 결과에도 그대로 적용.
- 관찰: 이 환경의 `get_document.structuredContent.tabs`는 `tabId`, `title`, `body`가 직접 있는 평탄화 구조입니다. 네이티브 예시 경로로 읽으면 값을 찾지 못합니다.
- 성공 접근: 결과 키를 먼저 확인하고 실제 `tabs[i].body.content`를 재귀 순회하여 표·문단·링크를 확인했습니다. 쓰기에는 읽은 revision과 실제 tabId를 사용했습니다.
- 적용/검증: Google Docs 커넥터를 사용하는 경우. 최종 재조회에서 14장/18표/15개 내부 링크 일치. 관련 문서는 아래 인수인계 및 원격 가이드입니다.

### Windows에서 문서 읽기 브리지 대신 네이티브 결과 확인

- 실패 접근: POSIX 셸 기반 읽기 브리지를 Git Bash로 실행. 실행 파일 존재는 확인했으나 셸 생성에 실패했습니다. 정확한 호스트 원인은 확정하지 않았습니다.
- 성공 접근: 연결된 Google Docs 커넥터로 문서·표·문단 전체 구조를 읽고 기존 제목/링크/표를 보존하는 범위 갱신으로 진행했습니다. 본문에 칩·드롭다운 등 별도 네이티브 제어가 없음을 먼저 확인했습니다.
- 적용/검증: 동일 Windows 브리지 제한이고 필요한 구조가 커넥터에서 확인되는 경우에만 해당합니다. 인증 정보나 브라우저 내부 상태를 우회 추출하지 않았습니다.

### PDF 내보내기 다운로드와 렌더링

- 실패 접근: 제한된 실행 환경의 다운로드가 HttpRequestException으로 실패했고, 복잡한 한 줄 Python 람다 기반 렌더링은 구문 오류가 발생했습니다.
- 성공 접근: 승인된 `require_escalated` 실행으로 커넥터가 제공한 PDF를 내려받고, 여러 줄의 단순 PyMuPDF/Pillow 스크립트로 22쪽을 렌더링했습니다. 인증 설정 변경이나 토큰 출력은 하지 않았습니다.
- 적용/검증: 허가된 문서의 PDF 검증 작업. 다운로드 URL은 민감한 임시 서명 URL이므로 기록하지 않습니다. `PYTHONUTF8=1`로 한국어 진단 출력을 유지하고 모든 페이지 이미지 및 최종 수정 페이지를 확인했습니다.
- 전역 `C:/Users/yjlim/.codex/memories/HARNESS_LESSONS.md`는 이 호스트에 없으므로 다른 사용자 프로필을 생성하지 않고 프로젝트 기록에 보존했습니다.
