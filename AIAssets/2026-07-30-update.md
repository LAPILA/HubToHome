# 2026-07-30 Update

## 전투 피해 숫자 피드백

### 변경 사항

- `BattleManager`에 피해 표시 전용 이벤트를 추가하고 기존 피해 이벤트와 시나리오 이벤트는 유지했다.
- 실제 피해가 발생한 대상의 `CharacterPivotId.Center`를 화면 좌표로 변환해 TMP 숫자를 표시한다.
- 일반 피해는 재생 중 크기가 고정되며, 크리티컬은 0.45배에서 1.65배로 빠르게 확대된 뒤 축소하지 않는다.
- 표시 이동이 끝난 뒤 최소 0.30초를 유지하고 0.24초 동안 이동과 함께 페이드한다.
- 동료가 가한 피해는 공격 동료의 상징색, 동료가 받은 피해는 피격 동료의 상징색을 사용하며 미지정 시 흰색을 사용한다.
- 회피와 점프 성공은 흰색 `MISS`를 표시하고, 패링 성공은 기존 규칙대로 표시하지 않는다.
- TMP 외곽선은 검은색 0.08로 제한하고, 반복 생성은 Battle UI 수명에 종속된 로컬 풀을 사용한다.
- 투사체와 연쇄 공격 종료 후 Perfect QTE 상태를 초기화해 이후 액션에 크리티컬 표시가 누적되지 않도록 했다.

### 설정 위치

- 동료 상징색: `CharacterData.BattleSymbolColor`
- 글자 크기, 외곽선, 이동, 유지, 페이드, 크리티컬 확대: `BattleDamagePopupPresenter`의 Odin Inspector 그룹
- 런타임 연결: `BattleUIController`가 Presenter를 자동 생성하고 현재 전투 카메라를 바인딩한다.

### 검증

- Unity EditMode 전체 테스트 1007개 통과.
- 일반 피해 고정 크기, 크리티컬 단방향 확대, 최소 유지 시간, 풀 재사용 초기화를 DOTween 시퀀스 테스트로 검증했다.
- 실제 타깃 중앙의 월드 좌표 변환, Battle UI 레이어 상속, 색 우선순위, MISS 이벤트를 검증했다.
- 640x480 기준 Silver SDF 런타임 시각 확인을 수행했다.
- 신규 `.meta` GUID 전체 중복 0건을 확인했다. C# 컴파일 오류는 없으며, 강제 도메인 재로드 때 자산 경로 없이 출력되는 Unity 내부 `unexpected guid mismatch` 메시지는 기존과 동일하게 재현된다.

### 주의점

- 기존 캐릭터 데이터의 상징색 기본값은 흰색이다. 캐릭터별 색은 해당 `CharacterData` Inspector에서 지정해야 한다.
- 상점, 인벤토리, 메뉴 및 전투 밸런스 계산은 변경하지 않았다.
- 작업 트리에 있던 TMP 폰트 및 오디오 변경은 이번 작업에서 수정하지 않았다.

## 공용 전투·선택 SFX 연결

- `AudioManager.prefab`에 `Hit.wav`, `MeetEnemy.wav`, `Select.wav`를 공용 SFX로 등록했다.
- 실제 양수 피해가 발행될 때 Hit, 오버월드 적 또는 AreaTrigger 조우 때 MeetEnemy, 대사 선택 확정과 실제 아이템 지급 성공 때 Select가 재생된다.
- 적 프리팹의 개별 조우 SFX가 있으면 우선 사용하고, 비어 있으면 AudioManager의 공용 MeetEnemy를 사용한다.
- BunnySlime 오버월드 프리팹에도 MeetEnemy 참조를 명시했다.
- 피해 숫자 전체 위치는 기존 `BattleUIController > Damage Popup > 기준 위치 보정`에서 조절하며 기본값은 `(0, 12)`다.
- 피해 숫자 기본 글자 크기를 최종 60으로 조정하고, NeoDunggeunmoPro-Regular SDF를 심리스/전용 전투의 전용 폰트로 연결했다.

### 작업 운영 합의

- 쇼케이스, PlayMode, 전체 테스트와 일반 QA는 사용자가 직접 수행한다.
- AI는 코드·프리팹 구현과 배치에 집중하며, 코드 오류가 발생했거나 컴파일 오류가 의심될 때만 최소 검증을 수행한다.
- 이번 변경에서는 Unity 테스트와 쇼케이스 재생을 실행하지 않았다.

## 공용 Battle Host 단일 원본 통합

- `SeamlessBattleHost.prefab`을 심리스 전투와 전용 `BattleScene`의 공용 구성 원본으로 확정했다.
- 전용 `BattleScene`의 독립 `BattleManager`, `PositionManager`, Battle UI 계층을 제거하고 공용 프리팹 인스턴스로 교체했다.
- 전용 씬에는 배경, 후처리, 카메라를 유지하고 프리팹 인스턴스에는 아래 전용 오버라이드만 둔다.
  - Battle UI 활성화
  - `BattleManager._isDedicatedBattleScene = true`
  - 씬 Main Camera를 `BattleUIController._worldCamera`에 연결
- 기존 전용 UI의 0 스케일과 TMP 런타임 재질 오버라이드가 공용 프리팹 인스턴스에 남지 않도록 동기화 도구에서 되돌린다.
- 기존 `RebuildPrefab()`은 더 이상 `BattleScene`을 복제하지 않고 공용 프리팹을 조회하는 호환 API로 유지했다.

- 전용 씬의 배경, 카메라, 후처리는 `Assets/_Game/Content/Maps/Battle/BattleScene.unity`에서 관리한다.
- 공용 전투 런타임 계층을 전용 씬에 별도로 복사하지 않는다.

### 주요 파일

- PlayMode, 쇼케이스, 전체 테스트는 작업 운영 합의에 따라 실행하지 않았다.
- 동기화 전 원본 씬 백업은 `Temp/Backups/BattleScene_BeforeSharedHost_20260730.unity`에 있다.

## 적 공용 프리팹 통합

### 변경 사항

- `BunnySlime_Overworld.prefab`을 GUID를 유지한 `BunnySlime.prefab`으로 승격했다.
- `BunnySlime_Battle.prefab`과 전투 전용 Animator Controller를 제거했다.
- 공용 Animator Controller는 `BunnySlime.controller` 하나이며 현재 `Idle` 상태만 사용한다.
- `EnemyData.BattlePrefab`을 직렬화 호환이 유지되는 `EnemyData.Prefab`으로 이관했다.
- 기존 EnemyData 에셋과 TestMap 생성기가 공용 프리팹 경로를 참조하도록 갱신했다.

### 런타임 규칙

- 오버월드 배치와 전투 생성은 같은 `EnemyData.Prefab`을 사용한다.
- 전투에서 생성한 복제본은 `BattleManager`가 `OverworldEnemy.DisableForBattleInstance()`를 호출해 조우 Collider와 오버월드 동작만 끈다.
- `EnemyCharacter.SetBattleMode(true)`는 Animator에 해당 파라미터가 있을 때만 Trigger를 사용하므로 Idle-only Controller도 안전하게 유지된다.
- 별도 `_Overworld` / `_Battle` 프리팹, 모드별 스케일 변경, 중복 Animator Controller를 만들지 않는다.

- 런타임 `Assembly-CSharp`를 먼저 갱신한 뒤 `Assembly-CSharp-Editor`까지 Unity Roslyn 최소 컴파일을 통과했다.

## 공용 게임플레이 카메라 리그

### 변경 사항

- `Assets/_Game/Core/Prefabs/Camera/GameplayCameraRig.prefab`을 게임플레이 카메라의 단일 원본으로 추가했다.
- 리그는 Main Camera, Cinemachine Brain, 32 PPU/640x480 Pixel Perfect Camera, 기본 Cinemachine Camera, Follow, Pixel Perfect 연동, Impulse, `CameraController`를 소유한다.
- 기본 Orthographic Lens는 4, Main Camera와 Cinemachine Camera의 월드 Z는 -1로 통일했다.
- 아래 게임플레이 씬을 공용 프리팹 인스턴스로 교체했다.
  - BattleScene
  - TestMap
  - MapFieldStarter 템플릿
  - PrologueSubway Overworld
  - ShowcaseStation
  - TravelTrain
  - WideField
- Player Follow와 `CameraController._centerTarget`은 각 오버월드 씬의 Prefab Override로 유지했다.
- BattleScene의 `BackgroundManager._mainCamera`와 공용 Battle Host의 `BattleUIController._worldCamera` 참조를 새 Main Camera에 다시 연결했다.
- 타이틀과 인트로 씬은 별도 연출 카메라 구성이므로 통합 대상에서 제외했다.
- `RoomMapSampleBuilder`가 단순 Main Camera를 다시 생성하지 않고 공용 리그를 인스턴스화하도록 변경했다.

### Cinemachine 사용 경계

- 줌은 Cinemachine Lens, 추적은 Follow, 다중 대상 구도는 Target Group/Group Framing을 사용한다.
- 흔들림은 Impulse, 가상 카메라 전환은 Priority와 Brain Blend를 사용한다.
- 컷신은 두 번째 실제 Camera를 만들지 않고 별도 Cinemachine Camera 또는 Timeline의 Cinemachine Track을 사용한다.
- 코드는 대상·프리셋·소유권만 전달하고 카메라 Transform 이동 공식을 중복 구현하지 않는다.
