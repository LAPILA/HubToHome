## 바로 확인하는 위치

1. `Assets/_Game/Content/Maps/Development/TestMap/TestMap.unity`의 `QA_Marker_Vendor`와 상호작용한다.
2. `대화 / 아이템 구매 / 아이템 판매 / 상담·마사지 / 나가기`를 방향키·확인·취소로 조작한다.
3. 대화에서 `남자? 여자?`를 선택하면 “남자라구요!”와 함께 배경이 짧게 흔들린다. 설정의 화면 흔들림을 0으로 두면 흔들리지 않는다.
4. 무료 상담 또는 마사지를 선택하면 후열을 포함한 전체 파티 HP/AP가 회복된다. 이미 모두 회복된 경우 그대로 안내한다.

거래는 기존 소지금을 사용한다. 샘플 상점을 연다고 돈을 자동 지급하거나 저장하지 않는다. 기존 테스트맵 부트스트랩의 GlobalDataManager/DialogueManager/UI가 준비된 정상 진입 흐름을 사용한다.

## 새 상점을 만드는 순서

1. Project 창에서 위 `QA_Shop_DebugInventory.asset`을 복제하고 원하는 콘텐츠 폴더에 둔다.
2. `Shop ID`를 새 고유 ID로 바꾸고 표시 이름·상인 표시 이름·전체 상점 이미지·기본 대사 화자를 설정한다.
3. 상품 목록을 수정한다. 복제된 상품의 Entry ID·구매 카운터 Flag도 새 상점용으로 바꾼다. 구매 카운터 Flag를 그대로 쓰면 한정 판매 횟수가 원래 상점과 공유된다. 아이템은 기존 등록 에셋을 연결한다.
4. 대화 주제를 추가한다. 짧은 문장은 `기본 대사`에 직접 작성하고, 긴 대사·분기는 기존 대화 메이커에서 만든 `DialogueData`를 연결한다.
5. 주제 전체에서 그림을 바꾸려면 `대화 중 상점 이미지`를 지정한다. 특정 문장에서 바꾸거나 흔들려면 그 문장의 `EventTriggerID`와 같은 ID를 상점의 `대사 이벤트 반응`에 등록한다. 짧은 기본 대사는 해당 주제의 `이벤트 ID`를 사용한다.
6. 서비스 메뉴 이름과 회복 서비스를 수정한 뒤, 맵에 배치한 `VendorMarker`의 상점 데이터에 새 에셋을 연결한다. 마커의 Shop ID도 새 상점 ID와 맞춘다.

`DialogueData`를 연결한 주제는 각 노드의 화자를 그대로 사용한다. 상점의 기본 화자나 짧은 기본 대사 설정이 연결된 대화의 내용을 덮어쓰지 않는다.

## 종료와 대화

상점이 연 대화의 generation을 보관하고 강제 종료 시 그 대화만 취소한다. 일시 생성한 대사/화자 객체는 종료 때 해제하며 연결한 `DialogueData`·`SpeakerData` 에셋은 파괴하지 않는다. 대화의 닫기 애니메이션 후 메뉴를 복귀시킨다. 대화 종료·중단 시 기본 상점 그림을 복구하고 흔들림을 정리한다. 상점 종료·비활성·소유 씬 해제·활성 씬 변경에서는 세션과 이벤트 구독까지 정리한다.

`shop.ian.gender_reveal`는 `QA_Shop_DebugInventory.asset`의 반응 목록에 등록한 이안 샘플 이벤트다. 공용 코드에 이안 전용 분기는 없다. 다른 상점에서도 원하는 ID를 반응 목록에 등록하면 전체 이미지 교체·흔들림을 사용할 수 있다. 등록되지 않은 ID는 상점 이미지에 영향을 주지 않는다. 긴 대화는 각 노드의 기존 `EventTriggerID`를 그대로 사용하며, 큰 연출이나 스토리 전투는 기존 대화/시나리오 흐름에서 작성한다.

## 후속: 입장 암전과 BGM

입장하면 현재 맵이 0.12초 동안 어두워지고, 완전히 검어진 시점에 상점 화면으로 바뀐 뒤 0.3초 동안 밝아진다. DOTween과 공용 AudioManager 모두 unscaled time을 사용한다. 전환 동안 메뉴 확인 입력은 잠시 막고 강제 종료 시 Tween을 중단한다.

음악은 입장 전 재생 위치·볼륨·무음 여부를 보관해 정상 종료 시 복구한다. 다른 시스템이 곡을 바꾼 경우 건드리지 않는다. 직접 씬이 교체되면 아직 상점 곡이 재생 중인 경우에만 멈추고 새 씬의 음악 선택을 따른다. 기존 MapTransitionService 경로는 씬 전환을 시작하기 전에 상점을 닫는다.

수정: `ShopUI.cs`, `ShopDefinition.cs`, `QA_Shop_DebugInventory.asset`, `main_loop.wav.meta`. 원본 WAV는 그대로이며 긴 BGM은 Streaming/loadInBackground로 설정했다. 실제 첫 재생 로딩·루프 연결점·음량은 플레이에서 확인할 항목이다.

## 후속 수정: 상점에서 맵 환경음 차단

실제 TestMap 원인은 루트 `GameObject`의 독립 AudioSource(fileID 234319519)가 `PlayOnAwake + Loop`로 피아노 곡을 직접 재생하던 것이다. 공용 AudioManager와 믹서를 우회하므로 상점 BGM을 교체해도 계속 들렸다. 해당 컴포넌트의 자동 재생/활성을 끄고 같은 곡을 `MapSettings._mapBGM`으로 옮겼다. 오브젝트나 클립을 삭제하지 않았다. 기존 TestMap의 `_ambienceLoop`는 비어 있었다.

추가로 일반 맵의 환경음도 상점에서 숨기도록 `AudioManager.SuppressAmbience()`를 연결했다. ShopUI가 입장 시 사용하고 모든 닫기/비활성/씬 전환 경로에서 해제한다.

환경음 채널만 즉시 음소거하므로 상점 BGM·UI 효과음·대사는 유지된다. 환경음의 재생 위치·페이드·맵이 선택한 클립을 보존하며, 기존 음소거 상태와 중복 사용도 처리한다. 오래된 맵 클립을 스냅샷으로 다시 재생하지 않는다. 상점당 핸들 하나만 할당하며 매 프레임 탐색은 추가하지 않았다.

씬 파일은 다시 열어서 반영한다. 열려 있는 씬의 이전 AudioSource 설정을 다시 저장하면 이번 변경을 덮을 수 있다. 이제 맵 음악도 공용 BGM 볼륨 설정을 따른다.
