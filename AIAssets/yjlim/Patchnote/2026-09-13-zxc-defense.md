# Z / X / C 방어 개편

기본 전투를 **지속 가드·저스트 가드 / 회피 / 연계 반격**으로 구성했습니다. 기존 기본공격, 전체공격, 스킬 타임라인과 시나리오의 `battle.skill.timeline`이 같은 판정 결과를 사용합니다. 새로운 전투 모드나 별도 게이지는 추가하지 않았습니다.

## 1. 플레이 규칙

| 입력 | 사용 방법 | 성공 결과 | 기본 수치 |
| --- | --- | --- | --- |
| Z 가드 | 타격 순간까지 누르고 있기 | 일반 피해 감소, AP 보상 없음 | 피해 배율 0.5, 유지시간 제한 없음 |
| Z 저스트 가드 | 타격 직전에 새로 누르기 | 피해 없음, 기존 AP 보상 | 타격 전 0.12초 / 공용 Host AP +20 |
| X 회피 | 타격 전에 한 번 누르기 | 피해 없음, AP·반격 보상 없음 | 타격 전 0.22초 |
| C 연계 반격 | 반격 가능 공격의 타격 전에 한 번 누르기 | 해당 스킬 중단, 생존 전열 연계 공격 | 타격 전 0.18초 / 각 아군 ATK × 1.5 |

위 판정 시간은 난도 배율 1 기준입니다. 기존 난도 배율과 스킬의 개별 Perfect 구간을 적용합니다. `판정 시간` 0.8초는 입력 안내가 열린 뒤 타격까지의 전체 시간이지, 0.8초 아무 때나 회피/반격이 성공한다는 뜻이 아닙니다.

- 먼저 누르고 있던 Z는 여러 타격에 계속 가드할 수 있지만 저스트 가드가 되지는 않습니다.
- 타격 하나의 첫 새 입력만 판정합니다. 너무 일찍 눌렀다가 연타해도 저스트 구간이 갱신되지 않습니다. Z를 다시 잡는 것은 일반 가드로만 인정합니다.
- X/C를 고르면 그 타격의 대응이 확정됩니다. 실패한 뒤 Z를 누르거나 이미 Z를 누르고 있어도 가드로 덮지 않습니다.
- 같은 프레임의 복수 새 입력은 무효입니다. 한 입력으로 연속 타격 두 개를 해결할 수 없습니다.
- C는 모든 강공격에 통하지 않습니다. 반격 가능 공격은 Z가 불가능하고, X로 안전하게 피하거나 C로 반격할 수 있습니다. 실패는 원래 공격 피해이며 별도 벌칙은 없습니다.
- 실제 피해는 기존 DEF·속성 계산을 거칩니다. 가드의 0.5는 기존 피해 입력 배율이므로 최종 HP 감소량이 항상 정확히 절반인 것은 아닙니다.

## 2. C 연계 반격의 구성

1. 적의 전조와 입력 안내가 나옵니다. 반격 가능 공격에는 `가드 불가 · 연계 반격 기회`를 표시합니다.
2. C 성공 시 들어올 피해를 막고 해당 적 스킬의 나머지 블록을 실행하지 않습니다.
3. 방어한 캐릭터부터 현재 전열의 생존 아군 최대 3명이 짧게 공격합니다. 기본 공격 애니메이션·효과와 DOTween 접근/복귀를 재사용합니다.
4. 각 아군의 ATK에 반격 배율을 곱한 물리 피해를 줍니다. 한 명만 살아 있어도 단독 반격합니다.
5. 이후 적이 살아 있으면 복귀하고, 기존 전투 흐름에서 승리·다음 턴을 처리합니다.

후열·전투불능·비활성 캐릭터는 참여하지 않습니다. 도중에 적이 죽으면 나머지 공격은 중단합니다. 아군의 AP, 정상 행동 순서, 추가 행동 완료 이벤트, 행동에 따른 출혈 틱을 소비하거나 발생시키지 않습니다. 전열 교체 규칙은 변경하지 않았습니다.

## 3. 새 반격 공격 만들기

`Hub To Home > 제작 > 스킬 메이커`에서 새 스킬을 만들 때 **연계 반격 공격** 템플릿을 선택합니다. 기존 스킬을 덮어쓰지 않고 새 자산을 만듭니다.

템플릿은 접근 → 전조·방어 대응 → 피해 → 복귀의 기존 블록으로 구성됩니다. 기본 전조 0.6초, 판정 시간 0.8초, 반격 배율 1.5입니다. 적의 원래 공격은 ATK × 1.8이며 실패 추가 배율은 1.0으로 둡니다. 반격 실패에 별도의 벌칙 피해를 더하지 않으며, 이 공격 수치를 다른 스킬에 일괄 적용하지 않습니다.

제작 순서:

1. 새 스킬을 저장할 콘텐츠 폴더와 이름을 선택합니다.
2. 스킬 이름·ID·적 전용 설정을 확인합니다.
3. **방어 대응** 블록에서 `공격 대응 방식 = 연계 반격 가능`을 확인합니다.
4. 적에 맞는 전조 VFX/스프라이트/Animator Trigger와 공격 애니메이션을 연결합니다. 템플릿은 아트 참조까지 추측해서 연결하지 않으므로 검사에 표시된 누락 참조를 채웁니다.
5. `연계 반격: 각 아군 ATK 배율`, 판정 시간, 실패 피해 배율을 조절합니다.
6. 검사 화면의 오류를 해소한 뒤 저장하고, 사용할 `EnemyData`의 스킬 목록에 연결합니다. 생성만으로 적의 기존 스킬 목록을 바꾸지는 않습니다.

기존 스킬에서는 타격 직전의 `Action_DefenseWindow`만 설정하면 됩니다. 새 Action ID, 새 시나리오 YAML 문법, 수동 관리 참조 JSON 작성은 필요하지 않습니다.

방어 결과는 다음 피해 블록에서 소비됩니다. 방어창 → 피해 → 다음 방어창 → 피해 순서를 지키세요. 피해 없이 방어창만 연속으로 넣으면 앞선 배율이 남을 수 있어 제작 검사에서 경고합니다. 런타임이 의도한 다단 공격을 임의로 재작성하지는 않습니다.

| 방어 대응 설정 | 새 모드에서 허용되는 입력 |
| --- | --- |
| 일반 / 기존 Any·ParryOrDodge·ParryOnly | Z 가드·저스트 가드, X 회피 |
| 회피 전용 / 기존 JumpOnly·DodgeOnly·DodgeOrJump | X 회피 |
| 연계 반격 가능 (`Counterable`) | X 회피, C 연계 반격 / Z 불가 |

기존 점프 전용 자산은 회피 전용으로 해석합니다. 자동으로 C 공격으로 바꾸지 않았습니다. `Counterable`은 enum 뒤에 추가했으며 기존 번호·직렬화 필드·프리팹 참조와 공격 스킬 QTE의 C 입력은 유지합니다.

## 4. 공용 조절 위치

- 공용 `SeamlessBattleHost`의 `QTEManager > Z / X / C 방어`: 새 모드 사용, 가드 피해 배율, 회피 구간, 연계 반격 구간.
- `QTEManager`의 Perfect 구간: 저스트 가드 시간. 스킬의 `개별 판정 구간 사용`으로 해당 스킬의 Perfect 구간을 덮어쓸 수 있습니다.
- `BattleManager._apOnParryPerfect`: 저스트 가드 AP 보상. 공용 프리팹의 현재 값은 20입니다.
- 스킬 `Action_DefenseWindow.CounterDamageMultiplier`: 해당 반격에 참여하는 아군 각각의 ATK 배율.
- 이전 시간제 Z 방어는 호환 옵션으로 남아 있습니다. 새 모드를 끈 경우에만 적용되며 새 모드에서는 0.4초 제한을 사용하지 않습니다.

추가 Hierarchy 오브젝트나 서비스 참조 연결은 필요하지 않습니다. 기존 QTEManager와 공용 전투 Host를 사용합니다. C 전용 보스 스킬은 제작자가 템플릿/블록 설정으로 명시적으로 등록해야 합니다.

입력은 저장된 Confirm/Cancel/Menu 키 재설정을 따릅니다. 재설정 전 Z/X/C가 동시에 남아 오판정되던 우회 입력은 제거했습니다. 패드는 아래쪽 버튼 = 가드, 오른쪽 = 회피, 위쪽 = 반격으로 공용 InputAction에 연결합니다. 기기마다 A/B/X/Y 글자가 다르므로 위치 기준입니다. 이번에는 새 모바일 터치 버튼이나 패드 전용 아이콘 자동 전환까지 만들지 않았으며, 화면 안내는 설정된 키보드 키 이름을 사용합니다.

## 5. 구조와 중단 처리

- `GameInput`: 입력 통로. 방어의 C만 새 Counter 의미로 해석합니다.
- `DefenseJudgementPolicy / ActiveDefenseAttempt`: 시간·입력·피해 결과를 순수 판정합니다.
- `QTEManager`: 한 번에 하나의 QTE, 입력 소비, 마감, 일시정지, 취소와 결과 알림을 소유합니다.
- `Action_DefenseWindow`: 판정을 기존 스킬 피해에 연결하고 C 성공 시 스킬을 중단합니다.
- `BattleLinkCounterService`: 전열 구성과 짧은 반격 연출·물리 피해를 담당합니다.
- `BattleTurnQteModuleControllerService`: 턴, 적 복귀, 승패와 후열 진입을 계속 담당합니다.
- `DefenseQTEUI / BattleUIController`: 허용 입력과 가드·저스트 가드·회피·연계 반격 결과를 표시합니다.

모듈 변경·전투 종료·대상 소멸·시나리오 취소 시 이후 피해를 차단하고 소유한 Tween과 전조·방어 포즈를 정리합니다. BattleManager의 공유 반격 서비스는 모듈 해제·도주·종료·강제중단·파괴에서 `CancelActive()`를 호출해 코루틴의 finally에만 복구를 맡기지 않습니다. 세대 번호와 멱등 해제로 늦은 finally가 새 위치를 덮는 것도 방지합니다. 반격 성공과 QTE/시퀀스 취소는 별개로 취급하며 다른 연출의 Tween을 일괄 종료하지 않습니다.

## 6. 검증 범위

정적 컴파일과 소스 검증 결과는 [당일 기록](../../2026-09-13-update.md)에 남깁니다. 입력 경계, 반격 참여자, 취소, UI 복원, 템플릿 검사 회귀 테스트 소스를 보강했지만 Unity 테스트를 실행하지는 않았습니다.

사용자 확인이 필요한 부분은 실제 30/60 FPS 타이밍 체감, 적마다 전조 가독성, 캐릭터별 공격 모션·복귀 모습, 작은 화면 UI, 연결 기기의 버튼 입력입니다. 실기 성능이나 연출 품질 검증까지 완료했다고 보지 않습니다. 씬·프리팹·기존 스킬 자산 자동 수정과 커밋·푸시는 하지 않습니다.

주요 변경 파일: `DefenseJudgementPolicy`, `QTEManager`, `GameInput`, `PlayerController`, `BattleLinkCounterService`, `SkillActionBlocks`, `EnemyAttackAuthoring`, `BattleManager`, `BattleStateMachine`, `BattleTurnQteModuleControllerService`, `BattleSkillTimelineRunner`, `DefenseQTEUI`, `BattleUIController`, 스킬 메이커와 관련 테스트 소스.
