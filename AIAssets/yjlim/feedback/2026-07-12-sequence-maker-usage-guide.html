02-B

Sequence와 Shot의 역할은 다르다

블록 순서는 Sequence가 소유하고, 한 샷 안에서 여러 물체와 렌즈가 어떻게 움직이는지는 Cinematic Shot Asset이 소유한다.

Sequence대기 → 샷 → 여운 → 암전 → 2초 대기 → 카메라 해제 → 페이드. 전체 사건의 순서와 완료 대기를 표현한다.
Stage IDoverworld.subway_intro · Scene 안의 전용 카메라와 연출 대상을 묶는 안정적인 이름.
Shot IDsubway_arrival · 해당 Stage에서 재생할 구체적인 카메라/대상 모션 묶음.
Train MotionX -30 → 24, 8초, Linear. 화면 밖에서 들어와 오른쪽으로 지나간다.
Camera Motion4.45초 지연 후 rail (-2.0625, 3.75) → (21.9, 3.75), 3.55초. 기차 Sprite 중심보다 왼쪽 2 unit을 같은 속도로 따라간다.
Lens MotionOrthographic Size 10 → 7, 4.45초 지연 후 3.55초. 기차 전체가 들어오는 여유 있는 줌인이다.
Position Damping(0, 0, 0). 일정 속도 rail을 지연 없이 정확히 따라가며 Pixel Perfect 출력에서 생기는 추적 떨림을 줄인다.
편집 위치Assets/_Game/Content/Cinematics/Overworld/overworld_intro_subway_arrival.asset을 Project 창에서 선택해 Inspector에서 수정한다.

어디에 무엇을 넣을까?

“잠시 기다린다”, “대사를 한다”, “화면을 가린다”처럼 다른 시스템과 연결되는 사건은 Sequence 블록으로 둔다. 반대로 한 카메라 샷 안에서 기차와 rail이 정밀하게 같이 움직이는 값은 Shot Asset에 둔다. 복잡한 키프레임이 필요할 때만 timeline.play를 선택한다.

03

실제 화면을 읽는 순서

왼쪽에서 대상을 찾고, 가운데에서 흐름을 편집하고, 오른쪽에서 선택한 대상이나 블록의 값을 조정한다.

1
편집 대상Battle Scenario 또는 독립 Action Sequence Asset을 선택한다.
2
탐색최근 작업, 전투 흐름, 독립 시퀀스, 즐겨찾기를 찾는다.
3
블록 흐름위에서 아래로 순차 실행된다. 드래그로 순서를 바꾸고 우클릭으로 복제·삭제·추출한다.
4
속성 Inspector시퀀스 설명, 블록 이름, 파라미터, 값 출처, 사용 위치를 편집한다.
5
명령과 재생검증·저장·액션 추가, 안전 미리보기와 Play Mode 테스트를 실행한다.
6
하단 패널문제, 실행 기록, 현재 YAML을 확인한다. 오류 행을 누르면 문제 위치로 이동한다.
04

두 가지 제작 방식

결과물은 같다. 사람이 처음부터 조립할 수도 있고, 자연어 요구사항으로 AI가 초안을 만든 뒤 사람이 Sequence Maker에서 타이밍과 순서를 다듬을 수도 있다.

사람이 직접 만들기

작은 연출, 기존 액션만 사용하는 흐름, 수치 튜닝에 적합하다.

  1. Action Sequence Asset 준비Project 창의 Create / HubToHome / Scenario / Action Sequence로 만들거나 기존 시퀀스를 선택한다.
  2. 편집 대상 선택상단 Object Field 또는 왼쪽 탐색에서 Asset을 연다.
  3. 시퀀스 정보 작성오른쪽에서 안정적인 Sequence ID, 표시 이름, 무엇을 하는지, 언제 쓰는지를 적는다.
  4. 액션 찾기상단 액션 버튼을 누르고 “기다리기”, “샷”, “페이드”처럼 의미로 검색한다.
  5. 블록 삽입·정렬삽입한 블록을 드래그해 순서를 맞춘다. 동시에 실행할 것은 flow.parallel 안에 넣는다.
  6. 파라미터 설정블록을 선택하고 오른쪽 Inspector에서 시간, ID, 색상, 대상 등을 입력한다.
  7. 검증상단 검증을 누르고 하단 문제 탭이 0인지 확인한다.
  8. 안전 미리보기시작할 블록을 선택해 앞 블록을 빠르게 준비한 뒤 해당 위치부터 재생한다.
  9. 저장Ctrl+S 또는 저장. Runtime Asset과 YAML Source가 함께 동기화된다.

AI와 함께 만들기

새 액션·Stage·Shot·트리거·씬 연결이 함께 필요한 복합 연출에 적합하다.

  1. 장면을 자연어로 설명어디서 시작하고 무엇이 보이며 언제 끝나는지 순서대로 말한다.
  2. 발동 조건 명시첫 진입, 전투 시작, HP 50%, 두 번째 만남처럼 WHEN과 반복 정책을 알려준다.
  3. 유지할 상태와 금지 사항 명시씬 전환 금지, 원본 캐릭터 유지, 전투 HP 유지 등을 적는다.
  4. AI가 기존 계약 확인Action Catalog, Trigger Library, 기존 Scene/Prefab, Scenario Source를 먼저 읽는다.
  5. AI가 Source/Runtime 동기화YAML, Runtime Asset, Shot/Stage, 필요한 Adapter와 Catalog를 함께 갱신한다.
  6. AI가 검증컴파일, Catalog validation, YAML round-trip, EditMode/PlayMode를 실행한다.
  7. 사람이 Sequence Maker에서 다듬기블록 이름, 순서, 대기 시간, 페이드 시간을 눈으로 보고 조정한다.
  8. AI가 문서와 Skill 최신화새 액션이나 포맷이 생겼다면 작업 지침과 시나리오 Skill까지 같은 변경에 반영한다.
[환경]
OverworldScene 첫 진입. 별도 Scene 전환 없이 진행.

[발동]
SceneLoader가 검은 화면에서 Stage를 준비하고 1초 동안 화면을 밝힌 뒤 1회 실행. 저장 데이터에서 이미 완료했으면 재생하지 않음.

[연출 순서]
1. 밝아진 줌아웃 구도를 0.75초 보여준다.
2. 지하철이 왼쪽 화면 밖에서 오른쪽으로 8초 이동한다.
3. 기차가 중앙에 도달할 즈음 카메라가 Sprite 중심보다 살짝 왼쪽을 따라가며 10에서 7로 줌인한다.
4. 0.35초 유지 후 1초 동안 검게 페이드한다.
5. 완전히 어두운 화면을 2초 유지한다.
6. 원래 오버월드 카메라로 즉시 복귀한다.
7. 0.9초 동안 다시 밝히고 Exploration 상태로 끝낸다.

[유지 / 금지]
- Player, ZEV, 기본 카메라의 원본 Scene 참조를 파괴하지 않는다.
- 전환용 별도 Scene을 만들지 않는다.
- 기존 Action Sequence/YAML 동기화 규칙을 사용한다.

[검증]
- Sequence Maker에서 사람이 순서와 시간을 수정 가능해야 한다.
- Action Catalog validation, YAML round-trip, 전체 EditMode 테스트를 실행한다.
- 작업 문서와 hubtohome-scenario-authoring Skill을 최신화한다.
05

트리거는 “언제”, 시퀀스는 “무엇”

지하철은 Scene의 SceneActionSequenceTrigger가 실행한다. 전투에서는 Battle Scenario의 Trigger Rule이 이벤트와 조건을 평가하고 같은 Action Sequence 체계를 호출한다.

예: 보스 HP가 처음 50% 아래로 내려간 뒤

eventIdparticipant.hp_changed
HP 값이 바뀐 순간의 공식 이벤트.
condition 1event.participant
여러 참가자 중 보스의 변화만 선택.
condition 2number.crossed_below
이전 값과 현재 값 사이에서 0.5를 처음 통과했는지 검사.
timingcheckpoint: skill.finished
공격 중간이 아니라 현재 스킬이 완전히 끝난 뒤 실행.
onceencounter_memory
같은 Encounter에서 다시 발동하지 않고 저장에도 연결.
do.sequenceboss.phase2.transition
대사·BGM·페이드·모듈 전환을 담은 시퀀스 실행.
rules:
  - id: boss_phase2
    name: "보스 2페이즈 전환"
    when:
      eventId: participant.hp_changed
      timing: checkpoint
      checkpoint: skill.finished
      once: encounter_memory
      conditions:
        id: boss-phase2-root
        all:
          - id: boss-target
            condition: event.participant
            params:
              participant: boss
          - id: hp-half
            condition: number.crossed_below
            params:
              previousPath: event.previousRatio
              currentPath: event.currentRatio
              threshold: 0.5
    do:
      sequence: boss.phase2.transition
      inputs:
        enemy: ${event.subject}
        ratio: ${event.currentRatio}
지하철 예시에는 Battle Rule이 없다

오버월드 Scene 첫 공개라는 생명주기는 Scene Component가 이미 소유한다. 억지로 Battle Scenario Rule에 넣지 않는다. 반대로 HP 변화, 스킬 종료, 모듈 결과처럼 전투 데이터가 결정해야 하는 사건은 Scene Component가 아니라 Trigger Rule에 둔다.

07

저장·검증·재생의 안전 규칙

초록색 재생 버튼만 누르는 것으로 작업이 끝나지 않는다. 데이터 계약, Source 동기화, 실제 Context를 각각 확인한다.

저장 전

  • Sequence ID가 고유하고 안정적인가
  • 사람이 읽는 이름과 용도를 적었는가
  • 액션 블록 이름이 장면의 의도를 말하는가
  • 필수 ID와 시간이 비어 있지 않은가

검증

  • 알 수 없는 Action ID가 없는가
  • Dialogue, Audio, Actor, Module ID가 해석되는가
  • Trigger Event와 Condition 파라미터가 유효한가
  • YAML Source와 Runtime Asset이 같은가

재생

  • 안전 미리보기로 선택 블록까지 상태 준비
  • Play Mode 테스트로 실제 Scene Context 확인
  • 실행 기록에서 실패 블록과 메시지 확인
  • 카메라·입력·GameState가 끝에 복구되는가
“선택 블록부터 재생”은 앞 블록을 무시하지 않는다

선택 위치에 필요한 카메라·Stage·상태를 만들기 위해 앞 블록을 빠르게 준비한 뒤 선택 블록부터 실제 속도로 재생한다. 준비할 수 없는 위험 액션은 정책에 따라 건너뛰거나 Play Mode 테스트를 요구한다.

YAML과 Runtime Asset 중 무엇이 진짜인가?

Scenario YAML이 사람이 읽고 AI가 관리하는 Source of Truth이고, ScriptableObject는 Unity Runtime 표현이다. Sequence Maker는 Runtime Asset을 편집하지만 저장 Coordinator가 YAML round-trip과 외부 변경 충돌을 확인한 뒤 둘을 동기화한다. Unity .asset YAML을 손으로 편집하지 않는다.
