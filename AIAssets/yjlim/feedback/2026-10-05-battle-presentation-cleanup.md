# 전투 표현 안정화 · 2026-10-05

최근 작업의 중단·재사용·입력 경계만 정리했습니다. HP/피해/상태이상 계산, 전열·후열 편성, 수동 교대 유무, 턴 순서, 기존 자산은 바꾸지 않았습니다. 전 프로젝트의 모든 버그가 제거되었다는 의미는 아닙니다.

## 확인한 문제와 수정

| 영역 | 기존 경로의 문제 | 이번 처리 |

## 변경 소유권

- `GameInput`: 입력을 허용하는 공통 경계. 모달의 입력 기능 자체를 끄지는 않음.
- `BattleManager`: 파티 승계와 턴 재개. `BattlePartyWavePresentation`: 연출 트윈·원색·도착 위치 복원만 소유.
- `BattleDamageBatchTracker`: 표시용 행동 묶음 수명. 피해 계산에는 관여하지 않음.
- `BattleDamagePopupPresenter`: 합계·풀·레이아웃. `BattleDamagePopupView`: 숫자 표시와 자신의 트윈.
- `BattleSpeechBubble`: 기존 Rule/Show API를 보존한 멱등 초기화와 표시 성공 판정.

직렬화 이름, enum 값, prefab hierarchy 경로는 유지했습니다. 새로 연결할 Inspector 항목은 없습니다.

## 확인 결과와 한계

Runtime/Editor CLI 최종 증분 빌드 오류0/경고0. Runtime 재컴파일에서 나온 기존 경고2(ConfigPanelUI Inspector 할당 필드)는 이번 범위에서 변경하지 않았습니다. 의존성까지 다시 빌드하면 기존 Febucci 경고도 남아 있습니다.

프로덕션 `BattleDamageBatchTracker` 소스를 직접 연결한 별도 관리형 검사에서 다음 6,000조건을 통과했습니다: 종료 직후 CurrentId, 종료 콜백의 ID, Clear, 단조 증가 ID, 오래된 Dispose, Activation 종료. 수정 전 동일한 검사에서 종료한 ID가 남는 실패를 재현했습니다.

회귀 검사11개를 추가하고 컴파일했습니다. 모달 닫힘/방어 입력 소비2, 교체 중단/세대/이벤트 취소3, 말풍선 빈 콘텐츠/초기화2, 피해 묶음 종료1, 팝업 파괴 치환/가로 경계/CanvasGroup 파괴3. **Unity NUnit·실제 Play는 실행하지 않았습니다.**

## 사용자가 확인할 순서

1. 전투 중 일반 대사창에서 Z/X/C를 누르고 닫기: 뒤의 메뉴/방어가 같이 실행되지 않아야 함. 닫은 뒤 새 입력은 정상 작동.
2. 캐릭터 말풍선: 텍스트 → 아이콘 → 혼합 → 텍스트 순서. 이전 아이콘 잔류 없음, 빈 규칙은 소비되지 않음.
3. 기존 3+3 실습: 전열 전체 사망 → 0.5초 페이드 → 후열 왼쪽 밖 진입 → Idle → 다음 턴.
4. 같은 실습 중 전투 종료/호스트 비활성화: 투명도·이동 위치·교체 잠금이 다음 전투에 남지 않아야 함.
5. 연타·속성 피해: 같은 행동은 누적, 새 행동은 새 합계. 여러 속성 숫자가 세로로 정렬되고 과도하게 긴 수치는 화면 폭 안으로 축소.

기존 글자 깨짐은 원인 미확인입니다. 실제 화면 없이 SDF 폰트·카메라·Pixel Perfect 설정을 바꾸지 않았습니다.

## 재사용할 작업 절차 기록

- 날짜/맥락: 2026-10-05, Unity를 재생하지 않는 CLI 회귀 검사.
- 실패: `Temp/BattleCleanupChecks`에 만든 검사 프로젝트가 후속 실행 시 없어 MSB1009 발생. 파일이 사라진 주체는 확인하지 못함.
- 성공: Git에서 제외되는 프로젝트 내부 `Library/CodexChecks`에 검사 파일을 만들고 실제 Runtime 소스를 링크하여 실행. 6,000조건 통과. 지속 검사는 커밋 대상 NUnit 소스에 보존.
- 적용: Unity의 Temp 파일을 장기 보존된 검증 산출물로 가정하지 말 것. 프로젝트 파일에 새 코드가 이미 포함되어 있는지 확인 후 중복 include 없이 빌드.
- 패치 실패: 여러 파일 수정 중 일부만 적용된 상태에서 오류가 반환됨. 재적용 전에 `rg`로 이미 반영된 선언을 확인하고, 남은 파일에만 단일 파일 패치를 적용. 같은 검사 메서드가 중복되었을 때 컴파일에서 CS0111로 탐지·제거. 도구 내부 재시도 여부는 미확인.
- Git 검사: 이 CRLF 저장소에서 검사 목적으로 `core.autocrlf=false`를 강제하면 CR 문자가 공백 오류처럼 대량 표시됨. 저장소 기본 설정의 `git diff --check`로 검사하며 파일 전체 줄바꿈은 바꾸지 않음.
- 요청된 전역 `C:/Users/yjlim/.codex/memories`는 현재 호스트에 존재하지 않고 쓰기 허용 범위 밖이므로, 이 프로젝트 문서에 기록함. 다른 사용자 프로필은 생성하지 않음.
