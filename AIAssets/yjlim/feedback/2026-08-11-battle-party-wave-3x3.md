# 3+3 파티 웨이브 전투 구현 피드백

## 결과

요청한 규칙만 구현했다. 전투 시작 시 앞 3명은 활성 전열, 다음 3명은 생성·데이터 적용이 끝난 비활성 후열이다. 수동 교대는 없으며, 전열 전원이 쓰러진 뒤 현재 행동이 끝나면 후열이 한꺼번에 활성화된다.

후열 투입은 새 전투 시작이 아니다. 적의 HP와 상태, 전투 시나리오와 보상 진행 상태를 유지하고, 기존 턴 큐만 폐기한 뒤 새 전열 기준으로 다시 계산한다. 적과 전열이 같은 행동에서 함께 전멸하면 승리를 우선한다.

## F2 테스트 방법

1. 전투에 들어가기 전에 F2를 연다.
2. `Data` 탭에서 `Prepare 6-Member Wave Party`를 누른다.
3. 전투에 들어가 전열 3명만 화면과 파티 UI에 표시되는지 확인한다.
4. 플레이어 행동 선택 상태에서 F2의 `Battle` 탭을 연다.
5. `Defeat Active Wave`를 누른다.
6. `후열이 전투에 합류했다!` 내레이션 뒤 후열이 기존 1~3번 위치에 함께 등장하는지 확인한다.
7. 후열로 공격, 승리, 도주를 각각 확인한다.

`Prepare 6-Member Wave Party`는 서로 다른 Catalog 캐릭터를 우선 사용한다. 현재 프로젝트의 등록 캐릭터가 부족하면 리더 데이터를 복제한다. 복제 인원은 같은 `CharacterDataID`를 공유하므로 웨이브 전환과 UI 확인에만 사용해야 한다. 보상 재동기화나 시나리오 참가자 ID 검증에는 고유 ID를 가진 실제 6인 데이터를 사용한다.

## 안전 처리

- 7명 이상 파티는 앞 6명만 사용하고 기존 데이터를 삭제하지 않는다.
- 전열 생존자가 한 명이라도 있으면 후열을 투입하지 않는다.
- 후열이 없으면 기존 패배 경로를 사용한다.
- 중복 전환 요청과 전투 종료 뒤 늦게 도착하는 Coroutine을 version으로 무효화한다.
- 비활성 후열은 턴 큐, 공격·회복 대상, 참가자 명령 해석에 포함하지 않는다.
- 심리스 Scene Player는 절대 추가 생성 목록으로 파괴하지 않는다.
- 파티 UI는 기존 3칸을 재사용하며 후열 UI나 교대 버튼을 만들지 않았다.

## 검증 결과

- Unity Editor 실제 컴파일 성공
- 독립 Runtime/Editor Roslyn 컴파일 오류 0개
- 신규·직접 관련 EditMode 17/17 통과
- 보상·전투 이벤트·UI 인접 회귀 11/11 통과
- 마지막 수정 뒤 핵심 EditMode 16/16 재통과
- Scene, Prefab, ScriptableObject 자산 변경 없음

실제 Play 화면에서의 F2 수동 절차는 아직 실행하지 않았다.

## 검증 하네스 메모

Unity Domain Reload 중 `unity-cli-connector`의 기존 포트가 즉시 해제되지 않으면 새 서버가 다음 포트로 올라올 수 있다. 고정 포트 polling이 시간 초과될 때는 컴파일 실패로 판단하지 말고 `Editor.log`의 `HTTP server started on port`와 해당 Unity 프로세스의 listening port를 다시 확인한다. 이번 작업에서는 최초 8090에서 재로드 뒤 8092로 이동했으며, 새 포트에서 Editor 컴파일 완료와 테스트 결과를 정상 회수했다.
