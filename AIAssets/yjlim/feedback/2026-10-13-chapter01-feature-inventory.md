# 챕터 1 · 미완성 기능과 기획 결정 목록

> 기준: 2026-10-13 현재 작업 트리. 주인공 위젤 + 동료 2명, 총 3인. 아래 배열은 기능 분류이며 우선순위가 아니다.
>
> 이 문서는 구현 지시서가 아니라 기획을 받기 위한 현황표다. “기반 있음”은 코드 경로의 존재를 뜻하며, 완성된 콘텐츠나 Unity 실행 검증을 뜻하지 않는다.

## 읽는 법

- **구현 보강**: 비어 있는 실행 경로나 연결부가 확인됨. 해당 기능을 쓰기로 정하면 개발이 필요하다.
- **기획·데이터**: 기존 기능으로 표현할 기반이 있음. 챕터 1의 규칙·수치·배치를 정해야 한다.
- **통합 검증**: 기능을 새로 만들기보다 실제 콘텐츠를 연결하고 플레이 결과를 확인해야 한다.
- **선택 확장**: 챕터 1에 사용하지 않으면 만들 필요가 없다.

6인 편성, 수동 교대, 후열용 동료 추가, 후속 챕터 전용 전투는 이번 필수 범위에서 제외한다. 기존 후열 승계 코드를 삭제한다는 뜻은 아니다.

## 확인된 구현 공백

| 항목 | 확인 결과 | 기획과의 관계 |
| --- | --- | --- |
| 실제 동료 2명 | 본편 AllyDB에는 WizzelDB, 고유 자원에는 WizelPressure가 확인된다. 실험실의 색상 복제는 별개다. | 동료별 역할·기술·합류 조건이 정해져야 본편 데이터와 필요한 고유 규칙을 만들 수 있다. |
| 본편 동료 합류 경로 | Party.Add의 본편 경로는 초기 파티 구성이고, 추가 인원은 디버그/테스트 경로가 중심이다. 제작자가 합류·이탈을 지정하는 완결된 본편 이벤트 경로는 이번 검색에서 확인되지 않았다. | 언제 누구를 합류시키는지, 이미 합류한 이벤트를 다시 밟으면 어떻게 할지 정하고 저장까지 연결해야 한다. |
| 장비 획득 연결 | 장비 보관함과 일반 아이템 보관함이 분리되어 있다. 현재 상점 구매·전투 드롭·아이템 마커 지급은 일반 아이템 지급 경로를 사용한다. | 장비를 판매/드롭/보상으로 얻는다면 장비 보관함으로 분기하는 연결이 필요하다. 장비 장착 기능이 없다는 뜻은 아니다. |
| 장비 고유 효과 | EquipmentData의 PassiveEffectID와 EquipReactionDialogueID는 실행되지 않는 예약 필드다. | 단순 능력치 장비면 사용하지 않아도 된다. 조건부 효과나 장착 대사를 넣으려면 실행 규칙부터 정해야 한다. |
| 부활·정화 아이템 | 현재 아이템 효과는 Heal/Damage/ApplyStatus이며 죽은 대상은 사용 가능 검사에서 제외된다. 전용 부활/정화/복합 효과 액션은 없다. | 부활약, 해독제, HP·AP 동시 회복을 원하는 경우 확장 대상이다. 스킬의 정화 기능까지 없다는 뜻은 아니다. |
| 저장 지점 회복 | SavePoint와 SavePointMarker의 상호작용은 저장 요청이며, 그 자체에 파티 회복 호출은 없다. | 저장과 회복을 함께 제공하려면 회복 시점과 취소 시 처리를 정하고 연결해야 한다. |
| 전투 정보 열람 | 상태 아이콘·누적 수치는 있으나 전용 적 분석/상태 상세 화면은 확인되지 않았다. | 키보드로 저항·상태 설명을 어디에서 볼지 정해야 한다. |
| 현지화 범위 | 본문 LocalizationKey와 번역표는 있지만 DialogueUI의 화자명·선택지명은 원문을 직접 표시한다. 조작 안내 등에도 고정 문구가 남아 있다. | 번역 대상에 이름·선택지·메뉴·아이템·스킬·상태 설명을 포함하고 누락 경로를 연결해야 한다. |
| 터치 및 입력 기기 표시 | 패드 입력 기반은 있다. 자체 Scripts에서 터치 전용 조작 화면은 확인되지 않았고, 전투 안내는 키보드 문자열과 단일 이미지 모델이다. | 모바일 UI와 입력 기기별 안내 전환은 별도 구성 대상이다. 콘솔 실기기 지원 완료를 의미하지 않는다. |

## B. 성장과 스킬

EXP·레벨·능력치 투자·스킬 트리·장착·초기화 서비스는 있다. 기본 성장 데이터는 레벨당 능력치 3점/스킬 1점, 현재 트리는 최대 6개 장착이다. 이는 현재 데이터이지 확정 기획이 아니다.

| ID | 구분 | 사용자가 정할 내용 |
| --- | --- | --- |
| B1 | 기획·데이터 | 챕터 시작/종료 예상 레벨, 선택 전투를 하지 않아도 클리어 가능한지, 레벨업 자동 상승과 포인트 투자 비중. |
| B2 | 기획·데이터 | 각 캐릭터 기본 공격, 초기 스킬, 챕터 중 배울 스킬. 획득 방식은 레벨/포인트/이벤트 중 무엇인지, 장착 수는 몇 개인지. |
| B3 | 기획·데이터 / 필요 시 보강 | 스킬 장착 변경과 능력치·스킬 초기화가 언제 가능한지, 비용이 있는지. 서비스가 있다는 사실과 원하는 비용·장소 제한이 연결되어 있다는 사실은 다르다. |
| B4 | 기획·데이터 | 공격 QTE의 역할: 실패해도 기본 피해는 주는지, 성공 보상이 피해/AP/자원 중 무엇인지. 긴 연타 중 QTE 횟수, 반복 전투의 피로도도 함께 정한다. 플레이어 설명에 내부 블록·프레임 용어를 노출할 필요는 없다. |

## C. 전투 규칙과 적

Z 방어/저스트가드, X 회피, C 특수 반격, 속도 기반 반복 턴, 가중 랜덤 타깃, 데이터 블록 스킬과 전조는 이미 있다. 이를 새 시스템처럼 재구현할 필요는 없다.

| ID | 구분 | 사용자가 정할 내용 |
| --- | --- | --- |
| C1 | 기획·데이터 | 일반 방어 감소율, 저스트가드/AP/고유 자원 보상, 회피의 장점, C 성공 보상과 실패 피해. 기존 방어창을 유지할지 난이도별 차이를 둘지도 포함한다. |
| C2 | 기획·데이터 / 통합 검증 | 일반 공격은 매 타격 전조라는 현재 원칙에서, 예외로 리듬 선행 예고를 쓰는 기술이 있는지. 근접·투사체·전체 공격을 어떻게 구분해서 읽게 할지. |
| C3 | 기획·데이터 | 챕터 일반 적/강한 적/보스의 구성, 적 조합, 반복 전투 길이, 보스 체력 구간별 행동. 실험실 토끼와 제브의 동작이 본편 밸런스 완료를 뜻하지 않는다. |
| C4 | 기획·데이터 | 적 타깃 정책: 랜덤을 기본으로 유지하고 저체력/특정 상태/도발 등에 별도 규칙을 줄지. 도발 등 새 규칙을 쓰면 별도 구현 확인이 필요하다. |
| C5 | 기획·데이터 | 도주 가능 전투, 성공률과 실패 시 손해, 도주 후 적 재접촉 유예. 패배가 허용되는 이야기 전투가 있는지도 정한다. |
| C6 | 기획·데이터 | 전투 간 HP/AP 및 고유 자원의 유지·초기화 규칙. 위젤 압력은 현재 전투 내 자원이다. 유지하도록 바꾸면 저장·진입·종료 계약도 함께 바뀐다. |

## 별도로 필요하다고 정하지 않으면 제외할 것

6인 출전 편성, 수동 교대, 관계도/호감도, 제작/분해/강화, 도감, 업적, 미니맵, 일일 퀘스트, 새 게임+, 챕터별 특수 전투, 완전한 열차 경영은 현재 챕터를 완성하기 위한 자동 추가 목록이 아니다. 전용 기능이 확인되지 않았다는 이유만으로 개발 범위를 늘리지 않는다.

## 기획을 전달할 최소 형식

각 항목을 `ID / 사용할지 / 규칙 / 예시 / 하지 않을 것`로 답하면 된다. 예를 들어 `F5 / 사용 / 저장 지점 대화 시작 시 HP·AP 회복, 취소해도 유지 / 보스 직전 풍차 저장 지점 / 유료 숙박은 없음`처럼 게임에서 일어날 결과를 적는다. 이는 승인된 규칙이 아니라 답변 형식의 예다.

## 검증 범위와 남은 확인

현재 소스·필드·호출자 검색 및 제작 자산 목록에 근거한 정적 기능 감사다. “확인되지 않음”은 이 검색 범위에서 완성된 경로를 찾지 못했다는 의미이며 가능한 모든 간접 호출 부재를 증명한 말은 아니다. 특히 사용자 미커밋 변경이 많아 예전 TODO나 문서의 완료/미완료 표기는 그대로 신뢰하지 않았다.

게임 코드·직렬화 자산·시나리오 소스·원격 문서는 수정하지 않았다. Unity 실행, 재임포트, 빌드, 테스트, 커밋, push도 하지 않았다. 기존 테스트 파일의 존재를 이번 실행 결과로 표현하지 않는다. 기능별 수치의 재미와 실기기 성능은 실제 플레이/계측이 남아 있다.
