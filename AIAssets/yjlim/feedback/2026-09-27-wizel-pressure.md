# 위젤 압력 자원 — 구현 및 수정 위치

## 적용된 규칙

- 실험실 선두의 `위젤 · 압력`을 `위젤`로 변경했습니다. 본편 DB 표시 이름도 위젤입니다. 사용자가 지정한 주인공 이름은 기존 규칙대로 우선합니다.
- 전투 시작 step0, 최대 step4. 퍼펙트 패링과 C 특수 반격 성공 1회당 +1입니다. 일반 가드/회피는 획득하지 않습니다. C 획득량은 `CounterGain`에서 별도로 조절합니다. [후속 반영 기록](2026-09-27-counter-popups-dialogue.md).
- 스킬 시작 시 강화 조건을 평가하고, **충족한 경우에만 스킬에 지정한 단계만큼 한 번 소모**합니다. 필요 단계와 소모량은 독립 설정입니다.
- 부족해도 AP 등 기존 조건을 만족하면 기본 성능으로 사용합니다. 압력은 새 사용 제한이 아닙니다.
- 강화 배율은 해당 스킬 전체 타격에 유지됩니다. QTE 배율과 곱해지지만 QTE 종료/다음 타격 초기화에 지워지지 않습니다.
- 정상 완료 획득량은 한 번만 지급합니다. 중단·사망·취소에는 완료 획득이 없고, 이미 시작한 강화 스킬의 비용은 돌려주지 않습니다.
- 같은 DB나 같은 자원 정의를 쓰는 위젤 6명도 현재 압력은 각각 다릅니다. 후열 비활성화는 유지, 전투 시작/종료/중단은 초기화합니다. 세이브에는 저장하지 않습니다.
- 광역 공격이 대표자 한 명의 대응 창을 사용하는 경우, 기존 AP 보상과 마찬가지로 그 대표자만 획득합니다. 적 타격 수가 여러 개면 성공한 각 대응 창마다 보상합니다.

## 수정 순서

1. `Assets/_Game/Content/Characters/BattleResources/WizelPressure.asset`에서 최대 단계·시작 단계·패링 획득·C 획득을 변경합니다.
2. 캐릭터 DB의 **전투 고유 자원**에 해당 정의를 연결합니다. `WizzelDB`와 실험실 위젤 6개 DB에는 연결되어 있습니다.
3. 스킬 메이커에서 스킬 선택 → **기본 정보 → 고유 자원**을 편집합니다. 사용 자원, 완료 시 획득, 조건부 강화, 필요 단계, 소모 단계, 피해 배율 순서입니다.
4. 스킬 설명창에 현재 압력·조건 충족 여부·강화 효과·획득량이 함께 표시됩니다. 자원이 없는 캐릭터는 오른쪽 자원 이미지를 숨깁니다.

## 임시 수치 예시

최종 밸런스가 아닌 확인용 설정입니다. 기존 AP·공격 연출·QTE·스킬 ID는 변경하지 않았습니다.

| 스킬 | 완료 획득 | 강화 조건 | 소모 | 강화 피해 |
|---|---:|---:|---:|---:|
| 압력 베기 / 증기 찌르기 | +1 | 없음 | 0 | 기존 |
| 쌍압 절단 | 0 | 2 이상 | 2 | ×1.5 |
| 역류 참격 | 0 | 4 이상 | 4 | ×2 |
| 압력 난무 · 5초 | 0 | 4 이상 | 4 | 모든 타격 ×1.5 |
| 공중 회전 베기 | 0 | 3 이상 | 3 | 모든 타격 ×1.5 |
| 본편 연쇄공격 `Skill_MultiSlash` | +1 | 없음 | 0 | 기존 |
| 본편 콤보슬래쉬 `Skill_ComboSlash` | 0 | 2 이상 | 2 | ×1.5 |
| 본편 내려치기 `Skill_Crash` | 0 | 4 이상 | 4 | ×2 |

## 오른쪽 이미지와 애니메이션

기존 `ActorLargePortrait` Image와 `BattleUIController._largePortrait` 연결을 그대로 사용합니다. 런타임에 `BattleResourceView`를 한 번 연결하므로 씬/프리팹 재생성은 필요 없습니다. 턴 큐/파티 초상은 기존 Portrait/TurnOrderPortrait를 유지합니다. 구형 BattleLargePortrait 데이터는 호환성을 위해 보존하되 Inspector에서 숨겼습니다.

`Wizel_special_resources.aseprite`는 현재 64×64, step0~4 각각 1프레임/100ms입니다. 따라서 현재는 단계 변경 시 그림이 바뀌며, 같은 단계 안에서 움직이는 추가 프레임은 없습니다. 원본 Sprite와 AnimationClip의 실제 임포트 fileID를 확인해 단계별로 연결했습니다.

애니메이션을 늘릴 때:

1. Aseprite에서 해당 step 태그에 프레임을 추가하고 저장합니다.
2. Unity에서 원본 임포트가 끝나면 `WizelPressure.asset`을 선택합니다.
3. **원본 애니메이션에서 UI 프레임 갱신** 버튼을 누릅니다. 원본 클립의 SpriteRenderer 프레임/시간을 UI Image용 데이터로 복사합니다.
4. 단계별 반복 여부는 `반복` 필드에서 지정합니다. 원본이 한 SpriteRenderer 트랙인 경우를 지원합니다.

렌더텍스처·별도 카메라·런타임 AssetDatabase는 사용하지 않습니다. 상태 변화는 이벤트로 전달하고, 여러 프레임이 있는 단계에서만 프레임 시간을 진행합니다. 일시정지/설정창에서는 정지합니다.

## 코드 경계

- `BattleResourceDefinition`: 공유 설정과 단계별 표시 데이터. 전투 중 수정 금지.
- `CharacterBattleResource`: 캐릭터 인스턴스별 현재 값과 변경 이벤트.
- `SkillResourceEffect` / `SkillContext`: 시작 시 조건·소모·강화 확정, 정상 완료 획득.
- 기존 일반 턴 실행과 `BattleSkillTimelineRunner`: 같은 Begin/Complete 계약. 새 Scenario Action ID나 YAML 문법은 추가하지 않았습니다.
- `Action_Damage`, 투사체, 대상별 근접, 압력 난무, 공중 회전 베기: `EffectiveDamageMultiplier` 사용.
- `BattleResourceView` / `BattleUIController`: 현재 선택 아군의 자원 단계 표시.
- 스킬 메이커·캐릭터 DB·Lab 빌더: 데이터 편집/연결. Lab 재생성 시에도 원본 DB의 정의를 복사합니다.

## 검증 및 남은 확인

- 브랜치 `codex/gameplayEdit`. 커밋/푸시 없음.
- 런타임+Editor C# 빌드 오류 0. 기존 `ConfigPanelUI.CategoryLabel` CS0649 경고 2개가 남습니다.
- 캐릭터 DB 7개, 자원 설정 스킬 9개, 원본 단계 5개 연결을 정적으로 검사했습니다. 이번 자원 변경 범위의 `git diff --check` 통과.
- 인스턴스 독립성, 최대치, 조건 미달, 중복 소모/획득, QTE 배율 분리, 취소, 다른 자원, 빈 타임라인, UI 재연결, 원본 Clip/Sprite 대응의 회귀 테스트 코드를 추가/갱신했습니다. **Unity 테스트는 실행하지 않았습니다.**
- Unity Play/강제 Refresh/재임포트/열려 있는 씬 저장은 하지 않았습니다. 실제 UI 크기·자산 역직렬화·적 패링 타이밍은 Unity에서 확인해야 합니다.
- 본편/실험실에서 압력 베기 → 패링 → 쌍압 절단을 사용하면 단계 변화와 소비를 확인할 수 있습니다. C 보상이나 수치는 위 정의/스킬 데이터에서 조정하십시오.
