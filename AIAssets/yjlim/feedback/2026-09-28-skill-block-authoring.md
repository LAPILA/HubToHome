# 스킬 블록 제작 화면 정리

## 바로 사용하기

1. Unity 상단 **Hub To Home → 제작 → 스킬 메이커**를 엽니다.
2. 왼쪽에서 기존 스킬 선택 → **실행 블록** 탭으로 이동합니다.
3. **블록 추가**에서 용도별 분류를 선택합니다. 블록은 위에서 아래로 실행됩니다.
4. 블록 선택 → 아래 설정 편집. **목록 표시 이름**은 알아보기 쉬운 이름, **제작 메모**는 작업 설명입니다.
5. ↑↓로 순서 변경, 복제로 재사용, 삭제·수정은 Ctrl+Z로 되돌립니다. 마지막에 **검사** 탭을 확인합니다.

| 추가 메뉴 | 포함 블록 |
| --- | --- |
| 공통 · 흐름과 연출 | 대기, 이동, 애니메이션, 이펙트 재생 |
| 공통 · 피해와 효과 | 피해 적용, 상태 효과 부여, 투사체, 연쇄 근접 |
| 아군 전용 | 실시간 입력(QTE), 고속 연격, 공중 회전·교차 베기 |
| 적 공격 | 방어 대응, 적 공격 준비·클로즈업 |
| 사용자 정의 | 기존 확장 블록. 기존 검색·등록 경로 유지 |

## 방어 대응 편집 순서

- **대응 · 판정**: 공격 대응 방식, C 반격 ATK 배율, 판정 시간, 실패 피해 배율.
- **공격 모션 · 전조**: 공격 트리거, 타격까지 시간, 타격 직전 전조 프리팹·피벗, 준비 자세·판정 후 대기.
- **실패 연출 / 고급 · 개별 판정 / 추가 전조 · 예약 공격 / 구형 호환 설정**은 필요할 때 펼칩니다. 접어도 기존 설정은 계속 적용됩니다.
- 타격 직전 전조와 추가 전조는 서로 다른 설정입니다. 이번 정리는 표시만 묶으며 어느 쪽도 자동 해제하지 않습니다.

## 제작 시 주의

- 이동·애니메이션·이펙트만으로 피해가 생기지 않습니다. 별도 **피해 적용**을 연결합니다.
- 투사체·연쇄 근접·고속 연격·공중 회전은 피해를 포함하므로 같은 타격의 피해 블록을 중복 추가하지 않습니다.
- 아군 QTE와 적 Z/X/C 대응은 별개입니다. 적 입력에는 **방어 대응**을 사용합니다.
- C 반격 배율은 공격받은 아군 한 명의 ATK 기준입니다. 전열 전체가 반격한다는 기존 안내를 정정했습니다.
- 시간은 초, 피해 배율 1은 기본값입니다. 연쇄 근접의 기존 `DashSpeed`는 실제로 이동 **시간**이므로 표시 이름만 바로잡았습니다.

## 영향 범위 및 검증

- 변경: SkillMakerBlockEditor, SkillMakerWindow/USS, SkillActionBlocks의 표시 문자열·Odin 특성, Action_AerialCrossSlash/Action_EnemyWindup의 시간 단위 표시, 기존 Editor 테스트.
- 기존 자산·프리팹·씬·직렬화 필드명·기본값·enum 값·실행 로직은 유지합니다. 사용자 Aseprite와 앞선 전조 수정도 건드리지 않습니다.
- 변경한 런타임 파일 3개: Execute 본문 11개, 필드/기본값 105개, enum 5개를 HEAD와 대조해 유지 확인.
- 분류/이름 일치 6사례·사용자 정의 블록 생성 금지 검사 추가, 기존 C 안내 검사 보강. Unity 테스트는 실행하지 않고 컴파일만 확인합니다.
- Editor CLI 빌드 오류 0. Unity 화면 확인·Play·강제 Refresh·씬 저장은 하지 않았습니다.
- Drive 제작 가이드와 Notion 포트폴리오는 이번 작업에서 제외. 커밋·푸시 없음.

## 검증 스크립트 교훈

2026-09-28: Odin 표시 특성만 바꾼 소스의 필드 보존 검사에서, 줄 시작 정규식의 `\s`가 개행까지 소비해 인접 특성을 건너뛰고 공백 차이를 변경으로 잘못 보고했습니다. 줄 안 공백을 `[ \t]`로 제한하고 추출 선언을 Trim한 뒤 105개 필드/기본값 보존을 확인했습니다. 다중 행 C# 표시 특성을 정규식으로 검사할 때 적용합니다. 엔진 동작 검증을 대체하지 않습니다. 지정된 전역 메모리 경로는 현재 환경에 없어 프로젝트 인수인계에 기록합니다.
