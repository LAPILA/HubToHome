기존 입문 19편·전체 686파일 색인과 구별되는 대표 실행 경로 심화 해설이다. 모든 소스 줄을 검토했다거나 현재 게임이 완벽하다고 주장하지 않는다. 실제 실행하지 않은 실습은 예상 결과로 표기한다. 사용자 코드 이해·실험·설명을 포트폴리오 기여와 구분하도록 안내한다.

## 검토 교정

`SequenceSaveCoordinator`의 임시 파일 재읽기·ValidateRoundTrip은 모든 필드의 구조적 동등성 보장이 아니다. `ScenarioSourceExporter.cs`의 실제 파서는 알 수 없는 최상위 키를 건너뛸 수 있다. 이를 확인하고 07장의 주의 문단과 실습을 교정했다. 패턴의 이름보다 실제 보장 범위를 근거로 설명한다.

## 하네스 교훈 — 2026-10-12

### PowerShell 함수 이름과 파일 탐색

- 맥락: 소스 발췌를 읽는 짧은 도우미 함수.
- 실패: `R` 함수 이름은 기존 `Invoke-History` 별칭과 충돌했고, Windows rg에 파일 경로 와일드카드를 직접 전달하면 경로 오류가 났다.
- 성공: 고유한 `Read-StudyLines` 이름을 쓰고, rg의 `-g`로 파일 패턴을 제한했다.
- 적용 조건: PowerShell에서 단일 문자 함수명이나 셸이 확장할 것이라 가정한 파일 패턴을 사용할 때.
- 검증: 의도한 소스 파일·줄 범위가 출력되며 히스토리 명령이 실행되지 않는지 확인한다.

### Notion 가져오기 이름과 링크

- 맥락: `코드 따라 읽기.md`와 동명 하위 폴더의 ZIP 가져오기.
- 관찰: 파일과 폴더를 하나의 페이지로 합치지 않고 별도 형제로 만들었다. 초반 링크의 ‘찾을 수 없음’은 렌더 완료 뒤 정상 페이지 링크로 바뀌었다.
- 성공: 폴더를 ‘기능별 코드 해설 10편’으로 구분하고 색인을 진입점으로 사용했다. 링크는 데이터 누락으로 단정해 다시 만들지 않고 로딩 후 실제 목적지를 확인했다.
- 적용 조건: Markdown ZIP의 파일/폴더 이름이 같거나 새 가져오기 직후 링크를 검증할 때.
- 검증: 색인의 실제 10개 링크와 각 목적지 본문 확인. 재가져오기는 동기화가 아니라 중복 생성이므로 금지한다.

### Notion 코드 블록 지연 렌더

- 실패: 마지막 문단이나 main 본문을 기다리는 것만으로는 코드 로딩 완료를 보장하지 않았다. 설명은 표시되지만 코드 본문이 빠진 짧은 텍스트가 먼저 반환됐다.
- 성공: 해당 페이지의 실제 코드 한 구절과 figure 개수·본문을 로딩 후 확인했다. 첫 읽기에 없다는 이유로 다시 가져오지 않았다.
- 적용 조건: 새 페이지 이동 직후 코드/표/Mermaid가 포함된 긴 문서를 검증할 때.
- 검증: 예를 들어 00장의 `(routine as IDisposable)?.Dispose();`, 07장의 `List<YamlLine> lines = ReadLines`가 실제 원격 본문에 포함되는지 확인한다.

### Notion 입력은 결과를 읽고 다음 동작을 한다

- 관찰: 붙여넣기 후 제목이 두 번 들어간 경우가 있었다. 지연 반영인지 중복 이벤트인지 원인은 확정하지 않았다.
- 성공: 현재 편집 요소를 다시 읽고 두 번째 중복만 `selectText`의 prefix로 특정해 제거했다. 짧은 문단 교정은 selectText 후 typeText, 상태 확인으로 한 번만 반영되는 것을 확인했다. Enter 직후 바로 입력하면 문단 분리가 아직 안 된 경우가 있어, 다시 읽고 경계에 Enter를 적용했다.
- 적용 조건: 비동기 편집에서 오류 또는 지연이 발생한 뒤 재입력하려는 경우.
- 검증: 실제 문단·제목이 단 한 번 존재하는지 확인하며, 쓰기 오류를 ‘아무 변경도 없음’으로 가정하지 않는다.

전역 기록 경로 `C:/Users/yjlim/.codex/memories/HARNESS_LESSONS.md`는 이 환경에 존재하지 않는다. 다른 사용자 프로필을 임의 생성하지 않고 본 프로젝트 기록에 보존했다. 인증 정보·권한 그룹 정보는 수집하거나 기록하지 않았다.

후속 입력 복구: 홈 문단의 선택 후 Enter/붙여넣기가 반영되지 않고 편집 요소 준비가 시간 초과됐다. 실제 본문에 변화가 없음을 확인한 뒤 같은 탭을 새로고침하고, 화면 안으로 스크롤한 빈 문단을 명시적으로 클릭한 후 HTML 링크를 붙여넣자 한 번만 반영됐다. 지연 원인은 미확정이며, 새로고침 전에는 미저장 변경 여부를 반드시 확인한다. 검증은 실제 링크 주소와 해당 링크를 클릭한 목적지 페이지로 수행했다.
