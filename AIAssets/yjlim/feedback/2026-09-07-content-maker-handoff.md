# 콘텐츠 메이커 인계

- 브랜치: `codex/gameplayEdit`. 커밋/푸시 없음.
- 사용자 승인: 맵·마커·NPC·대사 통합 제작, 폴더 관리, Unity 대사 편집과 엑셀용 CSV 모두 포함. 세부 판단 위임.
- 시작: `Hub To Home → 제작 → 콘텐츠 메이커`.
- 사용법: [content-maker-guide](../../../docs/content-maker-guide.md).
- 다음 작업/학습 방향: [대사·스토리 도구와 포트폴리오 정리](2026-09-07-story-tools-learning-roadmap.md). 현재 구현과 미구현을 구분하며, 방 하나의 제작→플레이→저장·번역 구간 완성을 우선한다.

## 변경 범위

`Assets/_Game/Scripts/Editor/ContentMaker` 아래 Editor 전용 코드 13개와 meta를 추가했다. 공통 창/컨텍스트/경로 정책, 맵 생성·편집, 마커·NPC 생성·편집, 대사·화자 편집, CSV/시나리오 이름 변경 보호와 테스트 소스로 분리했다. 기존 런타임·씬·Prefab·ScriptableObject를 이번 작업에서 수정하지 않았다. 이전 승인 항목 3·4·5·6의 미커밋 변경은 그대로 보존했다.

## 구현 판단

- 기존 마커 작업창은 읽기 전용 검사/탐색이므로 유지하고 Scanner만 재사용한다.
- 고정 폴더를 지우거나 덮어쓰는 샘플 재생성 메뉴는 호출하지 않는다.
- 새로운 지도 런타임이나 별도 시퀀스 편집기는 만들지 않는다.
- CSV는 한 DialogueData 전체 교체 방식으로 결정했다. 런타임 노드 ID/소스 자동 병합 기능은 추가하지 않는다.
- 대사 이름 변경은 시나리오 Runtime/원문을 읽어 사용 여부를 검사하고, 사용 중이면 차단한다.
- 공용 화자는 Odin PropertyTree를 사용해 기존 Dictionary 직렬화와 Undo를 유지한다.
- 기존 Scene 등록은 명시적 대상/요약 확인을 받은 뒤 해당 Scene만 저장한다. 기존 목록과 시작 Room을 유지하고, 필요한 경우 단일 RoomContainer/Player 구성을 확인해 Coordinator를 연결한다.

## 안전 검토·검증

- 독립 리뷰에서 검사 버튼 예외 전파, 직접 Room 선택 시 지역 혼동, 중첩 ScrollView, ExitGUIException 처리, 실제 선택지가 없는 노드의 경고를 보정했다.
- 새로운 Room/Scene 생성은 Prefab Mode에서 차단하며, 마커 편집은 반대로 선택한 Room의 Prefab Stage에서만 허용한다.
- 목록 검색은 캐시를 필터링하며 자산/계층 변경 시 갱신한다. 새 Player 런타임 부하는 추가하지 않는다.
- 새 소스가 Unity 생성 csproj에 없어도 검증되도록 `Temp/ContentMakerCompile.targets`에서 Editor 컴파일 입력에 포함했다. 생성 csproj는 수정하지 않았다.
- C# 전체 컴파일 오류 0, 기존 경고 3(ConfigPanelUI 2, Febucci 1). 최종 증분 컴파일 오류 0/출력 경고 0. 경고를 고친 것은 아니다.
- CSV·경로·마커 helper 회귀 테스트 소스를 추가했지만 사용자 방침대로 실행하지 않았다.
- 실제 Unity UI·Prefab/Undo·Scene 저장·게임플레이 검증은 하지 않았다. 자동 Refresh/Play Mode/씬 저장도 실행하지 않았다.

## 알려진 범위

- `.xlsx` 직접 편집/자동 동기화가 아니라 Excel용 CSV이다.
- 기본 전투 NPC는 전투 선택지 방식. 자동 접근/공격 연출은 기존 시스템에서 설정한다.
- 퍼즐/상점 등은 기존 Runtime 참조까지 연결해야 한다. 기능을 배치했다고 새로운 게임 규칙이 자동 구현되지는 않는다.
- NPC 배치 Undo는 새 Prefab 파일을 삭제하지 않는다. Room 복제 시 외부 문/조건/완료 플래그/공유 데이터는 검토 대상이다.
- 새 Scene은 빌드 목록에 자동 등록되지 않는다.

## 후속 수정 — Unity에서 MapPanel 누락

- `ContentMakerMapPanel.cs.meta`와 `ContentMakerMarkerServiceTests.cs.meta`에 33자리 GUID가 들어가 Unity가 두 소스를 무시했다. Editor.log의 invalid GUID/asset ignored 메시지와 실제 컴파일 입력 누락으로 원인을 확인했다.
- 두 GUID만 정상 32자리로 교체했다. 잘못된 기존 GUID에 대한 다른 자산의 직렬화 참조는 없었다.
- 앞선 정적 컴파일은 소스를 직접 포함했으므로 Unity 임포트 문제를 검출하지 못했다. 메타데이터 검증도 고유성만 확인한 것이며 길이 검증이 누락됐음을 정정한다.
- 수정 후 관련 `.meta` 17개 모두 정확한 GUID 형식과 고유성 검사를 통과했다. 실제 Unity 자동 재임포트/재컴파일 결과는 아직 확인하지 않았다. 코드·씬 수정이나 강제 Refresh, 플레이 테스트는 없다.

## 후속 정리 — 메뉴 39개에서 6개로

사용자 요청에 따라 시나리오를 제외한 상단 메뉴를 정리했다. [현재 메뉴와 사용법](../../../docs/content-maker-guide.md)을 기준으로 작업한다.

- 제작은 콘텐츠 메이커 하나로 모았다. 방 이름과 크기로 기본 방을 만들며 마을·던전·실내 생성기를 따로 선택하지 않는다.
- 검사 2개(콘텐츠, 현재 편집 범위 맵·마커), 도구 3개(성장 밸런스, 저장 데이터 진단, 공용 전투 프리팹 열기)를 남겼다.
- 샘플/중복/고정 씬 수정 메뉴 33개를 제거했다. 공개 생성 함수·테스트 API·샘플 자산은 유지하고 호출자 없는 private 래퍼/전용 함수 14개만 정리했다. 기존 사용자 삭제 파일은 복원하지 않았다.
- 검사 창 수정 버튼은 `고급 유지보수`로 접었다. CreateAssetMenu 21개와 계층 마커 메뉴 12개는 한국어로 통일하되 실행 계약은 유지한다.
- 세부 변경 파일은 [당일 기록](../../2026-09-07-update.md)에 남겼다. 한글화는 사용자 표시 문구 중심이며 ID·파일명·클래스·직렬화 필드까지 번역하지 않는다.
- 실제 생성 csproj에서 누락 스크립트가 이제 포함됨을 확인하고 별도 소스 주입 없이 C# 컴파일했다. 오류 0/기존 ConfigPanelUI 경고 2, 최종 증분 오류 0/출력 경고 0.
- 시나리오 코드/메타 505개 해시 동일, 메이커 GUID 17개 정상, 메뉴 중복 및 변경 범위 diff 검사 통과. Unity 화면/플레이 테스트는 하지 않았으며 커밋/푸시도 없다.

## 최종 화면 정돈

- `ContentMakerWindow` 외곽과 세 편집 패널을 테마 대응/청록 강조/카드 구획으로 정리했다. 공용 GUI 스타일 C#과 메이커 전용 USS만 추가했으며 다른 도구의 스타일을 바꾸지 않는다.
- 선택 탭·목록 개수·빈 상태·경로 툴팁, 생성/배치/저장 강조, 대사 `파일 관리` 접기를 제공한다. 메뉴는 이전의 6개를 유지한다.
- 검색값 복원, 현재 탭 기준 파일 위치, 탭 이동 시 스크롤 초기화, 긴 상태 높이 제한, 스타일 임포트 지연 재로딩 안내를 보완했다.
- 모든 데이터/CSV/Undo/생성·저장 서비스와 시나리오는 유지한다. 수정/추가 파일 목록과 검증 상세는 당일 기록 참고.
- 정적 C# 컴파일 14개 포함 오류 0/출력 경고 0. 새 GUID 중복/형식 및 UTF-8/공백/독립 리뷰 확인. 실제 Unity 창을 조작하거나 화면 캡처로 비교하지 않았으므로 시각 배치는 수동 확인 대상이다.

## 현재 작업 방식 — 목록에서 추가·삭제

- 메뉴는 그대로 `Hub To Home → 제작 → 콘텐츠 메이커`. 상단은 **챕터 · 방 / 마커 · NPC / 대사 · 화자**다.
- 왼쪽 챕터 목록에서 지역을 고르고, 아래 방 목록에서 편집할 방을 선택한다. 대사 탭에서는 아래 목록이 대화 목록으로 바뀐다. 챕터·방 옆 **+ 추가 / 삭제**로 생성/삭제 확인 화면을 연다.
- 맵 상세의 접기/펴기는 제거했다. 선택한 방의 **방 설정 / 방 복제 / 씬 관리** 중 하나만 편집하며 챕터 정보로 돌아갈 수 있다. 기존 방 데이터/BGM/씬 등록 계약은 유지한다.
- 삭제는 검사 → 대상/막힌 연결 확인 → 최종 확인 → 휴지통 이동이다. 외부 연결을 자동 끊지 않는다. 실행 전 재검증, 부분 실패 후 미리보기 폐기/정보 화면 복귀를 포함한다. 방 삭제는 전용 3종만, 챕터 삭제는 해당 폴더 전체이므로 범위를 반드시 확인한다.
- 대사는 미선택 시 보이는 3단계로 시작하면 된다. 엑셀 CSV는 선택 기능이며 기존 저장·Undo 계약은 유지한다.
- 변경: Window/Context/USS/MapPanel/DialoguePanel, 신규 DeletionService/Tests 및 meta. 상세는 [당일 기록](../../2026-09-07-update.md), 실제 사용은 [제작 가이드](../../../docs/content-maker-guide.md).
- 검증: 정적 Editor 컴파일 오류 0/출력 경고 0, 메이커 C# 16개 및 meta 21개 확인. 독립 선택/삭제 흐름 리뷰 완료. 실제 자산을 삭제하거나 Unity 자동 테스트·Play Mode를 실행하지 않았다. 휴지통/시각 배치와 외부 세이브 호환성은 실제 사용 시 확인 대상이다.
- 브랜치 `codex/gameplayEdit`, 커밋/푸시 없음. 시나리오 및 사용자 기존 변경은 보존했다.

## 대사 작업 분리와 전체 프로젝트 학습 자료

- 대화 목록의 **+ 추가**는 문서 생성으로 연결한다. 대사 작업은 **대사 / 화자·표정 / 조건·NPC / CSV·번역 / 문서** 중 하나만 표시한다. 문서 생성·기본 설정이 편집 화면마다 중복 노출되지 않는다.
- 신규 `Dialogue/ContentMakerDialogueRulesPanel.cs`는 기존 FlagDialogueSelector의 생성·기본 대화·단일 플래그 비교·우선순위·순서·삭제·저장만 편집한다. 별도 스토리 런타임은 없다.
- 일반 NPC 조건 연결은 선택한 Room의 열린 PrefabStage 내부 NPCMarker 본체에만 허용한다. SerializedObject Undo와 dirty 표시를 사용하며 기존 연결 교체를 확인한다. 다른 방·씬·원본 NPC를 자동 수정하거나 방을 자동 저장하지 않는다.
- 본문 키가 없는 줄만 명시적으로 생성할 수 있다. 대본 CSV와 번역표를 구분하고 선택지/화자 이름 번역·여러 줄 번역표·XLSX/자동 동기화의 미지원 범위를 안내한다.
- 화자 작업에서 대사로 돌아올 때 라벨을 새로 계산해 변경 전 이름이 남지 않게 했다. 기존 CSV 검사·미리보기·Undo·Odin 화자 직렬화와 시나리오 계약은 유지한다.
- 공부 자료: [전체 학습 목차](../../../docs/learning/README.md). C#·알고리즘·자료구조, Unity 서비스/맵/저장/UI, 전투·캐릭터·아이템, 대사·시나리오, 제작 도구, 패턴·성능·검증, 실습·면접 정리를 실제 코드로 연결한 8개 문서다.
- 기존 사용법은 [제작 가이드](../../../docs/content-maker-guide.md)에만 갱신하고 장문의 중복 문서를 추가하지 않았다. 과제와 향후 개선, 현재 구현, 실측되지 않은 결과를 구분한다.
- 정적 Editor 컴파일 오류 0/출력 경고 0, ContentMaker 소스 17개/meta 22개 검증 및 독립 코드·문서 리뷰. 이번 범위의 Unity 실제 실행/콘텐츠 변경/커밋/푸시는 없다.
