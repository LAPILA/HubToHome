# 프롤로그 튜토리얼 — 제작·검수 안내

## 이번 흐름

창가 애니메이션 → 위젤이 보조 장치 점검·밸브 조정·시험 → 공용칸 탐색과 드래곤 대화 → 정전/후미 조사 → 백색체 전투 학습 → 압박·후퇴·구조 → 후미 문 잠금 → 전방 침입 → 위젤 단독 긴급 감속 → 차체 파손·탈선 → 완료 공간·자동저장·타이틀.

국가 설명과 이름 입력은 되살리지 않는다. 선택 NPC를 전부 만나야 진행하는 구조가 아니며 사건은 드래곤 대화를 **끝내야** 시작한다. 첫 전투는 공격/방어/정밀 방어/소모품을 관찰하되 일부러 HP0으로 만들지 않는다. 드래곤은 구조만 하며 실제 파티에 합류하지 않는다. 열차 분리나 두 번째 구조는 없다.

## 시작과 조작

타이틀의 새 게임으로 시작한다. `01_IntroScene`에서 `Prologue_start.aseprite` 창가 루프와 원래3줄 대사를 보여준다. 이후 `Region_Train` Q0의 왼쪽에서 시작하며 기관사와 위젤이 자동으로 걸어와 마주 보고 대화한 뒤 수리 조작으로 돌려준다. 수리칸→공용칸→사건칸→제어칸의 다음 목표는 모두 오른쪽이다. NPC/기계는 기존 상호작용 동작, 객차 문은 접촉 이동이다. 현재 목표는 필드 메뉴 상단에 표시한다. 전용 프롤로그 대사는 즉시 표시하며 Z 한 번마다 다음 페이지/문장으로 진행한다.

| 공간 | 주요 조작 | 다음 공간 |
| --- | --- | --- |
| Q0 수리칸 | 장치 점검 → 밸브 → 작동 시험 | 오른쪽 공용칸 |
| 공용칸 | 선택 대화, 드래곤과 대화 종료 | 오른쪽 사건칸 |
| 사건칸(기존 Rear) | 삽화 공개, 학습 전투, 구조 후 문 잠금 | 현재 방 유지 → 오른쪽 제어칸 |
| 기관실 | 전방 상황 확인, 긴급 제어대 조사 | 탈선 연출 |
| 완료 공간 | 자동저장 결과 확인 | 타이틀 복귀 |

전투의 RUN은 숨기지 않고 비활성으로 표시한다. 방어/회피/공격 QTE는 기존 규칙이다. 학습이 막히지 않도록 방어/소모품 연습에 작성 가능한 기회 상한이 있지만 전역 판정이나 피해 규칙을 바꾸지 않는다. 일찍 적의 공격 부위를 처치해도 본체를 영구 처치한 것으로 기록하지 않고 같은 후퇴/구조로 연결한다.

| 교체 대상 | 편집 위치 | 주의 |

| 재개 위치 | 프로필 ResumePoints | 안정적인 Room/SpawnPoint ID를 유지 |

NPC는 최종 아트가 아니라 위젤 샘플 외형의 색/크기를 바꾼 대체물이다. 백색체 역시 기존 Monster 그림을 정지 스프라이트와 임시 Animator로 사용한다. 최종 대사·아트 품질 완료를 의미하지 않는다.

새 역할 Prefab으로 교체할 때는 `PrologueTutorialRoleAnchor`의 기존 RoleId도 유지한다. 특히 후미 구조용 드래곤 앵커를 제거하면 제어기가 해당 역할을 찾을 수 없다. 그림 자식만 바꾸면 상호작용·역할 앵커·배치 좌표를 보존하기 쉽다.

## 저장·실패 경계

- 저장 형식 추가 없이 기존 완료 플래그를 사용한다. 수리 부분 단계, 사건, 후미 공개, 후퇴, 구조, 봉쇄, 전방 목격, 제어, 완료를 구분한다.
- 이미 구조를 본 뒤 잠금 조작 중 재개해도 구조를 반복하지 않는다. 미완료 장면은 안전 지점에서 다시 시작한다.
- 학습 회복품은 전투 전용/판매 불가, 1개 확보 사실을 먼저 기록한 뒤 메모리 재시도 복사본에 포함한다. 재시도마다 중복 지급하지 않는다.
- 실제 전멸에는 전투 직전 복사본 재시도/타이틀 선택을 제공한다. 이야기 후퇴는 전멸이 아니며 경험치·돈·드롭도 지급하지 않는다.
- 완료 방 도착 → 완료 플래그 → 자기 잠금 해제 → 자동저장 결과 → 완료 선택창 순서다. 선택창을 먼저 열어 저장이 영구 대기하지 않게 한다.
- 저장 실패는 성공으로 표시하지 않는다. 재시도 또는 저장 없이 복귀를 구분한다. 완료 저장 Continue는 탈선/최종 저장을 반복하지 않는다.
- 언어를 바꿔도 현재 본문·선택만 번역하며 노드 이벤트와 보상은 재실행하지 않는다.

## 생성 명령과 편집 보존

`PrologueTutorialContentBuilder.BuildBatch`는 닫힌 편집기의 명시적 배치 생성 진입점이다. 일반 `Build`는 열린 대상/dirty Scene/Prefab Mode에서 중단한다. 자동 OnLoad/새 제작 메뉴는 추가하지 않는다. 원본 시나리오를 실제 importer로 읽어 런타임 참조를 만들고 대상 두 Scene/Q0/새 샘플/카탈로그만 저장한다. Build Settings는 변경하지 않는다.

생성 이후 파일 해시는 `TutorialContent.manifest.json`에 기록한다. 사람이 결과를 편집한 뒤 생성기를 다시 실행하면 덮어쓰지 않고 중단한다. **일상적인 대사·그림 수정에 전체 생성기를 재실행하지 않는다.** 수정할 데이터/Prefab을 직접 열거나 기존 메이커를 사용한다. 재생성 충돌을 없애려고 기록 파일을 임의 삭제하지 않는다.

도입 회귀 전용 `PrologueTutorialOpeningPatch`는 전체 재생성이 아니다. 창가 원문 복제/기관사 역할·대사/Q0 승무원1개/객차 자동문만 변경하고 모든 이전 해시를 검사한다. 국가 설명·이름 입력은 복구하지 않는다. 기관사 도입 완료는 별도 플래그이며, 수리를 이미 마친 저장에서 새 장면을 강제 재생하지 않는다. 중단된 도입은 완료로 저장하지 않는다.

열린 Editor에서는 `ApplyInEditor()`가 모든 Scene의 저장 경로/clean 상태를 확인하고 Scene 파일 저장 없이 원래 구성을 복원한다. dirty를 일괄 해제하거나 전체 자산을 저장하지 않는다. 창가의 자동 프레임 캐시 포인터 변경은 디스크 복제본과 프레임/전체 작성 필드가 정확히 같은 경우에만 허용한다. **창가부터 보려면 타이틀의 새 게임으로 시작한다.** Region_Train을 직접 Play하면 IntroScene의 창가 구간은 실행하지 않으며, 이미 수리를 마친 저장은 기관사 도입을 반복하지 않는다.

Scene 파일은 일반 에셋/서브에셋 로더로 읽지 않는다. Scene의 편집 상태는 SceneManager 계열, 저장된 파일 변경은 생성 기록 해시로 검사한다. RoutingPatch는 실제 바뀐 대사·문·도착 위치만 저장한다. 이전 패치에서 발생한 `ReadObjectThreaded`는 이 검사 코드 오류를 수정한 것이며, 별도로 보고된 D3D12 대기 오류까지 해결됐다는 의미는 아니다. 오류 수정의 엔진 재실행/Play는 아직 하지 않았다.

## 검수 범위

명시적 Unity 자산 생성은 정상 종료했다. 실제 저장된 역할/대사/Room/Spawn/Host/시나리오 해시와1,082건 GUID참조를 별도로 확인했고, Q0 기존 타일·상자 보존을 Git 원본과 비교했다. 전체 C# CLI 오류0, 메타1,670개 검사를 통과했다. 이것은 실제 조작 플레이를 끝까지 진행한 결과는 아니다.

구체적인 실행 결과는 [당일 기록](../../2026-10-24-update.md)을 본다. C# CLI/관리형 대체 타입 검증/자산 생성과 Unity Play는 서로 다른 검증이다. 후속 엔진 확인은 다음을 포함한다.

- 새 게임부터 완료 저장까지 끊김 없이 1회 진행, 선택 NPC 건너뛰기.
- 조기 처치/실제 전멸/취소/설정창/Room 왕복/중간 저장 후 재개.
- KR/EN/JP/CN의 실제 글리프·긴 문장·페이지·선택창과 모바일 화면.
- 기존 토끼/제브 일반 전투의 승리·보상·후열·도주 규칙 유지.
- 카메라/배경/HUD의 픽셀 규칙, 연출 강도 설정, 실제 소리와 전환 박자.

실기기 발열·프레임·최종 번역 교정은 측정/원어민 검토 전 보장하지 않는다. 커밋·푸시는 수행하지 않는다.
