# 코드 공부와 포트폴리오 자료 정리

목적은 자체 Scripts를 읽으며 자료구조·알고리즘·패턴·실패 경계를 공부하고, 실제 본인 기여와 검증을 설명할 포트폴리오 근거를 만드는 것이다.

## 결과

- [학습실 홈](../../../docs/study/README.md) 아래 학습 원고 19개, 전체 폴더 색인, 날짜별 기록 색인, 영역별 코드 색인 12개를 분리했다.
- 자체 C# 686개, 테스트 분류 소스 204개, Scripts 포함 96개 디렉터리와 제작 UI 리소스 4개를 색인했다.
- 날짜별 AIAssets 업데이트 원문 28개를 연결했다. 과거 기록과 현재 동작을 구분하고 버전·샘플 삭제·검증 수치를 섞지 않았다.
- 초기 Notion 배치 계획은 notion-layout.json에 보관했다. 실제 게시는 학습 체크보드·코드·폴더·개발 기록 CSV의 네 DB이며, 학습 DB에 표/보드 두 보기와 학습 기록 양식을 만들었다. 갤러리/캘린더는 구현하지 않았다. 사용자 공부 상태는 전부 시작 전이다.
- AI 보조 개발임을 명시하고 기여 기록·직접 실험·설명 과제를 포함한다. 모든 줄 리뷰나 실기기 성능 검증을 주장하지 않는다.

## 게시 상태

지정 Notion 페이지 3f6641f6190180bb8567ff9caf83e5a9는 ID와 원본 URL 모두 NOT_FOUND였다. 연결된 Notion에서 HUB TO HOME 기존 페이지 검색은 성공했으므로 도구 전체 장애라고 단정하지 않는다. 브라우저 원본 링크는 로그인 페이지로 이동했다. 사용자에게 해당 페이지 접근 확인과 링크 재전달을 요청했다.

2026-10-11 재확인: 사용자가 같은 링크를 확정했다. 연결 도구는 UUID 조회에도 NOT_FOUND였으나, 기존 HUB TO HOME GDD 읽기는 성공했고 Notion 플러그인은 설치·활성 상태였다. 브라우저에서는 정확한 대상 URL의 제목이 **공부**인 페이지가 정상적으로 열렸다. 화면에 `Anyone with a Notion account can edit this page.` 및 `Sign up or login to edit`가 표시되어, 페이지 존재와 미로그인 편집 제한을 확인했다. 로그인 대화상자를 열어 사용자에게 인계했다. 링크 오류나 삭제로 단정하지 않으며, 연결 도구의 이 페이지 접근 실패 원인은 미확정이다. 같은 링크를 다시 요구하지 않는다.

최종 상태: 사용자 로그인 후 정확한 대상의 기존 내용을 확인하고 게시했다. 제목은 **HUB TO HOME · 개발 학습실**이다. 네이티브 ZIP 가져오기로 Markdown 62개와 CSV 4개를 등록하고, 생성한 자료실을 루트의 직접 자식으로 정리했다. 임시 빈 중간 페이지만 복구 가능한 휴지통으로 옮겼다. 다른 워크스페이스를 쓰거나 공유 권한을 바꾸지 않았다. 브라우저에서 홈·표·다이어그램·학습 보드의 표시를 확인했다. 연결 도구의 NOT_FOUND 원인은 확정하지 않았다.

## 게시 검증과 유지보수

2026-10-12 마무리: 재개 시 이전 임시 탭은 닫혀 있었으나 같은 인앱 브라우저에서 정확한 루트를 다시 열어 로그인·게시 내용을 확인했다. 원격 2026-10-11 개발 일지에 남아 있던 “Notion 게시 미완료” 문단을 최종 게시 결과로 교정했다. 루트 탭을 결과물로 보존했다.

2. 코드 색인의 12개 링크와 개발 기록 28개 링크, 학습 DB 19행을 확인했다. 학습 보드는 순서 오름차순으로 저장하고 단계 순서를 시작 전/읽는 중/직접 실험/설명 가능으로 맞췄다.

## 하네스 교훈

2026-10-11 문서 배치 편집: 한 apply_patch 안에 같은 파일을 별도 Update 작업 두 개로 넣으면 multiple operations target 검증 오류로 전체 패치가 거절됐다. 파일을 다시 읽어 미적용을 확인한 뒤 같은 파일의 여러 hunk를 하나의 Update 작업 아래 합치자 성공했다. 다수 문서에 공통 탐색 링크와 개별 교정을 동시에 넣을 때 적용한다. 검증은 변경 파일 첫 부분과 링크 검사로 수행한다. 전역 yjlim 메모리 경로는 현재 쓰기 범위 밖이므로 프로젝트 기록에 보존한다.

2026-10-11 Notion 접근: 연결 도구 NOT_FOUND를 페이지 부재로 해석하는 접근은 실패했다. 정확한 URL의 로그인된 브라우저에서는 읽기·편집이 가능했고, 사용자가 지정한 루트 아래 네이티브 가져오기로 게시했다. 커넥터 접근 범위와 브라우저 세션은 다를 수 있다. 적용 조건은 사용자가 목적지와 업로드 내용을 명시한 경우이며, 검증은 실제 루트 경로·본문·편집 완료 상태로 한다.

2026-10-11 Notion 서식: 여러 HTML 블록을 한 번에 붙이면 한 개의 인라인 문단으로 들어왔다. 가져오기 ZIP의 Markdown/CSV는 제목·표·코드·Mermaid·체크리스트·DB로 정상 변환됐다. 홈은 slash 명령과 Enter로 네이티브 블록을 각각 생성했다. 이 세션에서 Return은 효과가 없었고 Enter가 동작했다. 검증은 DOM의 표/체크박스/다이어그램과 실제 화면으로 수행한다.

2026-10-11 Notion 비동기 렌더: 이동 직후 main이 존재해도 본문 길이가 0이거나 임시 .md 제목이 보였다. 페이지 생성 실패가 아니며, 읽기 검증은 제목 존재만이 아니라 실제 본문이 포함된 main 조건을 기다린 뒤 수행해야 한다. 학습 해설은 500자 이상, 짧은 색인·기록은 별도 기준으로 확인했다. 소스가 짧다면 고정 글자 수를 재사용하지 않는다.

2026-10-11 Notion DB 편집: 빈 페이지 안내의 광범위한 텍스트 선택자가 템플릿 생성 항목을 선택했다. 이후 화면의 템플릿 편집 상태를 확인해 유용한 학습 기록 양식으로 완성했다. 카드 본문 작성 시에는 정확한 카드 제목과 본문 편집 요소를 확인하고, 생성 메뉴와 구분한 뒤 붙여넣는다. 템플릿을 만들었다고 모든 기존 카드에 본문이 적용됐다고 간주하지 않는다.

2026-10-12 Notion 문단 교정: setValue 뒤에는 내용이 남았고, fill은 target token mismatch를 반환했다. 이후 선택·붙여넣기에서 같은 문장이 두 번 관찰됐다. 선행 입력이 늦게 적용됐는지의 원인은 미확정이다. 정확한 중복 범위를 selectText의 prefix로 선택해 BackSpace로 하나만 제거하고 실제 문단 값이 한 번만 존재함을 확인했다. 실패 응답을 받았어도 쓰기가 전혀 없었다고 가정하지 말고, 다음 쓰기 전 현재 본문과 선택 범위를 확인한다. 관련 문서: [원격 개발 기록](https://app.notion.com/p/2026-10-11-3f6641f619018121a3b7da5bec6e138d).
