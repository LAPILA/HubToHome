# 날씨 샘플 · 창가 시작 · 피격 표시 사용법

2026-10-23 기준입니다. 날씨는 방 수명의 표시 기능이며, 기존 씬에 자동으로 배치하지 않았습니다. 아래 Prefab을 필요한 방에 직접 배치해야 보입니다. Sprite 미연결 상태의 도형은 교체용 임시 그림이지 최종 아트가 아닙니다.

## 날씨를 방에 배치하기

1. 사용할 Room Prefab을 Prefab Mode로 엽니다.
2. [WeatherSample.prefab](../../../Assets/_Game/Content/Maps/Shared/Weather/WeatherSample.prefab)을 방 루트 아래 자식으로 배치합니다. 기존 `Systems` 아래에 두어도 됩니다. 별도 Camera나 3D Ground는 추가하지 않습니다.
3. Transform은 우선 회전 0, 배율 1로 두고, `영역 중심 (로컬 XY)`과 `영역 크기`로 적용 범위를 맞춥니다. 선택하면 영역 테두리 Gizmo를 확인할 수 있습니다. 비의 영역은 낙하 시작점이 아니라 **바닥 착지점 범위**입니다.
4. Inspector에서 `안개 켜기`와 `비 켜기`를 각각 선택합니다. 안개만 또는 비만 사용할 수 있습니다.
5. 씬의 플레이어를 연결할 수 있는 배치라면 `플레이어 (선택)`을 지정합니다. 비워 두면 활성화 시 같은 씬의 활성 `PlayerController`를 한 번 찾아 캐싱합니다.

Prefab에는 설정과 재질 참조만 저장되어 있습니다. 안개 Renderer와 ParticleSystem은 Play 중 최초 한 번 만들고 재사용하므로, 편집 모드에서 실제 안개·비가 미리 재생되지는 않습니다. 방 교체로 비활성화되면 비와 물튀김을 지우고, 방 파괴 시 생성한 재질·Sprite·Texture도 해제합니다.

## 나중에 픽셀 아트로 바꾸기

Inspector의 다음 세 슬롯은 현재 비어 있습니다. 사용자 그림을 Sprite로 가져온 뒤 해당 슬롯에 연결하면 됩니다.

| 교체 슬롯 | 미연결 시 임시 표시 | 그림을 준비할 때 |
| --- | --- | --- |
| 안개 Sprite | 옅은 색의 사각 안개와 완만한 농도 변화 | 투명도를 가진 안개 그림. Import의 Mesh Type을 **Full Rect**, Filter Mode를 **Point**로 설정합니다. |
| 빗줄기 Sprite | 가늘고 긴 단색 선 | 세로 방향 빗줄기 한 장. 실제 폭·길이는 Inspector에서 조절합니다. |
| 물튀김 Sprite | 짧게 퍼지고 사라지는 타원형 고리 | 바닥 물튀김 한 장. 크기 확대·알파 감소는 샘플이 처리합니다. |

픽셀 그림의 Point 필터는 원본 픽셀의 보간 흐림을 줄이는 조건입니다. 월드 이동과 모든 확대 배율에서 화면 픽셀이 항상 1:1로 맞는다는 보장은 아닙니다. 안개는 그림 전체를 설정 영역에 맞춰 늘리므로, 원본 비율과 크게 다른 영역에서는 늘어짐을 확인해야 합니다. Tight 메시로 잘린 안개는 설정 영역 전체를 덮지 않을 수 있습니다.

전용 [안개 재질](../../../Assets/_Game/Presentation/Weather/WeatherFog.mat)과 [비·물튀김 원본 재질](../../../Assets/_Game/Presentation/Weather/WeatherParticle.mat)은 이미 연결되어 있습니다. 그림 교체 때문에 공유 원본 재질이나 공용 Renderer 설정을 수정할 필요는 없습니다.

## 기본값과 조절 기준

| Inspector 설정 | 샘플 기본값 | 의미 |
| --- | --- | --- |
| 영역 중심 / 크기 | `(0, 0)` / `24 × 14` | Prefab 로컬 XY 기준 적용 사각형 |
| 안개 색상 | RGBA `(0.72, 0.79, 0.86, 0.55)` | 알파로 전체 농도를 조절 |
| 플레이어 투명 반경 / 투명 경계 폭 | `0.8` / `0.55` | 월드 단위. 반경 안은 투명하고 바깥 경계 폭에서 원래 농도로 연결 |
| 초당 빗방울 수 | `90` | 영역 전체의 초당 생성 수. 단위 면적당 밀도는 아님 |
| 낙하 속도 / 시간 | `(-1.8, -14)` / `0.55초` | 월드 XY 고정 속도와 수명 |
| 빗줄기 폭 / 길이 | `0.035 / 0.35` | 월드 단위 표시 크기 |
| 물튀김 너비 / 유지 시간 | `0.2` / `0.16초` | 바닥의 짧은 착지 표시 |
| 안개 / 비 / 물튀김 정렬 | `Foreground 20` / `Foreground 10` / `Shadow 5` | 안개·비는 캐릭터 앞, 물튀김은 캐릭터 아래 |

플레이어가 사각 영역 밖에 있거나 비활성화되면 원형 구멍을 끕니다. 타깃을 매 프레임 다시 찾지는 않습니다. 플레이어가 늦게 생성되거나 임시 플레이어블로 바뀌면 [WeatherSample.SetTarget(Transform)](../../../Assets/_Game/Scripts/Overworld/Runtime/Weather/WeatherSample.cs)으로 명시적으로 바꿉니다. `SetTarget(null)`은 현재 구멍을 닫으며, 다시 자동 탐색하려면 재활성화하거나 새 타깃을 지정합니다.

## 비의 착지 방식과 비용

바닥 점 `P`를 먼저 고른 뒤 `시작점 = P - 속도 × 수명`으로 빗방울을 생성합니다. 중력·Noise·충돌 없이 일정하게 이동하고, 수명 종료 시 Death sub-emitter가 같은 위치에 물튀김을 만듭니다. 보이는 높이와 바닥의 점을 2D 좌표로 표현하는 것이므로 3D 바닥·Rigidbody·충돌 판정은 사용하지 않습니다. 기존 지형의 지붕·벽을 자동 판별하거나 실내를 가려 주는 기능은 없습니다.

안개는 월드 사각형 한 장의 투명 렌더링과 플레이어 주변 알파 계산입니다. 추가 Camera·RenderTexture·화면 후처리는 없지만, 큰 영역의 반투명 겹침과 입자 표시 비용까지 없는 것은 아닙니다. 비와 물튀김은 각각 최대 512입자, 한 프레임 생성은 최대 64개로 제한합니다. 긴 프레임에서는 생성 계산 시간을 최대 0.1초로 제한하고 밀린 생성을 몰아 하지 않으므로 일시적으로 비가 성겨질 수 있습니다. 높은 생성 수와 긴 낙하 시간을 함께 쓰면 입자 상한 때문에 요청한 밀도가 모두 표시되지 않을 수 있습니다.

## 함께 바뀐 시작·이름·피격 연결

- 새 게임은 국가 설명 4컷과 `그리고 현재…` 자막을 건너뛰고 기존 창가 위젤 애니메이션부터 시작합니다. 창가 주행음과 열차 객실·사고·후미 사건 연결은 유지합니다. 새 기계 수리 씬이나 대본은 추가하지 않았습니다.
- 이름 입력 흐름을 제거하고 주인공 표시명은 기존 현지화 기준의 `위젤 / WIZZEL`을 사용합니다. 동료·NPC 이름은 바꾸지 않습니다. 옛 저장의 이름 필드는 읽기 호환용으로 남기되 임의 주인공 이름의 표시 권한으로 쓰지 않습니다.
- 수동 저장 3칸·자동 저장 99번·기존 스키마와 원자 교체/백업 정책은 유지합니다. 날씨는 새 저장 필드를 만들지 않으며, 실제 사용자 저장 파일에 시험 데이터를 쓰지 않습니다.
- 직접 피해에는 즉시 Hurt·백색/기존 Hit VFX·방향 반동을 연결합니다. 최신 후속 조정은 캐릭터 정지 기본0과 공격 준비–명중 카메라 컷입니다. 상태이상 지속 피해 틱은 정지/카메라 컷에서 제외하고 직접 피격을 덮지 않으며, 백색 표시는 설정 `FlashIntensity=0`을 존중합니다. [최신 조정 방법](2026-10-23-battle-impact-cuts.md).

## 검증 범위

날씨의 실제 생산 계산을 관리형 대체 타입으로 실행하여 착지·원형 경계·생성 예산 2,013검사와 구조 5검사를 통과했습니다. 전용 셰이더의 정점/fragment 본문은 URP 선언을 대체한 D3D11 구문·형식 검사 4건을 통과했습니다. 새 자산의 직접 참조·GUID 유일성과 UTF-8 without BOM도 확인했습니다.

[날씨 회귀 테스트 소스](../../../Assets/_Game/Scripts/Overworld/Tests/Editor/WeatherSampleTests.cs)는 자산 참조, 안개 영역, Death sub-emitter, 재사용과 비활성화 정리, 가져온 셰이더 오류 검사를 포함합니다. **Unity Play·강제 Refresh/Reimport·엔진 NUnit·GPU 출력은 실행하지 않았습니다.** 실제 착지 프레임과 물튀김, 사용자 그림의 정렬·가독성, 모바일 성능은 Unity 수동 확인 대상입니다. 전체 C# 컴파일과 다른 변경의 통합 검증 결과는 [당일 기록](../../2026-10-23-update.md)을 확인합니다.
