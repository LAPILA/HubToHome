# 상점 후속 코드 검토

후속 상태: 전반 검토 후 사용자 승인으로 아래 상점 항목을 정리했다. 아래는 수정 전 근거이며 최신 구현은 [정리 패치노트](../Patchnote/2026-09-08-review-cleanup.md)를 따른다.

요청: 상점 코드에서 애매하거나 추가로 정리할 부분을 확인한다. 구현 요청은 아니므로 게임 코드·에셋은 수정하지 않았다. 브랜치 `codex/gameplayEdit`.

## 우선 정리 후보

### 1. 대화 종료 시간 의존 제거

- 근거: `Assets/_Game/Scripts/UI/Runtime/ShopUI.cs:510`은 unscaled 시간으로 0.21초 뒤 메뉴를 재개한다. `Assets/_Game/Scripts/UI/Runtime/DialogueUI.cs:104`의 닫기 Tween은 0.2초이지만 `SetUpdate(true)`가 없어 scaled 시간으로 진행한다.
- 영향: 시간 배율이 0.5이면 닫기에 실제 0.4초가 걸려 메뉴가 먼저 표시된다. 시간 배율 0에서는 닫기 Tween이 진행되지 않는다. 정상 배율에서도 대화창의 연출 시간을 변경하면 상점도 함께 수정해야 한다.
- 방향: 대화창의 닫기 완료/중단을 기준으로 메뉴를 복귀하고 UI Tween의 시간 기준을 일치시킨다. 대화창 종료 모듈 안에 시간 지식을 모아 Locality를 높인다.
- 확인 기준: 정상·느린·정지 시간 배율, 닫기 도중 재열기/상점 강제 종료. 이 검토에서 실행하지 않았다.

### 2. 회복 서비스의 거래 책임 정리

- 근거: `ShopUI.cs:400`부터 UI가 직접 차감→회복→환불을 실행한다. 구매·판매는 `ShopSession`과 기존 거래 모듈을 경유하지만 회복만 다르다. `ShopUI.cs:411`은 환불 반환값을 무시한다.
- `GlobalDataManager.cs:467`의 `RestorePartyVitals`는 이미 완치뿐 아니라 빈 파티·전투 중 차단 등에도 0을 반환한다. UI는 반환값 0을 모두 이미 회복된 것으로 해석한다.
- 방향: 회복 서비스도 기존 거래 패턴처럼 실행 결과/실패 이유를 한곳에서 정하고, UI는 결과 표시만 한다. 유료 서비스에서 결제·복구 정책을 따로 구현하는 일이 없도록 한다.
- 주의: 현재 동기식 `GlobalDataShopTransactionStore`의 일반 경로에서 실제 환불 실패 조건까지 확인한 것은 아니다. 환불 손실이 재현된 버그로 단정하지 않는다.

### 3. 거래 후 중복 화면 갱신 제거

- 근거: `ShopSession.cs:124,151`에서 거래 후 `Changed`를 발행하고, 구독자인 ShopUI가 Refresh한다. 그 뒤 `ShopUI.cs:362,380`에서 다시 Refresh한다. 판매는 그 과정에서 목록 재구축·정렬도 반복한다.
- 방향: 거래 결과 문구를 반영한 뒤 화면을 한 번 갱신하도록 순서를 통일한다. 무조건 한 호출을 지우면 실패 안내/선택 이동 갱신이 빠질 수 있으므로 기존 호출별 역할은 보존한다.
- 영향: 거래 입력당 중복 작업이며, 매 프레임 부하나 발열 원인으로 확인한 것은 아니다. 새 캐시/프레임워크를 추가할 필요는 없다.

### 4. 복제한 상점의 구매 카운터 중복 경고

- 근거: `ShopDefinition.cs:472` 이후는 Entry ID 중복을 검사하지만 구매 카운터 Flag 중복은 검사하지 않는다. `ShopTransactionService.cs:113,257`은 작성한 Flag를 그대로 읽고 쓴다.
- 영향: 상점/상품을 복제한 뒤 Shop ID와 Entry ID만 바꾸면 동일 Flag를 사용하는 상품의 한정 판매 횟수가 공유된다.
- 방향: 기존 Project Content Validation에 상점 간 카운터 중복 경고를 더한다. 의도적인 공유를 허용하되 제작자가 확인할 수 있게 한다. 기존 세이브와 연결되는 Flag를 자동 변경하거나 오류로 일괄 금지하지 않는다.

## 후순위 확인 사항

- `ShopUI.Presentation.cs:147`의 음악 복구는 현재 클립이 상점 클립과 같은지로 판단한다. 다른 연출이 같은 클립을 다시 요청하거나 다른 곡을 거쳐 같은 클립으로 돌아오면 새 요청과 기존 상점 요청을 구별하지 못한다. 상점 도중 외부 음악 연출을 연결할 때 재생 요청 식별을 보완할 후보이며, 현재 샘플에서 발생했다고 확인한 것은 아니다.
- partial 파일 분리는 읽는 위치를 나눈 것이며 별도 Module로 책임을 분리한 것은 아니다. 추가 partial 분할이나 일반화보다 위 결제·대화 종료 처리의 Locality를 먼저 개선하는 것이 유효하다. 현재 하나뿐인 상점 화면을 위해 새 런타임 싱글턴·상점 프레임워크·가상의 Seam을 늘릴 필요는 없다.

## 검증 범위

관련 코드, 호출 순서, 기존 ShopSession/AudioManager 테스트 소스를 읽었다. Unity 실행·Play·Refresh·테스트·빌드는 수행하지 않았다. 게임 코드/에셋 변경 및 커밋·푸시 없음. 검토 기록 2개만 작성했다.
