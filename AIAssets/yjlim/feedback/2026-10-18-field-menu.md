# 실제 Unity 필드 메뉴 · 사용법과 수정 위치

> 2026-10-19 개정: 현재 크기·조작·설정 모달·폴더는 [최신 사용법](2026-10-19-field-menu-navigation.md)을 따른다. 아래2026-10-18 기록의 Q/E필수 조작과 모바일전용 터치 제한은 대체됐다. 메뉴 코드 경로는 `UI/Runtime/FieldMenu/`로 이동했고 기존 데이터 제작 절차는 유효하다.

## 적용 결과

승인된 시안의 **게임 화면 내부**를 기존 `OverworldMenuUI`에 연결했다. 웹 페이지 외곽·임시 레벨업 버튼·가짜 파티/재화는 옮기지 않았다. 실제 현재 저장 파티와 캐릭터 DB를 읽는다. 기존 메뉴 프리팹 및 UIManager 등록을 그대로 사용하므로 별도의 씬 배치나 Inspector 연결은 없다.

| 화면 | 실제 기능 |
|---|---|
| 가방 | 소지 아이템, 분류, 개수, 설명, 동료 선택 후 기존 아이템 사용 서비스 호출 |
| 장비 | 동료별 6슬롯, 실제 소유 수량/전용 조건, 장착 전후 능력치 비교, 장착·해제 |
| 동료 → 상태·능력치 | HP/AP·최종 능력치, 여러 항목 초안 배분, 수량 입력·± 길게 누르기, 한 번에 적용·무료 초기화 |
| 동료 → 스킬 트리 | 실제 노드/선행 연결, 해금 가능/잠금/습득/장착 상태, 포인트 구매·장착/해제·무료 초기화 |
| 일지 | 월드에서 얻어 소지한 메모·책·기록의 본문 읽기. 퀘스트 목록 아님 |

상단의 파티 공용 Lv/EXP와 돈, 기존 현재 목표 한 줄, 선택 동료, 하단 동료 카드도 실제 데이터다. 파티를 추가하지 않으므로 본편 새 게임은 기존 규칙대로 위젤 한 명이다. 4번째 이후 동료는 이전/다음으로 선택하면 하단 카드도 다음 3명 묶음으로 표시한다. 가방에서도 이전/다음 동료 선택이 가능하다.

## 바로 확인하는 방법

1. 기존 플레이 흐름에서 필드 메뉴 **C**를 연다. 전투 중에는 기존 **Escape / 패드 Start / 모바일 일시정지** 경로를 사용한다.
2. 가방/장비/동료/일지 탭으로 전환한다. 별도 프리팹 교체나 초기화 버튼은 없다.
3. 동료의 능력치를 여러 항목에 미리 배분하고 **배분 한 번에 적용**을 누른다. 적용 전 동료/페이지를 바꿔도 초안이 유지된다. 나갈 때 초안이 있으면 폐기 확인을 표시하며 기본 선택은 돌아가기다.
4. 스킬 트리에서 노드를 고르고 우측 버튼으로 습득/장착을 실행한다. 실제 DB에 SkillTree가 없으면 임의 트리를 생성하지 않고 안내한다.
5. 일지에 기록이 없는 것은 오류가 아니다. 기본 카탈로그는 기존 화상/감전 안내만 있으며 획득 아이템 연결은 아래 제작 절차를 따른다.

### 조작

- 키보드: 좌우 페이지, 상하 목록, Z 확정, X 한 단계 뒤로, Q/E 동료, C 분류/동료 내부 탭, R 동료 초기화. 동료 내용에 들어간 뒤 방향키로 능력치/트리를 조작하며 X로 페이지 이동 단계에 돌아간다.
- 패드: 방향키/스틱과 기존 확인/취소, LB/RB 동료, 위쪽 버튼 분류/내부 탭. 기기별 안내를 표시하되 검증되지 않은 Nintendo A/B 아이콘을 추측하지 않는다.
- 모바일: 탭/목록/동료 카드/노드 직접 터치, 목록·트리·본문 밀기, 숫자 입력 또는 ± 길게 누르기. 메뉴가 닫힐 때까지 기존 게임플레이 가상패드를 숨기고 누름 상태를 해제한다. PC 마우스 클릭을 활성화하지 않는다.
- 실제 전투 세션 중에는 열람만 가능하다. 필드 아이템 사용·장비·성장 변경으로 턴 소비를 우회하지 않는다.

## 일지에 새 기록 넣기

1. 기존 아이템 제작 경로로 메모/책용 `ItemData`를 만든다. 종류는 `KeyItem`, 고유 ItemID를 지정한다. 영구 보관할 기록은 사용/판매/소모되지 않도록 설정한다.
2. `GameContentCatalog.Items`에 해당 아이템을 등록한다. 기존 `ItemPickupMarker` 또는 이벤트 지급 경로로 실제 획득하게 한다. 단순히 카탈로그에 넣는 것만으로 소지품이 생기지는 않는다.
3. `Assets/Resources/HubToHome/JournalCatalog.asset`의 기록을 추가한다. `획득 아이템 ID(RequiredItemId)`에 같은 ItemID, 제목/본문, 선택 아이콘을 지정한다. `현재 목표 후보(IsObjective)`는 끈다.
4. 추가 진행 조건이 있으면 기존 `Conditions`를 지정한다. 소지 수량 1 이상과 모든 표시 조건을 충족하면 일지에 나타난다.
5. 번역이 필요하면 `TitleKey`/`BodyKey`와 현지화 표를 연결한다. 이번 고정 UI 번역 101키가 콘텐츠 본문을 자동 번역하지는 않는다.

획득 상태는 기존 인벤토리 저장값을 사용한다. 새 퀘스트 저장 형식이나 수락/완료/보상 코드는 만들지 않았다. 목표 한 줄은 기존 플래그 기반 표시만 유지한다. 현재 구현은 **소지 중인** 기록이므로 기록을 제거하면 목록에서도 빠진다.

## 유지한 경계와 방어 처리

- 기존 직렬화 필드·enum 값·GUID는 유지했다. 기존 Top/Bottom/CategoryWindow는 런타임 비활성화하고 같은 루트의 형제 자식으로 새 뷰를 한 번 생성한다. 기존 씬/프리팹은 재저장하지 않았다.
- 뷰·목록·트리 노드·연결선은 캐시한다. 데이터 변경 이벤트 또는 사용자 조작에 갱신하며 매 프레임 파티/아이템/스킬을 재검색하지 않는다. 런타임 캐릭터 검색은 메뉴 열 때 한 번이다.
- 투자 실패는 일부 항목 반영/포인트 차감/원본 초기화를 남기지 않는다. 기존 장비 포함 HP/AP 부족량 보존 정책과 사망 상태를 유지한다. 장비 변경은 회복이 아니다.
- 동일 DB를 쓰는 3색 위젤도 `IsBoundToSaveData`의 정확한 저장 인스턴스로 동기화한다. 가방 사용의 기존 InventoryManager 동기화도 같은 경계를 사용한다.
- 숫자 입력은 다른 버튼을 누르기 전에 편집 종료→초안 갱신→명령 처리 순서다. 선택 해제/모달 차단/다음 프레임 활성화 소유권을 함께 검사한다. X/Start 중복과 닫기 입력의 다음 단계 누수도 차단한다.
- 애니메이션은 unscaled DOTween이며 메뉴가 소유한 TimeScale/게임 상태만 닫기·비활성·파괴에서 한 번 복원한다. 음악은 정지하지 않는다.
- `Screen.safeArea`와 카메라 출력의 교집합에 기존 정수 배율을 적용한다. Canvas 배율을 다시 곱하지 않는다. 기준 해상도 미만은 축소 예외이며 무손실을 보장하지 않는다.

- CLI 전체 컴파일: Runtime **412소스 / 오류0 / 경고219**, Editor/테스트 **347소스 / 오류0 / 경고0**. 기존 CS0649/CS1701 등을 포함하므로 경고 0 완료라고 하지 않는다.
- 실제 성장 서비스 관리형 검사 **12/12 통과**, Unity 수명 의존 GlobalData 이벤트 2개는 소스 컴파일만 했다.
- 실제 JournalCatalog 인메모리 대체형 검사 **22개**, 안전 영역 생산 메서드 추출 검사 **30개** 통과. 두 임시 검증 하네스는 파일로 보존하지 않았으며 엔진 통합 검사가 아니다.
- 기존 공통 픽셀 출력 관리형 **75개 + 자산5개** 재검사 통과.
- UTF-8/고유 meta 10쌍/직렬화 필드명 18개 보존/작업 범위 diff 검사를 수행했다. 전체 diff에는 기존 `Maps/Battle.meta`의 trailing whitespace가 있어 수정하지 않았다. 현지화는 고정 UI **101키×4언어**이며 실제 CSV parser에서 누락·중복·빈값·placeholder 불일치 0이다.
- 보존한 Unity Editor 회귀 소스: `FieldMenuEditingTests`14사례, `FieldMenuTouchInputTests`3사례, `FieldMenuViewportTests`11사례, 기존 성장·일지 테스트 확장. **컴파일만 확인했다.**
- Unity Play/강제 Refresh/시뮬레이터/실기기 실행/스크린샷은 하지 않았다. 실제 폰트 줄바꿈, 작은 폰에서 숫자 키보드·탭/드래그/길게 누르기, 패드 기기별 안내는 화면에서 최종 확인해야 한다. 무발열/무프레임저하를 선언하지 않는다.

## 하네스 교훈

2026-10-18, Windows PowerShell 파일 탐색: `rg path/Name*.cs`처럼 경로 인수에 와일드카드를 넣은 접근은 error123이 났다. 디렉터리와 `-g 'Name*.cs'`를 분리하거나 `rg --files`로 실제 경로를 찾으면 성공한다. 관련 코드 위치를 추정해 반복 조회하지 말고 이 형태를 사용한다. 검증은 명령 exit0과 실제 파일 목록이다. 현재 머신에는 yjlim 전역 메모리 경로가 없어 이 저장소 기록에 남겼다.

같은 날 새 meta 검증에서 FieldMenuTouchInput의 수기 GUID가 33자리인 것을 발견했다. 처음에는 줄바꿈 가정으로 정규식만 보완했지만 계속 실패했고, 원문 바이트/문자열 길이 확인으로 실제 길이 문제를 확정했다. 기존 참조가 없는 신규 meta만 32자리로 수정한 후 신규10쌍의 `[a-f0-9]{32}` 형식과 전체 Assets 내 중복 없음을 확인했다. 향후 GUID는 `Guid.NewGuid().ToString("N")`으로 생성하고, 정규식 실패를 인코딩/줄바꿈 문제로 먼저 단정하지 않는다.
