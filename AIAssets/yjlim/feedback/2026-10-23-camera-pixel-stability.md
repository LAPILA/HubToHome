# 전투 카메라 픽셀 안정화 — 제작·조정 규칙

전투 중 이동·점프·복귀마다 화면이 커졌다 작아지는 자동 배율 변경을 제거했습니다. 일반 전투는 시작할 때 결정한 정수 픽셀 배율을 유지하고, 필요한 구도 이동만 수행합니다. 공격·방어·전조·QTE의 시간과 HUD 배치는 변경하지 않았습니다.

## 1. 원인과 수정

이전 안전영역 보정은 캐릭터의 현재 위치를 매 프레임 읽고 필요한 렌즈 크기를 다시 계산했습니다. 무기·VFX 크기는 캐시로 제외했지만, 이동·홉·넉백·복귀만으로도 렌즈가 변했습니다. 여기에 매 타격의 짧은 줌과 스킬 확대가 겹쳐 화면 크기가 반복해서 바뀌었습니다.

픽셀 보정도 우회되고 있었습니다. 기존 `CinemachineContinuousPixelZoom`은 네이티브 `CinemachinePixelPerfect`를 끄고 `CorrectCinemachineOrthoSize()`의 반환값을 버렸습니다. 이 호출은 PPC의 Cinemachine 호환 모드는 켜지만, 반환값을 적용하지 않으면 실제 렌즈는 정수 픽셀 크기로 보정되지 않습니다. 안전영역의 Finalize 보정과 Brain의 카메라 간 보간도 이후에 렌즈를 바꿀 수 있었습니다.

수정 후에는 다음 순서를 사용합니다.

1. Body에서 PPC가 반환한 렌즈 크기를 적용합니다. 네이티브 확장은 임의로 켜거나 끄지 않습니다.
2. Finalize에서 방어 Hold 또는 전투 안전구도를 적용한 뒤, 렌즈와 XY 출력 위치를 다시 픽셀 격자에 맞춥니다. 엄격한 픽셀 경로의 Dutch는0입니다.
3. Brain의 `CameraUpdatedEvent`에서 보간이 끝난 실제 출력 렌즈도 다시 보정합니다. 방어 Hold가 전투 고정 배율보다 우선합니다. 렌더 직전 위치 정렬은 기존 URP PPC가 담당합니다.
4. 일반 전투에서는 타격 줌·스킬 줌·카메라 회전을 억제합니다. 방향 이동과 기존 공격 동작은 유지합니다.

새 카메라·RenderTexture 시스템·화면 캡처·GPU 패스는 추가하지 않았습니다.

## 2. 지켜야 할 픽셀 규격

공용 GameplayCameraRig의 기존 규격은 PPU32 / 기준640×480 / Windowbox / Upscale Render Texture / Point입니다. 이 규격에서 허용되는 렌즈 크기는 다음과 같습니다.

`기준 렌즈 = 480 ÷ (2 × 32) = 7.5`

`허용 렌즈 = 7.5 ÷ 정수 배율` →7.5,3.75,2.5,1.875…

Lens4는 원본1픽셀을 내부1.875픽셀로 표시하므로 정확한 정수 배율이 아닙니다. 이 규격에서 단순히 “4를 유지하면서 픽셀도 완전히 균일하게” 만드는 것은 불가능합니다. 가까운 값3.75를 무조건 선택하면 필요한 시야4보다 좁아질 수 있으므로, 전투 안전영역은 필요한 시야 이상인 허용값을 선택합니다. 예를 들어 최소 시야4가 필요하면7.5를 선택합니다.

원본 픽셀을 축소하지 않는 상한은 기준 렌즈7.5입니다. 그보다 넓은 전투 배치를 자동으로 무한히 줌아웃하지 않습니다. 배치가 고정 시야를 넘으면 경고를 한 번 출력하므로, 캐릭터 간격·이동 범위·점프 높이를 제작 데이터에서 조정해야 합니다.

## 3. Inspector에서 조정할 곳

`GameplayCameraRig → CameraController → 전투 시야 · HUD 가림 방지`

| 항목 | 기본값 | 사용 기준 |
| --- | --- | --- |
| 전투 UI 안전영역 사용 | 켜짐 | 하단 HUD와 상단 턴 큐를 제외한 구도 사용 |
| 전투 기준 픽셀 확대 배율 |1 | 기본 전투 렌즈는7.5. 배율2는3.75를 먼저 요청하지만 안전영역이 부족하면 더 넓은 허용값 선택 |
| 전투 최소 카메라 크기 |3.75 | 허용 렌즈로 올림. 실제 기본 렌즈가3.75라는 의미는 아님 |
| 아군 뒤 회피 여유 |1.6 | 아군 왼쪽 후퇴 공간 예약 |
| 몸체 가장자리 여유 |0.25 | 캐릭터 몸체 주변 여유 |

전투 진입 시 `기준 렌즈 ÷ 확대 배율`로 요청값을 만든 뒤 안전영역을 계산하고 `SnapSizeAtLeast`로 고정값을 선택합니다. 이후 같은 전투의 이동·홉·복귀·행동 변경으로는 렌즈를 다시 키우거나 줄이지 않습니다. 중심 보정만 수행합니다. PPC가 비활성에서 활성으로 바뀌거나 픽셀 기준이 변경된 경우에는 모드에 맞게 고정값을 다시 계산합니다.

현재 기본값에서 더 가까운 화면이 필요하면 우선 전투 배치를 좁히고 배율2를 검토하십시오. 임의의 실수 Lens값이나 반복 줌으로 해결하면 같은 문제가 재발합니다. 변경한 Inspector값의 실제 화면 체감은 별도 Play 확인이 필요합니다.

## 4. 제어권과 종료

- 명령 종료의 `Release()`와 전투 안전영역 정책의 소유권은 별개입니다. 명령이 끝났다는 이유만으로 같은 전투의 픽셀 정책을 제거하지 않습니다.
- HUD가 일시적으로 숨겨져도 같은 전투의 정책 소유권과 고정 배율은 유지합니다. UI 화면 영역을 얻을 수 없을 때는 중심 보정만 건너뜁니다. 메뉴를 열고 닫았다는 이유로 배율이 다시 선택되지 않습니다.
- Timeline 대여·컴포넌트 비활성화·실제 전투 종료에서는 정책 소유권을 명시적으로 분리하고 기존 연출 제어권을 존중합니다. Timeline 중에도 픽셀 격자 보정 자체는 계속 적용됩니다.
- 방어 Hold는 이미 확보한 구도를 고정하며 Brain 출력에서도 우선합니다. 다음 명령이 이전 Hold나 종료 처리를 덮어쓰지 않도록 기존 토큰을 유지합니다.
- 전투가 끝나면 몸체 캐시·전투 고정 렌즈·용량 경고 상태를 초기화합니다. 컴포넌트 비활성화·파괴 시 출력 이벤트 구독도 해제합니다.

## 5. UI와 별개로 구분할 것

기존 UI의640×480 Overlay·정수 확대·정수 시작점 정책과 URP Render Scale1·AA 비활성 정책은 유지합니다. UI는 월드 조명·카메라 줌의 영향을 받지 않습니다.640×480보다 작은 실제 출력에서 UI를 모두 보이게 축소하면 원본 픽셀의 무손실 보존은 불가능합니다.

화면 절단 ScreenSplit·배경 충격파 같은 의도적인 왜곡, 스프라이트 자체의 임의 회전·크기 변화는 카메라 격자와 별개입니다. 이번 수정이 이러한 효과의 모양까지 원본 픽셀과 동일하게 만드는 것은 아닙니다.

## 6. 코드와 검증 범위

주요 생산 코드:

- `Assets/_Game/Scripts/Camera/Runtime/CameraPixelGridPolicy.cs`: 기준 렌즈·안전 방향 정수 배율·좌표 격자 계산.
- `Assets/_Game/Scripts/Camera/Runtime/BattleCameraViewportFraming.cs`: 기존 적응형 Fit 보존, 고정 렌즈 중심 보정용 FitAtFixedSize 추가.
- `Assets/_Game/Scripts/Camera/Runtime/CameraController.BattleViewport.cs`: 몸체 캐시·전투 고정 배율·정책 소유권·용량 경고.
- `Assets/_Game/Scripts/Camera/Runtime/CinemachineContinuousPixelZoom.cs`: 기존 이름을 보존한 PPC 어댑터. Body·Finalize·Brain 출력 보정과 구독 정리.
- `Assets/_Game/Scripts/Camera/Runtime/CameraController.BattleMotion.cs`: 엄격 픽셀 전투에서 타격·스킬 줌과 회전 억제.

회귀 코드는 `CameraPixelGridPolicyTests.cs`, `BattleCameraViewportFramingTests.cs`, `CameraFramingTests.cs`에 있습니다. 관리형 하네스는 `Library/CodexChecks/PixelGrid/PixelGridCheck.csproj`이며 생산 소스와 공유 Editor 테스트를 직접 연결합니다.

- `_Game`메타1,555개 GUID32자리·중복 검사.
