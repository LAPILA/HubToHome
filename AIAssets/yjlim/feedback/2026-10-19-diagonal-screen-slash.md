# 단층 베기 — 사선 화면 절단 실험

토끼 전투 실험실의 **첫 위젤 → SKILL → 7번째 `단층 베기`**에서 확인하는 표시 전용 샘플입니다. AP12를 쓰며 기존 물리 피해 뒤에 **0.18초 확대 → 1초 유지 → 0.3초 복원**합니다. 잔상은 별도 캡처가 아닌 실시간 분할 화면 유지이며 틈은 완전 검정입니다. 새 QTE나 추가 조작 단계는 없습니다.

## 바로 확인하기

1. Unity 상단 **Hub To Home → 테스트 → 전투 실험실 열기**를 선택합니다.
2. `BunnySlimeBattleLab` 씬에서 직접 Play를 누릅니다.
3. **토끼 슬라임 · 통합 → Z 시작** 후 첫 위젤의 턴에 **SKILL → 단층 베기**를 선택합니다. 목록 아래쪽의 7번째입니다.
4. 기존 대상 선택으로 적을 지정합니다. **접근 → 공격 준비 → 참격/피해 → 사선 화면 분할 → 복귀** 순서입니다.

현재 샘플은 첫 위젤에게만 추가했습니다. 원소 실습 18스킬, 다른 동료 편성, 본편 위젤 DB, 저장 형식과 시나리오 문법은 바꾸지 않습니다. **원소 실험실 기본 연결 복원** 메뉴도 첫 위젤의 7번째 스킬을 다시 연결합니다.

## 그림을 실제로 자르는 것인가요?

아닙니다. 맵·캐릭터·충돌체는 그대로 두고, 카메라가 그린 색상 화면을 읽는 좌표만 바꿉니다.

1. 화면 중심을 지나는 사선을 기준으로 각 픽셀이 어느 쪽인지 구분합니다.
2. 양쪽의 표시 좌표를 반대 방향으로 밀고 조금씩 비틉니다.
3. 벌어진 틈은 검정으로 채우고 바깥 양쪽에 흰 외곽선을 그립니다. 최대폭 도달 순간 선 두께를 잠깐 강조하고,1초 유지 뒤 원래 화면으로 복구합니다.

캐릭터 애니메이션은 계속 진행하므로 캡처한 정지 그림을 밀어내는 방식과 다릅니다. `Action_Damage`가 피해를 처리하고 `Action_ScreenSplit`은 뒤에서 표시만 맡습니다. 셰이더를 사용할 수 없어 연출을 생략해도 앞서 적용된 피해를 취소하거나 별도 전투 판정을 만들지 않습니다.

HUD·QTE·대사는 기존 **Screen Space Overlay** 경계에 있어 이 화면 변형의 영향을 받지 않습니다. 반대로 월드에 직접 그리는 말풍선/VFX 등은 게임 화면과 함께 변형될 수 있습니다.

## 어디서 조정하나요?

**Hub To Home → 제작 → 스킬 메이커**에서 `단층 베기`를 검색합니다. 실행 블록 중 **사선 화면 절단**을 선택합니다.

| 항목 | 샘플 값 | 의미 |
| --- | --- | --- |
| 벌어지는 시간 | 0.18초 | 0폭에서 최대폭까지 부드럽게 확대 |
| 갈라진 화면 유지 | 1초 | 최대로 갈라진 표시 유지 |
| 복원 시간 | 0.3초 | 유지 후 원래 화면으로 복원 |
| 절단 각도 | -35도 | 화면 중심을 지나는 사선 방향 |
| 갈라지는 폭 | 22 | 각 방향 이동량, 전체 틈44기준픽셀 |
| 양쪽 비틀림 | 1.5도 | 화면 양쪽의 작은 회전량 |
| 외곽선 두께 | 1.25 | 틈 양쪽 바깥에 그리는 선의 기준 픽셀 두께 |
| 외곽선 색상 | 흰색 | 색상 변경 가능, 알파는 불투명도/강도 |
| 외곽선 순간 강조 | 0.65 | 벌어지는 순간 두께를 약2.06픽셀로 강조 후 기본두께 복귀 |

이동 폭·비틀림은 기존 **화면 흔들림 강도**, 외곽선 알파는 **플래시 강도** 설정을 따릅니다. 0폭에서 자연스럽게 벌어지고1초 유지한 뒤 부드럽게 닫힙니다(전체1.48초). 확대/복원은 양 끝 기울기가0인 cubic smoothstep을 사용합니다. 순간 강조는 최대폭 도달 전후0.16초씩의 짧은 두께 펄스이며0이면 꺼집니다. 블러/Bloom이 아니라 같은 셰이더의 선 너비만 바꿉니다. 일시정지는 모든 구간을 함께 멈춥니다. 기존 `Duration`은 복원 시간, `ExpandDuration`/`HoldDuration`은 확대/유지 시간입니다. 색상·두께의 직렬화 필드명 `LineColor`/`LineWidthPixels`도 보존했습니다. 확대0은 즉시 벌어지는 방식, 외곽선 두께0 또는 색상 알파0은 선 끄기입니다.

다른 스킬에 붙일 때는 **블록 추가 → 공통 · 흐름과 연출 → 사선 화면 절단**을 사용합니다. 동일 타격의 **피해 적용 바로 뒤**에 두면 됩니다. 표시 블록만으로는 피해가 생기지 않습니다. 다른 카메라에서 사용하려면 해당 Renderer에도 기능 연결이 필요하며, 이번에는 실험실 전용 Renderer에만 연결했습니다.

RendererFeature가 Shader 자산을 직접 참조합니다. **별도로 편집할 `.mat` 파일은 없으며**, 최초 사용 시 만든 런타임 재질을 이후 시전에서 재사용합니다. RendererFeature가 해제될 때 자신이 만든 재질도 정리합니다.

스킬이 끝나거나 중단되면 `finally`에서 자기 토큰을 반납합니다. 같은 카메라에 새 화면 효과가 들어와 이전 것을 대체한 경우, 이전 스킬의 정리가 새 효과까지 지우지 않습니다. 소유자 비활성/파괴·장면 이탈도 정리 대상으로 처리합니다. 공유 카메라 Transform이나 피해 값을 화면 복원용으로 수정하지 않습니다.

결정타로 마지막 적이 사망해도 이 블록은 실행합니다. `CanRunWithoutLivingTargets`를 명시한 표시 블록만 허용하며, 일반 피해/타깃 의존 블록의 중단은 유지합니다. 강제 전투 중단·모듈 이탈은 현재 행동 scope를 무효화하므로 코루틴의 `finally` 실행 여부와 별도로 다음 렌더 조회에서 잔여 효과를 제거합니다. 일반 턴과 시나리오의 기존 스킬 호출에 같은 마지막 대상 정책을 적용했습니다.

## 성능 우선 설계와 한계

- **URP 17.3 RenderGraph 전용**입니다. Compatibility Mode를 바꾸지 않으며 구형 렌더 경로용 중복 구현은 없습니다.
- 효과가 없을 때는 해당 기능의 렌더 패스를 등록하지 않습니다. 휴면 상태에서 화면 캡처나 블러를 계속 수행하지 않습니다.
- 활성 효과 자체는 전체 화면 처리 **1패스**, 셰이더의 화면 텍스처 읽기는 픽셀당 **Point 샘플 1회**입니다. 추가 카메라·깊이/노멀 샘플링·노이즈 텍스처·블러를 사용하지 않습니다. Renderer2D는 활성 패스의 Color 요청으로 중간 색상 타깃을 준비하며 별도 CopyColor 패스를 만들지 않습니다. 이때 URP가 동반 관리하는 depth attachment까지 없다는 뜻은 아닙니다.
- 재질은 첫 사용 이후 재사용합니다. 효과를 그리는 동안 필요한 임시 색상 타깃은 RenderGraph가 관리합니다. 최종 합성 등 URP 자체 비용까지 모두 1패스라는 뜻은 아닙니다.
- 확대/순간 강조가 끝난 유지 구간에서는 삼각함수 계산을 반복하지 않습니다. 외곽선도 같은 색상 패스에서 계산하며 텍스처 읽기나 패스를 늘리지 않습니다. 다만0.3초 버전보다 효과 표시시간이 길어져 총 GPU작업량까지 같다는 뜻은 아닙니다.
- Point 샘플은 보간에 의한 흐림을 피하지만, 화면을 비틀 때 픽셀의 완전한 1:1 대응이나 모든 회전 각도의 균일한 도트 두께를 보장하지는 않습니다.

**최초 재질 생성·셰이더 컴파일 비용, GPU 시간, 실제 모바일 발열은 아직 측정하지 않았습니다.** 짧게 동작하고 휴면 비용을 줄이는 구조를 선택했지만, 실기기 검증 없이 무발열·프레임 저하 없음을 보장하지 않습니다.

이번 문서는 코드/연결 계약을 설명하며 **Unity Play·GPU 렌더링·실기기 성능 확인은 미실행**입니다. CLI 컴파일과 정적 검사 결과는 [당일 기록](../../2026-10-19-update.md)을 기준으로 확인합니다.

### D3D11 구문 오류 수정

초기 셰이더의 `line` 지역 변수는 HLSL 예약어와 충돌했습니다. `cutLineMask`로 변경했으며, 뒤따른 `lerp` 오류도 분리한 fragment의 D3D11 컴파일에서 해소됨을 확인했습니다. 계산과 렌더 비용은 그대로입니다. C# 컴파일만으로는 이 오류를 발견할 수 없어, 가져온 셰이더의 컴파일 오류 유무를 확인하는 Editor 회귀검사도 추가했습니다. Unity 전체 variant/GPU 검증을 완료했다는 뜻은 아닙니다.
