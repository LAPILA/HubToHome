한줄 판단

Vertical Slice

이 프로젝트는 단순 전투 테스트가 아니라, 타이틀 -> 인트로/이름 입력 -> 오버월드 -> 대화/접촉 조우 -> 전투 -> 복귀까지 첫 번째 플레이어블 루프가 붙어 있는 상태입니다. 다만 저장 복구, 전투 정책 분리, 데이터 검증, 상태이상/아이템 마감은 아직 기반 공사가 더 필요합니다.

현재 플레이 루프

Playable Path
1. Title TitleMenuManager가 새 게임, Continue, Settings, Quit 메뉴를 다룹니다.
2. Intro / Dialogue IntroManager, DialogueManager, NameInputUI로 초반 대사와 이름 입력이 연결됩니다.
3. Overworld PlayerController, 상호작용, NPC 대화, 순찰 적 접촉 조우가 존재합니다.
4. Battle BattleManager가 전용 배틀 씬/심리스 전투, 턴, QTE, 승패 복귀를 처리합니다.

구현된 시스템

Current Features

코어 부트스트랩/전역 서비스 구현됨

GameBootstrap와 CoreSettings prefab 계층이 있고, 오디오, UI, 씬 로더, 전역 데이터, 플래그, 오브젝트 풀을 전역 서비스로 씁니다.

  • AudioManager, SceneLoader, UIManager
  • GlobalDataManager, GameFlagManager, ObjectPoolManager

설정/입력 계층 사용 가능

설정 저장과 즉시 적용은 GameConfigManager, 실제 입력 파사드는 GameInput, 화면 UI는 ConfigPanelUI가 맡습니다.

  • 볼륨, 언어, 텍스트 속도, 자동 진행, 흔들림, 전체화면, VSync, FPS
  • 키 리바인딩과 설정 패널 내 키 캡처

현지화/대화 부분 구현

LocalizationManager와 CSV 테이블이 있고, 대화 데이터는 ScriptableObject 기반입니다. 대화 스타일은 오버월드/시네마틱으로 나뉩니다.

  • DialogueData, SpeakerData, DialogueUI
  • 선택지 분기와 선택지 기반 전투 진입

오버월드 조작/상호작용 프로토타입

플레이어 이동, Y축 sorting, 상호작용 인터페이스, 저장 포인트, 지역 트리거, 대화형 전투 NPC, 순찰 적이 들어가 있습니다.

  • PlayerController, InteractionSystem, SavePoint
  • AreaTrigger, DialogueBattleNPC, OverworldEnemy

전투 진입 파이프라인 좋은 방향

BattleEncounterService가 오버월드 접촉, 대화 선택지, 전용 BattleScene 로드를 한 경로로 모읍니다.

  • 적 목록, BGM, 복귀 씬, 조우 ID 전달
  • 심리스 전투와 전용 배틀 씬 전투 모두 고려

턴제 전투 핵심 구현

BattleManager가 파티/적 생성, 턴 큐, 메뉴 선택, 기본 공격, 스킬, 아이템, 도주, 승패 처리를 담당합니다.

  • 속도 기반 턴 큐와 visible turn queue
  • MP 회복, 데미지 이벤트, 나레이션 이벤트

스킬 타임라인 강점

SkillData가 ActionTimeline을 들고, SkillActionBlock 파생 블록으로 이동, 애니메이션, 데미지, QTE, VFX, 방어창, 투사체, 연속 근접을 조립합니다.

  • Action_Move, Action_PlayAnim, Action_Damage
  • Action_DefenseWindow, Action_Projectile, Action_SequentialMelee

패링/회피/점프 방어 구현 중

33원정대식 반응 방어를 목표로 QTEManager, GameInput, Action_DefenseWindow, PlayerController가 연결되어 있습니다.

  • Z/X/C 기반 방어 입력 fallback
  • 전조 VFX, 입력 판정 창, 성공 시 데미지 무효 흐름

캐릭터/스탯/상태이상 기반 있음

CharacterBase를 중심으로 플레이어/적이 나뉘고, HP/MP/ATK/DEF/SPD, 원소 타입, 다수 상태이상 클래스가 있습니다.

  • PlayerCharacter, EnemyCharacter, AllyCharacter
  • Burn, Freeze, Bleed, Poison, Bind, Stun, Berserk, StatModifier 등

전투 UI/나레이션 꽤 진행됨

전투 메뉴, 서브메뉴, 파티 슬롯, 턴 초상화, 방어 QTE UI, 전투 나레이션, 말풍선 규칙이 분리되어 있습니다.

  • BattleUIController, BattleMenuUI, BattleSubMenu
  • BattleNarrationUI, BattleSpeechBubble

아이템/인벤토리 초기 기반

ItemData와 InventoryManager가 있으나, 상태이상 적용과 전투 아이템 정책은 아직 문자열 분기 의존이 큽니다.

  • 소모품, 키아이템, 장비 타입
  • HP/MP 회복, 데미지, 상태이상 적용 설계 흔적

연출/VFX/카메라 구현 있음

텔레그래프 VFX, 캐릭터 피격/잔상 효과, 자동 despawn, 배경 관리, 전투 카메라 임팩트가 들어가 있습니다.

  • CharacterVFX, CharacterGhostTrail, VFXAutoDespawn
  • Cinemachine, Pixel Perfect Camera, PostProcess Battle profile

다음 분석 후보
우선도 영역 현재 상태 시니어가 해줄 만한 일
높음 저장/이어하기 SaveManager는 슬롯 파일 저장/로드가 있으나, 타이틀 Continue는 아직 실질 로드 루프와 약하게 연결되어 있습니다. 저장 슬롯, 마지막 씬, GlobalData 복원, Continue 버튼 정책을 닫기
높음 BattleManager 비대화 전투 진입, 턴, 적 AI, 방어 판정, 연출, 종료가 한 파일에 몰려 있습니다. 전투 상태 전이, 적 행동 실행, 방어 판정 정책을 분리
중간 스킬/방어 데이터 검증 데이터 드리븐 구조는 좋지만, 잘못된 블록 조합을 막는 검증 레이어가 없습니다. 에디터 검증기, 스킬 타임라인 lint, 전조/판정 누락 경고 추가
중간 아이템/상태이상 상태이상 클래스는 많지만 적용 경로는 문자열 분기 중심입니다. StatusFactory 또는 registry로 전투/아이템 공용 적용 경로 만들기
중간 전투 카메라/연출 기능은 있으나 CameraController가 TMP 예제 폴더에 있고, 픽셀 퍼펙트 전투와 Dutch roll이 충돌할 수 있습니다. first-party 폴더로 이동하고 흔들림 정책/옵션 적용 정리
중간 설정/현지화 마감 설정 시스템은 usable하지만 일부 선택지/메뉴 텍스트는 현지화 파이프라인 밖에 남아 있습니다. 문자열 키 체계와 설정 UI 표시 정책 마감

시니어 관점의 첫 인상

다음 단계로 이어갈 지점

주니어가 만든 프로젝트치고는 기능이 꽤 많이 붙어 있습니다. 특히 BattleEncounterService와 SkillActionBlock 계열은 확장 방향이 좋습니다. 반대로 위험한 곳은 플레이 루프의 끝부분입니다. 저장 복구, 전투 종료 후 월드 상태, 적 행동/방어 판정의 단일 정책화가 아직 덜 닫혀 있습니다.

다음 분석은 "새 기능을 더 붙이기"보다, 이미 있는 수직 슬라이스를 제품화 가능한 기반으로 조이는 쪽이 효율적입니다. 특히 저장/전투 정책/데이터 검증을 잡아주면 이후 콘텐츠를 넣을 때 사고가 크게 줄어듭니다.
