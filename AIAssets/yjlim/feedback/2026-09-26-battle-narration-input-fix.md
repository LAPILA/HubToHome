# 빈 공격 안내 프레임·확인 입력 중복 수정

브랜치 `codex/gameplayEdit`. 커밋/푸시 없음. [당일 기록](../../2026-09-26-update.md) · [인덱스](../../index.md)

## 보고된 증상과 확인한 코드 경로

- 속성/상태 효과 공격 뒤 상단 안내창에 **글자 없이 프레임만 남음**. 사용자에게 빈 프레임임을 확인했습니다.
- 확인 키 연타 시 확인음이 두 번 들리는 경우.
- BattleUIController와 BattleNarrationUI가 문구 유효성 검사 전에 GameObject를 켰습니다. 빈 문자열이면 그 직후 반환하여 코루틴이나 종료 처리가 없고, 기존 HideImmediate는 alpha도 1로 남겼습니다. 빈 요청만으로 해당 상태를 만들 수 있는 코드 경로입니다. 실제 전투에서 어느 요청이 빈 문구를 전달했는지까지는 실행 로그로 확정하지 않았습니다.
- BattleMenuUI.Update에는 입력 소비/활성화 프레임 가드가 있지만 Button.onClick이 호출하는 Confirm에는 없었습니다. 대상 확정 후 같은 프레임에 다시 활성화된 메뉴로 콜백이 들어오면 명령/효과음이 다시 실행될 수 있었습니다. 실제 청음 재현은 하지 않았습니다.

## 수정

1. null/빈 문자열/공백 안내는 양쪽 진입점에서 표시 전에 거부합니다. 유효한 기존 안내를 빈 요청이 지우지도 않습니다.
2. 창 활성화는 BattleNarrationUI만 소유합니다. 초기화를 멱등적으로 처리하고, 메시지를 큐에 넣은 뒤 창을 켭니다.
3. 숨길 때 alpha=0 및 입력 차단. 비활성화 시 큐/코루틴 핸들/확인 대기 상태를 정리하고 큐 종료도 finally에서 숨깁니다.
4. 내레이션의 확인 입력은 WasPressedThisFrame을 다시 눌림 상태로 가공하지 않고 프레임당 한 번 소비합니다. 코루틴 대기 중 키를 뗀 프레임을 놓쳐 다음 입력을 무시하거나, 내레이션을 넘긴 키가 메뉴/방어로 전달되는 것을 방지합니다.
5. 메뉴 버튼 콜백에도 활성화 프레임/소비된 입력 가드를 적용하고, 효과음·외부 동작 전에 명령 입력을 잠급니다. 서로 다른 정상 입력을 시간 제한으로 막거나 전체 오디오를 차단하지 않습니다.

상태 효과 수치, 피해, 방어 판정, 턴/대상 선택 단계와 음원은 변경하지 않았습니다. 씬/프리팹/직렬화 참조 수정이나 수동 연결은 없습니다.

## 검증과 남은 확인

Runtime/Editor CLI 컴파일 오류 0, 기존 ConfigPanelUI CS0649 경고 2. 회귀 검사 코드는 컴파일만 했습니다. 기존 사용자 요청대로 Unity Play/EditMode 테스트·강제 Refresh·재임포트·씬 저장은 하지 않았으며, 실제 화면/청음 재검증은 남아 있습니다.

사용자 확인: 상태 효과 공격 후 빈 테두리가 남지 않는지, 내레이션 넘기기와 메뉴→대상 확정을 빠르게 눌러도 같은 입력의 확인음/명령이 중복되지 않는지 확인합니다. 서로 다른 유효한 두 번의 확정은 각각 소리가 나는 기존 동작을 유지합니다.

이번 진단은 diagnose/Unity 스킬의 수명·입력 경계 점검을 적용하되, 기존 Unity 실행 금지에 따라 직접 재현/테스트 실행 대신 소스 경로와 컴파일만 확인했습니다.

하네스 기록: 큰 문서 묶음은 출력 제한으로 중간이 잘리므로 파일/줄 구간을 나눠 읽습니다. Windows rg에는 파일 인자 `Status*` 대신 실제 경로 또는 디렉터리와 `-g`를 사용합니다. 이번 실패 후 실제 StatusEffect.cs 경로를 확인하여 조회했습니다. 기존 [하네스 교훈](2026-09-26-battle-camera-beats-rapid-skill.md)을 재확인했으며, 허용 경로 밖의 전역 메모리 대신 이 프로젝트에 기록합니다.
