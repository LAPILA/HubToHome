# 토끼 슬라임 — 3색 위젤 속성 실험실

## 사용

실제 전투 1:1 문제 후속 수정: 추가 동료가 공용 프리팹의 InteractionSystem 중복 처리에서 GameObject째 삭제되던 원인을 제거했습니다. 또한 전투 등록 뒤 실행되는 PlayerController.Start가 필드 좌표로 돌아가지 않도록 했습니다. **토끼·ZEV 모두 전열은 원본/청록/보라 위젤 3명, 적은 1명**입니다. 월드에 동료를 수동 배치할 필요가 없습니다. 기존 후열 실습 역시 전열3으로 시작하고 전멸 시 후열3이 교대합니다.

`Assets/_Game/Content/Maps/Development/BunnySlimeBattleLab/Scenes/BunnySlimeBattleLab.unity`를 단독으로 열고 Play를 누르면 **전투 선택 전부터 원본·청록·보라 위젤 3명**이 보입니다. 첫 번째 토끼 통합 전투를 선택하면 전열 3명으로 참가합니다. 기존 본편 세션을 실행한 상태에서는 덮어쓰지 않고 진입을 거부합니다.

시작 화면 후속 수정: 명단 카드만 있던 전체 화면 메뉴를 상하 패널로 바꾸고, 주인공 옆에 동료 표시용 SpriteRenderer 2개를 둡니다. 전투 진입 전에는 숨기며 실제 PlayerCharacter 생성·3/6명 편성·저장 복구는 기존 경로입니다. 메뉴 복귀 때 재사용하므로 참가자가 중복되지 않습니다. 이 미리보기는 정적인 대기 스프라이트이며 별도의 AI/충돌/애니메이터가 없습니다.

| 캐릭터 | 6스킬 역할 |
|---|---|
| 원본 위젤 | 화상·출혈 부여, 3타, 즉발/소비, 압력 강화 |
| 청록 위젤 | 냉기·빙결·중독, 중독 즉발, 전체 정화·회복 |
| 보라 위젤 | 감전 축적, 2타·광역·50타, 감전 소비 기절·방전 |

전체 스킬명과 확인 순서는 [실험실 제작 문서](../../../docs/bunny-slime-battle-lab.md)에 있습니다. 기존 전멸 실습은 전열3+후열3이며, 일반 전투에는 후열을 넣지 않습니다.

## 편집 위치

- 스킬: `Content/Skills/Ally/BattleLab/Elements`, `Content/Skills/Enemy/BunnySlime/Elements`. 기존 스킬 메이커에서 기본 정보의 **누적 상태**와 **누적 상태 · 소비/정화/회복** 블록을 편집합니다.
- 계수/상한: `Content/Maps/Development/BunnySlimeBattleLab/Data/ElementalStatusLabProfile.asset`.
- 파티: 같은 Data의 `Party/front`, `support`, `striker`. `BattleSpriteTint`, `StatusProfile`, `DefaultSkills` 연결. 본편 WizzelDB를 복제/덮어쓰지 않습니다.
- 연결만 복원: `Hub To Home > 테스트 > 원소 실험실 기본 연결 복원`. 수정한 스킬 타임라인이나 씬을 재생성하지 않습니다.

## 규칙

- 최신 대상 선정은 순환 대신 **최근 집중 완화 가중 랜덤**입니다. 낮은 HP 우선도 최대25%, 최근4회/직전 대상 확률 감소, 다른 대상이 있으면 동일3연속 금지. 여러 적이 이력을 공유하고 단일 스킬 연타는 대상을 유지합니다. 전체 공격/대기/예약 준비는 이력을 소비하지 않습니다. [제브 냉기·감전/전열 개별 순회](2026-10-02-zev-cold-electric.md)를 참고하세요.
- SDU 3, 상한 화상99/냉기10/감전999/출혈99/중독99. 저항은 확률이 아닌 부여량 배율이며 소수는 누적합니다.
- 화상은 자기 턴 끝에 피해 후 -1. 출혈은 실제 공격/스킬 완료 후 피해·-1. 아이템과 반격은 새 출혈을 발동하지 않습니다. 중독은 자기 턴 끝 피해 후 +3.
- 냉기10은 냉기값을 지우고 빙결. 빙결 중 행동과 Z/X/C 차단, 다음 직접타격 1회 ×1.5 파쇄 또는 자기 턴 1회 스킵. 상태 피해는 파쇄하지 않습니다. 해제 후 실제 행동을 완료할 때까지 재빙결/기절을 제한합니다.
- 감전은 실제 타격마다 추가 피해·1% 방전. 50타 예제는 감전 피해 계수0.1, 감전 부여0.2/타를 별도로 설정했습니다. 최소1 강제 올림은 없습니다.
- 일반 방어는 새 부여량도 줄이고 완전 방어·회피는 부여0. 상태 피해는 회피 무적과 별개입니다.
- 기간제 일반 버프와 기존 구형 상태 데이터는 유지합니다. 전투 전체를 새 상태로 일괄 마이그레이션하지 않았습니다.

## 표시·수명

피해 숫자 가독성 후속: 상태 피해는 약자 없이 **숫자+색상**만 표시합니다. 기본 크기60→30, 아군/적 모두 오른쪽입니다. 연타 숫자의 글자/이동 영역이 겹치지 않도록 배치하고 공간이 차면 가장 오래된 표시부터 정리합니다(피해 계산은 보존). `BattleUIController > Damage Popup > 글자 크기`에서 조절합니다. 스킬 QTE는 일반/연타 모두 상단 좌우 우선이며 캐릭터의 현재 화면 영역을 피합니다. 입력 중 위치/판정은 바꾸지 않습니다. 관리형 배치 검사와 Runtime/Editor 빌드는 통과했으며 Unity 실제 화면은 미검증입니다.

적 발밑에는 `Icon.png`의 **화상16 · 냉기2 · 감전3 · 출혈1 · 중독19**와 현재 누적 수치를 표시합니다. 상태가 생길 때 나타나고 0/정화/사망/전투 종료 시 숨깁니다. 빙결은 냉기 아이콘 옆 `빙`이며 남은 턴 숫자가 아닙니다. 아이콘16px, 숫자10px, 최대3개씩 줄바꿈합니다. 카메라 줌/회전에도 크기·정방향을 유지하며 적 위치를 따라갑니다.

조절 위치는 공유 `SeamlessBattleHost > BattleUI > BattleUIRoot > BattleUIController > 적 하단 상태`입니다. **발밑 간격(px)** 기본8, **한 줄 최대 개수** 기본3. 스프라이트는 연결 완료했으며 토끼/ZEV를 포함한 공유 Host 전투에서 사용합니다. 적 객체에 별도 컴포넌트를 붙이지 않습니다. 표시 수치는 이벤트로 갱신하고 적별 셀은 재사용합니다. 씬 변경 없이 공용 프리팹 참조만 추가했습니다. Runtime/Editor 컴파일은 통과했으며 실제 Play 화면은 미검증입니다.

평소 파티 상태줄은 약자+값 두 항목과 나머지 개수입니다. 일반 버프가 함께 있으면 기존 아이콘 한 칸을 남기며 빙결을 우선합니다. 대상 선택 중 기존 설명칸에 해당 대상의 전체 상태를 표시하고 취소 시 스킬 설명을 복원합니다. 새 상단 패널은 없습니다. 상태 피해 숫자도 기존 팝업 풀을 사용합니다.

현재 상태는 actor 인스턴스만 소유합니다. 본편 저장 파일은 읽거나 쓰지 않으며 기존 실험실 세션 소유권/복구 경로를 유지합니다. 순수 누적값 갱신은 속도 턴 예고를 재계산하지 않습니다. 상태 피해의 HP 임계/처치 이벤트는 원래 전투 시나리오 큐로 통지하며 일반 타격 소리/숫자를 중복 발생시키지 않습니다.

## 검증 및 남은 확인

아래 순환 분배 수치는 이전 구현 기록입니다. 최신 랜덤 분배는9,000회에 2,939/3,154/2,907회, 동일3연속0회이며 상세 변경은 제브 문서/당일 기록에 있습니다.

대상 선정 후속: 기존 첫 생존 아군 고정 선택을 공통 순환 선택으로 교체했습니다. 실제 선택 메서드를 추출한 관리형 검사에서 이전 12/0/0 편중을 재현하고, 수정 후 300회가 100/100/100으로 분배됨을 확인했습니다. 사망/비활성/null/빈 파티/교체 검사 통과. 일반 공격·스킬 간 순번 공유, 광역/대기의 비소비, 연타 대상 유지를 NUnit 회귀 검사에 추가하고 Runtime/Editor 컴파일 오류0(기존 경고2)를 확인했습니다. NUnit 실행·Unity Play는 하지 않았습니다. [스킬 제작 안내](2026-09-28-skill-block-authoring.md)도 상태 부여·소비·압력·DB 연결까지 갱신했습니다.

상태 아이콘 바인딩 예외 수정: 초기 빈 아이콘 배열로 갱신한 뒤 3칸을 연결하면, 최초 길이로 고정된 위치/크기 캐시에서 범위를 넘던 문제를 재현했습니다. 현재는 실제 RectTransform별로 원본을 보관하여 개수/순서/참조 변경과 대체 글자 크기 복원을 처리합니다. 수정 전 실패·수정 후 통과를 실제 레이아웃 메서드의 관리형 대역 검사로 확인했고 Runtime/Editor 컴파일 오류0입니다. Unity에서의 정확한 배열 교체 시점과 렌더 결과는 미확인입니다. 추가 Inspector 연결이나 씬 재생성은 필요 없습니다.

Runtime/Editor C# 빌드, 신규 자산 GUID·ID·카탈로그·managed-reference 검사와 변경 범위 검토를 수행합니다. NUnit 회귀 검사를 추가했으나 Unity Play/Refresh/NUnit 실행은 하지 않습니다. 실제 640×480 상태줄 가독성, 전투 진입/복귀, 임시 틴트·방어창·50타 체감과 밸런스는 수동 확인이 남습니다. 수치는 제품 밸런스 확정값이 아닙니다.
