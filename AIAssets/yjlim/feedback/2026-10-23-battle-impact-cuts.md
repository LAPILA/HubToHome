# 공격 준비–명중 컷 · 전투 피드백

## 이번 변경의 중심

이전의 ‘피격 캐릭터를 먼저 멈춘 뒤 Hurt’를 기본 해제했다. 캐릭터는 즉시 피격 자세로 반응하고, 카메라가 **공격 직전 구도 고정 → 명중 순간 빠른 전환 → 짧게 유지 → 복귀**의 박자를 담당한다. 기존 대기·피해 확정·방어 입력 시간을 늘리지 않는다.

| 항목 | 적용 내용 | 조정 위치 |
| --- | --- | --- |
| 카메라 준비 | 공격 시작의 기존 시간 안에서0.05초 구도만 고정 | CameraController → 명중 컷·준비 고정 후 빠른 전환 |
| 명중 컷 |0.025초 진입/0.025초 유지/0.075초 복귀, 기본2.5% 줌·최대0.1유닛 방향 이동 | 같은 그룹의 시간·거리·타격 줌 |
| 연타·전체 공격 | 컷 진행 중 요청/0.12초 내 재요청은 생략, 늦게 큐에서 재생하지 않음. 피해·타수는 그대로 | 연타 컷 최소 간격 |
| 피격 자세 | 기본 Animator 정지0, 즉시 Hurt·백색·기존 Hit VFX | CharacterHitFeedback → 명중 피드백 |
| 방향 반동 | 실제 공격자 반대 방향으로 짧게 밀림,0.05초 이내 밀림/0.12초 이내 복귀. 적의 매번 위로 튀는 반동 제거 | 기존 캐릭터 피격 반동 값, 런타임 상한 적용 |
| 처치 마무리 | 적에게만0.06초 백색 강조 후 기존 사망 페이드, 명중음 낮은 음높이 | 기존 Enemy 사망 흐름·AudioManager |
| HP | 숫자와 실제 바 즉시 변경, 잃은 구간만0.12초 대기+0.28초 감소 | PartySlotUI → 피격 HP 표시 |
| 상태 변화 | 아군HUD·적 발밑의 새 상태/빙결 전환만1.12배 국소 반응 | 각 상태 표시 컴포넌트 → 상태 변화 반응 |
| 음향 | 기존 명중음4보이스 상한·작은 음색 변주,35ms 같은 순간 중복 제한·합산 음량 상한 | AudioManager → 명중 효과음 혼합 |
| 대상·행동자 표시 | 기존 대상 청록 테두리/현재 행동 노랑 배경 유지, 새 중복 마크 없음 | 기존 PartySlotUI/BattleUIController |

약한 피해의 카메라 강도도 기본60%를 확보하고, 최대 HP 대비 피해에 따라100%까지 강조한다. 피해량 자체를 증폭하지 않는다. 연타의 매 타격을 전부 크게 흔들지 않는다. 일반 카메라 컷에는 회전·랜덤 흔들림을 넣지 않는다.

## 연결과 소유권

기존 캐릭터/전투 공통 경로에서 호출되므로 새 씬 배치·Prefab/DB 연결은 필요 없다. 기본 공격·스킬 공격 애니메이션 시작은 `RequestBattleImpactPreparation`, 실제 양수 직접 피해는 `RequestBattleHitCut`에 연결했다. 압력난무는 공격 루프를 시작할 때만 준비 요청하며 입력·타수 시계를 바꾸지 않는다. 등록된 특수 카메라 연출 구간은 기존 연출이 우선한다.

- 실제 방어창의 카메라 hold 중에는 명중 컷을 생략한다. 방어 결과가 확정되어 hold가 해제된 뒤의 grace에는 즉시 허용하고, 다음 방어가 열리면 컷을 취소해 원래 최종 카메라 상태를 복구한다.
- Timeline·새 명령 토큰·모달·씬 종료가 우선한다. 진행 중이던 구도/렌즈 전환은 명중 컷 동안 일시정지하고 복귀 후 이어간다. 중간값에 고착되지 않는다.
- HUD는 기존 화면 공간 배치를 유지한다. 화면 흔들림 설정0에서는 명중 카메라 컷도 하지 않으며 플래시0에서는 백색을 표시하지 않는다.
- HP 잔여 Image는 원본 뒤에 한 번 생성/재사용하며 입력을 받지 않는다. 회복·재바인딩·원본 교체·비활성/파괴 시 자기 표시/Tween만 정리한다. 연타는 목표만 갱신하고 잔여바의 종료 시각을 계속 미루지 않는다.
- 상태 표시는 같은 값 갱신·틱·수치 증감·최초 바인딩에는 반복 반응하지 않는다. 해제 상태는 즉시 사라지며 가려진 상태 변화는 기존 `+N`에만 반응한다. 상태 규칙/중첩/기간은 변경하지 않았다.
- 오디오는 기존 SFX Mixer/리스너·공간 설정을 복사한다. 설정 볼륨0은 이미 울리는 보이스에도 믹서를 통해 적용된다. UI·전조·음성·BGM의 소스 음높이/재생은 건드리지 않는다. 가드/패링은 기존 VFX 내장 음향을 유지한다.

캐릭터별 피격 정지를 다시 원하면 `CharacterHitFeedback`의 기본/강한/연타 정지 시간을 조정한다. 기존 Prefab에 해당 컴포넌트를 미리 저장하고 시간을 지정한 경우 그 사용자 값을 자동 덮어쓰지 않는다. Play 중 자동 추가된 컴포넌트의 값은 종료 후 보존되지 않는다. 기본 캐릭터에는 기존 자동 추가 경로가 적용된다.

## 새로 만들지 않은 부분

스미어 원화·새 그림자 아트·무기/재질별 신규 녹음·패드 진동과 설정 화면은 추가하지 않았다. 스킬의 준비/가속/후속 자세는 기존 클립/블록 데이터로 편집하며 전체 스킬 시간을 자동 재작성하지 않았다. 기존 입력 예약·키 소모·방어/QTE 판정과 HUD의 즉각적인 메뉴 반응도 유지한다. 아군 사망은 후열/계속 싸우기 흐름이 소유하므로 별도 처치 페이드를 덮지 않는다.

## 검증과 확인할 것

- 전체 CLI: Runtime440/Editor366소스 오류0, 기존 경고225/0.
- 생산 코드 관리형 검사: 피격 수명201단언, 카메라 곡선10,027단언, 명중 오디오236단언, 상태 전환16,398단언 통과. Unity/DOTween/상태 입력 대체 타입을 사용한 검사는 실제 엔진 재생이 아니다.
- Editor 회귀 소스를 추가/컴파일했다. 선택적인 양수 피격 정지의 기존 복구 계약도 테스트에 남기고, 새 기본0초·방향 반동·처치 표시·진행 중 카메라 전환 재개 검사를 추가했다.
- 독립 검토에서 발견한 카메라 중간 구도 고착과 HP 잔여바 원본 교체 시 옛 부모 재사용 문제를 수정했다.
- **Unity Play/강제 Refresh/Reimport/씬 저장·엔진 NUnit·GPU/모바일·콘솔 체감 검사는 하지 않았다.** 실제 쾌감·발열/프레임 무결함은 보장하지 않는다. 실제 사용자 save I/O·커밋/push도 하지 않았다.

수동 확인은 실험실에서 일반 단타 → 압력난무 → 적의 연속 공격 → X/C 대응 → 처치 순서로 보면 된다. 전조를 읽는 동안 화면이 안정적인지, 명중 순간만 팍 움직이는지, 카메라가 원위치/원래 목적지로 복귀하는지, HP 잔여바와 상태 아이콘이 과하게 반복되지 않는지 확인한다.
