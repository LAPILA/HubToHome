# 챕터 1 프로그래밍 기반 · 적용과 제작 인수인계

2026-10-16 사용자 확정안 기준. **구현과 컴파일 확인**, **실제 플레이 확인**, **아직 기획하지 않은 콘텐츠**를 구분한다. 새 동료의 역할·스킬·고유 자원, 실제 보상 수치, 보스 패턴은 임의로 만들지 않았다.

## 1. 이번에 연결한 규칙

| 영역 | 현재 구현 계약 |
|---|---|
| 파티 | 새 게임의 기존 주인공 1명 유지. 이벤트로 동료 중복 없이 합류·저장. 기존 전열 최대 3명/후열 구조 재사용. 필드 동료 오브젝트는 생성하지 않음 |
| 성장 | EXP·레벨은 파티 공용, 최대99. 경험치는 멤버 수만큼 곱하지 않음. 레벨업 보상은 각자의 능력치/스킬 포인트이며 수치는 직접 투자로만 상승 |
| 스킬 | 기본 스킬 + 캐릭터별 포인트 구매 트리. 초기화 무료. 레거시 레벨 자동 해금은 기본 비활성, 이미 저장된 습득 목록은 유지 |
| 방어/QTE | 일반 방어 피해35%, 저스트가드 피해0+AP. 회피 기본 AP보상 없음. 공격 QTE 완전 성공은 정상1배, 실패는 설정된 감소 배율. 기존 고유 자원/장비 효과는 별도 |
| 아이템 | 최대99(더 작은 제작 한도는 유지). 저장 파티의 비생성 동료도 필드 아이템 사용. 전투 부활 대상·정화·전체 범위·양 진영 선택 연결 |
| 장비 | 장비 상품/상자/드롭은 장비 보관함에 지급. 중복 보유·장착분 판매 보호·특수 장비 판매 금지. 조건부 HP/AP 효과 실행 훅 연결 |
| 저장 | 수동 파일 쓰기 성공 후에만 회복·일반 적 재등장. 취소/실패에는 적용하지 않음. 자동 저장에는 휴식 효과 없음 |
| 재도전 | 보스/도주불가 필수전투는 전투 직전 메모리 스냅샷. 일반 패배는 최근 저장. 훈련용 패배 복귀는 기존 정책 유지 |
| 진행 | 완료된 시퀀스/보스 승리/합류/명시적 진행 완료 이벤트 자동 저장 예약. 잡담·저장 확인창 종료는 자동 저장 이벤트가 아님 |
| NPC | 저장 플래그 + 소지 아이템 수 조건으로 대사 선택. 둘 다 입력하면 AND. 선택만으로 아이템을 소비하지 않음 |
| 대화 | X로 일반 선형 대사 구간 건너뛰기. 노드 이벤트는 정상 경로와 동일하게 실행. 선택지·이름 입력은 멈춰서 사용자 결정 |
| 메뉴/입력 | 아이템/일지/현재 목표, 전투 중 Escape·패드 Start·모바일 Ⅱ 메뉴. 메뉴 중 전투시간 정지·음악 유지. 패드 안내 전환/해제 fallback, 모바일 터치 전용 가상 입력 |
| 언어 | 화자·선택지 번역키, 한/영/일/중 기본문구30행, 줄바꿈/인용부호 CSV 파서. 전체 기존 게임 문구 번역 완료는 아님 |

전투 후 HP/AP 유지와 전투 상태 제거, 공평한 가중 랜덤 타깃, 도주 실패의 행동 소비와 접촉 유예, 무료 재투자/6장비 슬롯은 기존 흐름을 확인해 재사용했다. 속도 턴 스케줄은 이번에 변경하지 않았다.

## 2. 동료를 실제로 합류시키는 순서

1. `CharacterData`에 고유 `CharacterID`, 기본 능력치, `BattlePrefab`, `DefaultSkills`, 성장 프로필/스킬 트리를 설정한다. **게임 콘텐츠 카탈로그의 아군 목록에도 등록한다.** 미등록 데이터는 저장 후 복원이 불가능하므로 합류를 거절한다.
2. 합류 이벤트를 소유하는 오브젝트에 `PartyRecruitmentTrigger`를 추가한다. 합류할 동료, 호출 이벤트 ID, 완료 플래그를 지정한다. 예: `ch01.companion.join`, `ch01.companion.joined`.
3. 기존 대사 노드의 `EventTriggerID` 또는 UnityEvent에서 해당 이벤트/`Recruit()`를 호출한다. 이것은 디버그 기능이 아닌 본편 경로다.
4. 합류 성공 후 현재 파티 레벨·EXP와 레벨에 해당하는 개인 포인트를 지급하고 자동 저장을 예약한다. 같은 동료를 다시 호출해도 인원·포인트를 중복 지급하지 않는다.
5. 필드에는 기존 주인공만 남고, 다음 전투에서 저장 파티를 읽어 출전한다. 전열3명 이상 구성에는 각 동료의 유효한 전투 프리팹 또는 기존 공용 대체 프리팹이 필요하다. 연결이 없으면 에러를 기록하며 임의 캐릭터를 복제하지 않는다.

초기 장비/실제 스킬 구성이 미정이므로 동료별 임시 장비를 자동 지급하지 않았다. 합동 스킬과 동료 고유 자원도 추가하지 않았다.

## 3. 성장·스킬 제작

- `PartyProgressionService`가 공유 EXP를 한 번 계산한다. 저장 멤버의 Level/EXP 필드는 기존 표시/전투 API 호환용으로 동기화한다.
- EXP 곡선은 최초 파티 리더의 `CurveCharacterId`로 고정해 나중에 합류한 동료가 곡선을 바꾸지 않는다.
- `GrowthBalanceProfile`에서 레벨별 능력치 포인트·스킬 포인트, 투자1당 환산값을 조정한다. 기존 기본값은 능력치3/스킬1이며 이번에 밸런스를 임의 재작성하지 않았다.
- `CharacterData.SkillTree`의 노드 비용/선행 조건/스킬 참조를 작성한다. `DefaultSkills`는 시작 스킬이다. `AllowLegacyLevelUnlocks`는 이전 콘텐츠 호환용이고 본편 기본값은 false다.
- 챕터15/30/45/60/75/99는 제작 목표이지 강제 제한이 아니다. 실제 전투 수·경험치 보상이 확정되어야 목표 도달 시간을 맞출 수 있다.
- 전투 중 메뉴에서는 능력치를 확인할 수 있지만 성장/장비 수정은 기존 전투 안전 경계로 차단한다. 필드 변경/초기화에 돈은 들지 않는다.

## 4. 아이템·장비·NPC·일지 제작

- 장비는 `EquipmentData`를 만든 후 `ItemData.Type=Equipment`, `Equipment=해당 장비`로 상품을 연결한다. 상품과 장비를 각각 카탈로그에 등록한다. 무기 제한과 판매 불가 여부는 장비 데이터에 작성한다.
- `TriggeredEffects`는 전투 시작(최초 전열), 자기 턴 시작, 저스트가드, 회피, C특수 반격에서 HP/AP 회복을 지원한다. 공격력 조건 변화 등 **모든 종류의 패시브가 구현된 것은 아니다**. `PassiveEffectID`만 적어서는 작동하지 않는다.
- 부활은 HP 대상/회복량을 설정하고 전투 불능 동료에게 사용한다. HP/AP가 가득 찼거나 정화할 상태가 없으면 소모하지 않는다. 전투 밖에는 상태이상이 남지 않으므로 정화·상태 부여는 필드에서 거절한다.
- 상한을 넘은 획득분은 보관하지 않으며 실제 추가된 수량만 보상으로 표시한다. 초과 보상 보관함/우편은 추가하지 않았다. 옛 저장에99초과 재고가 있으면 런타임 로드 시 상한 적용에 주의한다.
- 콘텐츠 메이커의 진행별 대화에 플래그 키와 `필요한 소지 아이템 ID/개수`를 입력한다. 둘 중 하나만 사용할 수도 있다. 반복 방지는 완료 플래그로 작성한다. 아이템 전달/소비는 별도 확정 이벤트에서 처리한다.
- `Resources/HubToHome/JournalCatalog.asset`에서 메모와 목표를 작성한다. 현재 화상·감전 안내만 들어 있고 **스토리 목표는 비워 두었다**. 조건 플래그를 작성해야 실제 진행에 맞춰 내용이 바뀐다.

## 5. 저장·재도전에서 반드시 지정할 데이터

`EnemyData.Rank`는 Normal/Elite/Boss, `Kind`는 Human/Monster/WhiteEntity다. 기존 에셋의 이름을 보고 자동 분류하지 않았다. 본편 보스/엘리트는 등급을 지정하고 필수전투는 기존 도주 불가 정책을 설정한다.

수동 슬롯0~2는 저장 성공과 동시에 휴식한다. 자동 슬롯99는 진행만 기록한다. 파일 원자 교체가 실패하면 회복/일반 적 복귀도 하지 않는다. 적의 승리 이력·일회성 대화/상자·이벤트 플래그는 휴식으로 지우지 않는다.

`SceneActionSequenceTrigger`는 정상 완료에 기본 자동 저장을 예약한다. 별도 진행 시스템은 `ProgressSaveTrigger`를 **진행이 확정되는 완료 이벤트**에 연결한다. 단순 마지막 문장을 표시하는 시점이나 잡담에 연결하지 않는다. 실제 쓰기는 전투/대화/결과/씬 전환이 종료된 필드 안전 경계에서 수행한다.

보스/필수전투 재도전은 원래 방을 로드하고 같은 조우 ID로 다시 진입한다. 조우 ID가 중복되거나 소스가 사라지면 다른 전투를 추측해 실행하지 않는다. 재도전 체크포인트는 메모리 전용이며 앱 종료 후에는 최근 디스크 저장을 사용한다.

## 6. 저장 v5 호환

v0~v4 → v5에서 `PartyProgression`을 추가한다. 기존 멤버 중 최고 레벨, 그 레벨의 최대 EXP를 가져오며 EXP를 합산하지 않는다. 투자·스킬·장비·HP/AP를 보존하고 낮은 레벨 멤버는 공유 레벨로 동기화한다. 사용한 스킬 포인트를 초기화 순서 때문에 잃던 경로도 보정했다.

미래 버전 저장은 기존처럼 거절한다. 이후 챕터에서 고유 ID를 변경/삭제한다면 별도의 ID 마이그레이션이 필요하며, 버전 번호만 높인다고 임의 콘텐츠 변경까지 호환되는 것은 아니다.

## 7. 검증 결과와 남은 확인

실행한 순수 관리형 검사: **공유 성장9 + 방어117 + 공격QTE22 + 저장코덱17 = 165/165 통과**. 실제 프로젝트 소스와 NUnit 사례를 사용하되 Unity 엔진/데이터 모양 일부는 검사 대체 타입을 쓴다. MonoBehaviour 수명주기·입력 장치·렌더링을 검증했다는 의미는 아니다.

전체 소스 CLI 컴파일은 Runtime/Editor/테스트를 포함한다. 최종 소스 수와 경고 수는 [당일 기록](../../2026-10-16-update.md)을 따른다. Unity Play, 강제 임포트, 씬/프리팹 저장, 커밋/push는 하지 않았다.

아래는 제작 데이터/Unity에서 확인해야 한다.

- 본편 동료2명의 실제 데이터, 프리팹·카탈로그 연결, 스킬/장비/보상 가격과 수치.
- 메뉴 열기 전후 연타·투사체·방어·QTE 타이밍, 모바일 배치와 실제 패드. 독립 실험실에 Overworld 메뉴 패널이 등록되지 않으면 메뉴가 자동 생성되지는 않는다.
- 저장 취소/파일 쓰기 실패/성공, 보스 재도전, 일반 적만 재등장하는 씬·방 배치 확인.
- 일/중 글리프가 포함된 실제 폰트, 기존 본편 문자열 전체 번역, 저사양 실기기 프레임/메모리/발열 측정.
- 초기화/조건부 장비/합류/스킵/저장 거래 관련 Unity NUnit은 작성·컴파일만 확인했다.

발열0·프레임저하0·로딩0은 보장하지 않는다. 신규 코드는 프레임별 전체 검색을 추가하지 않고 기기 이벤트/고정 터치 배열/기존 캐시를 사용한다. 기존 암전 준비 구간은 유지했지만 기기별 측정 없이 로딩 시간을 확정할 수 없다.

## 하네스 교훈

새 타입이 추가되면 오래된 독립 검사 프로젝트의 대체 타입/참조가 뒤처질 수 있다. 2026-10-16 기존 CombatFoundationChecks는 신규 성장/장비 타입을 몰라 컴파일되지 않았고, 실제 정책 소스를 직접 포함한 범위별 검사와 최신 소스 전체 Roslyn 컴파일로 구분 검증했다. Unity 생성 csproj의 Compile 목록은 에디터를 갱신하지 않으면 새 파일을 놓치므로 검사 전 최신 디렉터리에서 소스를 수집하고 기존 DLL 참조만 재사용한다. 실제 저장 파일이나 Unity Library/ScriptAssemblies를 덮어쓰지 않고 `Library/CodexChecks`에 결과를 둔다.
