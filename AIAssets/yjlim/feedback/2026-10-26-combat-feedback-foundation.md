# 전투 피드백 — 공통 기반 정리

평타·스킬 구성·전조 말풍선 기획을 제외한 피드백을 공용 런타임에 반영했습니다. 적 이름이나 스킬 ID를 검사하는 분기는 추가하지 않았습니다. 기존 무정지 공격·C 성공 연출·후열·저장·엄격 픽셀 카메라 정책은 유지합니다.

## 적용한 규칙

| 항목 | 현재 기본값 / 동작 |
| --- | --- |
| 저스트 가드 | 명중 전 0.12초, 늦은 입력 유예 0.03초 |
| 회피 | 0.22초, 기본 AP 보상 없음 |
| C 특수 반격 | 0.18초, Counterable6 / CounterOnly7 모두 C 전용 |
| 일반 방어 | Z 홀드 지속, 피해 65% 감소, 여러 타격에도 유지 |
| 연타 방지 | 예고 구간 첫 대응 확정, Z/X/C 공통 0.18초 재준비. 짧은 공격은 길이 절반 이하 |
| 기본 AP | 본인 턴 +2, 저스트 +2, 한 적 행동당 아군별 기본 저스트 합계 최대 +6 |
| Lab AP | 장비 포함 최대40, 시작20. 전투 종료 후 재실험 준비 시에만 초기화 |
| 누적 강화 | 10 / 25 / 50부터 상태 피해 ×1.25 / ×1.5 / ×2 |
| 공격 QTE | 기본 수동. 설정에서 자동 입력 선택 가능, 방어는 자동화하지 않음 |
| 보스 진행 | 보스/선택 적용 적의 HP·비율·선택적 체력 마커 표시 |

전조 그림·위치·표시 시간은 바꾸지 않았습니다. 기존 긴 예고와 짧은 성공 구간을 분리했습니다. 예고 때 너무 일찍 누른 Z는 계속 들고 있으면 일반 방어이며, 저스트 성공으로 바뀌지 않습니다. 잘못된 키나 동시 입력 뒤 다른 키로 덮어쓰지 못합니다. 전조 전에 눌렀던 입력을 소급해 성공시키지도 않습니다. 숨은 확률 실패는 없습니다.

## 입력·보상 소유권

- `DefenseJudgementPolicy`는 성공창과 C 전용 가부를 계산합니다. `ActiveDefenseAttempt`가 타격의 첫 시도를, `ParryRearmState`가 배우의 공통 재준비를 소유합니다.
- `PlayerController`의 실제 press 시각·동시 입력 상태를 선택적 `IActiveDefenseAttemptSource`로 전달합니다. 기존 방어 입력 인터페이스와 enum 숫자는 유지합니다.
- 상단 비모달 전투 기록이 적 공격 중 Z를 확인 키로 소비해 홀드 방어가 끊기던 충돌을 수정했습니다. 대응 중에는 기록이 Z를 가져가지 않으며 메뉴 확인 입력의 방어 유출 차단은 유지합니다.
- `BattleParryRewardBudget<T>`와 `BattleManager.BeginParryRewardAction()`은 한 적 행동의 아군별 AP 예산을 소유합니다. 일반·구형·시나리오 스킬 실행이 같은 예산을 쓰며 중첩 scope도 새 예산을 열지 않습니다. 중단 후 오래된 Dispose가 다음 행동을 닫지 못하게 세대로 구분합니다.
- 명시적 장비 보상·압력 자원은 기본 AP 예산과 별도입니다. C 보상을 저스트 AP로 중복 계산하지 않습니다. 본편 최대 AP·장비·성장·HP/AP 저장 승계는 변경하지 않았습니다.

## 아이템 재사용 방법

기존 아이템의 `ElementalPayload`는 비어 있으면 이전 동작 그대로입니다. 새로 만들 때는 아이템 메이커/Inspector에서 다음을 설정합니다.

1. 소비 아이템, 전투 사용 가능, 대상 범위를 지정합니다.
2. 기존 회복 등 효과가 없는 순수 누적 아이템은 `ActionType=None`으로 둡니다.
3. `ElementalPayload.Operation`을 `AddBuildup` 또는 `ConsumeForDamage`로 고릅니다.
4. 상태 종류와 부여/최대 소비량을 입력합니다. 소비 공격은 소비량당 피해도 입력합니다.
5. 전투 전용 누적 효과는 필드에서 거부합니다. 기존 회복과 함께 붙이면 기존 주 효과의 사용 조건도 충족해야 합니다.
6. 장비의 `TriggeredEffects`에 `ItemUsed`를 선택하면 성공한 아이템 행동당 한 번 적용합니다. 전체 대상 아이템도 대상 수만큼 반복 발동하지 않습니다.

Lab에는 축전병(감전4), 방전탄(감전 최대6 소비·소비량당18 피해)을 각각5개 준비합니다. Lab 밸브 장비에는 아이템 성공 사용 시 AP2 회복 예시가 있습니다. `Data/Items` 샘플과 기존 카탈로그에 연결했으며 실제 저장 인벤토리는 Lab 진입 전 상태로 복구합니다.

효과 직전에 한 개만 소모하고, 무효 대상·취소·효과 없음에는 소모/장비 발동/턴 소비를 하지 않습니다. 저항 때문에 정수 누적이 아직0이어도 소수 잔량이 증가했다면 유효 사용으로 처리해야 합니다. 누적 소비 피해는 기존 상태 피해 이벤트를 사용하며 일반 피해 결과를 다시 더하지 않습니다. `ItemUsed=5`는 기존 트리거 숫자0~4 뒤에 추가했습니다.

## 누적 상태 조정

`ElementalStatusProfile → 중첩 강도`에서 임계값·배율·최대 배율·사용 여부를 조정합니다. 프로필이 없는 기존 적도 공용 기본값을 사용합니다. 화상·감전·출혈·중독의 실제 상태 피해에만 적용하며 냉기 취약/빙결·저항·자연 증감·소수 이월은 유지합니다. 감전은 새 피해 기여분만 강화하고 이미 쌓인 소수 피해 잔량을 다시 곱하지 않습니다.

상태 설명에는 강도·배율이 표시되고, 단계가 올라갈 때 기존 아이콘만 짧게 강조합니다. 피해 숫자에 글자를 붙이거나 HUD 폭을 늘리지 않습니다.

## QTE·보스 UI 조정

- 설정 → 게임플레이 → **공격 QTE 자동 입력**. 기본 꺼짐이며 기존 PlayerPrefs 지연 저장·초기화·한/영/일/중 표시를 사용합니다. 원래 입력 창의 시계대로 정상 성공 피해를 주며 공격 속도나 타수를 바꾸지 않습니다.
- 수동 QTE도 공용 안전 영역의 일관된 측면 위치에 표시합니다. 배우 배제 영역에 걸리면 안전 위치로 보정합니다. 스킬별 키 패턴·횟수·데이터는 그대로입니다.
- QTE 마지막 창에서도 일시정지·호출자 취소를 다시 검사합니다. 메뉴 정지 중 마지막 자동 성공이 전달되는 경계 문제를 실소스로 재현해 수정했습니다.
- `EnemyData → 체력 진행 표시 / 체력 구간 표시`를 사용합니다. 보스 등급은 자동 표시, 엘리트 등은 선택 적용입니다. ZEV Lab은 남은 HP50% 마커만 켰으며 등급·HP·기존 페이즈 조건은 바꾸지 않았습니다.
- 상단 왼쪽 170×32에 한 대상만 표시합니다. HP 이벤트로 갱신하고, HP 변경 없는 비활성화·파괴도 표시에서 제외합니다. 시나리오/무적/보상은 UI가 판단하지 않습니다. 새 카메라·렌더 패스는 없습니다.

## 이번에 보류한 기획

- 평타의 AP 수급·전용 역할·추가 효과.
- 스킬6개 장착, 스킬별 비용·설계·QTE 개수/패턴·연출 재구성.
- 전조 말풍선, 스킬명 선행 안내, 공격 예고 체계 재설계.
- 보스별 목표 전투 길이·새 패턴·HP 재조정. HP 표시가 전투 길이를 해결했다고 보지 않습니다.

## 검증과 남은 확인

실제 소스 기반 관리형 검증: 방어 정책158개, 공통 재준비479검사+8연결 계약, 홀드 입력26검사, 누적 상태18사례69검사, QTE/표시14사례162검사+5계약, AP 보상 예산/중단·아이템 단일 소비 검사. 기존 C 포커스10사례108검사와 실제 DOTween DLL Startup/Goto 계약, 스킬 잠금429검사·메뉴19검사·메뉴 인계12사례, 배우 포커스11사례15검사도 재확인했습니다.

전체 Runtime/Editor C# 컴파일 오류0. Editor 테스트는 추가/컴파일했으나 엔진에서 실행한 결과가 아닙니다. 관리형 경계 대역은 실제 Unity InputSystem 콜백·코루틴 스케줄링·Canvas·애니메이션·GPU 동작을 보증하지 않습니다. Unity Play/강제 Refresh·리임포트·씬 저장·실제 저장 I/O·기기 성능 측정은 하지 않았습니다. 커밋·푸시도 하지 않았습니다.

직접 확인할 것은 Z 연타/키 교대와 홀드 다단 공격, C 공격의 X 실패, 저스트 난이도 체감, 자동 QTE 감상, 아이템 연계의 실전 가치, 작은 보스 HP 글자 가독성입니다. 수치는 데이터에서 조정하되 제외한 기획을 임의로 덧붙이지 않습니다.
