## 작업 환경 교훈

- 최초 `--no-restore` 실패는 Temp/project.assets.json 부재(NETSDK1004)였고 한 번 restore 포함 직렬 빌드 후 해결됐습니다. 이후 Unity가 자체 갱신한 csproj에 새 파일이 포함되어 임시 targets와 중복된 CS2002가 발생했습니다. 실제 Compile 항목을 확인하고 임시 targets 없이 재빌드하니 기존 경고 2개만 남았습니다. 새 파일 존재와 csproj 포함 여부는 별개로 확인하세요.
- Unity YAML 블록 결합 때 기존 마지막 줄에 다음 `--- !u!`가 붙어 첫 신규 객체가 인식되지 않는 문제가 있었습니다. 블록 끝을 정규화해 줄바꿈으로 연결하고 모든 내부 fileID 및 부모→자식 목록을 검사하여 해결했습니다. YAML 자산을 텍스트 수정할 때 구문 컴파일만으로 자산 유효성을 판단하지 마세요.
- functions의 strict module에서 eval로 선언한 함수는 바깥에 노출되지 않습니다. 저장한 함수 소스를 괄호로 감싼 표현식으로 eval해 반환값을 변수에 저장하면 재사용됩니다.
- Windows apply_patch 기준 경로는 셸 workdir과 별개입니다. 실제 하위 Unity 루트 절대 경로를 사용했습니다.
- 사용자 지침의 yjlim 전역 메모리 경로는 이 환경에 없었습니다. 다른 사용자 디렉터리를 만들지 않고 프로젝트의 이 기록으로 교훈을 보존했습니다.

브랜치 `codex/gameplayEdit`, 커밋/푸시 없음. 작업 전부터 있던 `ProjectSettings/EditorBuildSettings.asset` 수정은 보존했습니다.
