## 최신 후속 · Unity 런타임 경계 검수

사용자 선택에 따라 별도 프롤로그 웹사이트가 아니라 Unity 게임 코드를 검수했다. 전체 컴파일 기준선 뒤 저장/장비/성장, 대화/UI 입력, 맵 전환/동료 수명, 최근 카메라/피격/음향의 중단 경계를 검토했다. 기존 dirty 변경은 보존하고 확인된 결함5개와 오래된 테스트 호출1개에만 범위를 제한했다.

- AtomicSaveStorage: 유효 `.tmp`만 남은 복구 상태에서 다음 쓰기 실패가 유일한 복구본을 삭제하던 경로를 수정했다. Save 내부에서만 먼저 보존하며 Load·스키마·미래 버전/정상 Backup 보호는 유지한다.
- DialogueUI/Manager: 독립 저장/불러오기 prompt만 선택 단축키를 끄고 X 취소의 Update 순서 의존성을 제거했다. 일반 이야기 단축키는 유지한다. 예상 밖 일반 패널 Disable/Destroy도 source가 일치하는 재생을 취소한다.
- PlayerController: 선제공격 코루틴/실행 세대/상태 소유권의 공통 종료 경로를 추가해 비활성화 뒤 Cutscene 고착과 이전 완료의 새 상태 침범을 막는다. 성공 전투 진입은 기존 인계를 유지한다.
- MapTransitionService: 목적 Room과 이미 적용한 실제 도착 좌표로 문/마커 억제를 제한한다. 이전 비활성 Room의 같은 Spawn ID를 전역 재검색하지 않는다. RegionEntryCoordinatorTests의 오래된 private 2인자 호출은 공개 완료 API로 교체했다.

신규 회귀는 기존 Core/Dialogue/Overworld Editor 테스트 파일에 넣었다. 새 Inspector 연결, 자산/씬/프리팹/DB/저장 스키마/시나리오 문법 변경은 없다. 새 상시 Update 검색이나 GPU 작업도 추가하지 않았다. ## 최신 후속 · 화면 배율 펌핑과 픽셀 격자 복구

이전 HUD 시야 보정이 이동·홉마다 Lens를 즉시 바꿔 확대·축소를 만들었고, 연속 줌이 native PP 보정 반환값을 버려 분수 배율을 출력했다. 실제 패키지에서 Brain 블렌드도 vcam Finalize 뒤 Lens를 다시 보간함을 확인했다. 기존 Fit 재현은 한 프레임 Lens차0.283464/원본픽셀1.76→1.54배였다.

전투 시작에 HUD 안전영역을 확보하고 PP 허용 Lens로 올림해 session 동안 고정한다. 기본은PPU32/ref640×480의7.5/원본1배, 최소 요청3.75다. 중심만 보정하며 큰 배치는 경고한다. 기본 PP 확장을 더 이상 끄지 않고 Body/Finalize 반환값·최종XY격자·Dutch0·Brain 블렌드 후 출력 Lens 보정을 적용한다. Hold Lens는 블렌드보다 우선한다. 명령 Release와 전투 정책 owner 수명을 분리해 복귀 완료의 한 프레임 공백을 제거했다. 임시 HUD 숨김/Pause에서도 정책과 배율을 유지하고 중심 보정만 생략한다. PP 모드/기준 변경은 고정값을 재계산한다.

새 `CameraPixelGridPolicy.cs`/Editor테스트와meta, 기존 `BattleCameraViewportFraming.cs`의 FitAtFixedSize, CameraController.BattleViewport/BattleMotion/본체 disable 경계, CinemachineContinuousPixelZoom, 카메라 회귀를 수정했다. UI/피해/입력/전조 시계/저장/새 GPU패스는 변경하지 않았으며 이번 후속에서는 씬·프리팹 직렬화 변경이 없다. 전체 CLI447/370소스 오류0(경고225/0), 관리형52사례/73,689단언, 메타1,555개 검사 통과. 카메라 엔진 경로는 회귀 소스를 컴파일했을 뿐 재생하지 않았다. Unity Play/Refresh/Reimport/씬 저장·GPU·실기기·커밋/push 없음.

[규칙·조정 위치·검증 한계](yjlim/feedback/2026-10-23-camera-pixel-stability.md). 임의의 부드러운 확대·회전과 원본 픽셀 격자 보존은 동시 보장하지 않는다. 기존 UI 정수 배율/Point/Windowbox/RenderScale1은 유지한다. 기준 해상도 미만 축소·의도한 화면 왜곡·Sprite 자체 회전/비정수 크기는 별개다.

하네스 교훈: 정적 Fit 경계 검사만으로 시간축 배율 안정성이나 렌더 최종값을 검증할 수 없다. 이동·홉·복귀 연속 프레임과 Body→Finalize→Brain→URP 순서를 함께 검사한다. 관리형 Unity 대체 타입에 Random이 없어서 System/Unity 모호성이 하네스에서는 드러나지 않았고 전체 Editor CLI에서 발견되어 System.Random으로 명확화했다. Windows rg 경로에 폴더 와일드카드를 직접 넣거나 파일 위치를 추측하지 말고 rg --files로 찾은 실제 경로를 쓴다. 전역 yjlim 메모리 경로에는 쓰지 않았다.

## 이전 후속 · 전투 카메라 거리와 UI 가림 (Lens 정책은 위 기록으로 대체)

## 변경 요약

### 방에 넣는 안개·비 샘플

- `Assets/_Game/Content/Maps/Shared/Weather/WeatherSample.prefab`을 추가했다. 기존 씬에는 자동 배치하지 않았다.
- `WeatherSample`은 안개/비 독립 토글, 로컬 적용 영역, 타깃, 색·반경·밀도·속도와 그림3개 교체 슬롯을 제공한다. Odin 한글 라벨과 선택 Gizmo를 사용한다.
- 플레이어가 영역 안에 있을 때만 작은 원형 안개 구멍을 만든다. 명시적 타깃 또는 활성화 시 같은 씬 플레이어1회 탐색, 임시 플레이어블 변경은 `SetTarget`으로 연결한다.
- 비는 바닥 착지점을 먼저 고르고 `시작점=착지점-속도×수명`으로 역산한다. 충돌·중력·Noise·3D Ground 없이 Death sub-emitter가 물튀김을 만든다. 각 ParticleSystem 최대512, 프레임 생성64 상한이다.
- Renderer/입자/개별 재질/임시 도형을 최초 생성 후 재사용하고 disable에 입자를 지우며 destroy에 소유 자원을 해제한다. 매 프레임 전역 탐색이나 별도 RT/카메라/후처리는 없다.

### 창가부터 시작·고정 주인공

- Opening의 국가4컷과 '그리고 현재' 자막을 제거해 창가1페이지부터 시작한다. 창가 크기/반복·열차 주행음·객실 도착·임시3초 사건·후미 공개는 유지했다. 새 기계 수리 장면은 아직 만들지 않았다.
- IntroManager의 주행음 페이지를0으로 조정하고 Two empire BGM 코드/프로필4필드를 제거했다. 원본 아트·음원·옛 미사용 대본은 삭제하지 않았다.
- `NameInputUI.cs/.meta`, 이름 전용5개 GameObject/22개 YAML문서와 DialogueManager 참조를 제거했다. 공용 DialogueCanvas와 Overworld/Cinematic/BattleNarration 패널은 보존했다.
- WIZZEL/한국어 위젤 정체성을 사용한다. 옛 `SaveData.playerName` 필드와 RequestName enum/안전한 건너뛰기는 형식 호환용으로 남겼다. 로드에서 임의 이름을 표시명으로 복원하지 않는다. 동료/NPC 데이터와 런타임 표시명 API는 바꾸지 않았다.

### 직접 피격 표시

- HP와 피해 확정은 그대로 즉시 처리하고, 생존한 직접 피격 대상 Animator만0.035초 멈춘 뒤 백색 표시·Hurt·기존 반동을 실행한다. 치명타격은 기존 사망 처리/페이드를 우선한다.
- 백색은 검은 외곽선도 흰색이 되는 전용 셰이더다. 캐릭터별 최초 복제한 재질의 참조만 잠시 연결하며 공유 원본 내용은 수정하지 않는다. 원본 geometry/frame/flip/Y정렬 그대로, 추가 Renderer/Draw는 없다.
- 외부 재질/Animator 소유권 변경, 새 모션, 연타, disable/destroy, 전투 모달 정지와 Tween 정리를 처리한다. 플래시 설정0에서는 백색 표시를 하지 않는다. 전역 timeScale·음악·UI를 멈추지 않는다.
- 독립 검토에서 레거시 화상/독/출혈이 TakePureDamage를 통해 직접 타격으로 오분류되는 경로를 찾았다. `TakeLegacyStatusDamage`로 기존 피해/무적 규칙은 유지하고 새 정지만 제외했다. 기존 누적 속성 이벤트/합계를 임의로 섞지 않는다.
- Enemy의 선호 스킬 애니메이션 경로도 SetBattleTrigger 공통 취소를 통과하도록 보완해 지연 Hurt가 새 스킬을 덮지 않게 했다.
- 초기 overlay order+1 구현은 같은 order의 Y가림을 뚫을 수 있어 폐기했다. 새로운 SortingGroup을 강제하지 않고 원본 Renderer 재질 참조 방식으로 단순화했다.

수동3칸/자동99번/schema5/원자 교체/백업/수동 저장 성공 후 휴식 정책은 유지했다. 확정되지 않은 결함을 가정해 저장 구조를 재작성하지 않았으며 날씨 필드도 추가하지 않았다. 이름 로드 정책만 변경했다. 실제 사용자 저장 파일에 시험 읽기·쓰기를 하지 않았다.

## 오버월드 동료 동행 · 후속 승인 구현

### 범위와 소유권

- 사용자 승인: 실제 파티의 기본 리더+동료2명, 설정으로 전체6명까지 표시. 실제 길 추종, 고정/대기/임시 이탈/표시, 경유점 개별 이동/재합류, 맵·전투 복구를 지원한다. 새 게임은 여전히 주인공 한 명이다.
- 순수 `OverworldFollowerTrail`은1024점 순환 버퍼/누적 거리/이진 탐색과 Epoch를 가진다. Actor는 거리 커서를 걷기 때문에 최신 리더 좌표로 직선 이동하지 않는다. 제자리 방향 전환은 새 점을 추가하지 않는다.
- `OverworldPartyFollowerController`는 실제 CharacterSaveData 객체·순서로 표시를 동기화한다. 동일 DB 테스트 동료를 ID로 합치지 않는다. CharacterData에 선택적 `OverworldVisualPrefab`을 추가했으며 표시 컴포넌트만 복사한다. 입력/충돌/태그/상호작용·전투 스크립트는 복제하지 않는다.
- `OverworldFollowerActor`는 Follow/Hold/Detached와 Visible, 자기 DOTween 명령/세대를 소유한다. Follow 재개는 실제 보관 경로 위에서만 가능하며 실패하면 자동 순간 이동하지 않는다. Gather는 암전·도착용 명시 재배치이고 실제 파티 이탈과 다르다.
- `PlayerController`의 시작/모드/위치복원/비활성화와 `MapTransitionService` 도착에 연결했다. 기존 BattleLab preview/전투 생성 플레이어를 제외하고 수동 부착 설정을 보존한다. 도착 시 EnsureFor로 Start 순서에 의존하지 않으며 같은 좌표 방 이동도 reset한다.
- SaveData·GlobalDataManager·BattleManager·카메라 구조는 이번 동료 기능으로 변경하지 않았다. 기존 앞선 작업의 미커밋 변경을 보존한다. 카메라 자동 그룹 줌이나 새 길찾기 시스템은 만들지 않았다.

### 시퀀스 제작 연결

- 기존 Scene Action Sequence에 `overworld.party.mode / visibility / move / gather`4개를 등록했다. 명시 서비스/계약/adapter를 사용하고 move의 path는 중간 경유점 뒤에 최종 x/y를 붙인다. 월드 좌표·유한 값·슬롯·시간·길이를 검증한다.

### 브라우저 게시 재개 점검

## 적 중심 정지–참격–짧은 돌파 후속
