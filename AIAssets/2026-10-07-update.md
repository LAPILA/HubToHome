# 2026-10-07 · 전조/후열 선택·장비/저장 경계

브랜치 `codex/gameplayEdit`, 커밋/푸시 없음. 기존 작업 트리 변경을 보존하고 아래 범위만 추가했습니다. 시나리오·컷씬·아트·씬·기존 프리팹/DB 자산은 수정하지 않았습니다.

## 의도와 구현

- 사용자 승인: 기본은 매 타격 전조. 공통 성공 구간에 표시/핑이 시작되고 먼저 뜨던 흐린 원거리/특수 준비 신호는 제거. 기존 근접 Z 0.40초 최소 보정, 기타 Z0.24/X0.34/C0.28, 늦은 입력0.06초 유지. 카메라 안정화 시점은 넓은 회피 구간을 유지.
- 전열 전체 사망 + 생존 후열: `BattleReserveChoiceUI`를 호스트 자식으로 한 번 생성/재사용. 계속(기본)/포기 선택 전에는 승계하지 않음. 취소는 기본 항목으로 이동. 계속은 기존0.5초 페이드/후열 진입, 포기는 후열 미활성화/패배/GameOver. 새 입력만 다음 단계로 허용, 세대 기반 취소/모달 입력 차단.
- 실험실 패배 시 평소 메뉴 복귀는 유지. 포기는 GameOver를 우선하고 지연된 실험실 메뉴 재개를 차단.
- EquipmentLoadoutService의 읽기 전용 장착 조회와 런타임 슬롯/캐릭터 제한 검증 통일. 명시적인 장착/해제 시 HasInitializedEquipment를 기록하여 프리팹 기본 장비가 덮어쓰지 않게 함.
- StatBlock null 상태 사전 보호, 비정상 기본 배율=1/비정상 보정 무시/음수 최종 배율=0. int 변환 포화, DEF0 허용. 장비의 정상 음수 보정은 보존.
- Odin 장비 정보/보정/제한 한글화, 속성 피해 배율과 상태 적용 배율 구분. 기존 PassiveEffectID/EquipReactionDialogueID는 실제 소비자가 없어 예약 필드로 명시. 기능을 구현했다고 주장하지 않음.
- SaveDataCodec의 비유한 좌표 encode/decode 거부로 정상 백업 복구 유도. 금액/플레이시간 음수0, 잘못된 방향Down. 장비가 올린 HP/AP를 저장 기본 상한으로 잘라내지 않음. 스키마 v4 유지.
- SaveManager는 활성 전투/후열 선택/불러오기 동안 저장 거부. SavePoint/AreaMarker는 실패를 전파하고 성공 효과·자동 저장 방문 완료를 실제 성공에만 적용. 관련 저장 지점 트윈은 소유자 비활성화/파괴 때 종료.

## 작업 절차 교훈

- 새 Unity C#은 생성된 csproj에 자동 포함되지 않아 초기 CLI 빌드가 CS0246. Unity 새로고침 대신 `Library/CodexChecks/CombatFoundationCompile.targets`를 CustomAfterMicrosoftCommonTargets로 지정해 신규 UI만 포함, 오류0 확인. 기존 생성 csproj/프로젝트 설정은 수정하지 않음.
- 여러 파일 apply_patch 직후 첫 파일의 새 검사2개가 중복 삽입되어 CS0111 확인. 도구 내부 원인은 미확정. 실제 선언을 읽어 자신이 추가한 중복만 단일 파일 패치로 제거하고 rg/전체 컴파일 확인. 패치 반환만으로 최종 파일 상태를 가정하지 않음.
- 탐색은 Unity 루트 및 관련 도메인에 한정한다. 바깥 outputs의 문서 변환 임시 폴더는 접근 거부가 있어 넓은 rg 대상에서 제외한다. Windows에서는 위치 인자의 `*Defense*` 대신 `-g '*Defense*.cs'` 사용.
- 전역 교훈 위치 `C:/Users/yjlim/.codex/memories`는 현 호스트에 없고 허용 쓰기 범위 밖이므로 이 저장소에 기록. 다른 사용자 프로필을 만들지 않음.
