# 2026-07-12 Update

## 작업

- 현재 구현된 상위 게임 아키텍처를 사람용 시각 자료로 정리했다.
- `Primary Mode`, `Action Director`, `Game Module`, `Presentation Service`, `Scenario Source`, `Battle Session State`, `Encounter Memory`, 기존 시스템 어댑터의 책임과 연결을 한 화면에서 확인할 수 있게 했다.
- `OverworldScene` 첫 진입에 같은 씬 기반 지하철 시네마틱을 추가했다. 별도 Scene 없이 오프스테이지 `OverworldCinematicStage`, 전용 Cinemachine Camera, DOTween 기반 `CinematicShotAsset`, 독립 Action Sequence를 사용한다.
- 시퀀스 메이커가 `BattleScenarioData` 외에 독립 `ActionSequenceAsset`을 선택해 YAML 미리보기, 검증, 저장, 안전한 런타임 에셋 반영을 할 수 있게 확장됐다.
- `SceneLoader.SceneRevealCompleted`와 `SceneActionSequenceTrigger`를 연결했다. Stage는 전역 로더의 검은 화면 아래에서 준비되고, 화면이 밝아진 뒤에만 시퀀스가 시작된다.

## 이유

- 시퀀스를 만들기 전에 어떤 레이어가 언제 실행을 소유하고, 어떤 상태가 모듈 전환을 넘어 유지되는지 빠르게 확인할 기준이 필요했다.
- 짧은 오버월드 전환마다 Scene을 나누지 않고도 카메라, 대상 이동, 페이드, 이후 게임플레이 카메라 복귀를 안전하게 제작할 기준이 필요했다.

## Sequence Maker 전면 개편 설계

### 작업

- 현재 3패널 Sequence Maker를 일반인과 AI가 함께 쓰는 공식 작업공간으로 재구성하는 `002-sequence-maker-workbench` 요구사항을 확정했다.
- 통합 탐색, 세로 블록 흐름, 타입 입력, 안정적인 Block ID, 실행 위치 표시, 안전 미리보기, Play Mode 실제 실행, 선택 블록 준비 실행을 설계했다.
- 사람은 Runtime Asset을 직접 다듬고 명시적으로 YAML에 저장하며, AI는 YAML을 중심으로 작업하는 양방향 저작 흐름을 확정했다.
- Action Library와 Trigger Library를 카테고리별 YAML 원본과 생성 Unity 에셋으로 관리하는 방향을 확정했다.
- 고정 `BattleEventType` 규칙을 Scenario Event ID와 Trigger Condition 조합으로 확장하고, Action Sequence는 유한한 흐름을 조율하며 지속적인 게임플레이는 Game Module이 소유하도록 경계를 확정했다.

## Sequence Input, Value Binding, Sequence Call

### 작업

- `ActionSequenceContractData.Inputs`에 재사용 시퀀스의 공개 입력 ID, 표시 이름, 설명, 타입, 필수 여부, 기본 JSON 값을 추가했다.
- YAML에서는 값 참조를 `${input.actor}` 형태로 읽고 쓰며, Runtime Asset에서는 `{"$bind":"input.actor"}` 구조로 보존한다.
- `ActionExecutionContext`에 부모 값을 읽을 수 있고 로컬 값으로 덮어쓸 수 있는 스코프를 추가했다. 반환 값은 복제해 부모 토큰이 외부에서 변경되지 않게 했다.
- `ActionDirector`가 어댑터 실행 직전에 모든 바인딩을 리터럴 JSON으로 해석한다. 기존 QTE, 대화, 카메라, 오디오 어댑터 API는 변경하지 않았다.
- `sequence.call` 어댑터, `IActionSequenceResolver`, 자식 입력 바인딩, 실패/취소 전달, 런타임 재귀 방어를 추가했다.
- `SequenceCallGraphValidator`가 저장 전 직접/간접 순환과 없는 대상 시퀀스를 Block ID 기준으로 보고한다.

### 검증

- Unity EditMode `ScenarioValueResolverTests`, `ActionSequenceSourceSyncTests`, `SequenceCallActionAdapterTests`, `SequenceCallGraphValidatorTests` 집중 실행 25/25 통과.
- Unity 컴파일 오류 없음. MCP 플러그인의 기존 disposed-client 로그만 확인됨.
- 기존 사용자 변경인 Marker prefab, `EditorBuildSettings.asset`, `.codex/`는 스테이징 대상에서 제외한다.

- `ActionCatalogContractCopy`로 모든 새 필드를 한 번에 복사하고 Odin 호환 화면의 수동 복사 코드를 제거했다.
