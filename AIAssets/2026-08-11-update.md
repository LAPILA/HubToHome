# 2026-08-11 Update

## 3+3 파티 웨이브 전투 구현

### 완료 내용

- 전투 편성의 앞 6명을 전열 최대 3명과 후열 최대 3명으로 분리했다.
- 후열은 전투 시작 때 Prefab 생성과 저장 데이터 적용을 끝낸 뒤 비활성 상태로 대기한다.
- 수동 교대, 교대 입력, 교대 UI는 추가하지 않았다.
- 현재 행동이 완전히 끝난 시점에 전열 생존자가 없으면 후열 전체를 같은 전투의 다음 전열로 활성화한다.
- 적 HP·상태·전투 세션은 유지하고, 이전 턴 큐를 버린 뒤 새 전열로 `TurnCalc`를 다시 수행한다.
- 적과 전열이 동시에 전멸하면 승리를 먼저 확정하고 후열을 불필요하게 투입하지 않는다.
- 파티 UI는 기존 3개 슬롯만 새 전열에 다시 연결한다.
- 심리스 전투의 Scene Player는 생성·파괴 대상에서 제외하고, 추가 생성한 파티원만 기존 정리 목록이 소유한다.
- 보상 후 런타임 데이터 재적용은 파티 index 대신 유일한 `CharacterDataID`로 찾는다. ID가 비었거나 중복이면 잘못된 캐릭터에 데이터를 덮지 않고 오류를 기록한다.

### F2 테스트 도구

- `Data > Prepare 6-Member Wave Party`: 전투 밖에서 현재 런타임 파티를 6명까지 채운다.
- Catalog에 서로 다른 캐릭터가 있으면 고유 캐릭터를 우선 사용한다.
- Catalog 인원이 부족하면 리더 데이터를 복제한다. 이 복제 인원은 같은 `CharacterDataID`를 사용하므로 웨이브 활성화와 UI 확인 전용이다.
- 이미 6명 이상이면 기존 파티를 삭제하거나 줄이지 않는다. 전투는 앞 6명만 사용한다.
- `Battle > Defeat Active Wave`: `PlayerActionSelect` 상태에서 현재 전열을 전투불능으로 만들고 실제 `CompleteAction()` 경계로 넘긴다.

## Unity Editor 상단 메뉴 통합

- 프로젝트 전용 최상단 메뉴 `HubToHome` 31개를 기존 `Hub To Home` 아래로 통합했다.
- 최종 상단 등록은 `Hub To Home` 40개이며 `오버월드`, `시나리오`, `Battle`, `Content` 등 기존 하위 구조는 유지한다.
- `GameObject/HubToHome` 컨텍스트 메뉴, `Create > HubToHome` CreateAssetMenu, `Library/HubToHome` 파일 경로는 서로 다른 계약이므로 변경하지 않았다.
- 현재 맵·시나리오 운영 문서를 새 상단 경로에 맞췄고, 코드에 존재하지 않는 Action/Trigger Library 사람용 재생성 메뉴 안내는 제거했다.
- Unity 6000.3.8f1 Editor에서 ScriptAssemblies 컴파일과 Domain Reload를 완료했고 C# 오류가 없음을 확인했다.

## 모바일 발열·CPU 정적 감사

- 실제 기기 측정 전 단계로 런타임 프레임 루프, VFX/풀, 오버월드 적, 모바일 URP 설정을 감사했다.
- 최우선 위험은 모바일에서도 240 FPS까지 저장 가능한 프레임 정책과, Player 기준 0.01초 간격으로 잔상을 생성하며 독립 GhostPool root를 정리하지 않는 `CharacterGhostTrail`이다.
- 다음 순위는 오버월드 적의 중복 Animator 파라미터 갱신·Always Animate, 무제한 DDOL VFX 풀, Mobile RP의 HDR/그림자/Post Processing이다.
- 3+3 후열은 비활성 대기 중 CPU 비용은 없고 메모리와 GhostTrail Awake side effect만 추가된다.
- 상세 근거와 기기 검증 절차는 `AIAssets/yjlim/feedback/2026-08-11-mobile-thermal-cpu-risk-audit.md`에 기록했다.
