# 2026-10-25 — 전투 상단 결과 기록

브랜치 `gameplayEdit`. 사용자가 추천 구성 적용을 승인했다. 기존 dirty 변경은 보존했으며 커밋·푸시·Unity Play/Refresh/재임포트·씬 저장·실제 사용자 저장 I/O는 하지 않았다.

## 변경 이유와 승인 범위

- 피격/저체력 자동 말풍선의 “칫…” 등은 제거하고, 이야기 대화와 다른 연출 말풍선은 보존한다.
- 중앙 상단은 행동별 피해 합산·HP/AP 회복과 손실·상태 부여/해제·행동 불가 이유를 표시한다. 일반 기록은 자동 종료하며 Z로 빨리 넘길 수 있다. 새 스턴/감정/저항 계산은 추가하지 않는다.
- 기존 `HandleDamageDealt`는 양수 피해의 상단 표시가 꺼져 있고 회복만 기록했다. 회복 이벤트도 아래 피격 말풍선 분기로 흘렀다. 이 자동 말풍선 호출과 중복 회복 기록을 제거했다. HP바/피해 숫자/방어 판정은 유지한다.

## 코드 구성

| 소유자 | 역할 |
| --- | --- |
| `UI/Runtime/BattleCombatLogPresenter.cs` | 실제 CharacterBase HP/AP 전후 차이와 상태 변화 관찰, 대상별 손실/회복 별도 합산, 기존 피해 배치 종료 시 요약 |
| `UI/Runtime/BattleCombatLogFormatter.cs` | 실제 이름·스킬/아이템의 중립 헤더와 결과 행, 상태 이름/색,4언어 키/대체 문구 |
| `BattleStatusTransitionTracker` | 기존 종류 비교를 재사용하고 해제 항목 조회2개 추가. 초기bind·누적량·기간 갱신을 새 부여로 오인하지 않음 |
| `BattleManager` / `IBattleCombatLogHost` | 표시용 행동 메타데이터와 중단/종료 전 수집기 해제 이벤트만 전달 |
| `BattleTurnQteModuleControllerService` | 유효 행동 알림, 기존 기절/빙결의 턴 건너뛰기 이유, 아이템 배치를 안내 대기 전에 닫기, 턴 시작 AP/장비효과 한 묶음 |
| `BattleUIController` | 실제 전투/파티/모듈 수명에 따라 관찰기 연결·정리. 피격/저체력 자동 대사 호출 제거 |
| `BattleNarrationMessage` / `BattleNarrationUI` | 기본false인 즉시 표시 옵션. 일반 결과는 전체를 바로 표시하고0.85초 유지, Z로 즉시 종료. 기존 이야기 안내의 타이핑/Z단계는 유지 |

연타50회도 대상 하나의 합계 한 행이다. 대상별 HP 손실/회복과 AP 손실/회복은 서로 상쇄하지 않는다. HP 상한 초과 회복이나 과잉 피해 대신 실제 변화량을 쓴다. 기존 OnDamageDealt/OnElementalDamage의 숫자를 다시 더하지 않는다. 이름이 같아도 실제 배우 인스턴스가 다르면 행을 합치지 않는다. 한 안내에 최대3대상 행을 넣고 추가 대상은 다음 안내로 넘긴다.

공격 중 Z를 결과 안내가 소비하지 않도록 현재 행동 배치가 닫힐 때만 결과를 보낸다. C 반격의 하위 배치가 먼저 닫혀도 바깥 적 공격이 끝나기 전에는 요약을 열지 않는다. 기존 중앙창은 여전히 안전 경계에서 읽기를 기다리는 방식이며, 실시간 비차단 토스트로 바꾼 것이 아니다.

상태 정리/중단 전에 관찰기를 먼저 폐기한다. 모듈 종료에서도 Clear보다 Suspend가 앞선다. 모듈 중단 상태의 HUD Disable→Enable은 관찰기를 재생성하지 않는다. 새 전투는 기준값부터 다시 바인딩하고 종료 정리를 상태 해제 안내로 출력하지 않는다. 기절의 자기 턴1회 건너뛰기는 기존 규칙이며, 기존 기절이 모든 방어를 차단한다고 설명하지 않는다.

## 데이터와 편집 영향

- `Assets/Resources/LocalizationTable.csv`에 `battle.log.*`30키·120문구 추가. 기존 프롤로그/번역 내용과 UTF-8 BOM을 보존했다. 고유명사·스킬/아이템 이름은 기존 데이터의 현지화 getter를 사용한다.
- Scene/Prefab/ScriptableObject/원본 아트/음원/저장 형식은 변경하지 않았다. 기존 생성 기록166개 해시가 모두 일치한다. Inspector 재연결이나 전체 생성기 실행은 필요 없다.

### 하네스 교훈

- PowerShell 생성 helper `Move`/`SCB`가 기존 별칭과 충돌해 의도한 생성 함수로 실행되지 않았다. 고유 `NewShowcase*` prefix로 바꿔 성공했다. Unicode 스마트 따옴표도 구문 오류를 내 ASCII 구문으로 교정했다. 코드 생성 함수/변수는 시스템 명령·별칭 이름을 재사용하지 않고, 파일 작업 전에 완성된 패치/대상 경로를 검증한다.
- 새 Accent Editor 테스트가 IReadOnlyList에 List.Exists를 호출해 CS1929가 났다. 생산 API를 변경하지 않고 명시 for 검사로 고쳤다. 다른 새 테스트의 NUnit 컬렉션 단언 오버로드도 CollectionAssert로 교정했다. 전체 CLI로 테스트 소스까지 컴파일해야 이런 차이를 잡을 수 있다.
- 추정한 BattleDelay/UIRuntimeGuard 경로는 틀렸다. `rg --files`/class 검색으로 실제 경로를 찾았다. 기존 Windows 검색 교훈을 재사용하며 같은 실패를 새 API 누락으로 오판하지 않는다. 전역 메모리 쓰기 제한은 앞서 확인한 상태이므로 여기 지속 기록으로 남긴다.
