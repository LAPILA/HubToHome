# 2026-10-27 동료 추종 미세 떨림 수정

사용자는 리더·배경이 아니라 따라오는 동료만 미세하게 흔들린다고 확인했다. [동행 실험실](../docs/overworld-follower-lab-guide.md)의 기존 경로 추종·관람·저장 격리를 유지하는 후속 수정이다.

## 확인과 변경

- 실제 Controller/Actor/Trail을 사용한 관리형 검사에서 일정 속도 이동의 멈춤·Walk/Idle 반복은 재현되지 않았다. 카메라 LateUpdate, 리더 Rigidbody2D 보간과 공용 Animator 설정은 유지했다.
- 기존 간격0.9는32PPU에서28.8픽셀이다. 60fps 직선의 상대 픽셀 모델에서 첫 네 동료는22초 동안470/704/704/586회 위치가1픽셀 교대했다. 간격만29픽셀로 바꾸면 float 커서 누적 오차 때문에54~58회가 남았다.
- `OverworldPartyFollowerController.EffectiveSpacing`은 입력 간격을 기존 `GameConfigPolicy.WorldPixelsPerUnit`에 맞춘다. `_spacing` 직렬화 필드는 보존하며0.9는29/32로 적용한다. 실제 월드 좌표나 경로 모서리를 반올림하지 않는다.
- `OverworldFollowerActor.TickFollow`는 이동 예산과 목표 사이의 float 오차만 닫는다. 누적 거리의 float 정밀도를 반영하되 보정은 원본1픽셀 이하로 제한한다. 예산0이나 역방향에서는 전진하지 않는다. 별도 지연·Lerp·물리 객체·카메라 변경은 없다.

## 검증 범위

- 전체 Runtime500/Editor400소스 컴파일 오류0. 기존 Runtime 경고229개는 남아 있다.
- 기존 추종 제어 검사10그룹110단언, Trail15사례11,194단언 통과. 기존10,000회 정상Tick/경로 연산 검사에서 관리형 할당0을 유지한다.
- 실제 생산 코드를 사용하는 관리형 모델: 동료5명,30/60/120fps·45/90가변 프레임, 직선24초에서 상대 픽셀 교대0. 누적 커서4096/8192, 양·음방향의16추가사례259,488단언 통과.
- Unity 회귀 `OverworldFollowerMotionTests`11사례 추가(간격4·이동6·정지1). 초기 수정본9사례는 열린 편집기에서 비저장 임시 객체로 직접 호출해 통과했다. 최종 긴 거리2사례는 컴파일/관리형 모델 검사이며 Unity Test Runner 결과로 표현하지 않는다. Play/열린 씬/dirty 상태는 변경하지 않았다.
- GPU 영상·대각선/코너 체감·실기기FPS는 미검증이다. 정수 경로 간격이 모든 방향의XY 픽셀 간격까지 정수로 만든다는 의미는 아니다. 실제 재생에서 남는 떨림은 화면 영상과 함께 다시 구분한다.

## 하네스 교훈

- Unity의 `internal` API는 기본 Editor 어셈블리에서 직접 호출할 수 없어 새 검사 첫 컴파일이 실패했다. 공개 API를 넓히지 않고 테스트 전용 캐시된 반사 delegate로 연결하여 Runtime/Editor 오류0을 확인했다.
- 고정0.0001 오차만으로는 누적 거리1024이상의 float 정밀도 손실을 막지 못했다. 제한된 상대 오차와4096/8192거리 회귀를 추가했다.
- `Math.Round(ToEven)`은 정확한 반픽셀에서 홀수 픽셀 간격의 양 끝을 서로 반대로 반올림한다. 실제 월드 간격이 정확한 경우까지 떨림으로 오판하지 않도록 평행 이동 불변의 `floor(px+0.5)` 모델과ToEven 진단을 분리했다. GPU 검증을 대신하지 않는다.
- 제한 실행의 LOCALAPPDATA는 실제 사용자 Unity 로그 위치와 달랐고 localhost 연결도 차단됐다. 명시된 실제 로그 경로와 승인된 로컬 호출로 조회했다. Unity 연결 포트는 재컴파일 뒤 바뀔 수 있으므로 기본8090/이전 포트를 고정하지 않고 최신 시작 로그에서 읽는다. 계정·권한 그룹·인증정보는 조회하지 않았다.

## 넓은 간격·순차 출발·전시실 관람 후속

사용자가 넓은 간격과 차례로 출발하는 구성을 승인했다. 첨부 Reddit의 과거 위치 기록 아이디어를 참고하되 실제 DELTARUNE 내부 구현과 같다고 주장하지 않는다. 기존 고정 크기 거리 경로를 유지하며 시간 지연 입력 복사는 사용하지 않는다.

### 원인과 수정

- 기존 동료5명은 정지 후 같은 첫 프레임에 다시 움직였다. 기본 간격을1.5(48픽셀), 재출발 여유를0.5(16픽셀)로 설정하고 앞 Follow 동료의 실제 경로 커서를 목표로 사용한다. 앞 동료가 관람/이탈/개별 이동 중이면 리더 기준 슬롯 목표로 전환해 뒤쪽을 막지 않는다.
- 따라잡기 배율은 남은 거리에 비례해 연속적으로 증가하며 기본 상한1.5를 유지한다. 매 프레임 배열 생성·전역 탐색·물리 충돌을 추가하지 않았다. 수동으로 저장한 기존 `_spacing`은 덮어쓰지 않는다.
- 자연 정지와 Animator의 정지 표시를 분리했다. 메뉴/대화 정지, 이동 예산0, 명시 Hold→Follow 복귀에서는 재출발 문턱 때문에 작은 잔여 경로에 멈추지 않는다. 별도 코드 검토에서 이 경계 조건을 보완하고 최종 승인받았다.
- 전시실의 기존 출발 영역은 x−5.95~−4.45, y−1.5~1.5로 좁았다. 리더뿐 아니라 해당 동료도 지나야 해서 위쪽 우회/중간 정지/오른쪽 입장에서 관람이 시작되지 않았다. 두 `Departure Zone`을 방 중심22×12로 바꾸어 기본 양쪽 입장부터 관람하도록 했다. 자동 길찾기나 장애물 관통을 추가하지 않았으며 실제 출발점→경유점 충돌 검사는 유지한다.
- 관람 성공 검사에 마지막 `Out 2` 좌표·빈 `LastError`·같은 위치의 상호작용 대상을 추가했다. 실패 후 Hold로 복구된 상황을 정상 관람 완료로 오인하지 않는다. 한·영·일·중 안내와 생성기의 기본 문구도 입장 조건으로 맞췄다.

### 변경 파일과 직렬화 영향

- Runtime: `OverworldPartyFollowerController.cs`, `OverworldFollowerActor.cs`.
- Editor 검사: `OverworldFollowerMotionTests.cs`, `OverworldPartyFollowerTests.cs`, `OverworldFollowerLabIntegrationTests.cs`. 폴리라인 검사의 한 프레임 예산은0.3→0.4로 변경했다. 새 간격/속도 곡선의0.3은 모서리에 정확히 도착하므로, 모서리 이후 수직 이동까지 확인하려는 기존 의도를 유지한 조정이다.
- 작성 데이터: `OverworldFollowerLabRoomBuilder.cs`, `OverworldFollowerLabBuilder.cs`, `Room_FollowerLab_Exhibition.prefab`, `ExhibitionGuide.asset`, `LocalizationTable.csv`.
- Prefab은 두 출발 영역의 로컬 위치·BoxCollider2D 크기만 변경했다. GUID·관람 슬롯·대사·경유점 참조와 Scene은 유지한다. 기존 콘텐츠 생성기는 재실행하지 않았다. CSV의 기존 UTF-8 BOM도 보존했다.
- 제작 가이드2개, 이 기록/색인/브리핑/TODO/Overworld 규칙/실험실 피드백과 승인 [설계](../docs/superpowers/specs/2026-10-27-follower-spacing-observation-design.md)·[실행 계획](../docs/superpowers/plans/2026-10-27-follower-spacing-observation.md)을 갱신했다.

### 검증과 남은 범위

- 전체 Runtime500/Editor400 소스 컴파일 오류0. 기존 Runtime 경고229개는 남아 있다.
- 실제 생산 코드의 관리형 재출발 검사는 변경 전 `[1,1,1,1,1]` 프레임으로 실패했고 수정 후 `[4,7,10,13,16]`으로 순차 이동한다. 여유 거리0에서는 기존 동시 출발이다. 코너480프레임, Hold 선행자, 일시 정지/0예산/재합류 잔여 거리 포함 **4,833단언 통과**. 이 프레임 수는 하네스 조건의 결과이며 실제 고정 시간 지연이 아니다.
- 기존 Controller10그룹110단언, Trail15사례11,194단언, 관람24사례87단언, 세션16사례71단언 통과. Trail 기록/샘플/검색10,000회 관리형 추가 할당0바이트.
- 실제 전시실 Prefab의15개 장애물 AABB와 리더 몸체 크기를 반영한6개 입장/우회/중간정지 검사에서 동료4는(−1,1.4), 동료5는(3,−2)에 도착하고 LastError가 비어 있다. 기본 좌/우 입구에서 리더가 움직이지 않아도 관람한다. 이 검사는 관리형 기하 모델이며 네이티브 Physics2D 결과를 대신하지 않는다.
- Unity용 회귀도 확장해 컴파일했지만 열린 Editor에 최신 테스트가 아직 반영되지 않아 강제 Refresh/Play는 하지 않았다. **이번 수정 후 Native Play·GPU 화면·수동 대화·실기기 성능은 미검증**이다. 과거42/42 통과를 이번 수정의 검증으로 재사용하지 않는다.
- 임의 순간이동 지점/소품 재배치까지 모든 출발 경로가 안전한 것은 아니다. 통로가 막히면 기존 명시 오류와 안전 Hold가 적용된다.

### 후속 하네스 교훈

- 관람의 `IsHolding`만 검사하면 실패 복구도 통과한다. 실제 마지막 경유점 좌표와 `LastError`, 상호작용 대상 위치를 함께 확인한다. 일반 입구에서 리더가 정지하는 사례를 정상 횡단 사례와 별도로 둔다.
- 추종 시작 임계값을 Animator의 `IsMoving`에 직접 연결하면 메뉴 정지 후 작은 잔여 거리에서 멈춘다. 이동 의도를 따로 보존하고 명시 Follow 복귀·0예산·표시만 정지를 각각 검사한다.

브랜치 `gameplayEdit`. 커밋·푸시 없음. 사용자 기존 변경과 열린 씬 상태는 보존했다.
