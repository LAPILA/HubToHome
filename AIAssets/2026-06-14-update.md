## [2026-06-14 추가 구현 - audio/screen presentation runner 주입]

- Battle scenario context에서 `bgm.crossfade`와 `screen.fade`가 concrete runner service를 받을 수 있게 연결했습니다.
  - `AudioManagerActionRunner`: `IAudioActionRunner` 구현체입니다. `AudioManager.Instance`를 통해 BGM을 재생/크로스페이드하고, duration 동안 sequence 진행을 기다립니다.
  - `ResourcesAudioClipResolver`: BGM clip fallback resolver입니다. scenario 매핑에 없는 clip ID/path를 `Resources.Load<AudioClip>`로 해석합니다.
  - `ScreenTransitionRunner`: `IScreenTransitionRunner` 구현체입니다. 씬/프리팹을 수정하지 않고 런타임 full-screen overlay를 생성해 화면을 덮거나 다시 밝힙니다.
  - `BattleScenarioActionContextFactory`: 선택적으로 audio/screen runner를 context service에 등록할 수 있게 확장했습니다.
  - `BattleManager`: battle scenario context 생성 시 `AudioManagerActionRunner`, `ScreenTransitionRunner`를 주입합니다.
- 의도:
  - 사용자가 예시로 든 “대사 이후 BGM 변경, 화면 fade out/in, 모듈 전환” 시퀀스를 `BattleManager` 분기 없이 Action Sequence로 실행할 수 있게 하기 위한 presentation service 연결입니다.
- 한계:
  - 이 시점에는 BGM clip ID가 아직 Scenario Source 오디오 참조 테이블이 아니라 `Resources` 기반이었습니다. 이후 추가 구현으로 `BattleScenarioData.AudioClips` / Scenario Source `audioClips` 매핑이 추가되어 scenario 매핑을 먼저 쓰고 `Resources`는 fallback으로만 사용합니다.
  - 화면 overlay는 런타임 생성 방식이므로 씬 저장은 필요 없지만, 실제 UI sorting/카메라 표시와 함께 수동 검증이 필요합니다.
- 검증:

## [분석 결론]

- 기존 전투/대화/UI/스킬 시스템을 즉시 갈아엎는 방식은 권장하지 않습니다.
