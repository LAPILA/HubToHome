## 방어 반응 종료·피격 팝 연출 보정

- 기본 적 공격은 QTE 결과를 받은 뒤 `EnemyAttackVisualDuration`만큼 추가로 기다리지 않고 즉시 방어 결과를 적용하도록 정리했다. 성공 패링이 입력 결과와 같은 프레임에 재생된다.
- `Parry`와 `BattleMove`가 재생 중일 때 다음 턴 리셋이 `BattleIdle`로 먼저 덮어쓰지 않도록 Animator 상태 또는 방어 트윈 종료를 기다린 뒤 방어 리액션을 정리한다. 스킬의 `Action_DefenseWindow`에도 같은 종료 대기를 적용했다.
- 부분 방어는 `Parry`를 잘못 재생하지 않고, 실제 피해가 발생하면 기존 `Hurt` 애니메이션을 유지한다. 별도 `Hit` 트리거가 없으므로 `Hurt`를 피격 애니메이션으로 사용한다.
- 플레이어와 적 피격 연출은 기존 흔들림 대신 흰색 플래시와 DOTween 기반 위쪽 팝·원위치 복귀로 통일했다. 전투 중에는 전투 앵커를 기준으로 위치 누적을 막고, 화면 흔들림 접근성 배율 0에서는 팝 높이도 0이 된다.
- `TakeDamage()`가 이미 재생하는 피격 연출 뒤에 `PlayHurtEffect()`를 중복 호출하던 경로를 제거했다.
- 피격 색상 프리팹 기본값을 흰색으로 맞췄다.
- QTE 결과 콜백에서 성공 패링·회피 연출을 충돌 시점에 즉시 시작하고, 후속 보상 처리에서는 같은 연출을 중복 호출하지 않도록 분리했다.
- 회피 이동 트윈 완료 콜백은 위치만 원위치로 고정하며 `BattleMove`를 먼저 끊지 않는다. 전투 모듈이 방어 반응 종료를 기다린 뒤 Idle을 요청한다.

## 2026-09-15 전투 QTE·공격 타이밍 재정리

### 확정 동작

- 적 공격은 `QTEManager.StartBattleDefenseWindow()`만 사용한다. 이 경로는 방어 판정만 공유하고 `DefenseQTEUI` 패널·일반 방어 이벤트를 열거나 발행하지 않는다. 적 타임라인에 잘못 들어온 `Action_QTE`도 플레이어 스킬 전용으로 건너뛴다.
- 전투 중 `PlayerController`는 `BattleState.EnemyAction`에서 GameState의 이동 잠금과 관계없이 Z/X/C를 읽는다. 실제 공격이 연 방어창만 입력을 소비하고, 입력창 종료와 성공 모션 종료는 서로 분리된다.
- 기본 공격은 적 앞까지 이동한 뒤 추가 돌진·후미 이동 없이 준비 자세 → 제자리 공격 순서로 실행한다. 적 기본/광역 타격은 방어 결과 콜백 프레임에 공격 트리거·VFX·`TakeDamage`를 함께 시작한다.
- `Action_DefenseWindow`도 동일하게 준비 자세를 먼저 재생하고, 방어 결과가 확정된 프레임에 공격 트리거를 시작한다. 구형 `AttackAnimDelay`는 호환용 표시만 남기며 결과 후 피해를 늦추지 않는다.
- 모든 적 공격 경로에서 준비 자세를 보장한다. `EnemyCharacter.PlayAttackReady()`는 `BattleReady` → 레거시 `CrossCutReady` → `Telegraph` → `BattleIdle` 순으로 Animator 파라미터를 찾는다. 실제 공격에 쓰이는 `Skill` 트리거는 준비 자세의 대체값으로 사용하지 않는다. 방어창이 없는 레거시 `Action_PlayAnim`, `Action_Projectile`, `Action_SequentialMelee`도 중복되지 않게 준비 단계를 적용한다.
- 플레이어 스킬의 `Action_QTE`는 이동/애니메이션과 병행 실행한다. 피해·투사체 충돌·상태 적용 블록에서만 QTE 결과를 기다리므로 버튼 입력 동안 모션 전체가 정지하지 않는다.
- 저스트가드/회피의 입력 미리보기 트윈은 결과에 맞게 유지한다. 회피·점프는 이동 연출을 끝까지 보여주고, 패링/반격은 미리보기를 끊은 뒤 성공 모션으로 전환한다. 반격 플래시·펀치는 하나의 비스케일 DOTween 시퀀스로 수명 관리한다.

## 2026-09-15 방어 리액션 수명·입력 중복 보정

### 추가 확정 동작

- 타임라인형 적 스킬도 방어 결과를 `SkillContext`에 보관한다. `Action_Damage`, `Action_ApplyStatus`, `Action_Projectile`, `Action_SequentialMelee`, 그리고 타임라인 끝의 안전망이 결과 모션을 소비한 뒤에만 `ResetDefenseReactionLock()`을 호출한다. 따라서 `TakeDamage()`의 `Hurt`, 저스트가드 `Parry`, 회피/반격 트윈이 턴 종료의 전역 Idle 리셋에 잘리지 않는다.
- 방어창이 취소·중단되어 결과가 확정되지 않은 경우에는 `Action_DefenseWindow`의 `finally`에서 입력창과 미리보기 트윈을 즉시 복구한다. 확정된 경우에는 입력창만 닫고, 리액션 소비자가 시각 수명을 소유한다.
- `PlayerController`는 `EnemyAction`뿐 아니라 적 스킬 타임라인이 실행되는 `ActionExecute`에서도 Z/X/C를 캡처한다. 입력을 버퍼링한 컨트롤러의 동일 프레임 미리보기는 `QTEManager`가 다시 재생하지 않아 회피·점프 트윈 재시작을 막는다.
- 일반 플레이어 기본 공격의 공격 이펙트에서 위치 펀치를 제거했다. 타겟 앞 이동 → 준비 자세 → 제자리 공격만 수행하며 공격 중 추가 돌진이 없다. 타격·복귀 지연은 `WaitForSecondsRealtime`으로 통일했다.
- 적 방어창 시작 시 잔류한 방어 QTE 패널을 즉시 닫아, 적 공격에서 패널이 보이지 않는 계약을 보강했다.

## 2026-09-15 적 공격 선입력·스킬 QTE 충돌 보정

### 추가 확정 동작

- `PlayerController`는 적 행동의 접근·전조·실행 구간에서 Z/X/C를 계속 버퍼링한다. 방어 실행이 늦게 열려도 버퍼 입력을 소비하며, 방어창 시작 이전 입력은 타이밍 성공으로 소급하지 않는다. 따라서 미리 누른 Z는 충돌 시점까지 유지할 때만 일반 가드가 되고, 너무 이른 X/C는 성공 판정을 얻지 않는다.
- 플레이어 스킬의 `Action_QTE`가 실행 중이면 전투 방어 버퍼 수집을 일시적으로 양보한다. 같은 Z/X/C 입력이 스킬 QTE와 회피/패링 미리보기에 동시에 들어가는 교차 실행을 차단했다.
- 적 행동이 끝날 때 모든 전열의 방어 입력 버퍼를 비운다. 방어창이 없는 상태 부여 스킬에서 누른 키가 다음 적 공격으로 넘어가지 않으며, 전투 진입·이탈·씬 전환에도 같은 정리를 수행한다.
- `PlayerCharacter`의 실제 `TakeDamage()` 피격 팝 트윈 상태를 `PlayerController`가 관찰한다. 방어 리액션 정리는 Animator의 Hurt 상태뿐 아니라 이 트윈이 끝난 뒤에 수행하므로 피해 적용 프레임과 피격 모션이 분리되지 않는다.
