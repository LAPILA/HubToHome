# 2026-10-11 설정 저장과 진행도 저장 및 장비 안정화

브랜치 `codex/gameplayEdit`. 기존 변경을 유지했으며 커밋/푸시는 수행하지 않았다. 작업 전 백업은 `Library/CodexChecks/SettingsSaveEquipment/Original`에 있다.

## 변경

환경 설정은 즉시 적용하지만 디스크 기록을 0.5초 묶음 처리한다. 닫기·앱 일시 중지·종료 시 기록하며 저장 실패가 모달 해제를 막지 않는다. 설정창은 닫기 애니메이션까지 입력을 차단하고 소유 상태만 복구한다. 라벨과 값의 너비를 분리하고 데스크톱 해상도 정책을 공용화했다.

진행도는 저장 지점 확인창의 수동 0~2와 이벤트 자동 99로 분리했다. 자동 요청은 기존 GlobalDataManager의 코루틴으로 탐색 복귀를 기다리며 새 게임/로드에서 취소된다. 별도 전역 싱글톤이나 업데이트 검색 루프는 만들지 않았다. 저장은 원본을 바꾸지 않는 복사본으로 직렬화하고 필드 좌표 저장 시 이전 입구 ID를 비운다. 미래 버전 덮어쓰기와 백업 선삭제를 막았다. 타이틀은 기존 대화 패널을 재사용해 기록 선택/실패 안내를 제공한다.

장비 조회의 데이터 변경을 제거하고 파티 소속·수량·전투 중 변경 검사를 강화했다. 착용분 제거를 막으며 HP/AP는 현재량 유지와 상한 제한을 적용한다. 저항 규칙과 6슬롯, 미연결 예약 패시브는 변경하지 않았다.

## 검증

- 순수 관리형 검사 155/155 통과: 기존 Codec/Atomic 테스트, 실제 파일 교체·백업 복구, 실패 시 불변성, 슬롯 분리, 자동 요청 합치기/취소/전투·대화·씬 대기, 장비 교체 반복/수량/상한, 플랫폼 정책.
- 관리형 검사는 엔진 객체·DB·성장 공급자를 대체했다. Unity 수명과 실제 씬 배치는 통합 검증하지 않았다.
- CLI Runtime/Editor 컴파일 오류 0개. 기존 ConfigPanelUI의 직렬화 내부 필드 CS0649 두 개가 남는다. 클린 의존성 빌드에서 외부 Febucci 경고 한 개가 추가될 수 있다.
- Unity Play/EditMode/Refresh/Reimport, 씬/프리팹 저장, 외부 플러그인 변경 없음.

## 연결과 남은 확인

기존 저장 지점에는 추가 연결이 없다. 확인창에는 기존 DialogueManager 오버월드 패널이 필요하다. 자동 저장할 이벤트는 제작자가 ProgressSaveTrigger에 지정한다. 지정하지 않은 모든 보스/컷씬에 자동 저장하지 않는다. 설정과 선택창의 실제 글자/배치, 모바일 중단/재개, Switch 플랫폼 저장 백엔드는 기기 검증 대상이다.

## 후속 코드 학습실 정리

사용자 요청에 따라 docs/study에 학습 원고 19개, 폴더/날짜별 색인, 영역별 코드 색인 12개와 CSV 3개, Notion 배치 명세를 추가했다. 현재 자체 C# 686개(테스트 분류 204개), Scripts 포함 디렉터리 96개, 날짜별 업데이트 28개를 목록화했다. 핵심 경로의 자료구조·알고리즘·패턴과 실패 경계를 해설했으며 모든 줄 리뷰나 사용자 학습 완료를 주장하지 않는다. 게임 코드·씬·프리팹 변경 및 Unity 실행 없음. [학습실](../docs/study/README.md), [게시 상태와 재개 방법](yjlim/feedback/2026-10-11-code-study-portal.md).

초기에는 지정 Notion 페이지가 연결 도구에서 NOT_FOUND, 브라우저에서 미로그인 편집 제한으로 표시됐다. 사용자 로그인 후 정확한 페이지를 브라우저로 편집해 **HUB TO HOME · 개발 학습실**로 게시했다. Markdown 62개·CSV 4개 패키지를 네이티브 페이지·데이터베이스로 가져왔으며, 기능별 원고 19편·코드 색인 12편·개발 기록 28편의 본문을 다시 열어 확인했다. 홈 내비게이션, 표, 코드, Mermaid, 체크리스트, 학습 DB의 표/보드와 기록 양식을 구성했다. 게임 코드·씬·공유 권한은 변경하지 않았다. 실제 URL과 초기 계획과의 차이는 docs/study/notion-publication.json에 기록한다.

문서 편집 하네스 교훈: 동일 파일을 한 패치의 별도 Update 두 개로 지정하면 검증에서 거절됐다. 미적용 확인 후 한 Update 아래 여러 hunk로 묶어 성공했다. 상세는 위 재개 안내에 기록했다.

문서 검증 결과: Markdown 34개 UTF-8/코드 펜스 검사, 로컬 링크 871개, C# 색인 686개 실제 파일 일치, 폴더 96행, 개발 기록 28행, 학습 원고 19개 JSON 참조를 확인했고 오류 0개였다. 기존 AIAssets 변경의 diff --check도 통과했다.
