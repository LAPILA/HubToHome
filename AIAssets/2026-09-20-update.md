## 최신: 파괴된 Image 트윈 접근 수정 / 전투 UI 리팩토링

- 사용자 스택 `DOTweenModuleUI.DOColor(Image)`의 setter에 맞춰 프로젝트 전체 호출을 조사했다. 해당 Image overload는 파티 슬롯 초상화·HP 점멸과 전투 메뉴 선택 색상 5곳이었다. 생성 트윈의 숨김/파괴 정리가 누락됐고, 메뉴의 3개 DelayedCall도 소유자가 없어 닫힌 UI를 다시 갱신할 수 있었다. 실제 어느 Image가 발생시켰는지는 런타임 재현 없이 확정하지 않는다.
- `PartySlotUI`를 기존 BattleUIController 파일에서 별도 파일로 분리했다. 타입/네임스페이스/직렬화 필드/MP→AP 별칭은 유지한다. 7종 핸들을 직접 소유하고 Hide/Init/owner 종료에 Kill(false), 최신 HP/AP 표시 확정, 펀치 기준점 복구, 중복 Highlight 억제를 수행한다. Image/TMP를 생성 당시 캡처하고 getter/setter/종료 콜백에서 Unity null 검사를 한다.
- `BattleMenuUI`는 버튼 Image 캐시, 개별 색상/펀치 핸들, 메뉴 이동, 단일 지연 입력 복귀 핸들로 정리했다. Hide/Disable/Destroy에서 공통 해제하고 메뉴 Y/버튼 Scale을 복원한다. DOKill(true)로 이전 완료 콜백을 실행하던 경로와 비활성 메뉴 콜백/입력, 누락 버튼 탐색을 방어한다.
- `BattleUIController`는 실제 구독한 BattleManager를 보관하고 OnEnable/Start 중복 구독 방지, OnDisable/Destroy 해제를 수행한다. 슬롯/패널/플래시/흔들림 핸들을 종료에서 정리하고 커스텀 tweenTarget 플래시 교체도 핸들 기준으로 수행한다.

## 후속: 전조와 대응 판정 구간 동기화

사용자가 전조 중 입력해도 피해를 받는다고 보고함. 전조는 독립적인 0.3초 설정이었지만 실제 성공 구간은 Z 0.12/X 0.22/C 0.18초여서 표시 초반 입력이 실패했음. 전조 전에 누른 첫 입력이 확정되어 이후 정확한 입력도 무시되는 문제도 있었음. 사용자가 **전조 전 입력 제외, 전조 후 새 입력 판정**을 선택함.

- `DefenseJudgementPolicy`가 실제 요청의 난이도/길이 보정 후 성공 구간과 공통 전조 구간을 계산. 일반은 저스트가드, 회피 전용은 회피, 특수는 X/C 공통 구간. 표시 중 허용된 대응은 성공할 수 있게 함.
- `QTEManager`는 같은 시각으로 전조를 표시하고 입력 확정을 시작. 조기 입력은 소비하되 시도는 확정하지 않아 이후 새 입력을 받음. 이미 확정한 입력은 재입력으로 바꾸지 않음. 미리 유지한 Z는 일반 방어, C의 공격 제한 및 보상은 유지.
- 전조가 연결된 일반 공격은 X도 전조 이후 눌러야 하므로 더 이른 X 구간을 인정하지 않음. 전조 없는 호출은 기존 정책 유지. 스킬 블록은 프리팹 미설정 시 null 콜백을 전달함.
- `ImpactCueLeadTime`은 직렬화/API 호환만 유지하고 숨김/무시. 제작기에서 별도 시간을 넣지 않으며 검증기도 해당 구형 값 검사를 제거. GUID/씬/스킬 자산을 다시 생성할 필요 없음.
- 정확히 열린 시각과 매우 짧은 공격에서 float 뺄셈 오차로 실패하던 경계도 절대 시각 비교로 일치시킴.

수정 파일: `DefenseJudgementPolicy.cs`, `QTEManager.cs`, `SkillActionBlocks.cs`, `EnemyAttackAuthoring.cs`, `BunnySlimeLabContentBuilder.cs`, `DefenseJudgementPolicyTests.cs` 및 계약/사용 문서. 전조 전·후 입력과 경계/난이도/짧은 공격 회귀 검사 추가. 전조 프리팹의 Ping Clip은 계속 미정/null.

검증: 실제 정책 소스를 링크한 독립 C# 계산으로 기존 0.3초 표시 초반 Z/X/C 실패 3/3 재현. 수정 후 7종 공격 제한 × 난이도/길이/절대 시각/허용 입력/구간 내 위치 조합 7,425건 통과. 조기 입력 후 재시도, 경계값, 확정 후 재입력 차단, 유지 가드, 특수공격 Z 금지도 확인. Unity 테스트나 플레이가 아닌 순수 판정 계산 검증임. Runtime/Editor 직렬 빌드 확인; 실제 영상/입력 체감은 사용자 확인 필요. 임시 검증 소스는 Temp 아래에서만 사용했으며 지속 회귀 항목은 기존 테스트 파일에 추가함.
