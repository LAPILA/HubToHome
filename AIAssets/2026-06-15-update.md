## [변경]

- YAML 편집기/라운드트립 UI 작업은 후순위로 밀고, 런타임 아키텍처 진행으로 우선순위를 되돌렸습니다.
- `IGameModuleActionRunner`에 `CurrentModuleId` 계약을 추가했습니다.
- `BattleManager`가 전투 시나리오 Action Context를 만들 때마다 새 `GameModuleActionRunner`를 만들지 않고, 전투 시작 시 생성한 battle-scoped runner를 재사용하도록 변경했습니다.
- `BattleScenarioActionContextFactory`는 runner의 `CurrentModuleId`가 있으면 `BattleScenarioData.OpeningModule`보다 이를 우선 사용합니다.
- 기본 Battle Game Module 등록을 `BattleGameModuleRegistryFactory.CreateDefault()`로 옮겼습니다. 현재 등록 모듈은 compatibility `turn_qte`입니다.
- `BattleScenarioRuntime.SessionState`와 `BattleSessionState`를 추가했습니다.
  - 현재 범위: scenario id, Primary Mode, opening module, current module
  - `IGameModuleStateStore`를 통해 `GameModuleActionRunner`가 current module을 battle-scoped state에 반영합니다.
- `IBattleSessionStateReader`를 추가하고 `BattleScenarioActionContextFactory`가 이를 `ActionExecutionContext` service로 등록하게 했습니다.
  - runtime actions / Game Modules는 scenario/module state를 읽기 위해 `BattleManager`에 직접 접근하지 않고 context service를 사용할 수 있습니다.
- `BattleParticipantSnapshot`을 추가하고 `IBattleSessionStateReader`가 참가자 스냅샷 목록과 `TryGetParticipant(...)`를 제공하게 했습니다.
  - 현재 범위: subject id, player/enemy 구분, 표시명, HP/MP, 생존 여부, bind/stun/berserk/defend/invincible 플래그
  - `BattleManager`는 전투 시작 직후, battle scenario Action Context 생성 직전, HP/MP 이벤트 브리지 호출 시점에 `_playerParty` / `_enemies`에서 읽기 전용 스냅샷을 갱신합니다.
- `IBattleParticipantCommandRunner`를 추가하고 battle scenario Action Context service로 등록했습니다.
  - 현재 명령 범위: pure damage, HP heal, MP heal, MP consume
  - 첫 구현체는 `BattleManager` 내부 adapter이며, 기존 `CharacterBase` HP/MP 변경, UI 이벤트, scenario HP 이벤트, participant snapshot refresh를 그대로 경유합니다.
- `battle.participant.*` Action Adapter를 추가했습니다.
  - `battle.participant.damage`
  - `battle.participant.heal_hp`
  - `battle.participant.heal_mp`
  - `battle.participant.consume_mp`
  - 공통 파라미터: `subject`, 1 이상의 정수 `amount`
  - Battle 기본 `ActionDirector` registry에 등록했습니다.
- 관련 테스트를 보강했습니다.
  - 현재 runner module ID가 opening module보다 우선되는지 검증
  - 기본 battle module registry가 `turn_qte`를 포함하는지 검증
  - module switch가 injected state store를 갱신하는지 검증
  - `BattleScenarioRuntime`이 scenario 또는 null scenario에서 `BattleSessionState`를 생성하는지 검증
  - battle session state reader가 Action Context에 등록되고 module id 해석에 쓰이는지 검증
  - battle participant snapshot 저장/교체/EnemyData.EnemyId 기반 subject id 해석을 검증
  - battle participant command runner가 Action Context에 등록되는지와 command result 계약을 검증
  - `battle.participant.*` adapter의 runner 호출, runner 누락 실패, amount 검증, runner 실패 전파를 검증

## [의도]

- 이전 구조에서는 각 scenario trigger batch가 새 Action Context를 만들 때 `GameModuleActionRunner`도 새로 만들어질 수 있었습니다.
- 그러면 한 시퀀스에서 `module.switch: aim_shooter`가 성공해도, 다음 시퀀스는 다시 `OpeningModule`인 `turn_qte`로 시작한 것처럼 보일 위험이 있었습니다.
- 이 변경으로 “QTE 전투 중 적 HP 50% 이하 -> 대사/페이드 -> 슈팅 모듈 전환 -> 이후 다른 이벤트도 슈팅 모듈 상태를 유지” 같은 흐름을 runtime contract 수준에서 지킬 수 있습니다.
- `BattleSessionState`는 아직 전체 HP/MP/상태이상/참가자 소유자가 아닙니다. 이번 단계에서는 전투 모듈 연속성만 먼저 명시해, 이후 공통 전투 상태를 옮길 안전한 위치를 만들었습니다.
- 조회 seam인 `IBattleSessionStateReader`를 먼저 열어두면, 다음 concrete Game Module이 `BattleManager.Instance`에 의존하지 않고 전투 세션 상태를 읽을 수 있습니다.
- 참가자 스냅샷은 기존 Character/BattleManager 상태의 읽기 전용 뷰입니다. HP/MP 변경 소유권은 아직 `CharacterBase`와 기존 전투 흐름에 남겨 안정성을 지키고, 새 모듈이 상태를 읽는 경로만 먼저 표준화했습니다.
- 명령 runner는 HP/MP 변경 소유권을 새 시스템으로 옮긴 것이 아니라, 미래 Game Module이 기존 변경 경로를 한 군데로 요청하게 만드는 Adapter입니다.
- 이번 단계에서 이 command seam이 실제 Action Sequence grammar로 노출됐습니다. 따라서 future scenario나 module 전환 sequence가 legacy `SkillData.ActionTimeline` 없이도 HP/MP 변경을 요청할 수 있습니다.
- 편집기보다 먼저 이 runtime contract를 고정해야, 이후 YAML/커스텀 에디터가 잘못된 모델 위에 만들어지는 일을 피할 수 있습니다.

## [위험 / 후속]

- 실제 `aim_shooter`, `boxing` 같은 concrete module은 아직 구현되지 않았습니다.
- `BattleTurnQteGameModuleRuntime`은 여전히 compatibility wrapper입니다. 턴 계산, 플레이어 행동 선택, 적 행동, Battle Session State 전체를 소유하지 않습니다.
- 다음 아키텍처 우선순위는 `Battle Session State`의 참가자 스냅샷과 `IBattleParticipantCommandRunner`를 실제 concrete Game Module 또는 Action Adapter에서 사용하게 만드는 것입니다.
- 그중 Action Adapter 사용 경로는 시작됐습니다. 다음은 concrete `IGameModuleRuntime`이 이 reader/command seam을 실제 gameplay loop에서 사용하는 흐름입니다.
- Unity Editor EditMode 전체 테스트는 이번 작업 단위에서는 실행하지 않았습니다. 변경한 `BattleScenarioRuntimeTests`, `BattleScenarioActionContextFactoryTests` 클래스 단위 검증으로 우선 확인했습니다.
