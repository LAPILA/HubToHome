## 하네스 교훈

### 새 관리형 검사 프로젝트 복원

첫 `dotnet run --no-restore`는 새 프로젝트의 `obj/project.assets.json`이 없어 NETSDK1004로 실패했다. 설치된 SDK만 사용하는 `dotnet restore --ignore-failed-sources` 후 실행해 통과했다. 이미 복원한 프로젝트만 --no-restore로 실행한다. 관련: `Library/CodexChecks/PrologueRuntime`(ignored).

### 관리형 대체 타입은 생산 API와 함께 갱신

DialogueUI에 페이지 Clamp/Max를 추가한 뒤 옛 관리형 하네스에서 Mathf.Max가 없어 컴파일 실패했다. Unity 생산 코드를 바꾸지 않고 하네스에 실제 시그니처의 대체 메서드를 추가한 뒤38검사를 통과했다. 이런 실패를 Unity 소스 오류로 오판하지 않는다.

### Unity 배치의 프로세스/완료 증거

제한 환경에서는 OS 조회/라이선스 초기화 assertion을 남기고 생성기에 도달하지 않았다. 권한 검토를 거친 동일한 전용 배치 실행은 라이선스를 초기화하고 생성기에 도달했다. 제한 환경의 Get-Process에는 별도 권한으로 시작한 프로세스가 보이지 않았지만 `Library/EditorInstance.json`과 로그는 계속 갱신됐다. 프로세스가 없다고 추정해 중복 실행한 시도는 exit1로 끝났다. 이후 동일 권한 환경에서 기록된 PID를 확인했다. 다음에는 한 번 시작한 PID/실행 로그를 같은 환경에서 추적하고, 명령 반환0이나 제한된 프로세스 목록만으로 완료/종료를 판정하지 않는다. 라이선스 비밀 값은 기록하지 않는다.

### 자산 쓰기 전 의존 경로 검증

첫 실제 생성은 사용자가 이전에 알려준 `Presentation/Custom_VFX/Prefabs/Telegraph.prefab`이 현재 이동된 경로라 중단됐다. 실제 파일 검색으로 `Content/Art/Icons/Custom_VFX/Prefabs/Telegraph.prefab`을 확인했다. 코드/대본이 컴파일돼도 자산 경로는 보장되지 않는다. 필수 자산·컴포넌트·원본을 쓰기 전에 검사하고 실패 도중 생성된 파일도 해시 기록에 남겨 안전하게 재시도한다. 이번 부분 산출물84개는 생성 로그와 작업 전 clean 상태로 출처를 확인해 해시로 보존했으며 삭제하지 않았다.

## 남은 확인

최종 그림/공격 프레임은 샘플이다. NPC 외형은 색·크기로 구분한 위젤 대체물이고 백색체는 Monster 정지 이미지다. 프롤로그의 인상/전투 박자/카메라/4언어 글리프/모바일/실제 저장 재개는 Play에서 확인해야 한다. 실기기 발열·프레임·최종 번역 품질을 보장하지 않는다. Google Drive/Notion/웹사이트는 이번 범위에 포함하지 않았다.
