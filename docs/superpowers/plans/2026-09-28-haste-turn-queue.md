# 속도 버프와 턴 예고 연출

> 최종 상태 (2026-09-28): 아래는 구현 이력입니다. 사용자 요청으로 증기 가속 샘플·DB/카탈로그 연결·샘플 전용 검사를 제거했으며 스킬 설계는 보류합니다. 공용 상태·만료 예고·턴 큐 연출은 유지하고 PUSH합니다. 현재 사용법은 `AIAssets/yjlim/feedback/2026-09-28-speed-turns.md`를 따릅니다.

승인된 방향: 현재 행동과 누적 준비도를 보존하고, 속도 변경 즉시 미래 턴 예고만 갱신한다.

1. 기존 상태효과에 Haste 등록. 기본 SPD +30%, 대상의 다음 3개 턴 종료까지 유지. 현재 자신의 턴에 부여하면 그 턴은 차감하지 않는다. 재부여는 중첩 없이 기간 갱신.
2. 턴 서비스가 참여자의 상태 변경을 구독한다. 수치뿐 아니라 남은 기간 갱신도 미래 예고에 반영하며, 같은 순서라면 중복 알림을 생략한다. 턴 시작/종료는 일괄 갱신하며 모듈 종료/폐기 때 구독 해제.
3. 턴 UI는 배우 참조와 표시 출현 순서를 기준으로 슬롯을 재사용한다. 레이아웃 슬롯과 움직이는 초상을 분리하고 DOTween으로 위치 이동 + 전체 동시 소폭 확대/복귀. 같은 순서의 중복 알림은 재생하지 않는다.
4. 증기 가속 샘플을 기존 SkillData 블록으로 작성하고 위젤 원본/실험실 전열 DB 및 콘텐츠 카탈로그에 연결한다. 기존 저장 슬롯은 덮어쓰지 않는다.
5. 단위 테스트 추가, C# CLI 빌드, 직렬화 참조 점검. Unity Play/강제 리프레시는 수행하지 않는다.

완료: 1~5 구현 및 CLI 빌드/순수 계산기/자산 링크 확인. Unity 테스트는 코드 추가·컴파일만 수행했고 화면 확인은 미실행. 결과와 조절법은 `AIAssets/yjlim/feedback/2026-09-28-speed-turns.md`에 통합했다.

후속 확정: 공용 Haste 기본값 +30%는 유지하되 사용자 지정 증기 가속 샘플은 +100% / AP 8 / 3턴으로 상향했다. 원작 내부 수식의 완전 복제가 아닌 관찰 동작 기준으로 합의했으며, 현재 행동/진행량 보존과 즉시 예고 갱신 정책은 유지한다. 실험실 수치 가속 전후를 포함해 순수 검사 15개 통과, 추가 Unity 연결 검사 2개는 컴파일만 확인했다.

## 버그 수정: 만료 뒤 사라지는 연속 턴 예고

실제 계산기에서 재현: 위젤 SPD 20(기본 10, 가속 잔여 1턴), 적 SPD 12. 위젤 턴의 미래 예고는 `적/위젤/위젤/적/위젤`인데 자연 만료 뒤 실제는 `적/위젤/적/위젤/적`이었다. 기존 예고는 SPD가 영구 유지된다고 가정했다. 준비량 초기화나 UI만의 문제는 아니다.

현재 전투 규칙을 유지하는 수정안: 현재 행동의 종료 및 각 미래 행동의 시작/종료에 예정된 상태 만료를 읽기 전용으로 계산한다. 새 상태 부여/수동 해제/사망 등 새 사건이 없다면 기존 예고는 한 칸씩 그대로 실행된다. 가까운 턴 예약·버프 연장 규칙은 추가하지 않는다. 실제 상태 OnTick/OnRemove/HP/AP와 미래 행동 선택은 예고에서 실행하지 않는다.

- [x] 순수 계산기 검사에 가속의 현재 턴 만료·미래 턴 만료·슬로우 만료 및 재예고 안정성 실패 사례를 추가하고 CLI로 실패 확인.
- [x] `BattleSpeedTurnScheduler.AppendPreview`에 읽기 전용 미래 SPD 조회를 연결. 복사된 Entry의 미래 자기 턴 횟수만 증가. 실제 계산식/준비량/선제/동률 규칙은 유지.
- [x] `StatusEffect`/`HasteEffect`에 미래 시작·종료 횟수 기준 생존 조회, `CharacterBase`에 부작용 없는 SPD 예측 추가. `CharacterStatsCalculator`의 단일 스탯 계산은 현재 레이어/반올림 규칙과 공유.
- [x] 턴 서비스는 같은 SPD의 지속시간 갱신도 재예고. 반복 순서가 같으면 상태 알림 때문에 UI를 다시 알리지 않음. 턴 경계의 정상 알림 유지.
- [x] 상태/서비스 연결 검사 추가, 순수 CLI 실행 및 전체 C# 빌드. Unity 실행/강제 Refresh/씬 변경 없음.
- [x] 이전 '버프 만료는 미래 예고에 반영하지 않음' 규칙과 검증 한계를 인수인계/CONTEXT/도메인 규칙/당일 기록에 정정.

결과: 실패 3개 확인 후 수정, 순수 19개 통과(100조합/4,800행동의 남은 예고 보존 포함). Unity 의존 검사는 컴파일만 수행, 실제 Play는 미실행. 새 상태 부여/해제/사망 등 예측 불가능한 사건은 발생 후 갱신하며 예약 턴이나 가속 연장을 추가하지 않음.
