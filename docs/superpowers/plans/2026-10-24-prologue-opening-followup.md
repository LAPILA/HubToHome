# 프롤로그 도입 복구·기관사 장면 Implementation Plan

> **For agentic workers:** 기존 승인 프롤로그의 사용자 후속 수정이다. 분리된 파일 소유권으로 구현·독립 검토한다. 커밋/푸시, Play/엔진 NUnit/강제 Refresh는 하지 않는다.

**Goal:** 창가 원래 대사 복구, 수리 뒤 객차 이동의 발견성/자동 진입 수정, 창가 뒤 기관사·위젤의 자동 이동/마주보기 대화를 기존 프롤로그 앞에 연결한다.

**Architecture:** 그림/대사는 기존 IllustratedStory/DialogueData를 유지한다. Scene 수명 Controller가 작성 데이터의 로컬 위치·시간·역할/대사 ID를 읽어 DOTween으로 두 배우를 이동시키며 실제 PlayerController에는 취소 가능한 표시 소유권만 추가한다. 완료 사실만 기존 flags에 저장한다. 문은 기존 전환 서비스로 요청하며 자기 안의 체류/도착 억제로 왕복 재진입을 막는다.

**Tech Stack:** 기존 Unity6000.3.8f1, C#, DOTween, Odin, uGUI/TMP, CSV4언어.

## 사용자 후속 명세

- 사용자가 지정한 `Prologue_start.aseprite` 창가 루프와 기존3줄 원문을 복구한다. 국가 설명/이름 입력은 되살리지 않는다.
- 창가 종료 후 Q0에서 기관사가 접근하고 위젤도 짧게 이동한 뒤 좌우로 마주 보고 대화한다. 대화 뒤 수리 조작에 돌려준다. 기관사는 최신 사용자 지시로 추가하며 앞선 원문 제안서의 ‘기관사 없음’보다 우선한다.
- 새 역할은 conductor, 대사/외형은 교체형 샘플. 기본 내용은 시야 불량과 불안정한 보조장치 확인 의뢰다. 기존3단계 수리 뒤 드래곤/후미/탈선 흐름은 유지한다.
- 새 게임/미완료 수리 진입에서만 도입을 재생하고 완료 저장/이미 수리한 옛 진행에서는 재생하지 않는다. 취소에는 완료flag를 쓰지 않고 배우/입력을 복구한다.
- 공용칸으로 가는 문은 걷기 접촉으로 진입한다. 모든 객차 문에 동일 규칙을 적용하고 막힌 진행 조건은 유지한다. 도착 중/막 도착한 겹침과 복수 collider 중복은 이동 요청으로 처리하지 않는다.

### 안전 계약

- 자동문은 동일 플레이어의 collider 집합을 추적하고 마지막 collider가 나간 뒤에만 재무장한다. 도착 중 겹침은 시간만 지난다고 해제하지 않고 실제 Exit까지 억제한다. 요청 거절은 성공으로 기록하지 않으며 실패한 요청의 체류 정책도 검사한다.
- 표시 이동 lease 동안 일반 입력/idle Animator 갱신이 이동 포즈를 덮지 않는다. Player의 전투 진입/disable은 lease를 무효화한다. 완료·취소의 위치/방향 복원은 동일 배우·Room·실행세대가 아직 소유권을 가질 때만 한다.
- 좁은 자산 패치는 전체 대상의 baseline hash·dirty·필수 참조를 쓰기 전에 일괄 검증한다. 충돌 검사 때문에 일부만 변경된 상태를 만들지 않는다. 실행 중 예외의 부분 산출물은 출처/해시를 남겨 복구하되 원래 예외를 숨기지 않는다.

## Chunk 1 재현·계약

- [x] 실제 Editor 로그와 production 추출 하네스로 수리 대화 완료/다음 공간 정체를 구분한다. 창가 생성기의 Dialogue=null 회귀를 데이터 계약으로 검출한다.
- [x] Root: Definition에 역할/대사ID·Room-local 두 배우 위치·진입시간을 추가한다. PlayerController의 소유자 일치 표시 이동 lease를 추가하되 실제 일반 입력/전투/이동속도/카메라 규칙은 보존한다.
- [x] Runtime: Introduction partial, Resume 연결과 완료flag, 취소/disable/다른전투 소유권 정리. Door 자동 진입과 도착 억제/exit 재무장을 최소 구현하고 실제 코드를 연결한 관리형 검사로 확인한다.

## Chunk 2 콘텐츠·검증

- [x] Content: 원문3줄 창가 대화 복제+4언어, conductor 역할/화자/외형/도입·선택 대화. 원본 그림/클립/타일/상자/기존 저장 보존.
- [x] 전체 재생성 대신 해시 충돌/dirty Scene을 거부하는 전용 좁은 패치 명령으로 Opening/Profile/Q0/문만 수정한다. 처음 패치 후 다시 실행해도 사용자 편집을 덮지 않는다. 기존 full builder도 같은 올바른 초기값을 사용한다.
- [x] CLI 전체 오류0, 실제 source 관리형 회귀, 메타 GUID/번역/실제 연결 참조·manifest 검사. 현재 사용자 편집기가 켜져 있으면 닫힌 자산 배치 생성은 실행하지 않고 파일 잠금/저장 상태를 확인한다.
- [x] AIAssets 당일 기록/제작 안내/CONTEXT 갱신과 독립 검토. 실제 조작 Play는 별도 미검증으로 표기한다.

## 적용 중 확인한 안전 경계

- 열려 있는 Region_Train은 Edit Mode/clean 상태였다. 전체 생성기나 두 번째 Unity batch를 실행하지 않고 `ApplyInEditor`가 임시 빈 Scene에서 좁은 패치만 실행한 뒤 원래 Scene 구성을 복원한다. Scene 파일은 저장하지 않는다.
- 첫 사전 검사는 Story_TrainOpening의 dirty 표시로 쓰기 전에 중단됐다. 실제 native detached 디스크 로드와 전체 EditorJson 비교 결과 `_framesSourceClip`의 자동 갱신만 달랐고 그림/프레임/작성 필드는 같았다. 이 증명 조건을 만족하는 해당 한 경로만 예외로 허용하고, 다른 미저장 편집은 계속 거부한다. dirty 전역 해제/SaveAssets/사용자 파일 재임포트로 우회하지 않는다.
- 최종 ApplyInEditor 성공 및 원래 clean Scene 복원 확인. native 데이터 검사로 원래5프레임/3줄, 역할7/대사27, 자동문6개 확인. 메타1679개/생성기록166해시 통과. 두 Scene SHA256 및 Q0 타일4문서/상자1문서는 보존했다. Play/실기기/사용자 저장 I/O는 실행하지 않았다.
