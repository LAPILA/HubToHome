# 전투 상단 결과 기록 설계

2026-10-26 후속 승인으로 즉시 전체 표시/3대상 페이지 분할은 [고정3줄·한 줄 출력·스크롤 설계](2026-10-26-battle-chain-rolling-followup-design.md)로 대체됐다. 실제 HP/AP/상태 집계 계약은 그대로다.

2026-10-25 사용자 승인: 피격·저체력 자동 말풍선 제거, 이야기 대화 보존, 행동별 피해 합산·HP/AP 증감·상태 부여/해제 안내, 일반 기록 자동 종료 및 기존 Z 전체 표시/즉시 종료. 새 스턴이나 공격 상태는 추가하지 않는다.

## 표시 계약

- 중앙 상단 BattleNarrationUI를 재사용한다. 별도 창/전투 매니저/저장 형식을 만들지 않는다.
- 공격·스킬·아이템 이름과 대상별 실제 HP/AP 증감, 상태 변화가 한 결과 묶음이다. 연타는 합산하고 회복과 손실은 상쇄하지 않는다. 과잉 피해/회복은 실제 현재 값의 변화로 기록한다.
- 공격 중에는 결과 메시지를 열지 않는다. 기존 DamageBatches가 닫힌 안전 경계에 자동 종료 안내를 보낸다. 하위 반격/상태 반응도 현재 행동 묶음으로 모은다. 아이템은 결과 대기 전에 묶음을 명시적으로 닫는다.
- 기존 중앙 안내의 읽기/입력 차단 계약을 유지한다. 일반 결과는 짧은 유지 시간으로 자동 종료하며, 확인으로 전체 표시·다음 확인으로 즉시 종료한다. Z를 실제 적 공격/QTE 도중 가로채지 않는다.
- 일반 결과 묶음은 읽기 지연을 줄이려고 즉시 전체 표시/0.85초 자동 종료로 보낸다. 이미 전체가 보이면 Z한 번으로 닫힌다. 기존 타이핑 안내는 기본false인 즉시 표시 옵션으로 구분해 첫Z전체/다음Z종료를 보존한다.
- 피격/저체력의 자동 DamageTaken/LowHp 호출만 제거한다. 이야기 대화, 별도 짧은 연출 대사, 턴/스킬 대사 데이터와 외형은 삭제하지 않는다.

## 상태와 자원

CharacterBase.OnHPChanged/OnAPChanged를 유일한 실제 수치 원천으로 관찰한다. OnDamageDealt/OnElementalDamage를 다시 더하지 않는다. 새 바인딩은 기준 값만 저장한다. 상태는 기존 BattleStatusTransitionTracker의 종류 차이를 사용해 새 부여/해제를 판별한다. 지속시간 감소나 누적량 변경마다 부여 안내를 반복하지 않는다. 상태 정리/전투 종료/재바인딩은 로그를 만들지 않는다.

이미 구현된 기절·빙결 때문에 자기 턴을 건너뛰면 이유를 알린다. 기절이 모든 방어를 막는다고 설명하지 않는다. 기존 방어·상태·저항·연속 제어 방지 계산은 변경하지 않는다.

## 구현 경계

- 표시 전용 BattleCombatLogPresenter가 배우 구독·스냅샷·행동별 결과 누적/해제를 소유한다. 상태 비교기는 기존 타입을 확장하고 기존 사용자와 호환한다.
- BattleManager는 행동 시작의 표시 이벤트를 전달한다. Turn QTE 서비스는 공격/스킬/아이템/적 행동의 유효 시작과 행동 불가 안내만 연결한다. 전투 계산/턴 알고리즘은 유지한다.
- 새 문구는 KR/EN/JP/CN 번역 키와 대체 문구를 제공한다. 번역 시 숫자·이름 토큰을 사용하며 최종 번역 교정은 별도다. 기존 설정 ScriptableObject와 프리팹은 재저장하지 않는다.
- UI disable/종료/호스트 교체는 자기 구독과 대기 결과만 해제한다. 실제 파티/HP/AP/상태를 수정하지 않는다.

## 검증

실제 소스 기반 관리형 검사와 전체 C# CLI, 메타 GUID/참조/UTF-8·diff 검사. 연타50회·여러 대상·회복 상한·과잉 피해·AP 비용/회복·초기 바인딩·상태 신규/해제/수치만 변화·취소/전투 종료·다음 전투를 검사한다. Unity Play/Refresh/강제 import/사용자 저장 I/O/커밋/푸시는 하지 않는다.
