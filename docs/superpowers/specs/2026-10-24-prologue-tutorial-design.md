# 프롤로그 열차 튜토리얼 설계

기준일: 2026-10-24. 대상: Unity 게임의 새 게임 시작부터 열차 탈선까지. 제공 문서 `초안 제안서답장본.docx`와 사용자가 승인한 전체 흐름을 구현 기준으로 한다. 원본 문서는 수정하지 않는다.

## 1 목적과 승인된 방향

긴 국가 설명 대신 위젤의 수리 행동으로 시작한다. 정비공의 능력과 기계에 대한 흥미, 동료들의 첫인상, 한 백색체가 열차 전체를 위협하는 상황을 직접 조작과 짧은 대화로 전달한다. NPC·대본·초상·그림·음원은 샘플이며 교체할 수 있어야 한다.

전투만 분리한 교습형과 영상 중심형 대신, 사용자가 승인한 서사 내 학습형을 적용한다. 첫 전투는 학습 후 적의 압박 → 후퇴 → 드래곤 구조로 끝난다. HP 0·게임오버·실제 도주 성공으로 이 결과를 위장하지 않는다. 열차 분리, 두 번째 구조, 드래곤의 전투 파티 조기 합류는 넣지 않는다.

## 2 현재 구현과 변경 경계

현재 연결은 타이틀 → IntroScene 창가 반복 → Region_Train/Q0 → 실제 탐색3초 뒤 사건 → Q0 오른쪽 문턱에서 걷기/Monster 삽화 → 탐색 복귀다. 국가 설명4컷은 이미 제거됐다. 실제 Region_Train의 Room 목록은 Q0 하나이며 공용칸·후미 창고·기관실 및 전투/탈선은 연결되지 않았다.

기존 타이틀, 고정 이름 WIZZEL/위젤, RoomContainer/RegionEntryCoordinator/MapTransitionService, DialogueManager/DialogueUI, 전투·시퀀스·음향·저장 기반을 유지한다. 기존 과자 상자와 사용자 지형은 보존한다. 새 전역 매니저, 별도 대화 편집기, 독립 저장 파일, 상시 렌더 카메라는 만들지 않는다.

## 3 플레이 순서

| 단계 | 필수 조작과 전환 조건 | 주요 표현 |
| --- | --- | --- |
| 열차 도입 | 짧은 열차/안개 컷 후 조작 가능 | 샘플 창가 그림을 짧게 재사용. 국가 나레이션 없음 |
| 수리 | 부품 상태 확인 → 밸브 조정 → 작동 확인의 짧은 조사3회 | 별도 연타 미니게임 대신 방향 이동/확인 키를 자연스럽게 익힘. 수리를 끝낸 사실을 먼저 확정 |
| 휴식 이동 | 목표 ‘공용칸에서 쉬기’. 공용칸으로 이동 | 사슴의 위험 감지, 눈표범의 까칠한 치료 행동은 선택 관찰/대화 |
| 드래곤 교류 | 필수 대화가 정상 종료되고 패널도 닫힌 뒤 사건 시작 | 가벼운 식사/친분 → 짧은 정적 → 차체 충격·조명 이상. 단순 시간 경과 트리거 제거 |
| 후미 확인 | 목표 ‘후미칸 확인’. 백색체 공개 뒤 심리스 조우 | 같은 개체가 연료를 먹는 행동. 샘플 Monster 그림/적 외형 교체 가능 |
| 첫 전투 | 공격 → 방어/패링 → 소모품 학습 → 압박 연출 | 위젤1명 대 백색체1개체. 학습 판정과 전투 규칙을 분리 |
| 구조와 봉쇄 | 후퇴 완료 → 드래곤1회 구조 → 문 닫기/잠금 고정 | 구조는 후미 출입구 한 번만. 드래곤의 판단/힘과 위젤의 기술이 함께 작동 |
| 전방 이동 | 잠금 완료 후 기관실로 이동 | 천장/외벽의 소리·뻗은 몸, 대원들의 반복 대응. 새 개체/별도 강제 전투로 늘리지 않음 |
| 긴급 제어와 탈선 | 위젤 단독으로 긴급 제어 조작 → 감속 성공 → 주행부 파손 → 탈선 | 성공한 감속과 막지 못한 파손을 구분. 암전·금속음·짧은 컷으로 마무리하고 완료 체크포인트 기록 |

빠르게 진행할 때 약10~15분을 조정 목표로 삼되, 임의 시간 경과를 진행 조건으로 사용하지 않는다. 선택 대화와 탐색 시간은 별도다. 필수 대사는 짧게 나누며 인물들의 배경 설명을 한 번에 늘어놓지 않는다.

## 4 방 구성과 교체 가능한 역할

Q0/기존 ID `all.trainq0`는 첫 수리 객차로 유지한다. 최신 사용자 수정에 따라 연결은 Q0 → 공용칸 → 사건칸(기존 Rear) → 제어칸(기존 Control)이며 오른쪽으로 진행한다. 수리/사건/봉쇄 조건에 따라 다음 객차를 연다. 봉쇄 뒤 Q0으로 강제 복귀하지 않으며 저장 재개도 새 순방향 동선을 사용한다. 기존 Room ID/enum은 유지한다. 문은 기존 전환 서비스와 도착 재진입 억제를 사용한다.

탈선 뒤에는 다음 챕터 대신 동일 Scene의 완료 전용 안전 Room `all.train.prologue_end`로 도착한다. 기존 샘플 배경/어두운 정지 화면을 사용하는 종료 대기 공간이며 추가 스토리·탐색 콘텐츠를 만들지 않는다. 이 종점은 자동저장과 Continue의 일관된 복귀 주소를 위한 것이다.

콘텐츠 설정은 `PrologueTutorialDefinition` 성격의 단일 참조 묶음으로 관리한다. 수치/단계별 안내, 역할별 표시 Prefab·SpeakerData, DialogueData·삽화·음향·전투 참조를 보유하되 실제 재생/저장/보상을 소유하지 않는다. Odin에는 단계·역할·대사·전투·연출을 구분해 노출한다. 샘플 이미지는 기존 스프라이트를 재사용하고 신규 아트를 생성하지 않는다.

역할 ID는 protagonist / companion_dragon / companion_deer / companion_medic / crew / white_entity로 분리한다. ‘드래곤’ 같은 표시 이름, 실제 Sprite, 대본 문구를 코드의 진행 조건으로 비교하지 않는다. 드래곤은 NPC/연출 대상이며 이 프롤로그에서 실제 저장 파티에 합류하지 않는다.

## 5 기존 시나리오와 도메인 소유권

이야기 연출은 기존 Action Sequence/SceneActionSequencePlayer와 DialogueData/IllustratedStoryPlayer를 사용한다. Scenario Source YAML을 원본으로 두고 기존 동기화 경계로 Runtime Asset을 생성한다. 그림 플레이어를 전체 이야기 상태 기계로 확장하지 않는다.

방 범위의 튜토리얼 연결부는 현재 단계, 상호작용 완료, 대화 정상 완료, 전투 학습 결과와 다음 체크포인트 연결만 소유한다. 주행음은 기존 PrologueTrainAudioSession이, 화면·이동 Tween은 기존 표시 서비스와 해당 재생 세대가 소유한다. 기존 임시3초 사건/후미 문턱 경로는 새 튜토리얼 연결이 활성일 때 실행하지 않는다.

DialogueNode.EventTriggerID는 문장 표시 전 발생하므로 드래곤 대화 종료 조건으로 쓰지 않는다. 정상 완료 콜백과 IsPresentationVisible 종료를 사용하고, 정상 대화 스킵은 완료로 합류하며 강제 취소는 사건을 시작하지 않는다. 각 재생 세대가 자기 대사·Tween·오버레이·입력 잠금만 해제한다.

## 6 첫 전투 학습과 정상 후퇴

1. 공격: 기존 메뉴와 대상 선택을 그대로 사용한다. 실제 공격 완료를 확인한 뒤 다음 안내로 이동한다. QTE 성공 보상이나 피해 규칙을 재정의하지 않는다.
2. 방어: 기존 QTEManager.BattleDefenseResolved 결과를 관찰한다. 일반 방어와 저스트가드를 한 번에 설명하지 않고 방어를 먼저 경험시킨 뒤 타이밍 보상을 짧게 보여준다. 성공 판정을 조작하거나 다른 전투의 방어 창을 변경하지 않는다. 실패에는 짧게 다시 기회를 주며 무한 실패로 진행을 막지 않도록 데이터에 재시도 상한/보조 진행을 둔다.
3. 소모품: 실제 전투 아이템의 유효 대상·소모·효과 적용 완료 지점에 최소 결과 통지를 추가한다. 인벤토리 수량 감소만으로 완료를 추측하지 않는다. 필요한 샘플 회복품은 체크포인트에서1회 지급하고 중복 로드로 재지급하지 않는다. HP가 이미 가득 차 있어도 유효한 학습 사용을 진행할 수 있도록 첫 적 패턴/교육용 아이템 사용 조건을 데이터로 맞춘다.
4. 압박: 학습 종료 후 현재 행동을 끝낸 안전 경계에서 위기 연출을 실행한다. 플레이어의 실제 성공을 실패로 바꾸거나 피해/보상을 가짜로 계산하지 않는다.

정상 이야기 후퇴를 나타내는 명시적 결과 경계를 최소 추가한다. 기존 enum 값은 유지하고 필요 시 새 값을 끝에 추가한다. 이 경로는 승리 보상·처치/전멸 기록·도주 쿨다운·GameOver를 발생시키지 않으며 정상 세션 cleanup 후 스토리 후퇴 완료를 한 번만 통지한다. AbortSeamlessBattle 취소나 ReturnToExplorationOnDefeat 훈련 패배로 대체하지 않는다. 일반 전투/보스/실험실의 기존 승리·도주·패배 동작은 보존한다.

학습 중 치명 피해로 진행이 끊기면 일반 GameOver 대신 해당 튜토리얼 진입 전 메모리 체크포인트로 재시도한다. 이야기상의 후퇴는 이 실패 처리와 별개이며 사용자 승인대로 HP 0을 요구하지 않는다. 드래곤 구조 완료 후 기존 상태 범위 안에서 필요한 회복/필드 복귀를 확정한다.

이 조우는 필수전으로 RUN을 회색 비활성화한다. 전투 대상은 백색체 본체 전체가 아닌 좁은 입구에 뻗어 나온 부위로 표현한다. 학습 전에 이를 처치한 예외에도 처치 피해/모션은 유지하고 본체의 압박 연출을 이어 정상 이야기 후퇴로 수렴한다. 승리 보상·전체 백색체 처치 플래그는 지급하지 않는다. 미완료 학습을 위해 처치한 적을 되살리거나 무한 전투를 강제하지 않는다. 일반 첫 플레이의 기본 수치는 세 학습을 경험하도록 잡되 고레벨 옛 저장/극단 수치의 조기 처치도 안전하게 종료한다.

참가자는 이 조우의 임시 roster에서 위젤 CharacterID 하나만 선택한다. GlobalDataManager의 저장 파티 순서/인원은 변경하지 않는다. 위젤 참조가 없으면 시작 전 명확히 실패하고 임의 캐릭터를 생성하지 않는다. 다른 파티원의 HP/AP/성장/장비는 건드리지 않는다.

회복품은 이 샘플의 전투 전용 소모품이며 필드 사용/판매는 허용하지 않는다. 전투 진입 시 등록과 소지 여유를 먼저 검사하고, 부족한 경우1개를 정상 인벤토리에 지급한 뒤 지급 완료 플래그를 확정한다. 이미1개 이상 있으면 추가 지급 없이 확보 완료로 기록한다. 그 뒤 아이템과 확보 플래그를 포함한 메모리 재시도 snapshot을 잡는다. 재시도는 이 snapshot을 복원하며 별도 재지급하지 않는다. 아이템 수량 상한/등록 실패는 전투 잠금 전에 처리하고 오류를 숨기지 않는다.

## 7 현지화와 입력 안내

실제 프로젝트 형식 `Key,KR,EN,JP,CN`과 LocalizationManager를 사용한다. 새 본문·선택지·화자명·조사 문구·목표·튜토리얼 안내·실패/재시도 문구 모두4개 언어 열을 작성한다. 기존 번역 행을 덮어쓰지 않고 고유 접두사와 안정적인 키를 사용한다. NPC/대사 교체 시 키/참조만 변경하면 되도록 한다. 번역 누락은 기본문 대체가 있다는 이유로 완료 처리하지 않는다.

키 표시는 실제 입력 동작에 연결하고 본문에 Z/X/C를 고정 박아 넣지 않는다. 기존 키보드/패드/모바일 입력과 확인/취소 소비 경계를 유지한다. 최신 사용자 요청으로 전용 프롤로그27개 대사는 즉시 표시하고 확인(Z)1회당 다음 페이지/문장1단계로 진행한다. 일반 NPC 타이핑 기본값은 유지한다. 길게 누르기·연타·색 구분만을 필수 통과 조건으로 만들지 않는다. 언어 전환은 현재 페이지를 새 언어로 다시 표시하되 사건/보상은 재실행하지 않는 정책을 적용한다. 한국어/중국어/일본어 글리프와 영문 긴 문장의 줄바꿈은 별도 검증한다.

## 8 저장과 재개

새 저장 형식 대신 GlobalDataManager의 기존 플래그와 JournalCatalog 목표 투영을 사용한다. 새 완료 키는 `prologue.tutorial.repair.completed`, `prologue.tutorial.incident.completed`, `prologue.tutorial.rear.completed`, `prologue.tutorial.withdrawal.completed`, `prologue.tutorial.rescue.completed`, `prologue.tutorial.seal.completed`, `prologue.tutorial.forward.completed`, `prologue.tutorial.control.completed`, `prologue.tutorial.completed`로 고정한다. 물품 확보 키 `prologue.tutorial.supplies.ready`는 메모리 재시도 snapshot에도 포함한다. 수리의 부분 조작은 같은 접두사의 단계별 완료 사실로 관리한다. 구조와 전방 목격도 완료 사실을 따로 두어 이후 조작에서 취소/저장해도 완료 장면을 반복하지 않는다. 실행 중 코루틴·연출 시간·개별 버튼 입력은 저장하지 않는다.

자동저장은 기존 안정된 탐색 게이트에 요청한다. 로드 시 완료한 마지막 구간 다음의 안전한 위치에서 재개하며 미완료 연출은 처음부터 다시 실행한다. 전투 중에는 디스크 저장하지 않고 기존 메모리 재시도 경계를 사용한다. 취소/실패에는 완료 플래그·보상·자동저장을 추가하지 않는다. 기존 옛 reveal 플래그만으로 새 전투 학습/탈선을 완료한 것으로 취급하지 않는다. 새 완료 플래그가 없는 기존 열차 저장은 안전한 수리 도입 위치에서 시작하되 기존 인벤토리/파티를 초기화하지 않는다.

| 마지막 완료 사실 | 복귀 지점 | 다음 동작 |
| --- | --- | --- |
| 없음 | Q0 수리대 앞 | 미완료 수리 조작 |
| 수리 완료 | Q0 공용칸 방향 문 안쪽 | 공용칸 자유 탐색/드래곤 대화 |
| 이상 발생 완료 | 공용칸 후미 방향 문 안쪽 | 후미 이동 |
| 후미 공개 완료 | 후미 창고 입구 안쪽 | 전투 진입/재시도 |
| 이야기 후퇴 완료 | 후미 출입구 안전 위치 | 미완료 구조·봉쇄 재생 |
| 구조 완료 | 후미 출입구 안전 위치 | 문 잠금 조작만 대기 |
| 봉쇄 완료 | Rear 안전 위치 | 오른쪽 제어칸 이동 |
| 전방 목격 완료 | 기관실 입구 | 긴급 제어대 조작 |
| 긴급 제어 완료 | 기관실 제어대 안전 위치 | 미완료 파손·탈선 연출 재생 |
| 프롤로그 완료 | `all.train.prologue_end/default` | 완료 화면, 타이틀 복귀 |

탈선 후 완료 Room 도착과 최종 플래그를 확정하고 자기 Cutscene/대화/전투 잠금을 해제한다. 먼저 기존 안정 탐색 게이트로 자동저장을 끝내고 `SaveManager.AutoSaveCompleted`의 자기 세대 결과를 확인한 뒤 완료 모달을 표시한다. 완료 모달을 먼저 열어 자동저장을 영구 대기시키지 않는다. 종점에는 위험·문·보상 상호작용이 없으므로 이 짧은 저장 대기 중 조작해도 진행이 바뀌지 않는다. 저장 실패는 성공으로 표시하지 않고 재시도 또는 저장 없이 타이틀 복귀를 명시 선택하게 한다. Continue/자동 슬롯 로드는 완료 Room을 다시 준비하고 탈선·보상·최종 저장을 반복하지 않은 채 완료 화면을 연다. 이후 챕터 진입은 이번 범위가 아니다.

## 9 표현과 성능

감정 곡선은 안정된 기계 리듬 → 짧은 친분 → 소리의 단절 → 뒤쪽 정체 공개 → 좁은 공간의 압박 → 잠금 성공 → 천장 위 소리 → 감속 성공/기계 파손으로 만든다. 긴 흔들림·과도한 플래시·반복 구조·설명문을 늘리는 방식은 피한다.

640×480·정수 배율·기존 UI 조명 분리·Pixel Perfect 정책을 유지한다. 원화 교체 전에는 짧은 카메라 이동/컷·2D 조명/그림/암전/재사용 음향으로 표현한다. 상시 새 카메라/RT/블러 패스, 매 프레임 전역 검색, 무제한 입자/음원은 추가하지 않는다. 흔들림·플래시 강도 설정을 존중한다. GPU/실기기 발열과 프레임 보장은 측정 전 주장하지 않는다.

## 10 검증과 완료 기준

- 실제 코드 연결: 새 게임 → 위 표의 전체9단계 → 프롤로그 종료. 3초 자동 사건과 중복 발동하지 않음.
- 데이터 교체: 역할별 Prefab/초상/대사/삽화/전투 참조를 바꿔도 코드 문자열 변경 불필요. 기존 콘텐츠 메이커·시퀀스 메이커에서 관리 가능.
- 진행: 선택 NPC를 전부 건너뛰어도 완료 가능. 필수 대화 취소에는 사건 없음, 정상 스킵에는 동일 진행. 재시도/중복 입력/Room 왕복/로드에도 지급·후퇴·봉쇄가 중복되지 않음.
- 전투: 공격·방어 결과·아이템 실제 완료 관찰, 전투 종료 안전 경계, 정상 후퇴의 별도 결과와 무보상/비전멸 cleanup. 일반 전투 회귀 유지.
- 저장: 단계별 저장/로드·옛 플래그·기존 파티/인벤토리 보존. 스킵과 취소를 구분하고 정상 완료만 자동저장 예약.
- 현지화: 새 키 중복·빈4언어·깨진CSV·누락참조 검사, 언어 전환 시 사건 재실행 없음. 글꼴 실제 출력은 엔진 확인 대상으로 명시.
- 수명: 화면·음향·카메라·입력·대사·이동을 실행 소유자별 취소/disable/destroy/씬 이탈에서 정리.
- 도구: 전체 Runtime/Editor CLI, 관리형 진행/결과 회귀, 자산 참조·메타 GUID32hex/유일성 검사. Unity Play/Refresh/Reimport/열린 씬 저장은 별도 명시 실행 없이 하지 않는다. 자산 생성에 필요한 범위와 현재 열린 씬 덮어쓰기는 구분한다.

아트/샘플 외형을 최종 퀄리티로 주장하지 않는다. 4개 언어의 초안 번역은 연결/누락을 검증하되 최종 원어민 교정으로 보장하지 않는다. Unity 엔진/기기 확인과 관리형 대체 타입 검사는 결과를 분리해 보고한다. 커밋·push는 별도 요청 전 수행하지 않는다.
