# 전투 카메라 안전영역·픽셀 안정화 설계

## 문제와 목표

초기 수정은 가까운 행동 줌을 완화하고 전체 화면이 아닌 실제 HUD 안전영역에 캐릭터 몸체를 맞췄다. 그러나 최종 Fit이 현재 이동·홉·넉백 위치마다 렌즈를 다시 계산하면서 반복 확대·축소가 발생했다. 짧은 타격 줌과 스킬 줌도 이를 강화했다.

기존 연속 줌 어댑터는 네이티브 CinemachinePixelPerfect를 비활성화하고 CorrectCinemachineOrthoSize의 반환값을 버려, PPC 호환 모드는 켜지만 실제 렌즈의 픽셀 정렬은 우회했다. Body 이후의 안전영역 Finalize와 Brain 보간도 렌즈를 다시 바꿀 수 있었다.

목표는 기존 공격·방어·전조·QTE 시계, UI 배치, 토큰·Hold·Timeline 제어권을 보존하면서 한 전투의 배율을 고정하고 최종 출력까지 픽셀 규칙을 유지하는 것이다. 새 카메라·RT 시스템·GPU 패스는 추가하지 않는다.

## 픽셀 규약

공용 규격은 PPU32 /640×480 /Windowbox /Upscale Render Texture /Point이다. 기준 렌즈는 `480 / (2 ×32) =7.5`, 허용 렌즈는 `7.5 / n`이며 n은1이상의 정수다. Lens4는 원본1픽셀이1.875내부픽셀이 되어 정확한 정수 배율이 아니다.

CameraPixelGridPolicy는 기준 렌즈와 필요한 시야 이상인 정수 배율을 계산한다. 필요 시야4를 nearest3.75로 줄이지 않고7.5로 선택한다. 원본 픽셀을 축소하지 않는 상한은 기준 렌즈이며, 초과 배치를 무한 줌아웃으로 해결하지 않는다. 범위 초과는 전투당 한 번 경고하고 제작 위치·이동 높이를 조정한다.

## 전투 고정 구도

전투 기준 픽셀 확대 배율 기본값은1이고, 전투 최소 렌즈는3.75다. 진입 시 기준 렌즈 /확대 배율을 요청값으로 사용해 안전영역 Fit을 한 번 구한 뒤 SnapSizeAtLeast로 고정 렌즈를 선택한다. 기본 고정값은7.5다. 이후 이동·홉·복귀·행동 교체에서는 FitAtFixedSize로 중심만 보정한다. 이 메서드는 수용 불가능한 경계에서도 렌즈를 변경하지 않는다.

SpriteRenderer는 새 멤버 등록 시 조회하고 몸체 범위를 보존한다. 첫 Sprite가 늦게 준비되면 캐시를 한 번 보완한다. UI는 기존640×480content와 Screen.safeArea를 사용하고 하단162px+8px, 상단48px+8px를 미리 예약한다. HUD 진입·대사 슬라이드 중에도 예약 공간을 축소하지 않는다.

일반 전투의 타격 줌·스킬 줌·임의 Dutch 회전은 억제한다. 위치 이동과 공격 애니메이션은 유지한다. PPC 활성 모드나 기준 렌즈가 변경되면 고정값을 다시 계산한다.

## 출력·소유권 경계

- Body에서 PPC 보정 반환값을 렌즈에 적용한다. 네이티브 확장을 토글하지 않는다.
- Finalize에서는 방어 Hold 또는 전투 안전구도를 적용한 다음 렌즈와 XY를 다시 정렬한다. 엄격 픽셀 경로의 Dutch는0이다. 월드Z는 보존한다.
- CinemachineCore.CameraUpdatedEvent에서 Brain 보간 후 실제 출력 렌즈를 재보정한다. Hold가 전투 고정 렌즈보다 우선한다. 렌더 직전 위치 정렬은 기존 URP PPC를 이용한다.
- 명령 Release와 전투 안전영역 정책 소유권은 별개다. 명령 종료나 일시적인 HUD 숨김으로 정책을 지우지 않는다. 같은 전투의 고정 렌즈를 먼저 적용하고 UI 화면 영역을 얻을 수 있을 때만 중심을 보정한다. 출력 렌즈 재보정도 HUD 표시 여부에 의존하지 않는다.
- Timeline 대여·컴포넌트 비활성화·실제 전투 종료에서는 정책 소유권을 명시적으로 분리한다. Timeline에서도 픽셀 격자는 유지한다.
- 전투 종료는 몸체·고정 배율·경고 상태를 초기화한다. 비활성화·파괴는 출력 이벤트를 해제한다. 이전 토큰의 정리가 새 명령을 덮지 않는다.

## 검증과 한계

생산 순수 정책·프레이밍과 공유 Editor 테스트를 연결한 관리형 하네스에서52케이스 /73,689단언을 통과했다. Runtime447 /Editor370소스 CLI 오류0(경고225 /0), 메타1,555개32hex·중복 검사도 확인했다. CameraFramingTests의 엔진 의존 경로는 컴파일만 확인했다.

기존 UI 정수 Overlay, Render Scale1, AA 비활성 정책은 유지한다.640×480미만 출력의 축소는 무손실 보장이 아니다. ScreenSplit·배경 왜곡·스프라이트 자체의 회전/스케일은 별개다. 이번 턴의 씬·프리팹 변경과 추가 Inspector 연결은 없다. Unity Play·강제 Refresh/Reimport·GPU·실기기·체감은 미검증이다.
