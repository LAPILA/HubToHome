# 오버월드 6인 동행 실험실

상태: 2026-10-26 사용자 구현 승인. **위젤 포함 총6명**으로 시작하며 에디터에서 동료 추가·삭제가 쉬워야 한다는 후속 조건을 포함한다. 기존 추종 시스템을 재사용한다. 커밋·푸시는 요청하지 않았다.

## 1. 목표와 범위

새 개발 씬 하나에서 서로 연결된 Room3개를 걸어 다니며, 위젤+동료5명의 장애물 추종·달리기·급회전·대화·고정·재합류·방 이동을 확인한다. 두 번째 방에서는 마지막 동료2명이 소품을 구경하고, 가까이 가서 Z로 말을 걸 수 있다. 본편 새 게임·실제 파티 편성·기존 BattleLab·저장 데이터는 바꾸지 않는다.

추천 방식은 **독립 개발 씬1개 + Room Prefab3개**다. 별도 Scene3개 방식보다 현재 Room 전환 경로와 동료 도착 복구를 함께 확인하기 쉽고, 부트스트랩을 중복하지 않는다. 기존 TestMap에 추가하는 방식은 본편/기존 시험 동선과 섞이므로 채택하지 않는다.

이번 범위에서 새 길찾기·전투·퀘스트·카메라 리그·범용 제작창을 만들지 않는다. 델타룬의 동행 느낌을 참고할 뿐 원작 내부 알고리즘과 동일하다고 주장하지 않는다.

## 2. 파일과 작성 데이터

신규 콘텐츠는 `Assets/_Game/Content/Maps/Development/Regions/FollowerLab/` 아래에 모은다.

| 하위 폴더 | 내용 |
| --- | --- |
| Scenes | `FollowerLab.unity` 한 개 |
| Prefabs/Rooms | 창고, 전시실, 우회 통로 Room3개 |
| Data/Rooms | RoomDefinition3개 및 지역 데이터 |
| Data/Characters | 위젤 그림을 재사용한 색상 구분용 샘플 동료5개 |
| Data/Dialogue | 동료 대화, 안내판, 합류 성공/실패 안내 |
| Data | 실험실 파티·방 목록·안내를 연결하는 설정 |

위젤은 기존 WizzelDB를 참조하고 동료5개는 독립 stable ID와 색상을 가진다. 기존 DB를 수정하지 않는다. 필요한 신규 CharacterData만 기존 콘텐츠 카탈로그에 명시적으로 추가하고 전체 카탈로그 재생성은 하지 않는다. 그림·Animator는 기존 위젤 탐색 외형을 참조한다.

소품은 기존 잔디/벽/상자 등 사용 가능한 자산을 우선 재사용한다. 부족한 장식은 기존 단색 스프라이트의 조합으로 구분하며 신규 완성 아트처럼 취급하지 않는다. 바닥 시각 Tilemap과 실제 장애물 Collider를 분리한다. 한글 Odin Inspector에서 동료 슬롯, 관람 위치, 경유점, 대사, 이동 시간과 반복 정책을 수정할 수 있게 한다.

실험실 설정은 리더1명과 동료 목록(0~5명)을 분리한다. 동료 목록에서 추가·삭제·순서 변경과 CharacterData 교체를 제공한다. null/최대 인원 초과는 명확한 검증 오류로 시작을 막으며 임의로 목록을 잘라 저장하지 않는다. 설정은 다음 Play에 적용한다. 동료를 삭제해 관람 슬롯4/5가 없으면 해당 관람 지점만 건너뛰고 나머지 맵은 정상 동작한다.

## 3. 세 방의 시험 구성

연결은 `1 ↔ 2 ↔ 3`이며 방3에서 방1로 돌아가는 시험용 문을 추가한다. 입장 방향별 SpawnPoint를 지정하고 문 Trigger 밖의 안전한 바닥에 배치한다.

| 방 | 배치와 확인 항목 |
| --- | --- |
| 1 — 창고 | 긴 시작 통로, 상자 섬, ㄱ자·S자 통로, 좁은 문, U자 막다른 길. 걸음/Shift달리기/대각선/급반전 시 선두가 지난 모서리를 동료도 따라가는지 확인 |
| 2 — 전시실 | 전시물·벤치 주변 우회로와 넓은 관람 공간. 마지막 동료4·5번 슬롯이 서로 다른 소품으로 이동해 대기. 나머지3명은 위젤을 계속 따라감 |
| 3 — 우회 통로 | 기둥과 여러 갈림길, 긴 순환 경로, 좁은 출입구, 되돌아가는 문. 긴 경로·역주행·방 왕복·대기 동료 복구를 확인 |

실제 충돌은 리더만 처리한다. 동료에 PlayerController/InteractionSystem/조우 Collider를 복제하지 않는다. 시작·방 도착은 기존 실제 경로 초기화를 사용하므로 같은 도착점에서 짧게 겹칠 수 있다. 시작 통로를 충분히 길게 두어 몇 걸음 후6명 행렬이 펼쳐지게 하며, 벽 안에 가상의 시작 행렬을 생성하지 않는다.

안내판은 현재 방의 시험 항목과 조작만 알려 준다. 항상 보이는 큰 디버그 패널이나 별도 조작 체계를 추가하지 않는다. 화살표/WASD 이동, Shift달리기, Z상호작용, 기존 대화의 확인/취소를 사용한다.

## 4. 구경 → 대화 → 재합류

방2 도착 reset 이후, 관람 시작 구역을 리더가 통과하고 두 동료가 안전한 분기 지점까지 도달하면 한 번 실행한다. 뒤쪽 슬롯4·5를 사용해 남아 있는 행렬 중간에 빈자리를 만들지 않는다. 두 동료의 실제 현재 위치에서 작성된 안전 경유점을 따라 소품 앞으로 이동한 뒤 Hold한다. 이동 중에는 대화 프록시를 활성화하지 않는다.

Room 소유의 관람 제어기가 기존 Actor를 참조하며, 상호작용 프록시(Collider + IInteractable)를 관람 Hold 중에만 활성화한다. 프록시는 소품의 고정 좌표가 아니라 해당 Actor의 실제 위치에 동기화하므로 중단 후 다른 위치에 서 있어도 말을 걸 수 있다. 이동 중에는 끄고, 정상 도착/복구 시 위치를 갱신한다. 같은 외형의 별도 NPC를 생성하거나 실제 파티에서 탈퇴시키지 않는다. 기존 DialogueManager/DialogueData/SpeakerData를 사용한다.

대화는 짧은 관람 내용의 DialogueData를 먼저 재생하고, 정상 완료 및 닫힘 뒤 기존 `TryStartLocalizedChoicePrompt`로 **같이 가자 / 더 둘러봐**를 표시한다. 일반 DialogueData 선택지는 X취소를 제공하지 않으므로 독립 prompt의 기존 취소 콜백을 사용한다. 더 둘러봐·X취소는 Hold를 유지하고 반복 대화할 수 있다. 같이 가자는 prompt 닫힘 이후 자기 합류 이동을 시작한다. 대사 스킵·버튼 연타가 prompt나 이동을 중복 시작하지 않도록 한 실행 세대만 소유하며, 원래 대화가 강제 취소되면 다음 prompt를 열지 않는다.

합류는 소품→복귀 경유점→현재 리더 위치로 이동한다. 상호작용 가능한 관람 공간은 장애물 없는 안전 구역으로 작성하고, 마지막 구간을 포함한 경로가 리더 크기의 장애물 검사에 통과한 경우에만 시작한다. 합류 동안 리더 입력을 소유 범위로 잠시 막고 다른 동료는 현재 위치에서 대기한다. 마지막 위치가 기록된 리더 경로 위임을 확인한 뒤 기존 TrySetMode(Follow)를 호출한다. 오래된 최초 분기 경로가 만료되어도 최신 리더 위치를 도착점으로 쓰므로 과거 커서에 의존하지 않는다. 이 이동은 명시된 연출 경로이며 자동 길찾기가 아니다.

관람 출발과 합류 모두 Actor의 현재 위치부터 첫 경유점까지 포함해 경로를 검사한다. 경로가 막히거나 동료/리더/방이 사라지면 소유 이동만 취소한다. 경로가 유효한 실제 추종점에 도착하지 못했으나 Actor와 Room이 살아 있다면 Hold를 유지하고 실제 위치의 프록시를 다시 활성화해 재시도할 수 있다. 재시도 경로도 중단된 현재 위치 기준으로 검사한다. 사라진 Actor/Room의 프록시는 제거한다. 임의의 직선 관통·자동 순간이동으로 실패를 숨기지 않는다. 실패 안내를 표시하고 입력 잠금·대화·Tween을 멱등 해제한다.

방2를 떠나면 기존 MapTransitionService의 암전 도착 reset으로 전원 합류한다. 재입장하면 관람을 다시 시험할 수 있다. 관람 상태는 Room 수명의 임시 상태이며 진행 플래그나 저장 필드로 만들지 않는다.

## 5. 세션과 저장 보호

새 실험실 전용 세션 소유자를 둔다. 기존 BattleLab 컴포넌트는 일반 필드 추종을 제외하므로 재사용하지 않는다. 단독 씬의 새 Play에서만 시작하고 이미 본편 전역 세션/로드가 진행 중이면 파티를 교체하지 않고 명확하게 실행을 거부한다.

허용된 시작에서는 빈 전역 상태를 메모리로 보관한 뒤 테스트6인 SaveData를 기존 GlobalDataManager.FromSaveData 경로로 주입한다. 리더를 정확한 첫 저장 객체에 바인딩하고 Configure(leader,5)를 적용한다. 종료/disable/초기화 실패에는 자신의 파티 객체를 아직 소유하고 있을 때만 복구한다. 다른 로드/새 게임이 이미 파티를 교체했다면 과거 스냅샷으로 덮지 않는다. 기존 FromSaveData/ResetForNewGame은 PartyChanged를 발행하지 않으므로 공용 이벤트 의미를 변경하지 않고, 세션의 매 Update와 초기화/정리 경계에서 최대6개 참조를 확인한다. 감지 전까지 저장 차단은 유지하고 감지 시 해제한다. 새 파티의 추종 명령이나 다른 소유자의 저장 차단은 건드리지 않는다.

단순히 SavePoint를 배치하지 않는 것은 충분한 저장 격리가 아니다. SaveManager에 **소유자 수명의 진행 저장 차단 scope**를 두고 실험 세션이 진입 전부터 복구 완료까지 유지한다. CanSaveCurrentProgress, TrySaveProgress, TrySave와 RequestAutoSave가 같은 차단을 따른다. 실험 중 자동저장 요청은 거부하며 해제 뒤로 미루지 않는다. 저장 삭제 TryDelete도 차단한다. 설정 PlayerPrefs와 읽기 전용 슬롯 검사는 별개로 유지한다. 실제 저장 슬롯/경로/형식은 바꾸지 않는다.

scope는 중첩 해제·중복 Dispose·도메인 재로드 비활성 Play의 세대 초기화를 처리한다. 오래된 핸들이 새 세션의 차단을 해제하지 않게 한다. 일반적인 scope 재사용까지 보호하기 위해 획득 시 기존 대기 자동저장 예약도 취소한다. 한 프레임 안에 획득/해제되더라도 늦은 예약이 임시 데이터를 저장하지 못한다. 실험실에는 저장 오브젝트, 보상, 자동저장 시퀀스를 배치하지 않는다.

## 6. 책임 경계와 성능

- 추종 거리·방향·경로 버퍼·상태 전환은 기존 OverworldPartyFollowerController/Actor/Trail이 소유한다. 상한6명, 실제 지나온 경로, 마지막 방향 Idle, 충돌 없는 표시 객체 계약을 유지한다.
- 실험 세션은 초기 파티·저장 차단·복구만 소유한다. 관람 제어기는 슬롯·프록시·대화·자기 이동 명령만 소유한다. 데이터와 동작을 분리해 본편 Room에도 관람 동작을 재사용할 수 있게 한다.
- RoomContainer/MapTransitionService/RegionEntryCoordinator가 방 수명과 도착을, 기존 CameraController/GameplayCameraRig/Confiner가 카메라를 소유한다. 동료 때문에 렌즈를 바꾸거나 PixelPerfect 규칙을 우회하지 않는다.
- 정상 추종 프레임마다 LINQ·경로 배열 생성·전역 탐색·Prefab 생성은 하지 않는다. 관람 경로와 참조는 진입 때 준비하고 DOTween은 명시적 이동에만 쓴다.
- 대사·선택지·안내판은 기존 LocalizationKey를 사용해 한/영/일/중을 제공한다. 텍스트·화자·이미지는 교체 가능하며 새 대화 엔진을 추가하지 않는다.

## 7. 에셋 생성 안전성

신규 경로만 만드는 명시적 Editor 작업으로 생성한다. 같은 경로에 기존 결과가 있으면 덮어쓰지 않고 중단한다. 새 상시 메뉴/제작창은 추가하지 않는다. 기존 생성기의 전체 SaveAssets/자동 BuildSettings 등록을 그대로 호출하지 않는다.

새 임시 Additive 씬에서 구성하고 대상 Scene/Prefab/ScriptableObject만 저장한다. 배치 실행 직후의 이름 없는 깨끗한 시작 씬1개만 있는 경우에는 Unity의 Additive 제한 때문에 Single로 대체한다. 사용자의 열린 dirty 씬에는 적용하지 않는다. 종료 시 원래 활성 씬을 복원하고 자기 임시 씬만 닫는다. 본편 씬, 기존 BattleLab, Build Settings 내용은 변경하지 않는다. 새로운 meta는32자리 소문자 hex/유일성을 검사한다. 카탈로그는 씬 생성에 따른 자산 언로드를 고려해 최종 등록 직전에 다시 읽고 신규5개 참조만 추가한다. 생성 실패 시 새 부분 결과를 보존하며, 모든 자산 생성이 끝난 뒤 카탈로그만 누락된 경우 검증형 CompleteCatalogRegistration으로 복구한다.

## 8. 완료 검증과 인수 기준

1. 독립 FollowerLab 씬을 열어 Play하면 별도 영입 조작 없이 위젤+5명 파티가 준비되고, 움직이면6명 모두 색상 구분되어 나타난다.
2. 세 방의 모든 출입구를 양방향으로 통과할 수 있고, 선두의 충돌과 카메라 경계가 일치한다. 좁은 통로·모서리·역주행에서 동료가 벽을 직선으로 자르지 않는다.
3. 방2의 두 동료만 구경하며, 각 대화의 선택/취소/반복과 안전 재합류가 동작한다. 출발 중단·복귀 중단 후 재시도, 한 명만 합류한 상태의 방 이동, 대화 종료 프레임의 Room 해제를 각각 검사한다. 입력 잠금·중복 동료·늦은 콜백이 남지 않는다.
4. 방3에서는 대화하지 않고 떠났던 동료도 포함해 전원 다시 따라온다. 방2 재입장으로 동일 시험을 반복할 수 있다.
5. 실험 중 수동/직접/자동 저장 및 삭제는 실패 결과로 차단되고 실제 슬롯은 변경되지 않는다. 종료 후 차단이 남지 않으며 다른 세션 상태를 복구 코드가 덮지 않는다.
6. 생산 경로·상태·수명 단위 검사와 전체 Runtime/Editor 컴파일, 자산 연결/ID/meta/번역 검사를 수행한다. 가능하면 실제 Unity에서 신규 씬 재생/왕복/대화를 검증한다. 관리형 검사와 엔진 Play·실기기 성능 검증 결과는 구분해 보고한다.
7. `docs/overworld-party-follow-guide.md`에 씬 경로·테스트 순서·관람 데이터 편집·시작점 겹침·저장 차단을 추가하고 AIAssets의 당일 기록/사용자 인수 문서를 연결한다. 완료 전 네이티브 확인이 불가능하면 그 항목은 미검증으로 남긴다.
