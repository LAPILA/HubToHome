# 전투 기본 흐름 안정화

2026-10-07 사용자 승인: 매 타격 직전 신호를 기본으로 진행. 전열 전멸 시 계속 싸우기/포기하기, 스탯·장비·저항 및 저장 경계 정리. 시나리오·컷씬·아트와 신규 리듬 예고 시스템은 제외.

## 1. 전조

- 기존 QTEManager/DefenseJudgementPolicy가 표시·판정·모션의 단일 시계를 소유한다.
- 타격 신호는 해당 공격에 허용된 대응의 공통 성공 구간에만 나타난다. 흐린 선행 이펙트를 성공 신호와 혼동시키지 않는다.
- 기존 근접 Z 최소 여유, X의 넓은 판정, 늦은 입력 유예, 유지 Z 일반 방어를 보존한다. 공격 전에 잘못 누른 입력으로 새 성공 입력을 막지 않는다.
- 공격 준비는 첫 타격 전에 끝낸다. 시각적 연타를 무조건 같은 횟수의 입력으로 늘리지 않는다. 추가 예고는 별도 고급 연출이며 기본 신호가 아니다.
- 새로운 리듬 암기 모드/전역 슬로모션/입력 시스템은 추가하지 않는다.

## 2. 전열 전멸 선택

- 전열 전원 사망 + 살아 있는 후열이 있을 때만 선택한다. 개별 사망은 기존 처리.
- 선택 중 행동/대상/방어 입력을 차단한다. 기본 선택은 계속 싸우기, 취소는 기본 선택으로 이동할 뿐 포기로 결정하지 않는다.
- 계속 싸우기: 기존 0.5초 페이드 → 후열 화면 밖 진입 → Idle → 다음 턴.
- 포기하기: 후열을 활성화하지 않고 패배 처리 → 게임오버. 실험실의 자동 탐색 복귀 정책보다 명시적 포기를 우선한다. 디스크 저장을 덮어쓰지 않는다.
- 전투 종료/씬 전환/호스트 비활성화 시 선택창·입력 잠금·연출을 함께 정리한다. 재진입 세대를 검증한다.
- 선택창은 기존 640×480 UI 규칙, 공용 폰트, 키보드/패드 UI 입력 사용. 마우스 조작 추가 없음.

## 3. 스탯·장비·저장

- 새 장비 시스템을 만들지 않고 장착 검증/계산 경로를 일치시킨다. 잘못된 슬롯·캐릭터 제한 장비는 저장 미리보기와 실제 전투 모두 적용하지 않는다.
- 저항의 내부 의미(1=100%, 0=면역)를 보존하면서 피해 배율/상태 누적 배율을 구분하여 안내한다.
- 실제 코드로 확인 가능한 손상 데이터 경계만 보강한다. 임의 수치 밸런스 재설계나 저장 스키마 변경은 하지 않는다.
- 기존 원자적 저장·백업 복구·전투 밖 저장 정책을 유지한다.

## 검증

CLI 컴파일, 순수 C# 경계 검사, Unity 회귀 테스트 소스 추가. Unity 재생·강제 새로고침·재임포트는 하지 않는다. 실기기 조작감/렌더링/프레임 성능은 미검증으로 구분한다. 커밋/푸시 없음.
