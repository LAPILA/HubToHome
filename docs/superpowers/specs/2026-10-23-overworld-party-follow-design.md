# 오버월드 동료 추종 · 승인 설계

사용자 승인: 2026-10-23 ‘추천 구성으로 구현’. 주인공 포함 전열3명 기본, 설정으로 전체6명까지 표시한다. 기존 미커밋 날씨·피격·인트로 변경을 보존하며 커밋/push/Unity Play/Refresh/Reimport는 하지 않는다.

## 목표와 방식

플레이어의 실제 월드 이동 경로를 거리 순서로 보관하고 각 동료가 일정 간격 뒤의 경로를 재생한다. 입력 벡터를 기록하거나 현재 플레이어 위치로 직선 당기지 않는다. 별도 A*/NavMesh로 각기 다른 길을 고르지 않는다. 이는 델타룬의 탐색 분위기를 참고한 본 프로젝트 설계이며 원작 내부 구현을 확인·복제했다는 뜻은 아니다.

경로는 고정 상한의 순환 버퍼다. 같은 위치는 새 점을 만들지 않으며 모서리는 임의 단순화하지 않는다. 실제 물리 이동은 리더만 한다. 동료는 SpriteRenderer/Animator만 소유하고 PlayerController/CharacterBase/InteractionSystem/Rigidbody/Collider/Player태그를 복제하지 않아 문·조우·세이브를 재발동시키지 않는다.

Reset/Record의 int는 방향(Down0/Up1/Left2/Right3)이다. 경로는 별도 Epoch를 갖고 Reset마다 증가한다. 동료 커서는 같은 Epoch에서만 유효하다. 동료별 거리 커서를 속도×dt 예산으로 전진시키고 polyline 위 위치를 샘플링하며 최신 목표 좌표를 향해 MoveTowards/Lerp하지 않는다.

## 표시·식별

- 실제 GlobalDataManager.Party를 읽기만 한다. 동료/스탯/아이템을 테스트 목적으로 생성하지 않는다. 기본은 전열3명 중 리더를 뺀2명, 표시 상한은6명이다.
- 같은 DB ID의 두 동료도 서로 다른 저장 객체/현재 순서로 유지한다. 문자열 DB ID만으로 합치지 않는다. 연출 명령의 동료 번호는 **1=첫 번째 동료**, 최대5이며0은 전체 선택(개별 이동에는0 불가)이다.
- CharacterData에 선택적인 필드 표시용 Prefab을 둔다. 전용 외형이 없으면 BattlePrefab의 루트 SpriteRenderer/Animator, 그것도 없으면 리더 표시를 읽는 fallback을 제공한다. 외형 소스 자체를 Instantiate하지 않는다. 임의 게임플레이 스크립트/충돌은 복제하지 않는다. 중첩 외형은 명시한 표시용 계약과 검사로 지원한다.
- 동료 루트는 리더 자식이 아니라 같은 씬의 별도 루트다. 이동/배율 중복을 방지하고 수명은 리더가 소유한다. Characters/order3·발 피벗·기존 Y정렬을 유지한다.
- 기본 걷기 계약은 MoveX/MoveY/IsMoving, 마지막 진행 방향 Idle 유지다. 리더 달리기 속도를 반영하며 따라잡기는 상한을 둔다. 정상 이동 프레임마다 할당/전역 탐색/Instantiate하지 않는다.

## 연출 상태와 복구

- Follow: 보관 경로를 따라간다. Hold: 현재 위치와 경로 커서를 보관하고 멈춘다. Detached: 자동 추종에서 제외하되 전투 파티에서는 빼지 않는다. Hidden은 이동 상태와 독립된 표시 플래그다.
- 이동 명령은 한 동료의 명시 경유점/목표를 DOTween으로 실행한다. 새 명령은 자기 이전 이동만 취소한다. 경유점이 없는 개별 이동은 연출자가 통로를 책임지는 표시 이동이지 자동 길찾기가 아니다.
- 보관 경로 위에서 Hold를 풀면 커서부터 속도 상한 내에서 따라잡는다. 연출로 경로 밖에 있거나 과거 기록이 만료되면 벽을 가로지르는 직선 합류를 하지 않는다. 명시한 경유점으로 복귀하거나 암전/맵 도착 시 재집결한다. 강제 재집결은 모든 동료를 리더 위치에 모아 다음 실제 이동부터 줄을 편다. 가상의 뒤쪽 경로를 만들어 벽 안에 배치하지 않는다.
- 기존 대화/메뉴/전투진입 hold에서는 일반 추종을 멈춘다. Cutscene 전체를 무조건 숨기지는 않는다. 명시 연출 이동은 실행 가능하다. Battle 모드 진입 때 숨기고 필드 복귀/도착 때 경로를 재설정한다.
- 리더 Start(기존 battle clone guard 뒤), LoadPositionFromGlobal, MapTransitionService.TryApplyArrival에 좁은 연결을 둔다. 같은 좌표의 다른 방/짧은 warp도 거리 임계값에 의존하지 않고 reset한다. 예외적인 큰 이동도 감지한다.
- 실험실 BunnySlimeBattleLabSession은 기존 visual-only preview와 카메라 소유자가 있으므로 자동 일반 추종에서 제외한다. 기존 실험실·전투 객체/배치/카메라는 바꾸지 않는다.
- 이벤트/로드/새 게임으로 Party 객체가 바뀌면 동기화한다. 연출 고정/숨김은 runtime 표시 상태이며 세이브 스키마에 새 필드를 추가하지 않는다. 실제 영입·탈퇴와 구분한다.
- 경로 reset/맵 도착/전투 진입/리더 disable·destroy/roster 교체는 실행 중인 개별 이동도 자기 명령 세대로 취소하고 대기자를 종료시킨다. 이전 Tween/완료 콜백이 새 방 위치를 덮지 않아야 한다.
- Gather는 명시적인 암전·도착 재배치용이다. 일반 Follow/Rejoin에서 기록 만료를 숨기기 위해 자동 호출하지 않는다. 방 진입 reset은 연출 상태를 기본 Follow/표시로 초기화한다. 다음 방까지 지속되는 이야기상 이탈은 실제 파티 변경/기존 진행 플래그와 방 진입 시퀀스로 적용한다.

## 카메라·제작 연결

탐색 카메라는 기존 리더 Follow/Confiner/lens4를 유지한다. 동료 따라잡기/재합류 때문에 자동 group 줌이나 흔들림을 걸지 않는다. 개별 연출은 기존 CameraController의 제어권·focus/frame/reset을 사용하며 Cinemachine Transform을 직접 움직이지 않는다.

Odin 한글 Inspector와 공개 제어 API/UnityEvent 호출을 제공한다. 기존 Sequence Maker에는 좁은 서비스 기반 동료 제어 Action을 추가한다. Action Catalog·검증·Preparation 안전성·예시를 함께 연결하고 Source 문법의 기존 계약은 유지한다. 슬롯0(전체)/1~5, 명령별 유효 파라미터, 없는 동료 실패와 취소를 명확히 한다. Preview는 생산 파티/진행을 변경하지 않는다.

## 검증·문서

순환 버퍼의 모서리·거리·프레임 분할·오래된 커서·정지·재설정, 동일 DB 동료의 별도 유지, battle clone 제외, 문/조우 부작용 없는 외형, 명령 취소/복구를 검증한다. 전체 Runtime/Editor CLI 컴파일과 관리형 생산 코드 검사, 자산/meta/인코딩/문서 링크를 확인한다. 엔진 Play/NUnit/GPU/실기기·원작 동일성은 검증하지 않았다고 구분한다.

기존 Google Docs 제작 가이드의 캐릭터 장에 사용법·확인표를 추가하고 스타일/표/링크를 보존한다. Notion 학습실에는 데이터구조·상태·호출 흐름·실습을, 제작 운영실에는 이번 작업과 검증 게이트를 보기 좋게 연결한다. 기존 날짜·팀 담당자·미완료 작업을 임의로 완료시키지 않는다. 스크린샷은 가능한 편집기/문서 화면만, 실제 Unity 재생 화면을 만들어낸 것처럼 게시하지 않는다.
