# 기능별 코드 따라 읽기 설계

## 승인과 목적

사용자가 2026-10-12에 선택한 2번, ‘기능별 코드 해설서’를 구현한다. 기존 Notion 학습실과 색인은 보존한다. 제목만 아름다운 요약이 아니라 진입 함수 → 상태 소유자 → 계산 → UI 반영 → 실패 복구를 실제 소스와 연결한다.

## 범위

- 현재 작업 트리의 `Assets/_Game/Scripts`를 근거로 작성한다. 미커밋 변경도 포함하며 HEAD만을 현재 구현으로 주장하지 않는다.
- `docs/study/deep`에 입문 도구와 기능별 해설을 분리한다. 대표 흐름을 깊게 설명하고, 686개 파일 모든 줄을 설명했다는 주장은 하지 않는다.
- 원문 발췌, 경로, 줄 범위, SHA-256을 검증 가능한 매니페스트로 남긴다.
- 표, 짧은 흐름도, 코드, 실습 체크리스트를 사용한다. 긴 단일 페이지에 전부 몰지 않는다.
- 실제 Notion 목적지는 `3f6641f6190180bb8567ff9caf83e5a9`의 하위 자료실이다. 기존 내용/공유 권한을 변경하지 않는다.
- Unity 실행, 게임 소스 변경, 커밋, 푸시는 하지 않는다.

## 문서 규격

한 장은 현상/읽을 파일 → 호출 흐름 → 코드 발췌 해설 → 상태 추적 → 자료구조와 선택 이유 → 실패 경계 → 실습과 예상 결과 → 면접에서 설명할 질문 순서다. 실습은 실행하지 않았다면 예상 결과로 명시한다. 코드에서 확인한 사실과 설계 해석을 분리한다.

## 완료 기준

새 문서와 인용 소스의 정합성, 경로, 인코딩, 코드 펜스, 내부 링크를 검사한다. 새 문서만 네이티브 Markdown ZIP으로 가져오며 모든 새 페이지의 본문과 표/코드 표시를 확인한다. 루트에 새 자료실 링크를 연결하고 실제 URL을 로컬 기록에 남긴다.
