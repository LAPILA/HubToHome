# Battle Result Confirm Flow Design

## Goal

전투 결과를 자동으로 닫지 않고 플레이어 확인 입력으로 진행한다. 첫 페이지는 EXP, 골드, 드롭을 보여주고, 레벨업한 파티원은 한 명당 한 페이지로 분리해 성장 결과를 놓치지 않게 한다.

## Approach

- `BattleResultUI.Show`의 기존 호출 계약과 패널 외형을 유지한다.
- 결과 표시 순서는 보상 페이지 1개, `DidLevelUp`인 파티원 페이지 순서다.
- 각 페이지는 최소 입력 지연 뒤 새로운 확인 입력을 기다린다.
- 지연값이 0이어도 페이지마다 최소 한 프레임을 넘겨 같은 입력의 중복 소비를 막는다.
- 기본 입력은 `GameInput`의 확인, 전투 확인, 대화 진행 경로를 공유한다.
- 입력 공급자를 주입할 수 있게 해 실제 Input System 없이 페이지 진행을 검증한다.
- 완료, 강제 중단, 오브젝트 비활성화 모두 기존 단일 정리 경로를 사용한다.
- 표시 세대 토큰으로 외부 비활성화와 중복 실행을 감지해 오래된 코루틴이 새 UI를 정리하지 못하게 한다.

## Page Content

- 보상: `VICTORY` 또는 `INSTANT VICTORY`, EXP, 골드, 드롭 아이템
- 레벨업: `LEVEL UP`, 캐릭터 이름과 이전/새 레벨, 0보다 큰 능력치 상승량
- 레벨업하지 않은 파티원은 별도 페이지를 만들지 않는다.

## Compatibility

- 일반 전투, 심리스 전투, 오버월드 즉시 처치가 같은 흐름을 사용한다.
- `BattleRewardResult`, 보상 지급, 전투 종료, 저장 데이터는 변경하지 않는다.
- 기존 `_holdDuration` 직렬화 값은 최소 입력 지연 값으로 이전한다.
- Scene, Prefab, ScriptableObject는 수정하지 않는다.

## Verification

- 보상 페이지가 확인 입력 전까지 자동으로 닫히지 않는다.
- 레벨업 캐릭터마다 정확히 한 번의 추가 확인 입력을 요구한다.
- 코루틴 강제 폐기 시 Tween과 Raycast 차단이 남지 않는다.
- 지연 중 입력은 만료되고, 지연값 0에서도 다음 페이지 입력으로 재사용되지 않는다.
- 외부 실행자가 `Show`를 구동하더라도 양수 입력 지연 중 UI 비활성화 시 다음 프레임에 코루틴이 종료된다.
- 오래된 `Show`와 Fade가 새 표시의 상태나 Tween 소유권을 덮어쓰지 않는다.
- 실제 오버월드 즉시 처치 코루틴이 글로벌 결과 화면과 확인 대기를 사용한다.
- 보상·성장, TestMap 전투, 전체 EditMode 회귀를 통과한다.
