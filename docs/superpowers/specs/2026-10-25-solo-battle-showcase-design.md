# 위젤 단독 전투 연출 실험실

2026-10-25 사용자 승인: 토끼 통합/제브 연출 두 입구를 기본 외형 위젤1명으로 시작하고 후열 실습을 제거한다. 기존 위젤10종·제브 근접5종을 실험실 전용 사본으로 보강한다. 본편 DB·실제 저장·본편3+3 규칙은 보존한다.

## 실험실 경계

- `BunnySlimeBattleLabData.Party`는 기존 흰 위젤 샘플1명만 사용한다. 안정적 `lab.wizzel.front` ID와 원본 외형/압력 자원 참조를 유지해 시나리오 대상을 깨지 않는다. 다른 동료는 실행 파티/미리보기/입구에서 제외하며 참조가 있는 공용 자산을 임의 삭제하지 않는다.
- Session의 시작 검증·파티 구성·소유권 복원·메뉴 설명·생성기 기본값·회귀를 모두1인으로 맞춘다. 저장 파일을 읽거나 기록하지 않는 기존 새 세션 경계를 유지한다. 전멸 실습 입구는 제거하되 본편의 후열 교대는 삭제하지 않는다.
- 기존 두 Scenario Source와 대응 Runtime Asset을 함께 동기화한다. 등장 대상과 스킬 참조를 일치시키고 source hash를 갱신한다. 전체 생성기/씬/프리팹 재작성은 하지 않는다.

## 스킬과 재사용

- 위젤 원본 tests_Player10종과 제브 원본5종은 수정하지 않는다. 별도 실험실 사본의 고유 ID/GUID를 만들고 카탈로그·실험실 DB·시나리오가 그 사본을 읽는다.
- 기본 이동/대기/애니/VFX/실시간 QTE/연타/공중 교차/사선 화면 분할은 기존 블록을 사용한다. 이동 잔상은 이동 때만, 큰 강조는 핵심 순간에만 적용한다. 스킬 이름/캐릭터 이름에 따른 런타임 분기는 만들지 않는다.
- 새 `Action_PresentationAccent`는 컷인/실루엣 대비/짧은 점멸의 표시 전용 블록이다. 공용 표시 서비스가 Canvas를 지연 생성·재사용하고 원본 배우/공유 재질·전투 수치는 변경하지 않는다. Odin의 한글 이름/시간/색/강도/소리/스프라이트 필드로 다른 스킬에도 재사용한다.
- 위젤은 찌르기·이연·전후 돌파·고속 난무·공중 강하·증기 파열·사선 일섬·압력 결정타를 서로 다른 타이밍으로 조합한다. QTE는 아군 스킬만 사용하고 기존 실시간 판정/정상 피해·실패 감소 정책을 유지한다. 압력 강화/소모는 기존 ResourceEffect를 사용한다.
- 제브는 근접 냉기/감전5종이다. 준비→읽을 수 있는 전조/방어창→실제 타격 순서를 유지한다. X/Z/C 요구는 구별하며 원거리/QTE는 추가하지 않는다. 여러 아군을 순회하던 기술은 Lab 사본에서 단독 대상 다단 돌파로 바꿔1인전에서도 연격이 남게 한다. 과한 부여량은 Lab에서만 조정한다.

## 픽셀·성능·취소

엄격 Pixel Perfect의 고정 전투 Lens/정수 출력/Dutch0과 HUD/QTE 정방향을 유지한다. 화려함을 위해 전역 줌/회전/흔들림을 다시 켜지 않는다. 새 카메라/RenderTexture/상시 블러/휴면 Update를 추가하지 않는다. 효과는 짧고 활성 순간에만 실행하며 플래시 접근성 설정을 따른다.

연출은 소유 토큰과 finally로 정상 종료·스킬 취소·배우/호스트 소실·씬 전환을 정리한다. 이전 종료가 최신 표시를 숨기지 않는다. 적의 대응창/QTE/중앙창을 가리지 않으며 입력을 소비하지 않는다.

## 검증과 변경 제외

관리형 정책/수명/데이터 검사와 전체 C# CLI,15개 스킬 ID·RID·GUID·카탈로그·대상 수/전조-소비자 순서·Source/Runtime 해시를 확인한다. 원본 스킬/본편 DB/기존 Scene/Prefab 해시를 비교한다. Unity Play/강제 Refresh/전체 생성기/실기기 측정/실제 저장 I/O/커밋/푸시는 수행하지 않는다. 실제 시각 박자·프레임/발열·최종 아트 품질은 미검증으로 남긴다.
