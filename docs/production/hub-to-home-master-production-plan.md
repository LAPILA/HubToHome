# HUB TO HOME 제작 마스터 플랜

> 2026년 제작의 단일 기준 문서. 사용자가 범위와 우선순위를 수정한 뒤 같은 ID로 Jira 에픽과 작업을 생성한다.

## 1. 올해의 목표

### 최종 목표

- **Chapter 1:** 처음부터 끝까지 진행 가능하고 외부 테스트에 배포할 수 있는 상태
- **Chapter 2:** 핵심 지역, 이야기, 일반 전투, 대표 연출이 연결된 세로 단면
- **제작 기반:** 기획자가 맵, 대화, 컷씬, 적 조우, 스킬 데이터를 직접 배치하고 검증할 수 있는 상태

### Chapter 1 완료 조건

- 새 게임에서 Chapter 1 종료 지점까지 진행 차단 없이 플레이된다.
- 탐색, 대화, F 선공, 일반 전투, 보스전, 결과 복귀가 한 빌드에서 연결된다.
- 플레이어가 현재 목표와 이동 이유를 이해한다.
- 디버그 문구, Missing 참조, 의도하지 않은 임시 자산이 없다.
- 주요 해상도와 지원 입력에서 UI가 잘리지 않는다.
- 저장을 넣으면 실패·손상에 대응하고, 빼면 데모 정책을 명시한다.
- 치명적 버그와 진행 차단 버그가 0건이다.
- 외부 에셋, 폰트, 음악, 효과음의 라이선스가 기록되어 있다.

### Chapter 2 세로 단면 완료 조건

- 대표 지역 한 구간을 20~30분 플레이할 수 있다.
- 신규 적 규칙, 대표 전투 변주, 주요 시나리오 장면을 각각 하나 이상 검증한다.
- Chapter 1과 같은 제작 파이프라인으로 콘텐츠를 추가한다.
- 임시 아트·오디오는 허용하되 교체 목록과 제작 규격을 남긴다.

### 올해 범위에서 원칙적으로 제외

- 핵심 동료 5명의 전체 개인 서사와 최종 성장
- 모든 엔딩과 다회차 분기
- 완전한 상태이상 생태계와 대규모 장비 시스템
- Chapter 1에 쓰지 않는 별도 전투 Game Module
- 실제 사용 사례가 없는 범용 툴 재작성
- Chapter 1에 쓰지 않는 모든 맵 마커 기능
- 미드 배틀 저장과 전투 중 Continue

## 2. 팀 운영과 담당

| 코드 | 역할 | 주책임 | 지원 책임 |
|---|---|---|---|
| `DIR` | 사용자/디렉터 | 최종 결정, PM, 게임 기획, 통합 확인 | 시나리오 대체 작성, 아트·프로그래밍 지원 |
| `ART` | 아티스트 | 캐릭터, 배경, 타일, 전투 아트, UI 원화 | 아트 규격과 Unity 적용 확인 |
| `DEV` | 프로그래머 | 런타임, 에디터 도구, 통합, 빌드 | 기술 기획과 안정성 검토 |
| `SCN` | 시나리오 기획 | 플롯, 대사, 캐릭터 문서 | 구현용 데이터 정리 |
| `AI` | Codex/AI | 코드 보조, 테스트, 문서, Jira 정리 | 데이터 검증과 반복 작업 자동화 |

### 권장 작업 비율

| 분야 | 주담당 | 사용자 | 운영 원칙 |
|---|---:|---:|---|
| PM·게임 기획 | 사용자 80% | 사용자 중심 | 최종 결정은 사용자 한 명이 닫는다. |
| 시나리오 | SCN 50~70% | 30~50% | 일정이 밀리면 사용자가 직접 맡는다. |
| 아트 | ART 75~85% | 15~25% | ART가 본 제작, 사용자가 방향·보조·Unity 확인을 맡는다. |
| 프로그래밍 | DEV 75~85% | 15~25% | DEV가 구현, 사용자가 데이터 배치와 작은 보강을 맡는다. |
| QA | 전원 | 사용자 총괄 | 만든 사람이 아닌 사람이 최소 한 번 확인한다. |

### 사용자 주간 운영

시간 견적은 쓰지 않고 출근·재택 패턴을 작업 성격에만 반영한다.

- **월요일:** 주간 목표, 막힌 결정, Jira 우선순위 정리
- **화요일:** 기획 작성, Unity 배치, 통합 등 집중 작업
- **수·목요일:** 리뷰, 피드백, 작은 수정, 자료 정리
- **금요일:** 브랜치 통합, 테스트 빌드, 플레이 확인
- **주말:** 기본 일정에 넣지 않는 완충 구간

## 3. 분류 기준

### 우선순위

| 값 | 의미 |
|---|---|
| `P0` | 다른 제작을 막거나 플레이 진행을 깨뜨린다. |
| `P1` | Chapter 1 배포에 반드시 필요하다. |
| `P2` | 완성도 또는 Chapter 2 세로 단면에 필요하다. |
| `P3` | 확장 아이디어다. 올해 목표를 위협하면 보류한다. |

### 작업 크기

| 값 | 의미 |
|---|---|
| `XS` | 한 파일·데이터·결정 수준의 작은 작업 |
| `S` | 한 명이 한 검토 주기 안에 끝내는 산출물 |
| `M` | 여러 파일 또는 자산이 묶인 기능 |
| `L` | 둘 이상의 역할과 통합 확인이 필요한 기능 |
| `XL` | Jira 작업으로 만들지 않고 반드시 분할 |

### 상태

`할 일 → 진행 중 → 검토 중 → 완료`

- 결정 항목도 `할 일`에 두고 업무 유형을 `PM` 또는 `게임 기획`으로 둔다.
- 차단은 별도 상태 대신 Jira 차단 관계와 사유를 쓴다.
- 완료는 산출물, 완료 조건, 통합 확인이 모두 끝난 상태다.

## 5. 콘텐츠 범위 기준

수량은 이 표에서만 바꾼다. 개별 작업명은 가급적 수량을 반복하지 않고 `기준 범위`를 참조한다.

### Chapter 1

| 항목 | 기준 범위 | Stretch | 올해 제외 |
|---|---|---|---|
| 첫 플레이 | 45~60분 | 60~90분 | 90분 초과 |
| 지역 | 도입 1, 거점 1, 탐색 1, 클라이맥스 1 | 탐색 구간 1개 추가 | 별도 대형 던전 |
| 실내·보조 룸 | 1~2개 | 2개 추가 | 기능 없는 장식용 실내 |
| 컷씬 | 도입 1, 중간 1, 보스 전후 2 | 중간 1~2개 추가 | 장시간 비상호작용 영상 |
| 반복 NPC | 4~6명 | 4명 추가 | 고유 기능 없는 대량 NPC |
| 핵심 대화 캐릭터 | 3명 | 2명 추가 | Chapter 1에 필요 없는 동료 소개 |
| 일반 적 | 신규 2종 | 신규 1종 추가 | 3종 초과 신규 제작 |
| 정예 적 | 없음 | 1종 | 별도 정예 계열 |
| 보스 | 1종, 최대 2페이즈 | 짧은 추가 패턴 | 두 번째 보스 |
| 플레이 파티 | 주인공, 기존 동료가 준비됐으면 1명 | 추가 동료 1명 | 5인 동료 완성 |
| 활성 스킬 | 캐릭터당 3~4개 | 캐릭터당 1개 추가 | 대규모 스킬 트리 |
| 핵심 아이템 | 4~6개 | 4개 추가 | 대규모 장비·제작 시스템 |

Stretch는 기준 범위가 통합 빌드에서 끝난 뒤에만 시작한다. 기존 완성 자산을 재사용할 수 있다는 사실만으로 Stretch가 자동 승인되지는 않는다.

|---|---|---|

## 8. 역할별 Jira 필터

ID 목록을 문서에 중복 관리하지 않는다. Jira의 `업무 유형` 필드를 기준으로 저장 필터를 만든다.

| 저장 필터 | 필터 기준 |
|---|---|
| 내 PM 작업 | `업무 유형 = PM AND 상태 != 완료` |
| 내 게임 기획 작업 | `업무 유형 = 게임 기획 AND 상태 != 완료` |
| 내 시나리오 작업 | `업무 유형 = 시나리오 AND 상태 != 완료` |
| 내 프로그래밍 작업 | `업무 유형 = 프로그래밍 AND 상태 != 완료` |
| 내 아트 작업 | `업무 유형 = 아트 AND 상태 != 완료` |
| 내 음악·오디오 작업 | `업무 유형 = 음악·오디오 AND 상태 != 완료` |
| 내 QA 작업 | `업무 유형 = QA AND 상태 != 완료` |

실제 Jira 생성 시 각 필터에 `담당자 = 현재 사용자`와 `마일스톤`, `우선순위` 조건을 추가한다.

## 9. 분야별 완료 조건

### 기획·시나리오

- `TBD`에는 구현 차단 여부와 결정 시점이 있다.
- 장면마다 플레이어 목표, 진입 조건, 종료 상태가 있다.
- ID, 등장인물, 대사, 플래그, 보상이 구현 표에 있다.
- 원문과 Unity 데이터가 같은 버전이다.

### 아트

- 원본과 Unity export가 정해진 폴더에 있다.
- PPU, 피벗, Filter Mode, 압축, 정렬 규칙이 맞는다.
- 실제 카메라와 배경 위에서 크기·가독성을 확인했다.
- 임시 아트에는 교체 담당과 목표가 있다.

### 프로그래밍

- 실패·복구 경로 테스트가 있다.
- Inspector 참조와 저장 데이터 호환을 확인했다.
- Unity 콘솔 오류가 없고 Runtime/Editor 컴파일이 통과한다.
- 기획 조정값은 Inspector 또는 데이터에 노출한다.
- 실제 Chapter 1 사용 사례가 없는 범용 기능은 만들지 않는다.

### QA

- 재현 절차, 기대·실제 결과, 빌드·브랜치를 기록한다.
- 수정자가 아닌 사람이 검토한다.
- 수정 후 인접 기능도 회귀 확인한다.

## 10. 협업 도구

### Notion

- GDD 요약, 게임 규칙, 캐릭터 바이블, 지역 기능, 결정 기록을 둔다.
- 매일의 장문 작업 일지는 두지 않는다.
- 최신 규칙만 유지하고 Jira 링크를 연결한다.

### Google Drive

- 장편 시나리오 원문, 리뷰본, 콘셉트 원본, 외부 공유 자료를 둔다.
- 파일명에 상태를 계속 덧붙이지 않고 문서 버전 기록을 쓴다.

### Discord

- 빠른 질문, 피드백, 캐릭터·지역 스레드, 빌드 공지에 쓴다.
- 결정은 Discord에만 남기지 않고 Notion 또는 프로젝트 문서로 옮긴다.
- 업무 요청에는 Jira ID를 붙인다.

### Git

- 코드, Unity 에셋, 프로젝트 문서의 실제 변경 이력을 관리한다.
- 폴더 이동과 기능 변경을 다른 커밋으로 분리한다.
- Scene, Prefab, ScriptableObject 충돌은 담당자와 확인한다.

### Jira

- 할 일, 담당, 우선순위, 마일스톤, 차단 관계의 기준이다.
- 세부 원문 대신 Notion·Drive 링크를 연결한다.
- 완료 증거로 PR/커밋, Unity 경로, 테스트 결과 중 하나 이상을 붙인다.

## 11. Jira 생성 규칙

### 에픽

`EPIC 0~8`을 그대로 만든다. 결과형 에픽과 공용 제작 스트림 에픽을 함께 쓰는 혼합 구조다. `DEC-*`는 EPIC 1에 속한다.

### 업무 유형 필드

`PM / 게임 기획 / 시나리오 / 프로그래밍 / 아트 / 음악·오디오 / QA`

### 추가 필드

- `목표 마일스톤`: M0~M6
- `작업 크기`: XS/S/M/L
- `우선순위`: P0/P1/P2/P3를 Jira 우선순위에 대응
- `담당자`: `실행/지원`의 첫 번째 역할에 해당하는 실제 실행 책임자 한 명
- `지원자`: 나머지 검토·지원 인원
- `선행 ID`: 시작 전에 완료되어야 하는 결정 또는 작업

### 이슈 유형

- `Epic`: 기능·결과 묶음
- `Story`: 플레이어가 체감하는 결과
- `Task`: 기획서, 아트, 데이터, 도구, 검증
- `Bug`: 기대 결과와 다른 결함
- `Subtask`: 하나의 작업을 나눌 때만 사용. 모든 `L` 작업은 시작 전에 자산·화면·테스트 흐름별 Subtask로 분리

레이블은 기본 분류에 사용하지 않는다. 긴급 핫픽스나 외부 빌드 같은 일시적 묶음에만 쓴다.

### 생성 순서

1. `DEC-*`와 `FND-*`를 먼저 생성한다.
2. M0 결정 후 Chapter 1 P0/P1을 생성한다.
3. `CH2-001~003`은 M3~M4 사전 제작 작업으로 생성한다.
4. `CH2-004~007`은 M4 출시 승인 후에만 생성한다.
5. 마일스톤 미완료 작업은 자동 이월하지 않고 축소·분할·폐기한다.

| M2 → M3 | 모든 기능 구현 완료. 이후 기능 추가 금지 |
| M3 → M4 | 내부 완주·외부 테스트 1차 완료, 진행 차단 버그 0건 |
| M4 → M5 | `REL-016` 출시 승인 후 Chapter 2 본 제작 시작 |

## 13. 주요 위험

| 위험 | 조기 신호 | 대응 |
|---|---|---|
| 사용자가 승인 병목이 됨 | 여러 작업이 검토만 기다림 | 월·화에 결정 묶음 처리, 작은 선택은 담당자에게 위임 |
| 도구가 콘텐츠를 밀어냄 | 기능은 늘지만 실제 장면이 안 늘어남 | 새 도구에는 Chapter 1 사용 사례를 의무 연결 |
| 아트 규격이 늦게 바뀜 | 여러 PPU·크기가 혼재 | M1 전 `DEC-011`, `ART-002`, `MAP-002` 잠금 |
| 시나리오 범위 증가 | 새 인물·지역·분기 계속 추가 | 콘텐츠 상한과 1대1 교환 규칙 적용 |
| 연출이 전투 판정을 가림 | 카메라·VFX로 예고가 안 보임 | 판정 중 카메라 제한과 가독성 QA |
| 저장·분기가 지연시킴 | Continue와 다회차를 동시 설계 | 미드 배틀 저장 제외, Chapter 1에 필요한 사실만 저장 |
| 대규모 작업 트리로 머지 손실 | 삭제·신규가 수백 개 표시 | `FND-001` 전 추가 폴더 이동 중지 |
| 전문 인력 일정 변동 | 핵심 작업이 한 명에게만 존재 | 원본·규격·현황 문서화, 사용자용 최소 대체 경로 유지 |
