# 오버월드 6인 동행 실험실 사용법

기존 필드 추종과 Room 전환을 이용해 리더 1명과 동료 최대 5명의 이동·관람·재합류를 시험하는 독립 개발 씬입니다. 씬과 자산 생성은 완료되어 바로 열어 사용할 수 있습니다. 초기 구성의 Unity 배치 검사에서 6인 추종·두 동료 관람·개별 재합류·다음 방 이동·저장 차단 해제까지 통과했습니다. **2026-10-27의48픽셀 간격·순차 출발·입장 관람 수정은 컴파일과 관리형 검사까지 확인했으며, 변경 후 실제 Play는 미검증입니다.** 화면과 수동 대화 입력 감각, 모바일 성능은 마지막 체크리스트로 별도 확인하세요.

## 1. 시작 위치와 실행 조건

기준 폴더는 `Assets/_Game/Content/Maps/Development/Regions/FollowerLab`입니다.

| 대상 | 기준 폴더 아래 경로 |
| --- | --- |
| 실행 씬 | `Scenes/FollowerLab.unity` |
| 파티·시작 위치 설정 | `Data/FollowerLabDefinition.asset` |
| 창고 Room | `Prefabs/Rooms/Room_FollowerLab_Warehouse.prefab` |
| 전시 Room | `Prefabs/Rooms/Room_FollowerLab_Exhibition.prefab` |
| 우회로 Room | `Prefabs/Rooms/Room_FollowerLab_Detour.prefab` |
| Room 데이터 | `Data/Rooms/Room_FollowerLab_<Warehouse·Exhibition·Detour>_Definition.asset` |
| Area 데이터 | `Data/Areas/Area_FollowerLab_<Warehouse·Exhibition·Detour>.asset` |
| 실험용 동료 데이터 | `Data/Characters/Wizzel_Follower_1.asset` ~ `Wizzel_Follower_5.asset` |
| 안내·관람 대사와 화자 | `Data/Dialogue/` |

1. 현재 Play를 종료합니다. 열린 작업은 사용자가 필요한 범위만 저장합니다.
2. 생성된 `FollowerLab.unity`를 단독으로 엽니다. 본편 씬에 Additive로 추가하거나 이미 진행 중인 게임에서 불러오지 않습니다.
3. `FollowerLabDefinition.asset`의 리더·동료·시작 방/구역 참조를 확인한 뒤 새 Play를 시작합니다.
4. 기본 시작은 창고의 `default` 지점이며, 별도 영입 조작 없이 설정 목록으로 임시 파티를 준비합니다.

세션은 공용 Bootstrap보다 먼저 기존 전역 상태와 다른 실험 세션의 존재를 확인합니다. 기존 플레이 상태, 여러 열린 씬, 누락된 참조, 이미 존재하는 진행 정보가 있으면 시작을 거부합니다. 콘솔의 `OverworldFollowerLabSession` 오류를 확인하고 새 Play에서 다시 시작하세요. 컴포넌트를 껐다 켜서 같은 세션을 재시작하는 방식은 지원하지 않습니다.

새 프로젝트에서 결과가 아직 없다면 개발자가 `OverworldFollowerLabBuilder.Build()`를 명시적으로 실행합니다. 지금은 다시 실행할 필요가 없습니다. 상시 생성 메뉴는 없으며, 기존 FollowerLab 콘텐츠가 있으면 덮어쓰지 않고 중단합니다. 생성기는 Build Settings를 자동 변경하지 않습니다. 생성 실패로 남은 부분 결과도 자동 삭제하지 않습니다. 모든 자산이 만들어지고 카탈로그 등록만 누락된 경우에는 `CompleteCatalogRegistration()`이 경로/ID/정의를 검증한 뒤 신규 참조만 등록합니다.

## 2. Editor에서 인원과 순서 바꾸기

Play를 종료하고 `FollowerLabDefinition.asset`을 선택합니다. Odin Inspector의 `리더`와 `동료 목록 (최대 5명)`이 편집 진입점입니다.

- `+`로 항목을 추가하고 CharacterData를 연결합니다. 삭제 버튼은 목록의 참조를 제거하며 CharacterData 자산이나 카탈로그를 삭제하지 않습니다.
- 항목을 드래그하면 동료의 추종 순서가 바뀝니다. 동료 0명은 리더만, 2명은 총 3명, 5명은 총 6명입니다.
- 리더는 필수입니다. null 목록·빈 항목·중복 고유 ID·5명 초과는 시작 오류이며 자동으로 잘라내거나 저장하지 않습니다.
- 인라인 편집은 연결된 CharacterData 자체를 수정합니다. 기본 리더는 본편 `Assets/_Game/Content/Characters/AllyDB/WizzelDB.asset` 참조입니다. 실험용 수치를 바꾸려면 원본을 직접 고치지 말고 별도 CharacterData를 준비하세요.
- 새 CharacterData는 고유 `CharacterID`와 기본 능력치가 있어야 하고, `Assets/_Game/Resources/HubToHome/GameContentCatalog.asset`의 Characters에 동일한 자산으로 등록되어야 합니다. 기본 실험 동료 ID는 `lab.follower.1` ~ `lab.follower.5`입니다.

기본 동료는 청록·보라·주황·파랑·분홍 순서입니다. 외형/색상은 CharacterData의 기존 필드로 편집합니다. 실제 파티 생성은 실험 세션만 수행하며, 일반 맵의 영입 정책이나 전투 인원 규칙을 바꾸지 않습니다.

`시작 방`과 `시작 구역`은 서로 연결된 RoomDefinition/AreaDefinition 쌍이어야 합니다. `시작 지점 ID`는 해당 Room의 SpawnPoint와 일치해야 하며 기본값은 `default`입니다. 이 참조를 바꿀 때에는 씬의 RegionEntryCoordinator에 해당 Room도 등록되어 있는지 확인하세요.

## 3. 세 방의 시험 순서

방의 좌우 출구는 순환 구조입니다. 오른쪽으로 진행하면 **창고 → 전시 → 우회로 → 창고**, 왼쪽은 그 역순입니다. 출구 반대편의 `from_left` 또는 `from_right` SpawnPoint로 도착합니다.

| 방 / Room ID | 기본 시험 항목 |
| --- | --- |
| 창고 / `lab.follower.warehouse` | 번갈아 위·아래로 돌아야 하는 선반과 상자. 모서리·S자 이동·급반전·달리기 |
| 전시 / `lab.follower.exhibition` | 전시대·상자·두 관람 동료. 개별 대화·머물기·재합류 |
| 우회로 / `lab.follower.detour` | 중앙 섬·기둥·막다른 구간. 순환·분기·되돌아오기 |

기존 조작을 사용합니다: 방향키/WASD 이동, Shift 달리기, Z 상호작용·확인, X 취소. 각 방 입구 근처의 안내판에도 시험 항목이 있습니다.

처음 시작하거나 방을 이동하면 동료는 리더의 도착 위치에 겹쳐 있을 수 있습니다. 아직 기록된 이동 경로가 없기 때문이며, 리더가 실제로 걷기 시작하면 순서대로 펼쳐집니다. 벽 뒤에 가상의 줄을 만들거나 아직 지나지 않은 직선 경로로 배치하지 않습니다.

기본 경로 간격은48픽셀이고, 자연 정지 뒤에는 앞 동료가16픽셀 더 가면 차례로 출발합니다. `OverworldPartyFollowerController`의 `동료 간 경로 간격`·`재출발 여유 거리`에서 조절합니다. 영구 저장 방법은 [동행 제작 가이드](overworld-party-follow-guide.md)를 참고하세요.

## 4. 관람 동료와 대화·재합류

전시 Room의 `Systems/Observe Slot 4`, `Systems/Observe Slot 5`에 `OverworldFollowerObservation`이 배치됩니다. 동료 번호는 **리더를 제외한 목록 순서**입니다. 기본 순서에서 4번은 파랑, 5번은 분홍이며, 목록을 재정렬하면 다른 동료가 그 역할을 맡습니다. 안내판·대사·화자는 자동으로 재작성되지 않으므로 역할을 바꿨다면 함께 검토하세요.

1. 전시 Room의 좌·우 입구로 들어와 탐색이 가능해지면 파랑·분홍 동료가 각 관람 경유점으로 이동합니다. 입구에서 가만히 있어도 시작하며, 예전처럼 중앙의 좁은 영역을 끝 동료까지 통과시킬 필요가 없습니다.
2. 이동 중에는 말을 걸 수 없습니다. 도착해 기다리는 동료의 실제 위치로 다가가 Z로 대화합니다. 별도 NPC 복제본이 아니라 기존 동료 Actor를 대상으로 합니다.
3. 관람 대사가 정상적으로 끝나고 닫힌 뒤 `동료와 함께 이동할까요?` 선택창이 열립니다.
4. `함께 가기`를 선택하면 복귀 경유점과 현재 리더 위치를 따라 합류합니다. 복귀 동안 리더 입력이 잠시 제한되고 다른 추종 동료는 대기합니다.
5. `조금 더 구경해`를 선택하거나 선택창에서 X로 취소하면 그 자리에 남습니다. 다시 말을 걸 수 있습니다. 관람 대사가 강제로 취소되면 다음 선택창을 열지 않습니다.

관람 컴포넌트의 `없는 동료는 건너뛰기`는 기본으로 켜져 있습니다. 동료를 줄여 4·5번이 없으면 해당 관람만 건너뛰며, 인원 확인을 위해 동료를 새로 만들지 않습니다. 한 동료만 합류시킨 뒤 다음 방으로 이동해도 방 도착에서 전원이 다시 모입니다. 전시 Room에 재입장하면 관람을 다시 시험할 수 있습니다.

### 경로가 막히거나 이동을 중단한 경우

출발과 복귀 모두 동료의 현재 위치부터 첫 경유점까지, 그리고 복귀의 마지막 리더 위치까지 장애물 검사를 합니다. 자동 길찾기가 아니며 리더 몸체 크기를 기준으로 통과 가능한 경로만 시작합니다.

실험실의 출발 영역은 양쪽 기본 입구를 포함하도록 넓혔습니다. 영역 안 모든 지점에서 장애물을 무시하고 이동한다는 뜻은 아닙니다. 임의 위치로 순간 이동해 시작하거나 소품을 옮겼다면 경유점까지의 통로도 함께 확인하세요.

막힌 경로나 중단은 직선 관통·순간 이동으로 숨기지 않습니다. 동료와 Room이 남아 있으면 실제 중단 위치에서 기다리고 상호작용 위치도 그 좌표를 따릅니다. 실패 안내를 닫고 리더를 열린 통로 쪽으로 옮긴 뒤 다시 대화해 `함께 가기`를 선택하세요. Room이나 대상이 사라지면 해당 관람 작업은 종료됩니다.

관람 동작을 편집하려면 전시 Room Prefab에서 다음 항목을 함께 확인합니다.

- `관람 동료 번호`, `없는 동료는 건너뛰기`, `출발 영역`
- `관람 경유점`과 `복귀 경유점` Transform의 순서·위치
- `각 이동 시간`, `장애물 레이어`와 실제 충돌체 배치
- `관람 대화`, 질문·합류·계속 관람·실패 안내의 번역 키와 기본 문구

기본 관람 경유점은 `Out 1/2`, 복귀 경유점은 `Return 1/2` 자식입니다. 복귀 목록 뒤에는 실행 시점의 리더 위치가 붙으므로, 작성한 마지막 경유점만 안전하다고 충분하지 않습니다. 번역은 `Assets/Resources/LocalizationTable.csv`의 `follower_lab.*` 키를 사용합니다.

## 5. 임시 파티와 저장 보호

실험 세션은 빈 전역 상태의 메모리 복사본을 보관하고, 기존 `GlobalDataManager.FromSaveData` 경로로 임시 파티를 주입합니다. 시작 전에 진행 저장 차단을 획득하고 자기 상태 복구가 끝날 때까지 유지합니다.

- `CanSaveCurrentProgress`, `TrySaveProgress`, 직접 `TrySave`, `RequestAutoSave`, `TryDelete`가 같은 차단을 따릅니다.
- 실험 중 자동저장 요청은 거부하며 종료 후로 미루지 않습니다. 저장 지점이 없다는 사실만으로 격리하는 방식이 아닙니다.
- 설정용 PlayerPrefs와 읽기 전용 슬롯 검사는 별도입니다. 실제 저장 경로·슬롯·형식은 바꾸지 않습니다.
- Disable/Destroy/초기화 실패 시에는 아직 자기 파티 목록과 모든 멤버 참조를 소유한 경우에만 빈 상태로 복구합니다. 정리는 중복 호출해도 자기 저장 차단만 해제합니다.

다른 로드나 새 게임으로 파티가 바뀌면 과거 상태로 덮어쓰지 않습니다. 기존 `FromSaveData`와 새 게임 경로는 `PartyChanged`를 발행하지 않으므로, 세션의 **다음 Update**에서 목록·멤버 참조 변경을 확인해 종료합니다. 초기 리더 바인딩·방 진입·정리 경계에서도 소유권을 다시 확인하며, 변경 감지 전까지는 저장 차단이 유지됩니다. 기존 파티 이벤트가 발생하는 경로에서는 이를 보조 감지로 사용합니다.

이 보호는 실험 중 본편 로드를 권장한다는 뜻이 아닙니다. 본편으로 돌아갈 때에는 Play를 종료한 뒤 본편 씬을 별도로 여세요. 실험 세션 컴포넌트를 본편 씬이나 기존 BattleLab에 추가하지 않습니다.

## 6. 생성 결과 검수 체크리스트

아래 항목은 실행 결과를 보고 직접 체크합니다. 관리형 검사나 C# 컴파일 통과만으로 Unity Play·카메라·충돌·성능 검증을 완료했다고 판단하지 않습니다.

- [ ] 실험실 씬 하나만 새 Play로 실행되고 기본 리더+5명이 준비된다.
- [ ] 시작 위치의 겹침이 걷기 후 풀리며, 1·3·6인 설정과 목록 순서를 각각 확인한다.
- [ ] null·6명 동료·중복 ID는 자동 수정 없이 시작을 거부한다.
- [ ] 창고 모서리·달리기·역주행에서 동료가 벽을 가로지르지 않는다.
- [ ] 세 방을 오른쪽과 왼쪽 모두 순환하며 출입구·도착 방향·리더 충돌·카메라 경계가 맞는다.
- [ ] 전시의 4·5번 관람과 각각의 반복 대화·함께 가기·계속 관람·X 취소를 확인한다.
- [ ] 동료 수를 줄여 4·5번이 없을 때 해당 관람만 건너뛴다.
- [ ] 출발·복귀를 중단하거나 경로를 막았을 때 실제 위치에서 재시도할 수 있고 입력 잠금이 남지 않는다.
- [ ] 한 명만 합류한 상태로 방을 이동해도 다음 방에는 전원이 따라오며 전시 재입장이 가능하다.
- [ ] 대화가 닫히는 프레임에 방을 떠나도 늦은 선택창·중복 동료·이동 명령이 남지 않는다.
- [ ] 테스트용 저장소에서 수동·직접·자동 저장 및 삭제 차단, 종료 후 차단 해제를 확인한다. 사용자 실제 슬롯으로 검사하지 않는다.
- [ ] 다른 파티 교체·새 게임·세션 Disable/Destroy 후 이전 복사본이 새 상태를 덮지 않는다.
