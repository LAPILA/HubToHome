# UI 표시 상태와 입력 수명

[학습 홈](README.md) · [전체 코드 색인](20-code-atlas.md) · [이 영역의 모든 파일](code/ui.md)

UI는 전투 데이터를 보여 주지만 **전투 규칙 자체를 계산하는 곳은 아닙니다.** 화면 문제를 고칠 때 표시 순서와 실제 파티·대상 인덱스를 함께 바꾸지 않아야 합니다.

## 화면별 책임

| 화면 | 중심 코드 | 알아야 할 경계 |
| --- | --- | --- |
| 전투 전체 | BattleUIController | 실제 전투 이벤트 구독과 화면 연결 |
| 메뉴/목록 | BattleMenuUI / BattleSubMenu | 선택 기억·가능 여부·설명 |
| 턴 큐 | BattleTurnQueueView / Icon | 예고 표시와 슬롯 애니메이션 |
| 파티 | PartySlotUI | 실제 actor 구독, HP/AP/상태 표시 |
| 피해 숫자 | BattleDamagePopupPresenter / View | 표시 묶음·누적·풀 수명 |
| 설정 | ConfigPanelUI / OptionRowUI | 모달 소유권과 배치 |
| 상점 | ShopSession / ShopUI partial 파일 | 거래와 연출·화면 분리 |
| 공용 창 | Core/Runtime/UIManager / UI/Runtime/UIPanel | 등록 Dictionary와 창 Stack |

## 사건을 받아 화면을 갱신하기

데이터를 매 프레임 조회해 전부 다시 그리기보다 변경 이벤트를 구독합니다. 이때 OnEnable에서 구독만 하고 OnDisable에서 해제하지 않으면 재진입 때 두 번 실행될 수 있습니다. 소리 중복·오래된 캐릭터 접근·파괴된 Image에 Tween 적용 같은 오류로 이어집니다.

구독 해제는 “현재 Singleton”이 아니라 **실제로 구독했던 객체**에서 해야 합니다. 씬 이동으로 인스턴스가 바뀌면 현재 Singleton과 예전 이벤트 발신자가 다를 수 있습니다.

## Tween 소유권

화면이 만든 Tween은 그 화면이 보관하고 정리합니다. 숨김·재바인딩·비활성화·파괴 때 자신이 소유한 핸들만 종료합니다. DOTween.KillAll로 가리면 다른 전투·카메라 연출까지 끊을 수 있습니다.

정리 중 Kill의 완료 콜백을 실행해 게임 행동이 확정되지 않도록 주의합니다. Image/TMP가 Unity 관점에서 파괴됐는지 확인하는 검사도 필요합니다.

## 피해 누적의 키

BattleDamagePopupPresenter.Totals는 `(CharacterBase target, long batchId)`를 Dictionary 키로 사용하고, 각 묶음 안에 6종 표시 타입별 합계와 View 배열을 둡니다.

```text
대상 A / 행동 42
  물리  120 → 180
  화염   20 → 40
대상 B / 행동 42
  물리   70
```

캐릭터 데이터 ID나 색만으로 묶으면 복제 위젤 세 명의 피해가 합쳐질 수 있습니다. Batch는 표시 수명 구분이지 HP 계산 규칙이 아닙니다. 행동 종료 후 유지 시간은 현재 기본 0.7초입니다. 타격 간격이 길다는 이유로 중간에 묶음을 닫지 않습니다.

## UI Stack은 무엇을 해결하는가

UIManager는 패널 등록을 Dictionary, 열린 순서를 Stack으로 관리합니다. 마지막에 연 창을 먼저 닫고 이전 선택을 복구합니다. 단, 중간 패널 파괴·중복 등록은 단순 Pop만으로 해결되지 않아 유효하지 않은 상태 정리가 필요합니다.

ConfigPanelUI는 닫기 애니메이션 중에도 입력 잠금을 유지합니다. 다른 모달이 상태를 바꿨는데 과거 상태를 무조건 복구하면 안 되므로 “누가 이 잠금을 소유했는가”를 검사합니다.

## 640×480 배치와 키 안내

Pixel Perfect의 실제 표시 영역과 Canvas 기준이 다르면 화면 밖 배치나 글자 겹침이 생깁니다. UIViewportService, BattleHudViewport, DialogueCanvasViewport를 읽고 RectTransform·CanvasScaler·레이아웃 그룹의 소유권을 구분하세요. LayoutGroup이 배치하는 부모 좌표를 Tween이 동시에 덮어쓰면 흔들릴 수 있습니다.

안내 문구와 실제 입력 동작은 분리합니다. X가 메뉴 취소라고 해서 적 턴의 X 회피 의미를 덮어쓰지 않습니다. BattleInputHintView는 상태에 맞는 안내를 제공하며 실제 판정은 입력·전투 경로가 담당합니다.

## 공부 과제

- [ ] OnEnable→OnDisable을 두 번 반복할 때 구독 개수가 변하지 않는지 추적한다.
- [ ] 같은 CharacterData를 쓴 두 개체의 피해 묶음이 분리되는 이유를 설명한다.
- [ ] 창을 닫는 Tween이 취소돼도 입력 잠금이 남지 않아야 하는 경로를 찾는다.
- [ ] 대상 선택 테두리와 현재 행동자 배경을 분리한 이유를 설명한다.
