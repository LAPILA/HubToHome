## 사용법

1. 관심 있는 기능 장에서 “읽을 파일”을 엽니다.
2. 실제 코드가 필요하면 해당 장 끝의 영역별 파일 색인으로 갑니다.
3. 체크리스트를 본인이 수행하고 설명을 작성합니다.
4. 코드가 바뀌면 기능 문서와 개발 일지를 함께 갱신합니다.

**읽기 경고**: 파일 전체를 색인했지만 모든 줄을 정밀 리뷰한 것은 아닙니다. 확인된 구현, 코드에 대한 설계 해석, 아직 실행하지 않은 검증을 구분했습니다. 현재 문서만으로 상용 출시나 특정 회사 합격을 보증할 수 없습니다.

## Notion 게시 상태

2026-10-11, 요청하신 [HUB TO HOME · 개발 학습실](https://app.notion.com/p/3f6641f6190180bb8567ff9caf83e5a9)에 게시했습니다. 연결 도구는 여전히 해당 페이지를 찾지 못했지만, 사용자 로그인 후 브라우저에서 정확한 목적지의 편집 권한을 확인하고 네이티브 가져오기로 등록했습니다. 다른 워크스페이스로 옮기거나 공유 권한을 변경하지 않았습니다.

- 기능별 학습 19편, 코드 색인 12편, 날짜별 개발 기록 28편과 안내·색인을 여러 페이지로 분리했습니다. 게시용 묶음은 Markdown 62개와 CSV 4개입니다.
- 학습 체크보드, 전체 C# 파일, 폴더 목록, 개발 기록 목록은 네이티브 데이터베이스입니다. 학습 DB에는 표·진행 보드 두 보기와 **학습 기록 양식**을 만들었습니다.
- 진행 보드는 `시작 전 → 읽는 중 → 직접 실험 → 설명 가능`이며, 전부 시작 전으로 두었습니다. 카드는 공부 기록용이고 해설 본문은 홈의 기능별 라이브러리에서 엽니다.
- 본문 표·코드·Mermaid·체크리스트와 실제 페이지 링크를 보존했습니다. 로컬 소스 파일은 외부에서 열리지 않는 가짜 링크 대신 프로젝트 상대 경로로 표기합니다.
- [실제 게시 결과와 링크](notion-publication.json)를 기준으로 사용하세요. [초기 배치 계획](notion-layout.json)의 갤러리·캘린더 등은 계획일 뿐, 이번 게시에서 만든 보기로 간주하지 않습니다.

`build-notion-import.cjs`는 로컬 문서의 가져오기 패키지를 재생성하는 도구입니다. 실행만으로 Notion을 수정하지 않습니다. 같은 ZIP을 다시 가져오면 중복 페이지가 생기므로, 이후 내용 수정은 기존 페이지에서 수행합니다.

심화 자료는 `build-deep-import.cjs`가 `deep/source/*.md.in`의 소스 줄 범위를 읽어 생성합니다. `node docs/study/build-deep-import.cjs --check`로 현재 파일과 발췌·해시·링크를 검증할 수 있습니다. [근거 목록](deep/source-evidence.json)에 22개 소스 파일과 37개 발췌의 SHA-256을 기록했습니다. 코드가 바뀌면 문서가 자동으로 최신 내용이 되는 것은 아니며, 원고와 줄 범위를 검토한 뒤 재생성해야 합니다.
