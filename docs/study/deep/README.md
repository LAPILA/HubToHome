## 02 / 한 장 읽는 방법

1. **현상**: 화면에서 무슨 일이 일어나는지 먼저 떠올립니다.
2. **소유권**: 값의 원본을 가진 클래스와 보여주기만 하는 클래스를 구분합니다.
3. **호출 흐름**: 함수 순서와 중단될 수 있는 지점을 따라갑니다.
4. **코드**: 짧은 원문 발췌를 읽고 표의 숫자 변화를 손으로 계산합니다.
5. **실패 경계**: 파괴·취소·잘못된 데이터가 어디서 차단되는지 봅니다.
6. **실험**: 예상 결과를 먼저 쓰고, 직접 실행한 결과를 학습 체크보드에 기록합니다.

추천 시간은 30분입니다. 10분 읽기 → 10분 코드 찾기 → 5분 숫자 추적 → 5분 내 말로 설명하기. 한 번에 모든 파일을 외우지 않습니다.

## 03 / 근거와 한계

코드 블록은 현재 파일의 지정 줄을 그대로 추출합니다. 경로와 줄 번호를 함께 표기했습니다. 줄 번호는 이후 코드 편집으로 달라질 수 있으므로 함수 이름도 같이 찾으세요. 로컬 `docs/study/deep/source-evidence.json`에는 원문과 발췌의 SHA-256을 기록합니다.

**확인된 사실**은 읽은 구현을 뜻합니다. **설계 해석**은 그 구조가 주는 효과와 선택의 이유를 설명한 것입니다. **실습 예상**은 이번 문서 작업에서 Unity로 실행한 결과가 아닙니다. 현재 미커밋 변경도 근거에 포함하므로 Git HEAD만으로 완전히 같은 코드가 재현된다고 주장하지 않습니다.

이 자료실은 대표 기능을 끝까지 따라 읽는 해설입니다. 자체 C# 686개 전체의 모든 줄이나 모든 실행 경로를 정밀 검증했다는 뜻은 아닙니다. 기존 파일 색인으로 주변 구현을 찾아 확장해서 읽으세요.
