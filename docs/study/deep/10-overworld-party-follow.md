# 10 / 동료가 모서리를 돌아 따라오는 이유

> **현상 → 경로 자료구조 → 동료 상태 → 취소·맵 이동** 순서로 읽습니다. 이 문서는 이번 기능의 대표 경로 해설이며 프로젝트 전체 코드의 검증 완료를 뜻하지 않습니다.

## 한 가지 문제를 세 소유자로 나누기

| 원본 소유자 | 가진 것 | 갖지 않는 것 |
| --- | --- | --- |
| GlobalDataManager | 실제 파티·성장·저장 | 화면에서 기다리는 위치 |
| OverworldFollowerTrail | 리더가 실제로 지난 좌표와 누적 거리 | 물리 충돌·동료 HP·카메라 |
| Controller / Actor | 표시 객체·추종 커서·연출 명령 | 실제 합류·탈퇴·저장 파일 |

캐릭터의 ‘잠깐 여기 있어’와 ‘파티에서 탈퇴’를 같은 bool로 표현하면 전투·저장까지 잘못 바뀝니다. 이번에는 Follow/Hold/Detached와 Visible을 표시 상태로만 둡니다. 카메라 대상도 동료 평균 위치로 바꾸지 않으므로 따라잡는 동료 때문에 화면이 흔들리지 않습니다.

## 1. 현재 위치만 따라가면 왜 벽을 가로지를까요?

리더가 `(0,0) → (2,0) → (2,2)`로 모서리를 돌았다고 합시다. 뒤에 있는 동료를 현재 리더 `(2,2)`로 MoveTowards하면 대각선을 선택해 모서리 안쪽을 자릅니다. ‘얼마나 부드럽게’ 보간해도 경로 자체가 잘못된 문제는 해결되지 않습니다.

대신 경로를 세 점의 꺾은선으로 저장하고 **거리 커서**를 전진시킵니다.

| 누적 거리 | 위치 | 구간 |
| --- | --- | --- |
| 0 | (0,0) | 출발 |
| 1 | (1,0) | 첫 수평 구간 |
| 2 | (2,0) | 모서리 |
| 3 | (2,1) | 두 번째 수직 구간 |
| 4 | (2,2) | 현재 리더 |

동료가0.9 거리 뒤라면 목표 커서는3.1입니다. 화면 좌표를 목표로 당기는 대신 `현재 커서 + 속도×dt`를 계산하고 그 거리의 꺾은선 위치를 샘플링합니다. 정지와 재개도 같은 커서를 사용합니다.

## 2. 배열 기반 순환 버퍼

[OverworldFollowerTrail](../../../Assets/_Game/Scripts/Overworld/Runtime/Party/OverworldFollowerTrail.cs)을 먼저 읽으세요.

- 크기1024의 Point 배열을 한 번 할당합니다. `_oldest`와 `_count`로 논리 순서를 유지하고 가득 차면 가장 오래된 칸을 재사용합니다.
- 논리 i번째 점은 `(_oldest + i) % Capacity`로 찾습니다. 앞 원소를 RemoveAt(0)로 밀지 않습니다.
- 누적 거리는 내부 double로 더합니다. 점 사이 거리들을 매번 다시 합치지 않습니다.
- `TrySample`은 누적 거리가 정렬된 배열이라는 성질로 이진 탐색합니다. 구간 안의 위치만 선형 보간하므로 꺾은 모서리는 보존됩니다.
- `TryFindDistance`는 재합류할 때 남아 있는 선분에 위치를 투영합니다. 경로 근처인지 확인할 뿐, 그 함수가 캐릭터를 옮기지는 않습니다.
- 제자리 회전은 새 점을 추가하지 않습니다. 최신 정지 방향과 그 구간을 걸었던 방향도 분리합니다. 그렇지 않으면 리더가 고개만 돌렸는데 뒤 동료의 걷기 방향도 바뀝니다.

| 연산 | 시간 비용 | 추가 할당 |
| --- | --- | --- |
| Record / Reset | O(1) | 정상 반복에서는 없음 |
| 거리 샘플 | O(log n) | 없음 |
| 경로 위 위치 찾기 | O(n) | 없음 |
| 원본 배열 | O(capacity) 공간 | 생성 시1회 |

n은 무한히 커지지 않고 배열 상한을 따릅니다. 관리형 검사에서0B였다는 것은 이 계산 경로의 측정 결과이지 Animator·GPU·게임 전체의 무할당/무발열 보장은 아닙니다.

## 3. Epoch와 오래된 커서

방을 바꾸면 누적 거리는 다시0부터 시작합니다. 거리 숫자만 비교하면 이전 방의 ‘거리2’가 새 방의 ‘거리2’에 잘못 붙을 수 있습니다. 그래서 `Reset`마다 Epoch를 바꾸고 커서에도 해당 Epoch를 보관합니다.

배열이 오래된 점을 덮었을 때도 마찬가지입니다. 범위 밖 거리를 가장 오래된 점으로 강제 보정하면 지우지 않은 길을 순간 이동한 것처럼 건너뜁니다. 계산은 false를 반환하고 Actor는 Hold로 멈춥니다. 연출자가 남아 있는 길로 돌아오게 하거나, 암전 중 명시적으로 Gather해야 합니다.

## 4. 같은 DB와 같은 동료는 다릅니다

CharacterDataID는 외형·스탯 원본을 찾는 키이지 파티 개체의 고유 GUID가 아닙니다. 같은 위젤 DB를 사용하는 테스트 동료 두 명을 `Dictionary<string,Actor>`로 합치면 하나가 사라집니다.

현재 저장 모델의 개체 구분에 맞춰 CharacterSaveData 객체 참조와 현재 순서를 사용합니다. 로드로 저장 객체가 통째로 바뀌면 이전 Actor를 정리하고 새 목록을 표시합니다. 이 때문에 표시 계층이 데이터 ID를 바꾸거나 새 저장 GUID를 발급할 필요가 없습니다.

## 5. Coroutine과 DOTween 취소의 경계

[Actor](../../../Assets/_Game/Scripts/Overworld/Runtime/Party/OverworldFollowerActor.cs)의 이동 명령과 [Controller](../../../Assets/_Game/Scripts/Overworld/Runtime/Party/OverworldPartyFollowerController.cs)의 reset을 이어 읽으세요.

1. 새 명령은 이전 명령의 Tween만 취소합니다.
2. 각 이동은 자기 명령 객체와 세대를 갖습니다.
3. 완료 콜백은 아직 그 명령이 현재 소유자인지 검사합니다.
4. 방 이동·전투·리더 종료는 Tween을 죽이는 것뿐 아니라 기다리던 명령도 종료시킵니다.
5. 시퀀스 adapter는 취소/Dispose에서 자신이 기다리는 명령만 Cancel합니다.

Transform 전체 DOKill이나 카메라 전역 reset을 cleanup 대신 쓰면 다른 연출까지 중단됩니다. 반대로 Coroutine만 멈추고 DOTween을 남기면 도착한 새 방 좌표를 옛 이동이 덮습니다. 두 수명을 함께 닫아야 합니다.

## 30분 실습

아래는 **실습 예상**이지 Unity에서 실행해 확인한 결과가 아닙니다.

- 배열 크기를4로 만든 뒤7점을 기록합니다. Count와 OldestDistance를 손으로 계산하고 테스트와 비교하세요.
- ㄱ자 경로를 그려 거리1.5/2.5의 좌표를 구합니다. ‘리더 위치로 직접 이동’과 차이를 설명하세요.
- 동료를 Hold한 뒤 버퍼가 만료될 만큼 이동하면 어떻게 되어야 할까요? 왜 자동 순간 이동이 위험한가요?
- 같은 CharacterDataID인 파티원2명을 만들면 표시 구분은 무엇을 기준으로 해야 할까요?
- 개별 이동 중 방을 바꾸면 Tween, 기다리는 Action, 완료 콜백, Actor 위치가 각각 어떻게 끝나야 할까요?

포트폴리오에는 ‘델타룬과 같은 내부 기술’이 아니라 **기록 경로를 택한 이유, 버퍼 상한/오래된 커서 처리, 취소 회귀, 본인이 실행한 검증과 남은 엔진 검증**을 설명하세요. [제작 사용법](../../overworld-party-follow-guide.md)과 [승인 설계](../../superpowers/specs/2026-10-23-overworld-party-follow-design.md)를 함께 봅니다.
