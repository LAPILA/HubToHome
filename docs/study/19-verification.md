# 검증 범위와 학습 완료 기준

[학습 홈](README.md) · [전체 코드 색인](20-code-atlas.md)

**파일이 있다 → 컴파일된다 → 테스트가 통과한다 → 게임에서 맞게 동작한다 → 실제 기기에서 안전하다**는 서로 다른 수준입니다. 한 단계의 증거를 다음 단계의 완료로 바꾸지 않습니다.

## 현재 자료의 증거 수준

| 항목 | 확인된 범위 | 뜻하지 않는 것 |
| --- | --- | --- |
| C# 686개 / 테스트 분류 204개 | Scripts 전체 파일 색인 | 모든 줄 정밀 검토, 테스트 204개 통과 |
| 2026-10-11 CLI 컴파일 | Runtime/Editor 오류 0, 기존 경고 있음 | Unity Play, 실제 씬·직렬화 연결 검증 |
| 설정·저장·장비 관리형 155/155 | 해당 하네스에서 실제 계산·파일 작업과 대체 엔진 객체 검사 | 기기 저장·Unity 수명·UI 렌더링 통합 검사 |
| 2026-10-09 YAML 3,844개 비교 | 이전·통합 처리 결과의 동등성 비교 | 시나리오 전체 콘텐츠의 실행 보증 |
| Tests 폴더 | 관련 회귀 테스트 소스 존재 | 이번 문서 작업에서 실행 완료 |

이번 문서 작업은 게임 코드를 변경하거나 Unity를 실행하지 않았습니다.

## 테스트를 읽는 법

1. Arrange: 객체·데이터·실패 조건을 어떻게 준비했는지.
2. Act: 어떤 메서드 한 가지를 실행했는지.
3. Assert: 결과 값뿐 아니라 원본이 바뀌지 않았는지도 보는지.
4. 반복·취소·파괴·잘못된 입력의 경계가 있는지.
5. 대체 객체가 실제 Unity와 다른 부분은 무엇인지.

이 프로젝트는 외부 파일 시스템, 시계, 입력, 저장소 등을 대체할 수 있는 경계가 있습니다. 이는 빠른 검사를 돕지만 실제 엔진의 fake-null, 실행 순서, Canvas, Animator까지 대체 검사가 증명하지는 못합니다.

## 이후 실제 검증 목록

- [ ] 테스트 씬에서 3명 전열·후열 선택·포기를 직접 확인.
- [ ] 전조 시작·음원·타격·피해·방어 피드백의 프레임 관계 확인.
- [ ] 대화 중단·상점 종료·설정 닫기에서 입력 복구 확인.
- [ ] UI 확대/해상도별 클리핑·TMP 글자·슬롯 상태 확인.
- [ ] 저장 지점 3슬롯과 자동99, 제목 화면 Continue 왕복 확인.
- [ ] 앱 중단/재개 중 자동 저장·설정 저장 확인.
- [ ] 보유 1개 장비를 여러 명에게 장착하는 실패 처리 확인.
- [ ] 모바일 CPU/GPU/GC·발열·배터리, 목표 콘솔 저장/API 별도 확인.

이 목록은 **미실행 체크리스트**입니다. 현재 통과했다고 표시하지 않습니다.

## 학습 완료의 네 단계

| 단계 | 스스로 확인할 것 |
| --- | --- |
| 읽음 | 입력·출력·현재 상태 소유자를 설명 |
| 추적함 | 정상 경로와 취소 경로를 직접 그리기 |
| 검증함 | 테스트를 실행하거나 작은 모형으로 결과 재현 |
| 설명 가능 | AI 없이 선택 이유·대안·한계를 3분 설명 |

Notion 공부 상태를 “설명 가능”으로 옮길 기준도 여기에 맞춥니다. AI가 문서를 만들었다는 이유로 사용자의 공부를 완료 처리하지 않습니다.

## 자료를 업데이트할 때

1. Scripts 파일 색인을 다시 생성해 추가·삭제를 확인합니다.
2. 바뀐 기능 장과 개발 기록만 수정합니다.
3. 현재 기능 설명에 과거 스키마·옛 UI·보류된 기능이 섞이지 않았는지 확인합니다.
4. 코드 경로와 내부 문서 링크를 검사합니다.
5. 검증 결과에는 날짜·도구·대체 범위·실기기 여부를 남깁니다.
