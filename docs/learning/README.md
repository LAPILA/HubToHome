# Hub To Home · 프로젝트로 공부하는 개발 노트

기준: 2026-09-07 현재 작업 트리 / Unity 6000.3.8f1.

노션에서 보기: [HUB TO HOME · 개발 포트폴리오 & 스터디](https://app.notion.com/p/3d4641f6190180138c83e37717f558dd). 기술 사례·코드 발췌·학습 순서·실습 과제와 문서 ZIP을 모았습니다. 소스가 바뀌면 노션의 기준일과 설명도 함께 갱신하세요.

이 자료는 **현재 프로젝트를 읽고, 설명하고, 작은 수정을 직접 해 보는 학습용 안내서**입니다.
완성된 엔진이나 정답 코드라는 뜻은 아닙니다. 구현된 동작, 설계 의도, 남은 문제를 구분해 읽으세요.
모든 파일을 처음부터 읽는 대신 각 장에서 제시한 진입 메서드와 호출자를 왕복합니다.

게임 내용을 빨리 만들 목적이라면 [콘텐츠 메이커 사용법](../content-maker-guide.md)부터 보세요.
대사·상태·연출의 역할만 정리하려면 [스토리 도구 방향](../../AIAssets/yjlim/feedback/2026-09-07-story-tools-learning-roadmap.md)을 먼저 봅니다.
이 폴더에는 구현을 공부하는 내용을 모아 사용법·일일 작업 기록과 중복을 줄였습니다.

## 2. 처음 공부한다면 이 순서

1. **읽기:** 01에서 참조·컬렉션·이벤트의 의미를 익힙니다. 전체 암기 대신 작은 목록을 손으로 계산합니다.
2. **한 흐름 따라가기:** 02의 입력 → NPC 상호작용 → 04의 대사 표시를 따라갑니다.
3. **데이터 수정:** 메이커로 대사 한 줄과 표정 하나를 바꿉니다. 원본 자산과 씬 인스턴스가 다른 것을 확인합니다.
4. **규칙 계산:** 03의 스탯·피해를 손으로 계산한 뒤 실제 함수와 비교합니다.
5. **작은 기능 수정:** 05를 보고 에디터 검증 하나를 추가하는 연습을 합니다. 전체 시스템 재작성은 하지 않습니다.
6. **실패와 복구:** 06을 읽고 대화 취소·방 전환 실패 같은 정상 경로 밖의 동작을 설명합니다.
7. **기록:** 07의 양식으로 문제·판단·변경·검증·한계를 남깁니다.

C#에 익숙하다면 02 → 03 → 04 → 05 순으로 실행 흐름을 읽고, 01·06은 사전처럼 찾아봐도 됩니다.
각 장의 실습은 **앞으로 해 볼 과제**입니다. 이번 문서 작성 중 실행한 결과가 아닙니다.

## 3. 프로젝트 전체를 보는 지도

```text
제작 단계
  Content Maker ── 방/마커/대사/화자/조건 데이터
  Sequence Maker ── 시나리오 원문과 런타임 자산
                         ↓
게임 실행
  Core ── 초기화 · 입력 · 상태 · 저장 · 공용 서비스
    ├─ Overworld ── Room · 이동 · NPC · 상호작용
    ├─ Battle ── 참가자 · 턴 · 스킬 · QTE · 전투 종료
    │    └─ Characters / Items ── 스탯 · 효과 · 장비 · 인벤토리
    ├─ Scenario / Dialogue ── 사건 순서 · 조건 · 대사 · 중단/완료
    └─ UI / Camera / VFX / Shared ── 화면 · 시점 · 효과 · 공용 처리
```

이 그림은 읽는 순서를 위한 역할 지도입니다. 모든 참조가 한 방향으로만 흐르는 완전한 계층 구조라는 뜻은 아닙니다.
실제 호출 관계와 남아 있는 결합은 각 장에서 확인합니다.

| 소스 영역 | 주로 볼 장 | 처음 찾을 대상 |
|---|---|---|
| Core | 01·02·06 | GameBootstrap, GlobalDataManager, ObjectPoolManager |
| Overworld | 02·04 | RoomContainer, MapTransitionService, NPCMarker |
| Battle | 03·06 | BattleManager, BattleSkillTimelineRunner, DefenseJudgementPolicy |
| Characters | 03 | CharacterData, CharacterStats, CharacterBase |
| Items | 03 | InventoryManager, ItemEffectService |
| Scenario | 04·05·06 | ActionDirector, ActionExecutionContext, Sequence Maker |
| Dialogue | 04 | DialogueData, DialogueManager, DialogueUI, SpeakerData |
| Editor | 05 | ContentMakerWindow, 패널·서비스, CSV·삭제 보호 |
| UI·Camera | 02·03 | UIViewportService, QTEManager, 카메라 요청의 소유권 |
| VFX·Shared | 02 | 효과 반납, 잔상 재사용, 텍스트 공용 처리 |

## 4. 지금 구현된 것과 더 확인할 것

| 구분 | 현재 범위 | 이 문서가 완료를 보장하지 않는 것 |
|---|---|---|
| 제작창 | 챕터·방·마커·대사 제작, 조건 문서 편집, CSV 검사 후 적용 | 모든 Unity 버전·화면 배치·Undo 조합의 실기 검증 |
| 스토리 상태 | 저장 플래그, 단일 플래그 대화 선택, 일부 마커 반응 | 범용 다중조건 NPC 일정·위치·출현 저작기 |
| 번역 | 본문 번역 키 조회, 빈 키 생성 보조 | 선택지·이름 번역, 번역표의 여러 줄 셀, XLSX 자동 동기화 |
| 전투 | 3명 전열 전멸 시 후열 투입, 턴·QTE·스킬 실행 | 모든 상태효과의 행동 연결, 턴 큐 공정성·전체 밸런스 |
| 시나리오 | 액션/어댑터/조건/취소·실행 경로와 제작 파이프라인 | 모든 전투 모듈 완성, 범용 선택 결과 → 후속 시퀀스 분기 |
| 저장·성능 | 방어적 저장·복구 코드, 캐시·풀·범위별 정리 | 모든 장애에서 무손실, 저사양 휴대폰·Switch의 실측 성능 |

이 항목들은 이번에 임의로 대규모 수정하지 않았습니다. 현재 코드를 이해하기 위한 경계이며, 다음 개발의 우선순위를 잡을 때 사용할 수 있습니다.
오래된 설명과 현재 코드가 다르면 코드·검증 가능한 자산을 먼저 확인하고 문서를 갱신하세요.

## 5. 공부하는 동안 지킬 기준

- `구현이 있다`, `컴파일된다`, `테스트가 통과했다`, `실기에서 잘 동작한다`는 서로 다릅니다.
- 패턴 이름부터 붙이지 않습니다. 먼저 바뀌는 부분·상태의 주인·해제 책임을 설명합니다.
- 반복문 하나를 없앴다고 빨라졌다고 하지 않습니다. 대상 수, 호출 빈도, 할당, 기기 측정을 함께 봅니다.
- 새 ID를 만들 때 저장·외부 CSV·시나리오 참조에 영향을 주는지 확인합니다.
- 팀원 코드, 외부 라이브러리, AI 초안, 본인의 설계·수정·검증을 분리해서 기록합니다.
- 작은 기능 하나를 끝까지 검증하는 것이 관련 없는 기능을 여러 개 추가하는 것보다 학습 증거를 남기기 쉽습니다.

## 6. 문서 유지 방법

새 기능을 만들면 해당 장에 **호출 위치 / 데이터 구조 / 실패·정리 경로 / 직접 확인한 범위**만 덧붙입니다.
일일 변경 목록은 [AIAssets 인덱스](../../AIAssets/index.md)를 통해 기록하고, 같은 사용법을 여러 문서에 복제하지 않습니다.
문서의 코드 링크는 파일 기준입니다. 줄 번호가 바뀌면 함수 이름으로 검색하세요.
