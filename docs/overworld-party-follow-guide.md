# 오버월드 동료 동행 제작 가이드

> 기본은 **주인공 + 동료2명**입니다. 실제 파티원이 있어야 보이며, 이 기능이 동료·능력치·아이템을 새로 지급하지는 않습니다.

독립 개발 씬의 6인 파티·세 방·관람 대화 시험은 [동료 동행 실험실 사용법](overworld-follower-lab-guide.md)을 참고하세요.

## 1. 동료를 보이게 하기

1. 기존처럼 CharacterData를 만들고 콘텐츠 카탈로그에 등록합니다.
2. 이야기 이벤트의 `PartyRecruitmentTrigger` 또는 `GlobalDataManager.TryRecruitPartyMember`로 실제 합류시킵니다. 데이터 파일 생성만으로는 합류하지 않습니다.
3. 일반 필드의 PlayerController가 시작될 때 추종 제어기가 자동 연결됩니다. 문·맵마다 동료 프리팹을 따로 배치하지 않습니다.
4. 동료가 합류하면 실제 파티 순서대로 최대2명이 필드에 표시됩니다. 같은 DB를 쓰는 동료도 저장 객체가 다르면 별개로 유지합니다.

토끼 전투 실험실은 기존 미리보기와 카메라 구성을 사용하므로 일반 자동 추종에서 제외합니다. 전투용으로 생성한 PlayerController에도 자동 추종을 붙이지 않습니다.

### 표시 인원·간격을 저장해서 바꾸려면

기본 간격은 `1.5` 월드 단위, 현재32PPU 기준 **48픽셀**입니다. 자연스럽게 멈춘 뒤에는 앞 동료가 **16픽셀** 더 이동해야 다음 동료가 출발합니다. 고정 시간 지연이 아니라 실제 지나온 경로의 거리로 판단하므로 모서리는 그대로 따라갑니다. 관람 중인 동료 때문에 뒤쪽 전체가 멈추지는 않습니다.

기존 프리팹에 저장한 간격은 보존됩니다. 예전 값 `0.9`는29픽셀(`0.90625`)로 적용되므로, 수동 부착한 제어기에도 넓은 간격을 쓰려면 Inspector에서 `1.5`로 바꾸세요. 이동 경로의 좌표 자체는 반올림하지 않습니다. 카메라나 리더의 픽셀 퍼펙트 설정을 끄지 마세요. 확인 범위는 [검증 기록](../AIAssets/2026-10-27-update.md)을 참고하세요.

기본값 그대로면 추가 작업이 없습니다. 다른 값을 영구적으로 쓰려면 **Edit Mode에서 실제 필드 플레이어 프리팹에 `OverworldPartyFollowerController`를 추가**하고 설정한 뒤 프리팹을 저장합니다. Play 중 자동 생성된 컴포넌트에서 바꾼 값은 Play 종료 후 저장되지 않습니다.

| 설정 | 기본 | 편집 기준 |
| --- | --- | --- |
| 표시할 최대 동료 수 | 2 | 주인공을 제외한 수. 5면 주인공 포함6명 |
| 동료 간 경로 간격 | 1.5 | 48픽셀. 크게 하면 줄이 길어짐 |
| 재출발 여유 거리 | 0.5 | 자연 정지 후 앞 동료가16픽셀 더 이동하면 출발. 0이면 즉시 출발 |
| 따라잡기 속도 상한 배율 | 1.5 | 벌어진 간격에 비례해 부드럽게 따라잡는 속도 상한 |
| 경로 복귀 위치 허용 오차 | 0.02 | 개별 이동 후 실제 기록 경로 위인지 확인하는 오차 |
| 예외적 순간 이동 감지 거리 | 6 | 외부 큰 좌표 변경 보호용. 정상 문 이동은 별도 도착 통지 사용 |

메뉴·대화 때문에 잠시 멈추거나 명시적으로 Follow에 복귀할 때는 작은 잔여 거리도 끝까지 이동합니다. 재출발 여유는 자연스럽게 자리에 도착해 쉰 경우에만 다시 적용됩니다.

## 2. 캐릭터 그림·걷기 애니메이션 연결

CharacterData의 **OverworldVisualPrefab**은 선택 항목입니다. 전용 필드 그림이 준비되면 이 칸을 사용합니다.

| 연결 상태 | 읽는 원본 |
| --- | --- |
| OverworldVisualPrefab 연결 | 그 표시 전용 프리팹 |
| 비어 있고 BattlePrefab 연결 | 전투 프리팹 루트의 SpriteRenderer·Animator 표시 설정 |
| 둘 다 비어 있음 | 현재 리더의 표시 설정 |

원본 프리팹 자체를 Instantiate하지 않습니다. 입력·충돌·상호작용·전투 스크립트를 복제하지 않아 동료가 문이나 적 조우를 재발동시키지 않습니다. 동료 색상은 기존 CharacterData의 BattleSpriteTint를 사용합니다.

가장 간단한 표시 원본은 **루트에 SpriteRenderer + Animator**를 두는 것입니다. Animator의 방향 계약은 `MoveX`·`MoveY`(Float), `IsMoving`(Bool)이며, Down0/Up1/Left2/Right3을 사용합니다. 멈추면 마지막 진행 방향을 유지합니다. 탐색용 Idle/걷기 상태가 기본 상태여야 합니다.

여러 자식 스프라이트가 필요한 외형은 원본에 `OverworldFollowerVisualSource`를 붙이고 ‘표시 계층 루트’를 지정합니다. 그 아래는 Transform/SpriteRenderer/Animator만 사용하는 표시 전용 계층이어야 합니다. 게임플레이 이벤트·루트 모션·상태 머신 동작 스크립트는 넣지 않습니다. 임의 캐릭터 프리팹의 모든 기능을 복제하는 시스템이 아닙니다.

## 3. 연출에서 쓰는 동료 번호

- `1` = 첫 번째 동료, `2` = 두 번째 동료, 최대 `5`까지입니다. 주인공 번호가 아닙니다.
- `0` = 현재 표시된 동료 전체입니다. 상태·표시 변경에 사용합니다.
- 개별 이동에는 `0`을 사용할 수 없습니다. 없는 동료 번호는 명확한 오류로 종료합니다.
- 실제 합류/탈퇴로 파티 순서가 바뀌면 번호도 현재 표시 순서를 따릅니다. 긴 연출 사이에 편성이 바뀌는 구성을 피하세요.

## 4. 시퀀스 메이커에서 고정·이탈·이동

`Hub To Home → 시나리오 → 시퀀스 메이커`의 Action 검색에서 **동료**를 검색합니다. 새 시퀀스를 만드는 기존 절차는 그대로 사용합니다.

| Action | 용도 | 예시 파라미터 |
| --- | --- | --- |
| `overworld.party.mode` | 추종/고정/임시 이탈 | `slot: 1, mode: hold` |
| `overworld.party.visibility` | 표시/숨김 | `slot: 1, visible: false` |
| `overworld.party.move` | 한 동료를 연출 경로로 이동 | `slot: 1, x: 3, y: 2, duration: 0.6` |
| `overworld.party.gather` | 암전·도착 중 전체 재집결 | 파라미터 없음 |

상태와 표시 여부는 독립입니다. 숨겨도 Follow 상태면 경로를 따라갑니다. Detached는 자동 추종에서만 제외하며 **실제 전투 파티에서 탈퇴시키지 않습니다**.

### 잠시 기다렸다가 다시 따라오기

```yaml
- overworld.party.mode: { slot: 1, mode: hold }
- dialogue.wait: { id: friend.wait_here }
- overworld.party.mode: { slot: 1, mode: follow }
```

대화 ID는 해당 시퀀스의 기존 대화 매핑에 실제로 등록해야 합니다. 위 ID는 작성 예시이지 새 기본 대사가 아닙니다. Hold는 현재 위치·경로 커서를 보관합니다. Follow가 재개되면 그 지점부터 지나온 길을 이어 걸으며, 최신 주인공 위치로 직선 이동하지 않습니다.

### 따로 걸어가서 기다리기

```yaml
- overworld.party.mode: { slot: 1, mode: detach }
- overworld.party.move:
    slot: 1
    x: 3
    y: 2
    duration: 0.8
    path: [{ x: 1, y: 1 }, { x: 3, y: 1 }]
    rejoin: false
```

`path`는 중간 경유점이며 마지막에 x/y 목적지가 붙습니다. 시간은 전체 경로에 비례 배분합니다. 좌표는 **월드 좌표**입니다. 이 이동은 연출자가 통로를 정하는 동작이지 장애물을 자동 탐색하는 길찾기가 아닙니다. 모서리를 돌아야 하면 경유점을 지정하세요. 기본 완료 상태는 Hold입니다.

`rejoin: true`는 이동 완료 지점이 남아 있는 추종 경로 위일 때만 Follow로 복귀합니다. 경로 밖이거나 기록이 만료되면 실패·Hold이며 벽을 가로지르거나 자동 순간 이동하지 않습니다.

### 암전에서 다시 모으기

```yaml
- screen.fade: { mode: out, color: black, duration: 0.2 }
- overworld.party.gather: {}
- screen.fade: { mode: in, color: black, duration: 0.2 }
```

Gather는 작성자가 화면이 가려지는 것을 보장하고 호출하는 **명시적 재배치**입니다. 모든 동료를 리더 위치로 모으고 기본 Follow/표시로 초기화합니다. 아직 걸은 경로가 없으므로 잠시 겹쳐 있다가 실제 이동을 시작하면 줄이 펴집니다. 벽 안에 가상의 시작 줄을 만들지 않습니다.

## 5. 자동으로 처리하는 경계

| 상황 | 처리 |
| --- | --- |
| 대화·메뉴·진입 대기 | 일반 추종 정지. 연출이 직접 요청한 이동과 구분 |
| 심리스 전투 시작 | 기존 암전 이후 필드 동료 숨김. 전투 참가자는 기존 전투 시스템 사용 |
| 전투 종료·방 이동·위치 복원 | 옛 이동 명령 취소, 경로 세대 갱신, 도착 위치에서 재집결 |
| 새 이동·고정 명령 | 그 동료가 소유한 이전 이동만 취소 |
| 리더 종료·실제 파티 교체 | 소유 표시·Tween·명령 정리. 늦은 콜백은 새 위치를 덮지 않음 |

고정·숨김·임시 이탈은 방 단위 runtime 연출 상태이며 저장하지 않습니다. 다음 방에서도 이야기상 이탈해야 한다면 기존 진행 플래그/실제 파티 정책으로 결정하고 방 진입 시퀀스에서 다시 적용하세요. 카메라는 리더·기존 Confiner·기본 렌즈를 유지하며 동료 때문에 자동 확대/축소하지 않습니다. 연출 카메라는 기존 카메라 시스템을 사용합니다.

## 6. 문제가 생기면 확인할 순서

| 증상 | 먼저 볼 것 |
| --- | --- |
| 동료가 안 보임 | 실제 파티 합류 여부 → 최대 동료 수 → 외형 연결 → 숨김/전투 상태 |
| 같은 그림 두 동료 중 한 명이 안 보임 | 초기 위치 겹침인지 이동하며 확인. 같은 DB ID를 임의로 합치지 않음 |
| 정지 그림만 보임 | 표시 전용 Animator의 기본 상태와 MoveX/MoveY/IsMoving 파라미터 |
| Follow 재개가 실패함 | 기록 만료/경로 밖/진행 중 이동 여부. 경유점으로 복귀하거나 암전 Gather 사용 |
| 문·전투가 반복 발동 | 표시 원본에 플레이어·Collider를 직접 복제하지 않았는지 확인 |
| 실험실에서 동료가 중복됨 | 기존 Lab preview와 일반 필드 추종을 함께 강제로 구성하지 않았는지 확인 |

최종 확인은 제작자가 일반 필드에서 합니다: ㄱ자 통로·좁은 문·대각선 이동·달리기·고정/해제·개별 이동 취소·방 이동·전투 왕복·기존 저장 로드. CLI/관리형 검사는 실제 엔진 재생·모바일 발열·프레임을 대신하지 않습니다.
